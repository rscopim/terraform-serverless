🐙 Git & GitHub — Módulo 02

Branches — Trabalhando em Paralelo

Branches são o recurso que torna o Git tão poderoso. Elas permitem desenvolver funcionalidades, corrigir bugs e experimentar em linhas de trabalho isoladas, sem afetar o código principal. Neste módulo você aprende a criar, alternar, mergear e organizar branches como um profissional.

Seção 1

O que é uma Branch

Entender o que uma branch realmente é — e não apenas como usá-la — desmistifica todo o resto.

🌿 Branch é um Ponteiro

Ao contrário do que muitos imaginam, uma branch no Git não é uma "cópia" da pasta. É apenas um ponteiro leve para um commit específico. Quando você faz um novo commit, o ponteiro da branch atual avança automaticamente. Criar uma branch é uma operação instantânea e barata — o Git só escreve 40 bytes (o hash de um commit) em um arquivo.

Visualizando Branches como Ponteiros

          C0 ─── C1 ─── C2  ◀── main  (HEAD)
                          │
                          └─── C3 ◀── feature/login

# main aponta para C2
# feature/login aponta para C3
# HEAD indica em qual branch você está agora

💡 O que é o HEAD?

O HEAD é um ponteiro especial que indica em qual branch (e commit) você está no momento. Quando você troca de branch com git switch, o HEAD passa a apontar para a nova branch, e o Git atualiza os arquivos do working directory para refletirem aquele commit.

Seção 2

Criando e Alternando Branches

O Git moderno (2.23+) introduziu git switch e git restore para separar responsabilidades que antes eram todas do git checkout.

🔀 Comandos Essenciais

# Listar branches (a atual tem *)
git branch

# Listar também as remotas
git branch -a

# Criar uma branch nova (sem trocar para ela)
git branch feature/login

# Trocar de branch (forma moderna)
git switch feature/login

# Criar E trocar em um só comando
git switch -c feature/login
# equivalente antigo:
git checkout -b feature/login

# Voltar para a branch anterior (como 'cd -')
git switch -

# Renomear a branch atual
git branch -m novo-nome

# Deletar uma branch (já mergeada)
git branch -d feature/login

# Forçar deleção (mesmo sem merge — cuidado!)
git branch -D feature/experimento

💡 switch vs checkout

git switch serve apenas para trocar/criar branches — mais claro e seguro. git checkout ainda funciona e faz muito mais (trocar branch, restaurar arquivos, ir a commits), mas justamente por ser sobrecarregado gera confusão. Prefira switch e restore no dia a dia.

Seção 3

Merge — Integrando Branches

Depois de terminar o trabalho em uma branch, você integra as mudanças de volta com git merge. Existem dois tipos principais de merge, e entender a diferença ajuda a ler o histórico.

⏩ Fast-Forward Merge

Acontece quando a branch de destino não teve novos commits desde que a branch de trabalho foi criada. O Git apenas "avança" o ponteiro — não cria commit de merge.

# Situação: main não mudou desde que feature nasceu
#   C0 ─ C1 ◀── main
#          └─ C2 ─ C3 ◀── feature

git switch main
git merge feature
# Fast-forward! main agora aponta para C3
#   C0 ─ C1 ─ C2 ─ C3 ◀── main, feature

🔗 Three-Way Merge (com commit de merge)

Acontece quando ambas as branches evoluíram. O Git cria um novo "commit de merge" que une as duas histórias.

# Situação: main E feature receberam commits
#   C0 ─ C1 ─ C4 ◀── main
#          └─ C2 ─ C3 ◀── feature

git switch main
git merge feature
# Cria um commit de merge C5 com dois pais (C4 e C3)
#   C0 ─ C1 ─ C4 ─── C5 ◀── main
#          └─ C2 ─ C3 ─┘

# Forçar sempre um commit de merge (mesmo quando FF seria possível)
git merge --no-ff feature

# Merge sem commitar (para revisar antes)
git merge --no-commit feature

💡 --no-ff em times

Muitos times usam --no-ff em merges de feature para preservar no histórico o "agrupamento" de commits daquela funcionalidade. Assim fica visível onde uma feature começou e terminou, mesmo que um fast-forward fosse possível.

Seção 4

git stash — Guardando Trabalho Temporário

Às vezes você está no meio de uma mudança e precisa trocar de branch com urgência (um bug em produção!). O stash guarda suas alterações não commitadas em uma pilha temporária.

📦 Usando o Stash

# Guardar mudanças atuais (working dir fica limpo)
git stash

# Guardar com uma descrição
git stash push -m "wip: formulário de contato pela metade"

# Guardar incluindo arquivos untracked
git stash -u

# Listar stashes guardados
git stash list
# stash@{0}: On main: wip: formulário...
# stash@{1}: On feature: ...

# Aplicar o stash mais recente e removê-lo da pilha
git stash pop

# Aplicar sem remover da pilha
git stash apply stash@{1}

# Ver o conteúdo de um stash
git stash show -p stash@{0}

# Descartar um stash
git stash drop stash@{0}

# Limpar todos os stashes
git stash clear

🎯 Caso de uso clássico

# Você está codando uma feature e surge um bug urgente
git stash push -m "feature pela metade"
git switch main
git switch -c hotfix/bug-critico
# ... corrige, commita, faz merge ...
git switch feature/minha-feature
git stash pop     # retoma de onde parou
Seção 5

Convenções de Nomes de Branch

Nomes de branch padronizados tornam o repositório legível e facilitam automações (CI/CD que dispara por prefixo, por exemplo).

🏷️ Padrão Recomendado

PrefixoUsoExemplo
feature/Nova funcionalidadefeature/login-google
fix/Correção de bugfix/calculo-total
hotfix/Correção urgente em produçãohotfix/pagamento-500
refactor/Refatoração sem mudar comportamentorefactor/servico-email
docs/Documentaçãodocs/readme-api
chore/Tarefas de manutençãochore/atualiza-deps

✅ Boas práticas de nomeação

  • Use letras minúsculas e hífens (kebab-case)
  • Seja descritivo mas conciso
  • Inclua o número da issue quando existir: feature/123-login-google
  • Evite espaços, acentos e caracteres especiais
Seção 6

Branches Remotas e Tracking

Branches locais e remotas são entidades distintas. Entender o vínculo entre elas evita confusão ao colaborar.

🌐 Trabalhando com Branches Remotas

# Publicar uma branch local no remoto (e vincular)
git push -u origin feature/login

# Listar branches remotas
git branch -r

# Baixar referências de branches remotas novas
git fetch origin

# Criar branch local a partir de uma remota
git switch -c feature/login origin/feature/login
# (Git moderno detecta e vincula automaticamente:)
git switch feature/login

# Ver o vínculo (tracking) de cada branch
git branch -vv

# Deletar uma branch remota
git push origin --delete feature/antiga

# Limpar referências a branches remotas que não existem mais
git fetch --prune
Seção 7

Exercício Prático e Resumo

Vamos praticar um fluxo completo com branches, do nascimento ao merge e limpeza.

🧪 Fluxo Completo com Branch

# 1. Partir da main atualizada
git switch main
git pull

# 2. Criar branch de feature
git switch -c feature/saudacao

# 3. Fazer mudanças e commitar
echo "Olá, mundo!" > saudacao.txt
git add saudacao.txt
git commit -m "feat: adiciona arquivo de saudação"

# 4. Publicar a branch
git push -u origin feature/saudacao

# 5. Voltar para main e integrar
git switch main
git merge --no-ff feature/saudacao -m "merge: integra saudação"

# 6. Enviar main atualizada
git push

# 7. Limpar a branch (local e remota)
git branch -d feature/saudacao
git push origin --delete feature/saudacao

🎯 Resumo do Módulo 02

Você entendeu que branches são ponteiros leves, aprendeu a criar/alternar (switch), integrar (merge fast-forward e 3-way), guardar trabalho temporário (stash), seguir convenções de nomes e trabalhar com branches remotas. Na prática, quase todo trabalho profissional acontece em branches — nunca direto na main. No Módulo 03, veremos como colaborar via Pull Requests no GitHub.
