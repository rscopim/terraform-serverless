🐙 Git & GitHub — Módulo 01

Fundamentos do Git

Domine os comandos que você usará todos os dias: iniciar repositórios, rastrear mudanças, criar commits, sincronizar com o GitHub e navegar pelo histórico. Entenda o modelo mental das três áreas do Git — a chave para nunca mais ficar perdido sobre o estado dos seus arquivos.

Seção 1

O Modelo Mental do Git — Três Áreas

Entender como o Git organiza os arquivos é o conceito mais importante deste módulo. Uma vez que você "vê" as três áreas, todos os comandos passam a fazer sentido.

🗂️ Working Directory, Staging Area e Repository

O Git movimenta arquivos entre três áreas conceituais:

ÁreaO que éComando que leva até ela
Working Directory Seus arquivos como estão no disco, onde você edita (edição de arquivos)
Staging Area (Index) Área de preparação — o que entrará no próximo commit git add
Repository (.git) Histórico permanente de commits git commit

O Fluxo Básico Visualizado

  Working Directory          Staging Area           Repository
  ─────────────────          ────────────           ──────────
   edito arquivo.txt
          │
          │  git add arquivo.txt
          └──────────────────────▶ arquivo.txt (staged)
                                        │
                                        │  git commit -m "..."
                                        └──────────────────────▶ commit abc123
                                                                      │
                                                                      │  git push
                                                                      └──────▶ GitHub

💡 Por que existe a staging area?

Ela permite que você monte commits precisos. Você pode ter editado 5 arquivos, mas fazer commit de apenas 2 deles agora (relacionados a uma mesma mudança) e os outros 3 depois. Isso gera um histórico limpo, onde cada commit representa uma unidade lógica de trabalho.

📊 Os Estados de um Arquivo

EstadoSignificado
UntrackedNovo arquivo que o Git ainda não rastreia
ModifiedArquivo rastreado que foi alterado, mas não staged
StagedAlteração preparada para o próximo commit
Committed / UnmodifiedArquivo salvo no repositório, sem mudanças pendentes
Seção 2

Iniciando um Repositório — init e clone

Há duas formas de começar: criar um repositório novo do zero (init) ou baixar um existente (clone).

🌱 git init — Criando do Zero

Repositório Local Novo

# Criar uma pasta e iniciar o repositório
mkdir meu-projeto
cd meu-projeto
git init
# Initialized empty Git repository in .../meu-projeto/.git/

# O que aconteceu: foi criada a pasta oculta .git/
# que armazena TODO o histórico e a configuração do repo

# Ver o estado inicial
git status
# On branch main
# No commits yet
# nothing to commit

# Conectar a um repositório remoto no GitHub (criado vazio)
git remote add origin git@github.com:seuuser/meu-projeto.git
git remote -v   # verificar

📥 git clone — Baixando um Existente

Clonando do GitHub

# Via SSH (recomendado se você configurou chave)
git clone git@github.com:usuario/repositorio.git

# Via HTTPS
git clone https://github.com/usuario/repositorio.git

# Clonar em uma pasta com nome diferente
git clone git@github.com:usuario/repo.git minha-pasta

# Clonar apenas a última versão (shallow — mais rápido, sem histórico)
git clone --depth 1 git@github.com:usuario/repo.git

# Clonar uma branch específica
git clone -b develop git@github.com:usuario/repo.git

# O clone já configura o remote 'origin' automaticamente
Seção 3

Rastreando Mudanças — add e commit

O ciclo central do Git: você edita, adiciona ao staging e faz commit. Vamos detalhar cada comando com suas variações mais úteis.

➕ git add — Preparando Mudanças

Variações do add

# Adicionar um arquivo específico
git add arquivo.txt

# Adicionar vários arquivos
git add arquivo1.txt arquivo2.txt

# Adicionar todos os arquivos de uma pasta
git add src/

# Adicionar TUDO que mudou (novos, modificados, deletados)
git add .
git add -A          # equivalente, funciona de qualquer subpasta

# Adicionar interativamente (escolher trechos de um arquivo)
git add -p arquivo.txt
# y = incluir trecho, n = pular, s = dividir, q = sair

# Tirar um arquivo do staging (sem perder as edições)
git restore --staged arquivo.txt
# ou (Git antigo):
git reset HEAD arquivo.txt

💾 git commit — Salvando no Histórico

Formas de Fazer Commit

# Commit com mensagem inline
git commit -m "feat: adiciona validação de e-mail no formulário"

# Commit com título e corpo (boa prática para mudanças relevantes)
git commit -m "feat: adiciona cache de respostas" -m "Reduz chamadas à API em 60% usando um cache LRU de 5 minutos."

# Adicionar ao staging e commitar de uma vez (só arquivos JÁ rastreados)
git commit -am "fix: corrige cálculo de total"

# Abrir o editor para escrever a mensagem
git commit

# Corrigir o ÚLTIMO commit (mensagem ou arquivos esquecidos)
git add arquivo-esquecido.txt
git commit --amend -m "mensagem corrigida"
# ⚠️ Só faça amend em commits que ainda NÃO foram enviados (push)

✍️ Anatomia de uma boa mensagem de commit

  • Título curto (até ~50 caracteres), no imperativo: "adiciona", "corrige", "remove"
  • Linha em branco entre título e corpo
  • Corpo (opcional) explicando o porquê, não o como
  • Prefixos convencionais ajudam: feat:, fix:, docs:, refactor: (veremos SemVer e Conventional Commits no Módulo 06)
Seção 4

Inspecionando o Repositório

Saber o estado atual e o histórico é essencial. Estes comandos são os seus "olhos" no Git.

🔍 git status — O Estado Atual

# Estado completo
git status

# Formato resumido (mais rápido de ler)
git status -s
#  M arquivo.txt      → modificado, não staged
# M  outro.txt        → modificado e staged
# ?? novo.txt         → untracked
# A  adicionado.txt   → novo arquivo staged

📝 git diff — Vendo as Diferenças

# Mudanças no working directory (ainda não staged)
git diff

# Mudanças que já estão staged (o que entrará no commit)
git diff --staged      # ou --cached

# Diferença entre dois commits
git diff abc123 def456

# Diferença de um arquivo específico
git diff arquivo.txt

# Resumo estatístico (arquivos e linhas alteradas)
git diff --stat

📜 git log — Navegando o Histórico

# Histórico completo
git log

# Uma linha por commit (compacto)
git log --oneline

# Com grafo de branches e decoração
git log --oneline --graph --decorate --all

# Últimos 5 commits
git log -5

# Filtrar por autor ou por mensagem
git log --author="Ricardo"
git log --grep="fix"

# Ver o que mudou em cada commit
git log -p

# Ver quem alterou cada linha de um arquivo
git blame arquivo.txt
Seção 5

Sincronizando — push, pull e fetch

Até aqui tudo foi local. Estes comandos conectam seu repositório ao GitHub, enviando e recebendo mudanças.

⬆️ git push — Enviando Commits

# Primeiro push de uma branch nova (define o upstream)
git push -u origin main
# -u (--set-upstream) vincula a branch local à remota;
# depois disso, basta 'git push'

# Pushes seguintes
git push

# Enviar uma branch específica
git push origin feature/login

# Enviar tags
git push --tags

⬇️ git pull e git fetch — Recebendo Mudanças

# fetch: baixa as mudanças do remoto SEM aplicá-las
git fetch origin
# Você pode inspecionar antes de integrar

# pull: fetch + merge (baixa E integra na sua branch)
git pull
git pull origin main

# pull com rebase (histórico mais linear)
git pull --rebase

# Ver as diferenças entre local e remoto após um fetch
git log HEAD..origin/main --oneline

⚠️ fetch vs pull

fetch é seguro: só baixa, não muda seus arquivos. pull baixa E integra automaticamente, o que pode gerar merges ou conflitos inesperados. Se quiser controle, use fetch e depois merge/rebase manualmente.

Seção 6

.gitignore — Ignorando Arquivos

Nem tudo deve ir para o repositório: dependências, arquivos de build, segredos, caches. O .gitignore diz ao Git o que ignorar.

🚫 Sintaxe e Padrões

Exemplo de .gitignore

# Comentários começam com #

# Ignorar um arquivo específico
config.local.json

# Ignorar por extensão
*.log
*.tmp

# Ignorar uma pasta inteira
node_modules/
dist/
__pycache__/

# Ignorar tudo em uma pasta, MAS manter um arquivo
logs/*
!logs/.gitkeep

# Ignorar arquivos de ambiente e segredos (MUITO IMPORTANTE)
.env
.env.*
*.pem
*.key
credentials

# Padrões específicos de IDEs / SO
.vscode/
.idea/
.DS_Store
Thumbs.db

⚠️ Já commitei um arquivo que deveria ser ignorado!

Adicionar ao .gitignore não remove arquivos já rastreados. Use:

# Remove do rastreamento (mantém no disco), depois commit
git rm --cached arquivo-secreto.env
git commit -m "chore: remove arquivo sensível do versionamento"

# Se um SEGREDO foi commitado, considere-o COMPROMETIDO:
# rotacione a credencial imediatamente — remover do histórico não basta

💡 Templates prontos

O site gitignore.io e o repositório github/gitignore oferecem templates prontos por linguagem/ferramenta (Node, Python, Terraform, etc.). Ao criar um repo no GitHub, você pode escolher um .gitignore inicial automaticamente.

Seção 7

Desfazendo Mudanças e Exercício Guiado

Erros acontecem. Saber desfazer com segurança é tão importante quanto saber fazer. E ao final, um exercício que junta tudo.

↩️ Desfazendo com Segurança

# Descartar mudanças de um arquivo (volta ao último commit)
git restore arquivo.txt
# ⚠️ perde as edições não commitadas!

# Tirar do staging (mantém as edições)
git restore --staged arquivo.txt

# Desfazer o último commit MAS manter as mudanças no working dir
git reset --soft HEAD~1

# Desfazer o último commit e as mudanças do staging
git reset --mixed HEAD~1     # (padrão)

# Desfazer o último commit E descartar tudo (PERIGOSO)
git reset --hard HEAD~1

# Reverter um commit criando um NOVO commit que o desfaz (seguro p/ histórico público)
git revert abc123

⚠️ reset --hard e histórico já enviado

Nunca use reset --hard ou reescreva commits que já foram enviados (push) e que outras pessoas podem ter baixado. Para desfazer algo público, prefira git revert, que adiciona um commit de reversão sem apagar o histórico. Reescrita de histórico é tema do Módulo 05.

🧪 Exercício Guiado — Seu Primeiro Repositório Completo

Do init ao push, passo a passo

# 1. Criar e iniciar
mkdir meu-primeiro-repo && cd meu-primeiro-repo
git init

# 2. Criar um .gitignore
echo ".env" > .gitignore
echo "node_modules/" >> .gitignore

# 3. Criar um arquivo
echo "# Meu Primeiro Repositório" > README.md

# 4. Verificar o estado
git status        # README.md e .gitignore aparecem como untracked

# 5. Preparar e commitar
git add .
git status        # agora estão staged
git commit -m "chore: commit inicial com README e gitignore"

# 6. Ver o histórico
git log --oneline

# 7. Conectar ao GitHub (crie um repo vazio antes)
git remote add origin git@github.com:seuuser/meu-primeiro-repo.git
git branch -M main
git push -u origin main

# 🎉 Seu código está no GitHub!

🎯 Resumo do Módulo 01

Você domina agora o ciclo fundamental do Git: o modelo das três áreas, iniciar repositórios (init/clone), rastrear mudanças (add/commit), inspecionar (status/diff/log), sincronizar com o GitHub (push/pull/fetch), ignorar arquivos (.gitignore) e desfazer com segurança. Estes comandos representam 80% do uso diário. No Módulo 02, entramos no recurso mais poderoso do Git: branches.
