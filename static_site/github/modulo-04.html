🐙 Git & GitHub — Módulo 04

Resolução de Conflitos de Merge

Conflitos assustam iniciantes, mas são normais e totalmente gerenciáveis. Neste módulo você entende por que eles acontecem, aprende a ler os marcadores de conflito, a resolvê-los manualmente e com ferramentas visuais, e — o mais importante — a adotar hábitos que previnem conflitos difíceis.

Seção 1

Por que Conflitos Acontecem

Um conflito ocorre quando o Git não consegue decidir automaticamente como combinar duas mudanças. Entender a causa raiz ajuda a resolvê-los com confiança.

⚔️ A Origem de um Conflito

O Git resolve merges automaticamente na maioria das vezes. Mas quando a mesma região do mesmo arquivo foi alterada de formas diferentes em duas branches, o Git não tem como saber qual versão você quer — e pede sua intervenção.

💡 Quando o Git resolve sozinho vs quando pede ajuda

  • Resolve sozinho: mudanças em arquivos diferentes, ou em linhas distantes do mesmo arquivo
  • Pede ajuda (conflito): mudanças nas mesmas linhas, ou um lado editou e o outro deletou o arquivo

Exemplo que Gera Conflito

# Na branch main, a linha 1 do arquivo é:
#   titulo = "Bem-vindo"

# Você (feature) muda para:
#   titulo = "Olá, visitante"

# Um colega (main) muda a MESMA linha para:
#   titulo = "Seja bem-vindo"

# Ao mergear, o Git não sabe qual manter → CONFLITO
Seção 2

Lendo os Marcadores de Conflito

Quando ocorre um conflito, o Git insere marcadores especiais no arquivo. Saber lê-los é o primeiro passo para resolver.

🔖 Anatomia dos Marcadores

<<<<<<< HEAD
titulo = "Seja bem-vindo"        ← versão da branch ATUAL (onde você está)
=======
titulo = "Olá, visitante"        ← versão da branch que está sendo integrada
>>>>>>> feature/nova-saudacao

# Interpretação:
# <<<<<<< HEAD      → início da SUA versão
# =======            → divisor
# >>>>>>> branch    → fim da versão que vem da OUTRA branch

Resolvendo: você escolhe o resultado final

# Edite o arquivo removendo os marcadores e deixando o texto correto.
# Pode escolher um lado, o outro, ou combinar os dois:

titulo = "Olá, seja bem-vindo, visitante"

# Depois marque como resolvido e finalize
git add arquivo.txt
git commit          # conclui o merge (mensagem já vem preenchida)
Seção 3

Resolvendo Conflitos Passo a Passo

Vamos ao processo completo, desde detectar o conflito até finalizar a resolução com segurança.

🛠️ O Processo de Resolução

# 1. Ao mergear, o Git avisa do conflito
git merge feature/nova-saudacao
# CONFLICT (content): Merge conflict in index.html
# Automatic merge failed; fix conflicts and then commit the result.

# 2. Ver quais arquivos estão em conflito
git status
# Unmerged paths:
#   both modified:   index.html

# 3. Abrir o arquivo, resolver os marcadores manualmente
#    (ou use um editor com suporte a merge, como o VS Code)

# 4. Marcar cada arquivo resolvido
git add index.html

# 5. Verificar que não sobrou conflito
git status        # deve mostrar "All conflicts fixed"

# 6. Concluir o merge
git commit

# Se quiser ABORTAR o merge e voltar ao estado anterior:
git merge --abort

⚠️ Escolhendo um lado inteiro

# Aceitar a versão da branch ATUAL para um arquivo
git checkout --ours arquivo.txt

# Aceitar a versão da OUTRA branch
git checkout --theirs arquivo.txt

git add arquivo.txt
# ⚠️ Cuidado: isso descarta completamente o outro lado daquele arquivo

🔄 Conflitos Durante Rebase

Conflitos também ocorrem em rebase (Módulo 05). O fluxo é parecido, mas os comandos de continuação são diferentes:

# Durante um rebase com conflito:
# 1. Resolva os marcadores no arquivo
# 2. Marque como resolvido
git add arquivo.txt
# 3. Continue o rebase (NÃO use git commit aqui!)
git rebase --continue

# Pular o commit problemático
git rebase --skip

# Abortar o rebase inteiro
git rebase --abort

# ⚠️ Note: no merge você usa 'git commit'; no rebase, 'git rebase --continue'
Seção 4

Ferramentas de Merge

Resolver conflitos "na mão" funciona, mas ferramentas visuais tornam o processo muito mais rápido e seguro, especialmente em conflitos grandes.

🖥️ VS Code e mergetool

# O VS Code detecta conflitos e mostra botões:
# "Accept Current Change" | "Accept Incoming Change"
# "Accept Both Changes"   | "Compare Changes"
# Além de uma visão de 3 painéis (3-way merge editor)

# Configurar uma ferramenta de merge externa
git config --global merge.tool vscode
git config --global mergetool.vscode.cmd 'code --wait $MERGED'

# Abrir a ferramenta configurada nos arquivos em conflito
git mergetool

# Outras ferramentas populares: meld, kdiff3, Beyond Compare, p4merge

# Evitar arquivos .orig deixados pelo mergetool
git config --global mergetool.keepBackup false

💡 Diff3 — vendo a base comum

# Mostrar também a versão ORIGINAL (ancestral comum) nos marcadores
git config --global merge.conflictStyle diff3
# ou zdiff3 (Git 2.35+, mais enxuto)
git config --global merge.conflictStyle zdiff3
# Isso adiciona uma seção ||||||| com o código-base,
# ajudando a entender o que cada lado mudou
Seção 5

Prevenindo Conflitos

O melhor conflito é o que não acontece. Bons hábitos de trabalho reduzem drasticamente a frequência e a gravidade dos conflitos.

🛡️ Estratégias de Prevenção

Hábitos que evitam conflitos

  • Sincronize com frequência: faça pull da main várias vezes ao dia
  • Branches curtas: quanto mais tempo uma branch vive, mais ela diverge
  • PRs pequenos: mudanças menores conflitam menos e são revisadas mais rápido
  • Comunicação: combine com o time quem mexe em quais arquivos
  • Formatação consistente: um formatador automático (Prettier, Black) evita conflitos "cosméticos"
  • Rebase sua branch na main antes de abrir o PR para pegar conflitos cedo

Mantendo sua Branch Atualizada

# Trazer as novidades da main para sua branch regularmente
git switch feature/minha-feature
git fetch origin
git merge origin/main          # ou: git rebase origin/main

# Resolvendo conflitos cedo, aos poucos, é muito mais fácil
# do que enfrentar um conflito gigante no dia do merge final

🧰 git rerere — Reaproveitando Resoluções

# rerere = "reuse recorded resolution"
# O Git memoriza como você resolveu um conflito e reaplica
# automaticamente se o mesmo conflito reaparecer (comum em rebases longos)

git config --global rerere.enabled true

# Muito útil quando você rebaseia a mesma branch várias vezes
# e enfrenta os mesmos conflitos repetidamente
Seção 6

Conflitos no GitHub (Web)

PRs com conflitos podem ser resolvidos direto na interface do GitHub para casos simples, ou localmente para casos complexos.

🌐 Resolvendo pela Interface

# Quando um PR tem conflito, o GitHub mostra:
# "This branch has conflicts that must be resolved"

# Para conflitos SIMPLES: botão "Resolve conflicts" abre um
# editor web onde você remove os marcadores e marca como resolvido.

# Para conflitos COMPLEXOS: resolva localmente
git switch feature/minha-branch
git fetch origin
git merge origin/main
# ... resolve os conflitos localmente ...
git add . && git commit
git push
# O PR atualiza automaticamente e o conflito some
Seção 7

Exercício Prático e Resumo

Crie um conflito de propósito e resolva-o — a melhor forma de perder o medo.

🧪 Criando e Resolvendo um Conflito

# 1. Preparar
mkdir teste-conflito && cd teste-conflito && git init
echo "cor = azul" > config.txt
git add . && git commit -m "inicial"

# 2. Criar conflito em duas branches
git switch -c branch-a
echo "cor = vermelho" > config.txt
git commit -am "muda cor para vermelho"

git switch main
git switch -c branch-b
echo "cor = verde" > config.txt
git commit -am "muda cor para verde"

# 3. Mergear branch-a na main
git switch main
git merge branch-a       # fast-forward, sem conflito

# 4. Mergear branch-b → CONFLITO!
git merge branch-b
# CONFLICT (content): Merge conflict in config.txt

# 5. Resolver
git status               # vê o arquivo em conflito
# edite config.txt, escolha o resultado (ex: cor = vermelho)
git add config.txt
git commit

# 6. Confirmar
git log --oneline --graph

🎯 Resumo do Módulo 04

Conflitos deixaram de ser um bicho de sete cabeças. Você entende por que ocorrem, sabe ler e resolver os marcadores (<<<, ===, >>>), usa ferramentas visuais, aplica --ours/--theirs quando faz sentido, lida com conflitos em rebase e — principalmente — adota hábitos que os previnem. No Módulo 05, aprendemos a reescrever o histórico com rebase, cherry-pick e reset.
