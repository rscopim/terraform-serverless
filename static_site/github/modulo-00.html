Seção 1

Git vs GitHub — Entendendo a Diferença

Muita gente confunde os dois, mas são coisas distintas e complementares. Entender essa diferença é o primeiro passo para usar as ferramentas com propriedade.

🔧 O que é o Git

O Git é um sistema de controle de versão distribuído (DVCS) criado por Linus Torvalds em 2005 para o desenvolvimento do kernel Linux. Ele roda localmente na sua máquina e rastreia mudanças em arquivos ao longo do tempo, permitindo que você reverta versões, trabalhe em paralelo através de branches e colabore sem sobrescrever o trabalho dos outros.

💡 "Distribuído" significa o quê?

Diferente de sistemas centralizados antigos (como SVN), no Git cada desenvolvedor tem uma cópia completa do repositório e de todo o histórico. Você pode fazer commits, criar branches e navegar pelo histórico totalmente offline. A sincronização com o servidor remoto acontece apenas quando você quer (push/pull).

🐙 O que é o GitHub

O GitHub é uma plataforma de hospedagem de repositórios Git na nuvem, com recursos de colaboração construídos por cima do Git: Pull Requests, Issues, Actions (CI/CD), Projects, Pages, revisão de código e controle de acesso. É onde o código "vive" quando compartilhado com o time ou com o mundo. Alternativas incluem GitLab e Bitbucket.

Seção 2

Instalação do Git em Cada Sistema

O Git está disponível em todos os sistemas operacionais. Veja como instalar e verificar a instalação em cada plataforma.

💻 Instalando em Windows, macOS e Linux

Windows

# Opção 1: winget (Windows 10/11)
winget install --id Git.Git -e

# Opção 2: baixar de git-scm.com
# Inclui o Git Bash (terminal estilo Unix)

# Opção 3: Chocolatey
choco install git

# Verificar
git --version

macOS

# Opção 1: Homebrew (recomendado)
brew install git

# Opção 2: Xcode Command Line Tools
xcode-select --install

# Verificar
git --version

Linux

# Debian / Ubuntu
sudo apt update && sudo apt install git

# Fedora / RHEL
sudo dnf install git

# Arch
sudo pacman -S git

# Verificar
git --version

📌 Mantendo o Git atualizado

Versões novas do Git trazem melhorias de segurança e desempenho. Verifique periodicamente com git --version e atualize pelo mesmo gerenciador usado na instalação. A partir do Git 2.28 é possível definir o nome da branch inicial (veremos a seguir), recurso importante para o padrão main.

Seção 3

Configuração com git config

Antes do primeiro commit, o Git precisa saber quem você é. A configuração também define preferências que tornam seu fluxo de trabalho mais produtivo. Entender os níveis de configuração evita muita confusão.

🎚️ Os Três Níveis de Configuração

O Git lê configurações em cascata, do mais geral para o mais específico. O nível mais específico sempre vence.

Nível Flag Arquivo Escopo
System --system /etc/gitconfig Todos os usuários da máquina
Global --global ~/.gitconfig Seu usuário (todos os repos)
Local --local .git/config Apenas o repositório atual

⚙️ Configuração Inicial Essencial

Identidade e Preferências Globais

# IDENTIDADE (obrigatório — aparece em cada commit)
git config --global user.name "Seu Nome"
git config --global user.email "seu@email.com"

# BRANCH PADRÃO como main (Git 2.28+)
git config --global init.defaultBranch main

# EDITOR padrão para mensagens de commit
git config --global core.editor "code --wait"   # VS Code
# git config --global core.editor "nano"         # nano
# git config --global core.editor "vim"          # vim

# COMPORTAMENTO do pull (evita merges automáticos indesejados)
git config --global pull.rebase false   # merge (padrão)
# git config --global pull.rebase true  # rebase

# CORES no terminal
git config --global color.ui auto

# NORMALIZAÇÃO de fim de linha (importante em times multiplataforma)
git config --global core.autocrlf input   # Linux/macOS
# git config --global core.autocrlf true   # Windows

# Verificar tudo
git config --list --show-origin

⚠️ E-mail privado no GitHub

Se não quiser expor seu e-mail real nos commits públicos, o GitHub oferece um e-mail no-reply (ID+usuario@users.noreply.github.com) em Settings → Emails. Configure-o com git config --global user.email e ative "Keep my email addresses private".

🔗 Aliases — Atalhos que Economizam Tempo

Criando Atalhos para Comandos Frequentes

# Atalhos comuns
git config --global alias.st status
git config --global alias.co checkout
git config --global alias.br branch
git config --global alias.ci commit
git config --global alias.unstage "reset HEAD --"

# Um log bonito e resumido
git config --global alias.lg "log --oneline --graph --decorate --all"

# Agora você usa:
git st          # em vez de git status
git lg          # log visual com grafo de branches
Seção 4

Autenticação com Chaves SSH

SSH é a forma mais segura e conveniente de se autenticar no GitHub. Você gera um par de chaves (pública e privada), adiciona a pública ao GitHub, e nunca mais digita senha ao fazer push/pull.

🔐 Gerando e Configurando a Chave SSH

Passo a Passo Completo

# 1. Gerar par de chaves Ed25519 (mais moderno e seguro que RSA)
ssh-keygen -t ed25519 -C "seu@email.com"
# Pressione Enter para aceitar o local padrão (~/.ssh/id_ed25519)
# Defina uma passphrase (recomendado) ou deixe em branco

# 2. Iniciar o ssh-agent (gerencia as chaves em memória)
eval "$(ssh-agent -s)"

# 3. Adicionar a chave privada ao agent
ssh-add ~/.ssh/id_ed25519

# 4. Copiar a chave PÚBLICA para adicionar no GitHub
cat ~/.ssh/id_ed25519.pub          # Linux/macOS — copie a saída
# clip < ~/.ssh/id_ed25519.pub     # Windows
# pbcopy < ~/.ssh/id_ed25519.pub   # macOS

# 5. No GitHub: Settings → SSH and GPG keys → New SSH key
#    Cole a chave pública e salve

# 6. Testar a conexão
ssh -T git@github.com
# Resposta esperada:
# Hi seuusuario! You've successfully authenticated...

⚠️ Chave pública vs privada

  • Chave pública (.pub): pode ser compartilhada — é o que você cola no GitHub
  • Chave privada (sem extensão): NUNCA compartilhe ou faça commit dela. É o seu segredo

Seção 5

Tokens de Acesso Pessoal (PAT)

Desde 2021 o GitHub não aceita mais senha para operações Git via HTTPS. No lugar, você usa Personal Access Tokens (PAT). Eles também são usados para autenticar em APIs e ferramentas de terceiros.

🎟️ Criando e Usando um PAT

Fluxo de Criação

# No GitHub:
# Settings → Developer settings → Personal access tokens
#   → Fine-grained tokens (recomendado) OU Tokens (classic)
#
# Fine-grained tokens permitem escopo por repositório e permissões
# granulares (Contents: read/write, Issues, Pull requests, etc.)
#
# Defina:
# - Nome descritivo (ex: "laptop-pessoal-2026")
# - Expiração (evite "no expiration" — prefira 90 dias)
# - Repositórios e permissões mínimas necessárias

# Ao clonar via HTTPS, use o token como senha:
git clone https://github.com/user/repo.git
# Username: seu-usuario
# Password: cole-o-token-aqui (NÃO sua senha)

# Armazenar credenciais para não digitar toda vez
git config --global credential.helper store        # texto plano (cuidado)
git config --global credential.helper manager       # Windows (seguro)
git config --global credential.helper osxkeychain    # macOS (seguro)

🔒 Boas práticas de tokens

  • Use fine-grained tokens com o menor escopo possível (least privilege)
  • Sempre defina data de expiração — tokens eternos são risco de segurança
  • Nunca faça commit de um token no código — use variáveis de ambiente ou secrets
  • Revogue tokens que não usa mais em Settings → Developer settings
Seção 6

2FA e Commits Assinados com GPG

Segurança da conta e autenticidade dos commits são fundamentais. A autenticação de dois fatores protege sua conta; a assinatura GPG prova que os commits realmente vieram de você.

🛡️ Ativando 2FA (Two-Factor Authentication)

Configuração no GitHub

# GitHub → Settings → Password and authentication
#   → Two-factor authentication → Enable 2FA

# Métodos disponíveis (do mais para o menos seguro):
# 1. Security key / Passkey (WebAuthn) — mais seguro
# 2. Authenticator app (TOTP):
#    - Authy, Google Authenticator, 1Password, Microsoft Authenticator
# 3. SMS (menos seguro — evite se possível)

# IMPORTANTE: salve os recovery codes em local seguro!
# Sem eles, perder o celular = perder acesso à conta.

⚠️ 2FA agora é obrigatório

O GitHub tornou o 2FA obrigatório para todos os usuários que contribuem com código. Configure hoje — não deixe para depois.

✍️ Assinando Commits com GPG

Commits assinados exibem um selo "Verified" no GitHub, provando que vieram de você. Isso previne que alguém falsifique commits usando seu nome e e-mail.

Configuração de Assinatura GPG

# 1. Gerar uma chave GPG
gpg --full-generate-key
# Escolha: RSA and RSA, 4096 bits, validade, seu nome e e-mail

# 2. Listar chaves e pegar o ID
gpg --list-secret-keys --keyid-format=long
# Copie o ID após "sec   rsa4096/"  (ex: 3AA5C34371567BD2)

# 3. Exportar a chave pública
gpg --armor --export 3AA5C34371567BD2
# Cole no GitHub: Settings → SSH and GPG keys → New GPG key

# 4. Configurar o Git para assinar
git config --global user.signingkey 3AA5C34371567BD2
git config --global commit.gpgsign true

# 5. Fazer um commit assinado
git commit -S -m "feat: commit assinado"
# (com commit.gpgsign true, o -S é automático)

💡 Alternativa: assinatura SSH

Desde o Git 2.34, você pode assinar commits com sua chave SSH (mais simples que GPG): git config --global gpg.format ssh e git config --global user.signingkey ~/.ssh/id_ed25519.pub. Depois adicione a chave como "Signing Key" no GitHub.

Seção 7

Montando um Perfil Profissional

Seu perfil no GitHub é seu portfólio vivo. Recrutadores e colegas olham antes de entrevistas. Um perfil bem montado comunica competência e cuidado.

📇 O README de Perfil

Ao criar um repositório com o mesmo nome do seu usuário (ex: github.com/seuuser/seuuser), o README dele aparece no topo do seu perfil. É a sua vitrine.

Estrutura de um Bom README de Perfil

# Crie o repositório especial
# github.com → New repository → nome = seu-usuario
# Marque "Add a README file"

# Estrutura recomendada do README.md:
# ─────────────────────────────────────
# # Olá, eu sou o Ricardo 👋
#
# Cloud & DevOps Engineer | AWS | Terraform | Python
#
# ## 🛠️ Tecnologias
# ![AWS](badge) ![Terraform](badge) ![Python](badge)
#
# ## 📊 Estatísticas
# (github-readme-stats gera cards automáticos)
#
# ## 📫 Contato
# - LinkedIn: /in/seu-perfil
# - Portfólio: seusite.com
# ─────────────────────────────────────

✨ Ferramentas para turbinar o perfil

  • github-readme-stats — cards com suas estatísticas e linguagens mais usadas
  • shields.io — badges de tecnologias e status
  • Pinned repositories — fixe seus 6 melhores projetos no topo do perfil
  • Contribution graph — commits consistentes mostram atividade

✅ Checklist de Configuração Inicial

Antes de seguir para o Módulo 01, confirme:

  • ☐ Git instalado (git --version funciona)
  • ☐ user.name e user.email configurados globalmente
  • ☐ init.defaultBranch definido como main
  • ☐ Conta GitHub criada
  • ☐ Chave SSH gerada e adicionada ao GitHub (ssh -T git@github.com autentica)
  • ☐ 2FA ativado e recovery codes salvos
  • ☐ (Opcional) Commits assinados com GPG/SSH
  • ☐ (Opcional) README de perfil criado
