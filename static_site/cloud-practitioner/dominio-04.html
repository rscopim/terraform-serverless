Modelos de Preço EC2

ModeloDescontoCompromissoCaso de Uso
On-Demand0% (preço cheio)Nenhum — pague por hora/segundoWorkloads imprevisíveis, testes, curta duração
Reserved Instances (RI)Até 72%1 ou 3 anos — tipo específicoWorkloads estáveis e previsíveis (produção)
Savings PlansAté 72%1 ou 3 anos — $/hora de usoFlexível entre famílias/regiões/OS
Spot InstancesAté 90%Nenhum — pode ser interrompidoWorkloads tolerantes a falha (batch, CI/CD, big data)
Dedicated HostsVariávelServidor físico dedicadoCompliance, licenças por socket/core (BYOL)
Dedicated InstancesVariávelHardware dedicado (sem compartilhar)Isolamento de hardware sem gerenciar host

🎯 Para o exame: On-Demand = flexibilidade | Reserved/Savings Plans = economia para uso constante | Spot = mais barato mas pode ser interrompido | Dedicated = compliance/licenças.

Princípios de Preço AWSBilling
3 Drivers fundamentais de custo:
1. Compute: tempo de uso (hora/segundo)
2. Storage: GB armazenados por mês
3. Data Transfer OUT: dados saindo da AWS
   ⚠️ Data Transfer IN é GRATUITO

Princípios:
• Pay-as-you-go (pague pelo uso)
• Pay less when you reserve (desconto por compromisso)
• Pay less per unit by using more (volume discounts)
• Pay less as AWS grows (AWS repassa economia de escala)

Gratuito entre serviços na mesma região:
• EC2 → S3 (mesma região) = grátis
• EC2 → Internet = cobra data transfer out

AWS BudgetsAlertas
Tipos de budget:
• Cost Budget: alerta por valor ($)
• Usage Budget: alerta por uso (horas, GB)
• Reservation Budget: cobertura de RIs
• Savings Plans Budget: cobertura de SP

Ações automáticas:
• Enviar notificação (SNS, e-mail)
• Aplicar IAM policy restritiva
• Aplicar SCP para bloquear criação de recursos

Exemplo: alertar quando custo > 80% do budget mensal
Cost ExplorerAnálise
Funcionalidades:
• Visualizar custos por serviço, região, conta
• Filtrar por tags, linked accounts
• Forecast: previsão de custos futuros (12 meses)
• Right-sizing recommendations (EC2)
• Savings Plans recommendations
• Reservation coverage e utilization reports

Granularidade:
• Mensal, diário ou por hora
• Últimos 12 meses de dados
• Previsão para próximos 12 meses

AWS Trusted Advisor

5 CategoriasBest Practices
1. Cost Optimization:
   • Instâncias ociosas, EBS não utilizados
   • Reserved Instance optimization

2. Performance:
   • Instâncias over-provisioned
   • CloudFront optimization

3. Security:
   • Security Groups com acesso aberto (0.0.0.0/0)
   • MFA no root, IAM access keys

4. Fault Tolerance:
   • Backups, Multi-AZ, redundância
   • RDS backups, EBS snapshots

5. Service Limits:
   • Uso próximo dos limites de serviço
   • VPCs, EIPs, instâncias por região

Consolidated Billing (AWS Organizations)

Fatura ConsolidadaBilling
• Uma fatura para todas as contas da organização
• Management Account paga tudo
• Volume discounts agregados (todas as contas somam)
• Reserved Instances compartilhadas entre contas
• Savings Plans compartilhados
• Gratuito (sem custo adicional)

Benefício principal:
Conta A usa 3 TB S3 + Conta B usa 7 TB S3
= 10 TB total → desconto por volume aplicado a ambas
Otimização de CustosDicas
Estratégias para reduzir custos:
• Right-sizing: usar o tamanho correto de instância
• Reserved Instances / Savings Plans para uso constante
• Spot Instances para workloads tolerantes a falha
• Desligar recursos não utilizados (dev/test à noite)
• S3 Lifecycle policies (mover para Glacier)
• Use serviços serverless (Lambda, Fargate)
• Consolidar contas para volume discounts
• Usar Cost Allocation Tags para visibilidade
• Revisar Trusted Advisor regularmente
• Configurar AWS Budgets com alertas
