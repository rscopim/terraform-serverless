EC2 — Tipos de InstânciaFamílias
• General Purpose (t3, m5): balanceado
• Compute Optimized (c5): CPU intensivo
• Memory Optimized (r5): RAM intensivo
• Storage Optimized (i3): I/O intensivo
• Accelerated Computing (p3, g4): GPU/ML

Nomenclatura: m5.xlarge
m = família | 5 = geração | xlarge = tamanho
EC2 — Auto ScalingElasticidade
• Ajusta automaticamente o número de instâncias
• Scale Out: adiciona instâncias (demanda alta)
• Scale In: remove instâncias (demanda baixa)
• Mantém disponibilidade e otimiza custos

Componentes:
• Launch Template (configuração da instância)
• Auto Scaling Group (min/max/desired)
• Scaling Policies (quando escalar)
• ELB (distribui tráfego entre instâncias)

S3 — Classes de ArmazenamentoTiers
• S3 Standard: acesso frequente, alta disponibilidade
• S3 Standard-IA: acesso infrequente, custo menor
• S3 One Zone-IA: infrequente, 1 AZ (mais barato)
• S3 Intelligent-Tiering: move automaticamente
• S3 Glacier Instant Retrieval: arquivo, acesso ms
• S3 Glacier Flexible: arquivo, minutos a horas
• S3 Glacier Deep Archive: mais barato, 12-48h

Lifecycle Rules: mover objetos entre classes automaticamente
EBS vs EFS vs S3Comparação
EBS:
• Attached a 1 EC2 (mesma AZ)
• Block storage (como HD)
• Snapshots para backup

EFS:
• Compartilhado entre múltiplas EC2
• Multi-AZ automático
• Apenas Linux (NFS)

S3:
• Object storage (via HTTP/API)
• Ilimitado, serverless
• Não é file system (não monta como disco)

Networking (Rede)

Amazon VPCRede Virtual
Virtual Private Cloud — sua rede isolada na AWS:
• Subnets: públicas (internet) e privadas (interna)
• Internet Gateway (IGW): acesso à internet
• NAT Gateway: internet para subnets privadas (saída)
• Route Tables: regras de roteamento
• Security Groups: firewall stateful (instância)
• NACLs: firewall stateless (subnet)

Security Groups vs NACLs:
• SG: stateful, allow only, nível de instância
• NACL: stateless, allow + deny, nível de subnet
ConectividadeConexão
• VPC Peering: conecta 2 VPCs (não transitivo)
• Transit Gateway: hub central para múltiplas VPCs
• VPN Site-to-Site: conexão criptografada via internet
• AWS Direct Connect: conexão dedicada (fibra)
  - Mais estável, menor latência
  - Não passa pela internet pública
  - Leva semanas para provisionar
• VPC Endpoints: acesso privado a serviços AWS
  - Gateway Endpoint: S3, DynamoDB
  - Interface Endpoint: outros serviços

Infraestrutura Global AWS

Regiões e AZsGlobal
• Regions: áreas geográficas (us-east-1, sa-east-1)
  - Cada região é independente
  - Escolha baseada em: compliance, latência, serviços, preço

• Availability Zones (AZs): data centers isolados
  - Cada região tem 2-6 AZs
  - Conectadas por rede de alta velocidade
  - Isoladas contra falhas (energia, rede)
  - Multi-AZ = alta disponibilidade

• Edge Locations: pontos de presença para CDN
  - CloudFront, Route 53, WAF, Shield
  - Mais de 400 edge locations globalmente
Alta DisponibilidadeResiliência
Estratégias de resiliência:
• Multi-AZ: protege contra falha de data center
• Multi-Region: protege contra falha de região
• Auto Scaling: mantém capacidade desejada
• ELB: distribui tráfego entre instâncias saudáveis

Conceitos:
• RTO (Recovery Time Objective): tempo máximo de downtime
• RPO (Recovery Point Objective): perda máxima de dados

Disaster Recovery:
• Backup & Restore (mais barato, mais lento)
• Pilot Light (core mínimo rodando)
• Warm Standby (versão reduzida ativa)
• Multi-Site Active-Active (mais caro, mais rápido)
