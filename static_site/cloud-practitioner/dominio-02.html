Segurança e Conformidade

Modelo de responsabilidade compartilhada, IAM, MFA, AWS Organizations, compliance, criptografia e serviços de segurança da AWS.

Modelo de Responsabilidade Compartilhada

Define o que a AWS protege vs. o que o cliente protege:

ResponsabilidadeAWS (Segurança DA Cloud)Cliente (Segurança NA Cloud)
Infraestrutura física✅ Data centers, hardware, rede global—
Hypervisor✅ Virtualização, isolamento—
Sistema Operacional— (exceto serviços gerenciados)✅ Patches, configuração (EC2)
Rede✅ Infraestrutura de rede global✅ Security Groups, NACLs, VPC config
Dados—✅ Criptografia, backups, classificação
Identidade—✅ IAM, MFA, senhas, permissões
Aplicação—✅ Código, configuração, vulnerabilidades

🎯 Regra de ouro: Se você pode configurar no console AWS, é sua responsabilidade. Se não tem acesso, é responsabilidade da AWS.

AWS IAM (Identity and Access Management)

Serviço global para controlar acesso aos recursos AWS:

UsersIdentidade
• Representa uma pessoa ou aplicação
• Credenciais: senha (console) + access keys (CLI/API)
• Princípio: 1 user por pessoa física
• Root user: acesso total — usar apenas para tarefas específicas
• Ativar MFA no root user SEMPRE
GroupsOrganização
• Coleção de users
• Policies são atribuídas ao grupo
• Users herdam permissões do grupo
• Exemplos: Admins, Developers, Finance
• Um user pode pertencer a múltiplos grupos
• Groups NÃO podem conter outros groups
RolesDelegação
• Identidade temporária com permissões
• Não tem credenciais permanentes
• Assumida por: serviços AWS, users, contas externas
• Casos de uso:
  - EC2 acessando S3
  - Lambda acessando DynamoDB
  - Cross-account access
  - Federação (SSO)
PoliciesPermissões
• Documentos JSON que definem permissões
• Tipos:
  - AWS Managed (criadas pela AWS)
  - Customer Managed (criadas por você)
  - Inline (embutidas em user/group/role)
• Estrutura: Effect + Action + Resource
• Default: tudo negado (deny implícito)
• Deny explícito > Allow

💡 Princípio do Menor Privilégio: Conceda apenas as permissões mínimas necessárias para realizar a tarefa. Comece com zero permissões e adicione conforme necessário.

Multi-Factor Authentication (MFA)

Tipos de MFAAutenticação
• Virtual MFA device (Google Authenticator, Authy)
• Hardware TOTP token (key fob)
• Hardware MFA key (YubiKey - FIDO U2F)
• SMS (não recomendado para root)

Fatores de autenticação:
1. Algo que você SABE (senha)
2. Algo que você TEM (token/celular)
3. Algo que você É (biometria)
Boas PráticasSegurança
• SEMPRE ativar MFA no root user
• Ativar MFA para todos os users com console access
• Usar roles em vez de access keys quando possível
• Rotacionar access keys regularmente
• Nunca compartilhar credenciais
• Usar IAM Access Analyzer para revisar permissões
• Habilitar AWS CloudTrail para auditoria

AWS Organizations

Gerenciamento centralizado de múltiplas contas AWS:

ConceitosMulti-Account
• Management Account (conta raiz/payer)
• Member Accounts (contas membros)
• Organizational Units (OUs) — agrupamento lógico
• Consolidated Billing — fatura única
• Volume discounts — desconto por uso agregado

Estrutura:
Root
├── OU: Production
│   ├── Account: Prod-App
│   └── Account: Prod-DB
├── OU: Development
│   └── Account: Dev
└── OU: Security
    └── Account: Audit
SCPs (Service Control Policies)Restrição
• Políticas que RESTRINGEM permissões em OUs/contas
• NÃO concedem permissões (apenas limitam)
• Aplicadas na OU ou conta membro
• NÃO afetam a Management Account
• Hierárquicas: herdam da OU pai

Exemplo de SCP:
{
  "Effect": "Deny",
  "Action": "ec2:RunInstances",
  "Resource": "*",
  "Condition": {
    "StringNotEquals": {
      "ec2:Region": "us-east-1"
    }
  }
}

Compliance e Conformidade

AWS ArtifactCompliance
• Portal self-service para relatórios de compliance
• Acesso a documentos de auditoria da AWS
• Agreements (acordos): BAA, NDA
• Reports: SOC, PCI-DSS, ISO, HIPAA

Programas de compliance:
• SOC 1/2/3 (controles de segurança)
• PCI-DSS (dados de cartão de crédito)
• HIPAA (dados de saúde - EUA)
• GDPR (dados pessoais - Europa)
• LGPD (dados pessoais - Brasil)
• ISO 27001 (segurança da informação)
AWS ConfigAuditoria
• Monitora e registra configurações de recursos
• Avalia compliance com regras definidas
• Histórico de mudanças de configuração
• Regras: managed (AWS) ou custom

Exemplos de regras:
• S3 buckets devem ter encryption
• Security Groups não devem ter 0.0.0.0/0
• EBS volumes devem estar encrypted
• EC2 instances devem ter tags obrigatórias

NÃO previne mudanças — apenas detecta e alerta

Criptografia (KMS)

AWS KMSKey Management
AWS Key Management Service:
• Gerencia chaves de criptografia
• Integrado com a maioria dos serviços AWS
• Tipos de chaves:
  - AWS Managed Keys (aws/s3, aws/ebs)
  - Customer Managed Keys (CMK)
  - AWS Owned Keys (usadas internamente)

Encryption at Rest:
• Dados armazenados criptografados (S3, EBS, RDS)

Encryption in Transit:
• Dados em movimento criptografados (TLS/SSL, HTTPS)
Outros ServiçosSegurança
• CloudHSM: Hardware dedicado para chaves
  - Você gerencia as chaves (não a AWS)
  - FIPS 140-2 Level 3
  - Single-tenant (hardware exclusivo)

• AWS Certificate Manager (ACM):
  - Provisiona certificados SSL/TLS
  - Renovação automática
  - Gratuito para serviços AWS integrados

• AWS Secrets Manager:
  - Armazena e rotaciona secrets
  - DB passwords, API keys
  - Rotação automática

Serviços de Segurança

ServiçoFunçãoO que Detecta/Protege
Amazon GuardDutyDetecção inteligente de ameaçasAtividades maliciosas, comportamento anômalo, IPs suspeitos (ML-based)
Amazon InspectorAvaliação de vulnerabilidadesVulnerabilidades em EC2, containers e Lambda (CVEs, network exposure)
Amazon MacieProteção de dados sensíveisDados pessoais (PII) em S3 — cartões, CPFs, e-mails (ML-based)
AWS WAFWeb Application FirewallSQL injection, XSS, rate limiting, geo-blocking (Layer 7)
AWS ShieldProteção contra DDoSStandard (gratuito, Layer 3/4) | Advanced (pago, Layer 7, suporte 24/7)
AWS Security HubVisão centralizada de segurançaAgrega findings de GuardDuty, Inspector, Macie, Firewall Manager
AWS CloudTrailAuditoria de API callsQuem fez o quê, quando, de onde (log de todas as ações na conta)

🎯 Para o exame: GuardDuty = ameaças inteligentes | Inspector = vulnerabilidades | Macie = dados sensíveis em S3 | WAF = proteção web (L7) | Shield = DDoS.
