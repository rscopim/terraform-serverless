Seção 1

Introdução ao Amazon Bedrock

O Amazon Bedrock é o serviço gerenciado da AWS para IA generativa. Ele oferece acesso via API a modelos de fundação (foundation models) de vários provedores — Anthropic, Amazon, Meta, Mistral, Cohere, AI21 — sem que você precise gerenciar infraestrutura de GPU. Neste módulo você aprenderá a integrar esses modelos em aplicações Python de produção.

🧠 O que é IA Generativa e Foundation Models

IA generativa refere-se a modelos capazes de gerar conteúdo novo — texto, código, imagens, áudio — a partir de instruções em linguagem natural. Os foundation models (FMs) são grandes modelos treinados em enormes volumes de dados, capazes de realizar múltiplas tarefas sem re-treinamento específico. O Bedrock expõe esses modelos através de uma API unificada.

🎯 Por que usar o Amazon Bedrock?

  • Serverless: sem provisionar ou gerenciar GPUs — você paga por token consumido
  • Multi-modelo: troque entre Claude, Titan, Llama e outros mudando apenas o modelId
  • Privacidade: seus dados não são usados para treinar os modelos e não saem da sua conta AWS
  • Integração nativa: IAM, CloudWatch, VPC endpoints, KMS — tudo integrado ao ecossistema AWS
  • Converse API: interface unificada que abstrai as diferenças de formato entre provedores

🔑 Habilitando Acesso aos Modelos

Antes de invocar qualquer modelo, você precisa solicitar acesso a ele no console do Bedrock (Model access). Esse é um passo único por conta/região. Sem isso, as chamadas retornam AccessDeniedException.

📋 Verificação de Acesso e Listagem de Modelos

import boto3

# Client de controle (gerenciamento) do Bedrock
bedrock = boto3.client('bedrock', region_name='us-east-1')

# Listar todos os foundation models disponíveis na região
response = bedrock.list_foundation_models()

for modelo in response['modelSummaries']:
    print(f"ID: {modelo['modelId']}")
    print(f"  Provedor: {modelo['providerName']}")
    print(f"  Modalidades entrada: {modelo.get('inputModalities', [])}")
    print(f"  Modalidades saída: {modelo.get('outputModalities', [])}")
    print(f"  Streaming: {modelo.get('responseStreamingSupported', False)}")
    print()

# Filtrar apenas modelos de texto da Anthropic
for modelo in response['modelSummaries']:
    if modelo['providerName'] == 'Anthropic':
        print(modelo['modelId'])

# Verificar acesso concedido (models que você pode invocar)
# O acesso é solicitado no Console: Bedrock > Model access > Manage model access

⚠️ Dois clients diferentes

  • boto3.client('bedrock') → operações de gerenciamento (listar modelos, custom models, jobs)
  • boto3.client('bedrock-runtime') → operações de inferência (invocar modelos, gerar respostas)

Confundir os dois é o erro mais comum de quem começa com Bedrock.

💰 Modelos Disponíveis e Custos

Cada modelo tem um custo por 1.000 tokens de entrada e por 1.000 tokens de saída. Escolher o modelo certo para cada tarefa é a principal alavanca de controle de custo em aplicações de IA.

Modelo Provedor Melhor para Custo relativo
Claude 3 Haiku Anthropic Tarefas rápidas, classificação, extração, alto volume 💲 Baixo
Claude 3.5 Sonnet Anthropic Raciocínio, código, análise, visão (imagens) 💲💲 Médio
Claude 3 Opus Anthropic Tarefas complexas que exigem máxima qualidade 💲💲💲 Alto
Titan Text Express Amazon Geração de texto simples, resumos 💲 Baixo
Titan Embeddings Amazon Busca semântica, RAG, clustering 💲 Muito baixo
Llama 3 Meta Open-weight, chat, tarefas gerais 💲 Baixo

💡 Regra de ouro de custo

Use o modelo mais barato que resolve a tarefa. Haiku para classificação e extração em volume; Sonnet quando precisar de raciocínio ou visão; Opus só quando a qualidade for crítica. Monitore o campo usage retornado em cada chamada para rastrear tokens consumidos.

Seção 2

InvokeModel — Invocação Direta de Modelos

O método invoke_model() é a forma de baixo nível de chamar um modelo. Cada provedor tem seu próprio formato de body (JSON), o que exige atenção aos detalhes. É importante conhecê-lo porque dá controle total, mas veremos depois que a Converse API simplifica muito o trabalho multi-modelo.

🤖 Invocando Claude (Anthropic Messages API)

Os modelos Claude no Bedrock usam o formato de mensagens da Anthropic. O body precisa incluir anthropic_version, max_tokens e a lista de messages.

📋 Invocação Básica do Claude

import boto3
import json

bedrock_runtime = boto3.client('bedrock-runtime', region_name='us-east-1')

def invocar_claude(prompt: str, max_tokens: int = 1024) -> str:
    """Invoca o Claude 3 Sonnet com um prompt simples."""
    body = json.dumps({
        "anthropic_version": "bedrock-2023-05-31",
        "max_tokens": max_tokens,
        "messages": [
            {"role": "user", "content": prompt}
        ]
    })

    response = bedrock_runtime.invoke_model(
        modelId="anthropic.claude-3-sonnet-20240229-v1:0",
        contentType="application/json",
        accept="application/json",
        body=body
    )

    resultado = json.loads(response['body'].read())
    return resultado['content'][0]['text']

# Uso
resposta = invocar_claude("Explique o que é uma VPC na AWS em 3 frases.")
print(resposta)

📋 Claude com System Prompt e Parâmetros de Controle

def invocar_claude_avancado(
    prompt: str,
    sistema: str = "Você é um especialista AWS certificado.",
    temperature: float = 0.7,
    max_tokens: int = 2048
) -> dict:
    """Invoca o Claude com system prompt e retorna texto + uso de tokens."""
    body = json.dumps({
        "anthropic_version": "bedrock-2023-05-31",
        "max_tokens": max_tokens,
        "system": sistema,        # instrução de comportamento
        "temperature": temperature,  # 0 = determinístico, 1 = criativo
        "top_p": 0.9,             # nucleus sampling
        "messages": [
            {"role": "user", "content": prompt}
        ]
    })

    response = bedrock_runtime.invoke_model(
        modelId="anthropic.claude-3-sonnet-20240229-v1:0",
        body=body
    )

    resultado = json.loads(response['body'].read())
    return {
        "texto": resultado['content'][0]['text'],
        "tokens_entrada": resultado['usage']['input_tokens'],
        "tokens_saida": resultado['usage']['output_tokens'],
        "stop_reason": resultado['stop_reason']
    }

r = invocar_claude_avancado(
    "Liste 5 boas práticas de segurança para buckets S3.",
    temperature=0.3  # mais determinístico para respostas técnicas
)
print(r['texto'])
print(f"\nTokens: {r['tokens_entrada']} entrada + {r['tokens_saida']} saída")

🌡️ Entendendo temperature e top_p

  • temperature (0–1): controla a aleatoriedade. Baixo (0–0.3) para respostas técnicas e determinísticas; alto (0.7–1) para brainstorming e criatividade.
  • top_p (0–1): nucleus sampling — considera apenas os tokens mais prováveis que somam top_p de probabilidade. Ajuste um OU outro, não os dois ao mesmo tempo.
  • max_tokens: limite de tokens gerados na saída. Impacta diretamente o custo e o tempo de resposta.

📝 Invocando Amazon Titan e Meta Llama

Cada provedor tem um formato de body diferente. Veja como o Titan e o Llama diferem do Claude — é justamente essa fragmentação que a Converse API resolve.

Amazon Titan Text

def invocar_titan(prompt: str) -> str:
    body = json.dumps({
        "inputText": prompt,
        "textGenerationConfig": {
            "maxTokenCount": 512,
            "temperature": 0.7,
            "topP": 0.9,
            "stopSequences": []
        }
    })

    response = bedrock_runtime.invoke_model(
        modelId="amazon.titan-text-express-v1",
        body=body
    )
    resultado = json.loads(response['body'].read())
    return resultado['results'][0]['outputText']

print(invocar_titan("Resuma o que é o AWS Lambda."))

Meta Llama 3

def invocar_llama(prompt: str) -> str:
    # Llama usa formato de prompt com tags especiais
    prompt_formatado = f"""<|begin_of_text|><|start_header_id|>user<|end_header_id|>
{prompt}<|eot_id|><|start_header_id|>assistant<|end_header_id|>"""

    body = json.dumps({
        "prompt": prompt_formatado,
        "max_gen_len": 512,
        "temperature": 0.7,
        "top_p": 0.9
    })

    response = bedrock_runtime.invoke_model(
        modelId="meta.llama3-8b-instruct-v1:0",
        body=body
    )
    resultado = json.loads(response['body'].read())
    return resultado['generation']

print(invocar_llama("O que é infraestrutura como código?"))

⚠️ Formatos incompatíveis

Note como cada modelo exige uma estrutura de body totalmente diferente: Claude usa messages, Titan usa inputText/textGenerationConfig, Llama usa prompt/max_gen_len. Manter código para todos é trabalhoso e frágil. Por isso a próxima seção apresenta a Converse API.

🛡️ Tratamento de Erros na Invocação

📋 Chamada Robusta com Retry e Tratamento de Exceções

import time
from botocore.exceptions import ClientError

def invocar_com_retry(prompt: str, tentativas: int = 3) -> str:
    """Invoca o modelo com retry exponencial para throttling."""
    for tentativa in range(tentativas):
        try:
            return invocar_claude(prompt)
        except ClientError as e:
            codigo = e.response['Error']['Code']
            if codigo == 'ThrottlingException':
                espera = 2 ** tentativa  # backoff exponencial: 1s, 2s, 4s
                print(f"⏳ Throttling. Aguardando {espera}s...")
                time.sleep(espera)
            elif codigo == 'AccessDeniedException':
                raise RuntimeError(
                    "Sem acesso ao modelo. Habilite em Bedrock > Model access."
                ) from e
            elif codigo == 'ValidationException':
                raise ValueError(f"Body inválido: {e}") from e
            else:
                raise
    raise RuntimeError(f"Falhou após {tentativas} tentativas")
Seção 3

Converse API — A Interface Unificada

A Converse API (lançada em 2024) é a forma moderna e recomendada de usar o Bedrock. Ela oferece um formato único de request/response que funciona com todos os modelos, elimina a necessidade de conhecer o formato de cada provedor e suporta conversas multi-turno, system prompts, tool use e visão de forma padronizada.

💬 Converse — Chamada Básica

📋 Mesmo Código para Qualquer Modelo

import boto3

bedrock_runtime = boto3.client('bedrock-runtime', region_name='us-east-1')

def conversar(prompt: str, model_id: str = "anthropic.claude-3-sonnet-20240229-v1:0") -> str:
    """Usa a Converse API — mesmo formato para Claude, Titan, Llama, etc."""
    response = bedrock_runtime.converse(
        modelId=model_id,
        messages=[
            {
                "role": "user",
                "content": [{"text": prompt}]
            }
        ],
        inferenceConfig={
            "maxTokens": 1024,
            "temperature": 0.7,
            "topP": 0.9
        }
    )

    return response['output']['message']['content'][0]['text']

# Trocar de modelo é só mudar o argumento — o código não muda!
print(conversar("Explique o que é o DynamoDB."))
print(conversar("Explique o que é o DynamoDB.", "meta.llama3-8b-instruct-v1:0"))
print(conversar("Explique o que é o DynamoDB.", "amazon.titan-text-express-v1"))

📋 Mantendo Contexto entre Mensagens

def conversa_completa():
    system = [{"text": "Você é um tutor de AWS. Seja conciso e didático."}]

    messages = [
        {"role": "user", "content": [{"text": "O que é o S3?"}]}
    ]

    response = bedrock_runtime.converse(
        modelId="anthropic.claude-3-sonnet-20240229-v1:0",
        system=system,
        messages=messages,
        inferenceConfig={"maxTokens": 512, "temperature": 0.3}
    )

    resposta_assistente = response['output']['message']
    print("Assistente:", resposta_assistente['content'][0]['text'])

    # Adiciona a resposta ao histórico e faz nova pergunta com contexto
    messages.append(resposta_assistente)
    messages.append({
        "role": "user",
        "content": [{"text": "E como ele difere do EBS?"}]
    })

    response2 = bedrock_runtime.converse(
        modelId="anthropic.claude-3-sonnet-20240229-v1:0",
        system=system,
        messages=messages,
        inferenceConfig={"maxTokens": 512}
    )
    print("Assistente:", response2['output']['message']['content'][0]['text'])

    # A Converse API retorna uso de tokens padronizado
    uso = response2['usage']
    print(f"\nTokens: {uso['inputTokens']} entrada, {uso['outputTokens']} saída, {uso['totalTokens']} total")

conversa_completa()

Seção 4

Streaming de Respostas em Tempo Real

Para experiências de chat responsivas, você não quer esperar a resposta completa antes de exibir algo. O streaming entrega a resposta token a token, conforme o modelo gera — exatamente como você vê em interfaces de chat modernas. O Bedrock suporta streaming tanto no InvokeModel quanto na Converse API.

🌊 Streaming com converse_stream()

📋 Exibindo Tokens Conforme São Gerados

def conversar_streaming(prompt: str):
    """Faz streaming da resposta, imprimindo token a token."""
    response = bedrock_runtime.converse_stream(
        modelId="anthropic.claude-3-sonnet-20240229-v1:0",
        messages=[{"role": "user", "content": [{"text": prompt}]}],
        inferenceConfig={"maxTokens": 1024}
    )

    texto_completo = ""
    for evento in response['stream']:
        if 'contentBlockDelta' in evento:
            trecho = evento['contentBlockDelta']['delta']['text']
            print(trecho, end='', flush=True)  # imprime sem quebra de linha
            texto_completo += trecho

        # Evento final com metadados de uso
        elif 'metadata' in evento:
            uso = evento['metadata']['usage']
            print(f"\n\n[Tokens: {uso['totalTokens']}]")

    return texto_completo

conversar_streaming("Escreva um tutorial passo a passo de como criar uma função Lambda.")

⚡ Streaming com InvokeModelWithResponseStream

📋 Streaming de Baixo Nível (Claude)

def invoke_streaming(prompt: str):
    """Streaming usando invoke_model_with_response_stream."""
    body = json.dumps({
        "anthropic_version": "bedrock-2023-05-31",
        "max_tokens": 1024,
        "messages": [{"role": "user", "content": prompt}]
    })

    response = bedrock_runtime.invoke_model_with_response_stream(
        modelId="anthropic.claude-3-sonnet-20240229-v1:0",
        body=body
    )

    for evento in response['body']:
        chunk = json.loads(evento['chunk']['bytes'])
        if chunk['type'] == 'content_block_delta':
            print(chunk['delta']['text'], end='', flush=True)

invoke_streaming("Explique o conceito de idempotência em APIs.")

💡 Streaming em aplicações web

Em uma API (FastAPI, Flask) você repassa esses chunks como Server-Sent Events (SSE) ou WebSocket para o navegador, criando a experiência de "digitação" em tempo real. Em Lambda + API Gateway, use response streaming das Lambda Function URLs para suportar esse padrão.

Seção 5

Embeddings e Busca Semântica

Embeddings são representações vetoriais de texto — listas de números que capturam o significado semântico. Textos com significados parecidos ficam próximos no espaço vetorial. São a base da busca semântica, sistemas de recomendação e do RAG que veremos na próxima seção.

🔢 Gerando Embeddings com Titan

📋 Vetorizando Texto

import json
import numpy as np

def gerar_embedding(texto: str) -> list:
    """Gera um vetor de embedding para o texto usando Titan Embeddings."""
    body = json.dumps({"inputText": texto})

    response = bedrock_runtime.invoke_model(
        modelId="amazon.titan-embed-text-v2:0",
        body=body
    )

    resultado = json.loads(response['body'].read())
    return resultado['embedding']  # vetor de 1024 dimensões (v2)

def similaridade_cosseno(a: list, b: list) -> float:
    """Calcula a similaridade de cosseno entre dois vetores (-1 a 1)."""
    a, b = np.array(a), np.array(b)
    return float(np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b)))

# Comparando significados
emb1 = gerar_embedding("Como criar um bucket no S3?")
emb2 = gerar_embedding("Passos para provisionar armazenamento de objetos na AWS")
emb3 = gerar_embedding("Receita de bolo de chocolate")

print(f"S3 vs Storage AWS: {similaridade_cosseno(emb1, emb2):.3f}")  # ~0.7 (alto)
print(f"S3 vs Bolo:        {similaridade_cosseno(emb1, emb3):.3f}")  # ~0.1 (baixo)

🔍 Construindo uma Busca Semântica

📋 Mini Motor de Busca por Significado

class BuscaSemantica:
    """Índice simples de busca semântica em memória."""

    def __init__(self):
        self.documentos = []   # textos originais
        self.vetores = []      # embeddings correspondentes

    def indexar(self, textos: list):
        """Gera e armazena embeddings para uma lista de textos."""
        for texto in textos:
            self.documentos.append(texto)
            self.vetores.append(gerar_embedding(texto))
        print(f"✅ {len(textos)} documentos indexados")

    def buscar(self, consulta: str, top_k: int = 3) -> list:
        """Retorna os top_k documentos mais similares à consulta."""
        vetor_consulta = gerar_embedding(consulta)

        pontuacoes = [
            (doc, similaridade_cosseno(vetor_consulta, vet))
            for doc, vet in zip(self.documentos, self.vetores)
        ]
        pontuacoes.sort(key=lambda x: x[1], reverse=True)
        return pontuacoes[:top_k]

# Uso
indice = BuscaSemantica()
indice.indexar([
    "O S3 é um serviço de armazenamento de objetos escalável.",
    "O Lambda executa código sem provisionar servidores.",
    "O DynamoDB é um banco de dados NoSQL totalmente gerenciado.",
    "O EC2 fornece capacidade de computação redimensionável.",
    "O CloudFront é uma CDN para entrega de conteúdo com baixa latência.",
])

for doc, score in indice.buscar("Onde guardo meus arquivos na nuvem?"):
    print(f"{score:.3f} → {doc}")
# O documento sobre S3 aparece no topo, mesmo sem conter a palavra "arquivo"

🗄️ Em produção: bancos vetoriais

Para volumes reais, não guarde vetores em listas Python. Use bancos vetoriais como Amazon OpenSearch Serverless, pgvector (PostgreSQL/RDS), ou o Amazon Bedrock Knowledge Bases, que gerenciam a indexação e a busca por vizinhos mais próximos (ANN) de forma eficiente e escalável.

Seção 6

RAG — Retrieval-Augmented Generation

RAG combina busca semântica com geração de texto. Em vez de o modelo responder só com o que "sabe" do treinamento, você recupera trechos relevantes da sua própria base de conhecimento e os injeta no prompt. Isso reduz alucinações, mantém as respostas atualizadas e permite ao modelo citar fontes específicas.

🔗 O Padrão RAG na Prática

📋 Pipeline RAG Completo

class SistemaRAG:
    """RAG: busca contexto relevante e gera resposta fundamentada."""

    def __init__(self):
        self.indice = BuscaSemantica()

    def carregar_base(self, documentos: list):
        self.indice.indexar(documentos)

    def responder(self, pergunta: str, top_k: int = 3) -> str:
        # 1. RECUPERAÇÃO: busca os trechos mais relevantes
        resultados = self.indice.buscar(pergunta, top_k=top_k)
        contexto = "\n\n".join(f"- {doc}" for doc, _ in resultados)

        # 2. AUMENTO: injeta o contexto no prompt
        prompt = f"""Use APENAS o contexto abaixo para responder à pergunta.
Se a resposta não estiver no contexto, diga "Não encontrei essa informação".

CONTEXTO:
{contexto}

PERGUNTA: {pergunta}

RESPOSTA:"""

        # 3. GERAÇÃO: o modelo responde fundamentado no contexto
        response = bedrock_runtime.converse(
            modelId="anthropic.claude-3-haiku-20240307-v1:0",  # Haiku = barato
            messages=[{"role": "user", "content": [{"text": prompt}]}],
            inferenceConfig={"maxTokens": 512, "temperature": 0}  # 0 = factual
        )
        return response['output']['message']['content'][0]['text']

# Uso: base de conhecimento interna sobre políticas da empresa
rag = SistemaRAG()
rag.carregar_base([
    "A política de backup exige retenção de 30 dias para dados de produção.",
    "Deploys em produção só podem ocorrer entre 8h e 18h em dias úteis.",
    "Todo bucket S3 novo deve ter block public access habilitado por padrão.",
    "Credenciais IAM devem ser rotacionadas a cada 90 dias.",
])

print(rag.responder("Por quanto tempo os backups de produção são mantidos?"))
print(rag.responder("Posso fazer deploy no domingo?"))

🎯 Por que RAG é tão usado

  • Atualização sem re-treino: basta adicionar documentos à base
  • Menos alucinação: o modelo responde com base em fatos fornecidos
  • Rastreabilidade: você sabe de qual documento veio a resposta
  • Privacidade: dados sensíveis ficam na sua base, não no modelo

⚙️ Bedrock Knowledge Bases

A AWS oferece o Bedrock Knowledge Bases, um serviço gerenciado que automatiza todo o pipeline RAG: ingestão de documentos do S3, chunking, geração de embeddings, armazenamento em banco vetorial (OpenSearch) e recuperação. Você usa a API retrieve_and_generate() e o serviço cuida do resto.

Seção 7

Function Calling (Tool Use)

Tool use permite que o modelo chame funções do seu código. Você descreve as ferramentas disponíveis (nome, descrição, parâmetros) e o modelo decide quando usá-las, retornando os argumentos estruturados. Isso transforma um LLM de um gerador de texto em um agente capaz de consultar bancos de dados, chamar APIs e executar ações.

🛠️ Definindo e Executando Ferramentas

📋 Tool Use com a Converse API

import json

# Funções reais que o modelo poderá "chamar"
def obter_clima(cidade: str) -> dict:
    """Simula consulta a uma API de clima."""
    dados = {"São Paulo": 24, "Rio de Janeiro": 30, "Curitiba": 18}
    return {"cidade": cidade, "temperatura_c": dados.get(cidade, 22)}

def listar_instancias_ec2(estado: str = "running") -> dict:
    """Simula listagem de instâncias EC2."""
    return {"estado": estado, "quantidade": 5, "tipos": ["t3.micro", "t3.small"]}

# Registro de ferramentas disponíveis
FERRAMENTAS = {"obter_clima": obter_clima, "listar_instancias_ec2": listar_instancias_ec2}

tool_config = {
    "tools": [
        {
            "toolSpec": {
                "name": "obter_clima",
                "description": "Obtém a temperatura atual de uma cidade brasileira.",
                "inputSchema": {"json": {
                    "type": "object",
                    "properties": {"cidade": {"type": "string", "description": "Nome da cidade"}},
                    "required": ["cidade"]
                }}
            }
        },
        {
            "toolSpec": {
                "name": "listar_instancias_ec2",
                "description": "Lista instâncias EC2 por estado (running, stopped).",
                "inputSchema": {"json": {
                    "type": "object",
                    "properties": {"estado": {"type": "string"}},
                    "required": []
                }}
            }
        }
    ]
}

def agente_com_ferramentas(pergunta: str) -> str:
    messages = [{"role": "user", "content": [{"text": pergunta}]}]

    while True:
        response = bedrock_runtime.converse(
            modelId="anthropic.claude-3-sonnet-20240229-v1:0",
            messages=messages,
            toolConfig=tool_config,
            inferenceConfig={"maxTokens": 1024}
        )

        saida = response['output']['message']
        messages.append(saida)

        # O modelo quer usar uma ferramenta?
        if response['stopReason'] == 'tool_use':
            for bloco in saida['content']:
                if 'toolUse' in bloco:
                    tool = bloco['toolUse']
                    nome = tool['name']
                    args = tool['input']
                    print(f"🔧 Modelo chamou: {nome}({args})")

                    # Executa a função real
                    resultado = FERRAMENTAS[nome](**args)

                    # Devolve o resultado ao modelo
                    messages.append({
                        "role": "user",
                        "content": [{
                            "toolResult": {
                                "toolUseId": tool['toolUseId'],
                                "content": [{"json": resultado}]
                            }
                        }]
                    })
        else:
            # Resposta final em texto
            return saida['content'][0]['text']

print(agente_com_ferramentas("Qual a temperatura em Curitiba e quantas EC2 estão rodando?"))

⚠️ Segurança em tool use

O modelo decide QUAIS argumentos passar, mas VOCÊ controla o que a função faz. Nunca dê ao modelo ferramentas que executem ações destrutivas sem validação. Sempre valide os argumentos, aplique least privilege nas permissões IAM da Lambda, e exija confirmação humana para operações sensíveis (deletar recursos, gastar dinheiro, enviar e-mails em massa).

💡 Boas práticas de prompt

  • Papel + tarefa + formato: diga quem o modelo é, o que fazer e como responder
  • Delimitadores: use marcadores claros (CONTEXTO:, PERGUNTA:) para separar seções
  • Restrições explícitas: "responda em no máximo 3 frases", "use apenas o contexto"
  • Temperature baixa para tarefas factuais/extração; alta para criatividade

💰 Rastreando e Reduzindo Custos

📋 Calculadora de Custo de Tokens

# Preços aproximados por 1.000 tokens (verifique a tabela oficial atual)
PRECOS = {
    "anthropic.claude-3-haiku-20240307-v1:0":  {"entrada": 0.00025, "saida": 0.00125},
    "anthropic.claude-3-sonnet-20240229-v1:0": {"entrada": 0.003,   "saida": 0.015},
    "amazon.titan-text-express-v1":            {"entrada": 0.0002,  "saida": 0.0006},
}

def calcular_custo(model_id: str, tokens_entrada: int, tokens_saida: int) -> float:
    p = PRECOS[model_id]
    custo = (tokens_entrada / 1000 * p["entrada"]) + (tokens_saida / 1000 * p["saida"])
    return round(custo, 6)

def conversar_com_custo(prompt: str, model_id: str) -> dict:
    response = bedrock_runtime.converse(
        modelId=model_id,
        messages=[{"role": "user", "content": [{"text": prompt}]}],
        inferenceConfig={"maxTokens": 512}
    )
    uso = response['usage']
    custo = calcular_custo(model_id, uso['inputTokens'], uso['outputTokens'])
    return {
        "resposta": response['output']['message']['content'][0]['text'],
        "tokens": uso['totalTokens'],
        "custo_usd": custo
    }

r = conversar_com_custo("Resuma o que é o AWS Bedrock em 2 frases.",
                        "anthropic.claude-3-haiku-20240307-v1:0")
print(f"Custo: ${r['custo_usd']} | Tokens: {r['tokens']}")

⚠️ Estratégias de redução de custo

  • Escolha o modelo certo: Haiku custa ~12x menos que Sonnet para tarefas simples
  • Limite max_tokens: não gere mais do que precisa
  • Cache respostas: perguntas repetidas não precisam nova inferência (use DynamoDB/ElastiCache)
  • Prompt caching: o Bedrock suporta cache de prompts longos reutilizados, reduzindo custo de entrada
  • Encurte prompts: contexto desnecessário aumenta tokens de entrada em toda chamada

Vamos reunir tudo o que aprendemos em um chatbot especialista em AWS de produção: mantém histórico de conversa, usa system prompt, rastreia custos por sessão, suporta streaming, persiste conversas em disco e controla o modelo usado. 🤖 Implementação do Chatbot

📋 chatbot_aws.py — Aplicação Completa

"""
Chatbot especialista em AWS usando Amazon Bedrock (Converse API).
Recursos: memória de conversa, streaming, rastreio de custo, persistência.
"""
import boto3
import json
from datetime import datetime
from pathlib import Path


class ChatbotAWS:
    PRECOS = {
        "anthropic.claude-3-haiku-20240307-v1:0":  {"entrada": 0.00025, "saida": 0.00125},
        "anthropic.claude-3-sonnet-20240229-v1:0": {"entrada": 0.003,   "saida": 0.015},
    }

    def __init__(self, model_id: str = "anthropic.claude-3-haiku-20240307-v1:0"):
        self.client = boto3.client('bedrock-runtime', region_name='us-east-1')
        self.model_id = model_id
        self.messages = []          # histórico da conversa
        self.custo_total = 0.0      # custo acumulado da sessão
        self.tokens_total = 0
        self.system = [{"text": (
            "Você é um especialista AWS certificado (Solutions Architect). "
            "Responda de forma clara e prática, com exemplos de código quando "
            "relevante. Sempre mencione boas práticas de segurança e custo. "
            "Se não souber, diga que não sabe."
        )}]

    def _registrar_custo(self, uso: dict):
        p = self.PRECOS.get(self.model_id, {"entrada": 0, "saida": 0})
        custo = (uso['inputTokens'] / 1000 * p['entrada'] +
                 uso['outputTokens'] / 1000 * p['saida'])
        self.custo_total += custo
        self.tokens_total += uso['totalTokens']

    def enviar(self, mensagem: str) -> str:
        """Envia mensagem, mantém contexto e retorna a resposta."""
        self.messages.append({"role": "user", "content": [{"text": mensagem}]})

        response = self.client.converse(
            modelId=self.model_id,
            system=self.system,
            messages=self.messages,
            inferenceConfig={"maxTokens": 2048, "temperature": 0.3}
        )

        resposta_msg = response['output']['message']
        self.messages.append(resposta_msg)
        self._registrar_custo(response['usage'])
        return resposta_msg['content'][0]['text']

    def enviar_streaming(self, mensagem: str) -> str:
        """Versão com streaming — imprime token a token."""
        self.messages.append({"role": "user", "content": [{"text": mensagem}]})

        response = self.client.converse_stream(
            modelId=self.model_id,
            system=self.system,
            messages=self.messages,
            inferenceConfig={"maxTokens": 2048, "temperature": 0.3}
        )

        texto = ""
        for evento in response['stream']:
            if 'contentBlockDelta' in evento:
                trecho = evento['contentBlockDelta']['delta']['text']
                print(trecho, end='', flush=True)
                texto += trecho
            elif 'metadata' in evento:
                self._registrar_custo(evento['metadata']['usage'])

        self.messages.append({"role": "assistant", "content": [{"text": texto}]})
        print()
        return texto

    def resumo_sessao(self) -> str:
        return (f"Mensagens: {len(self.messages)} | "
                f"Tokens: {self.tokens_total} | "
                f"Custo: ${self.custo_total:.4f}")

    def salvar(self, pasta: str = "conversas"):
        Path(pasta).mkdir(exist_ok=True)
        arquivo = Path(pasta) / f"conversa_{datetime.now():%Y%m%d_%H%M%S}.json"
        dados = {
            "model_id": self.model_id,
            "custo_total": round(self.custo_total, 6),
            "tokens_total": self.tokens_total,
            "messages": self.messages,
        }
        arquivo.write_text(json.dumps(dados, indent=2, ensure_ascii=False),
                           encoding="utf-8")
        print(f"💾 Conversa salva em {arquivo}")


def main():
    bot = ChatbotAWS()
    print("🤖 Chatbot AWS — Bedrock (digite 'sair' para encerrar)\n")

    while True:
        pergunta = input("Você: ").strip()
        if pergunta.lower() in ("sair", "exit", "quit"):
            print(f"\n📊 {bot.resumo_sessao()}")
            bot.salvar()
            break
        if not pergunta:
            continue

        print("\n🤖 ", end="")
        bot.enviar_streaming(pergunta)
        print(f"   [{bot.resumo_sessao()}]\n")


if __name__ == "__main__":
    main()
