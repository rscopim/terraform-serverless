Condicionais — if, elif, else

Aprenda a tomar decisões no seu código com as estruturas condicionais do Python. Entenda como o interpretador avalia expressões booleanas, a diferença entre valores truthy e falsy, e domine todas as formas de escrita de condicionais — do simples if até o operador ternário.

1.1 — Contexto Booleano e Valores Truthy/Falsy

Antes de mergulhar nas condicionais, é essencial entender como o Python avalia expressões em um contexto booleano. Todo valor em Python pode ser tratado como True ou False quando usado em uma condição.

Python considera os seguintes valores como Falsy (equivalem a False):

Valores Falsy em Pythonconceito

Estes valores são avaliados como False em qualquer contexto booleano (if, while, and, or, not):

# Todos estes valores são considerados FALSY (False)
False           # O próprio booleano False
None            # O valor nulo do Python
0               # Zero inteiro
0.0             # Zero float
0j              # Zero complexo
""              # String vazia
[]              # Lista vazia
()              # Tupla vazia
{}              # Dicionário vazio
set()           # Set vazio
frozenset()     # Frozenset vazio
range(0)        # Range vazio
b""             # Bytes vazio
bytearray(b"")  # Bytearray vazio

# Verificando com bool()
print(bool(0))        # False
print(bool(""))       # False
print(bool([]))       # False
print(bool(None))     # False
print(bool({}))       # False
Valores Truthy em Pythonconceito

Qualquer valor que NÃO esteja na lista de falsy é considerado Truthy (equivale a True):

# Todos estes valores são considerados TRUTHY (True)
True            # O próprio booleano True

-1              # Números negativos também são truthy

(None,)         # Tupla com um elemento (não é vazia!)
{"a": 1}        # Dicionário com elementos
{0}             # Set com um elemento

# Verificando com bool()

print(bool("oi"))     # True
print(bool([0]))      # True — lista com 1 elemento!
print(bool(" "))      # True — string com espaço!
print(bool("False"))  # True — é uma string não-vazia!

💡 Regra Prática para Truthy/Falsy

Falsy = vazio ou zero. Se algo está vazio (string, lista, dict, set) ou é zero numérico, é Falsy. Todo o resto é Truthy. Essa regra cobre 99% dos casos no dia a dia.

Objetos personalizados podem definir seu próprio comportamento booleano implementando o método __bool__() ou __len__(). Se __len__ retorna 0, o objeto é Falsy.

1.2 — Estrutura if Simples

A estrutura if é a forma mais básica de tomada de decisão. O bloco de código indentado só é executado se a condição for avaliada como True (ou truthy).

ifsintaxe

Sintaxe básica do if — note os dois-pontos (:) e a indentação obrigatória:

# Sintaxe:
# if condição:
#     bloco_de_código  (indentado com 4 espaços)

# Exemplo básico
idade = 18
if idade >= 18:
    print("Você é maior de idade")
    print("Pode acessar o sistema")

# A indentação define o bloco
temperatura = 35
if temperatura > 30:
    print("Está muito quente!")      # Dentro do if
    print("Beba bastante água!")     # Dentro do if
print("Temperatura registrada.")     # FORA do if — sempre executa

# Condição com variável booleana
sistema_ativo = True
if sistema_ativo:
    iniciar_monitoramento()

# Condição com expressão
cpu_usage = 87.5
if cpu_usage > 80:
    enviar_alerta("CPU alta", cpu_usage)
    escalar_recursos()

⚠️ Erros Comuns com if

  • Esquecer os dois-pontos (:) — if idade >= 18 causa SyntaxError
  • Indentação inconsistente — Misturar tabs e espaços causa IndentationError
  • Usar = ao invés de == — if x = 5 é atribuição, não comparação (SyntaxError em Python)
  • Bloco vazio — Se não tem código ainda, use pass como placeholder

1.4 — Estrutura if-elif-else (Cadeia de Condições)

Quando existem múltiplas condições mutuamente exclusivas, use elif (abreviação de "else if"). O Python avalia as condições de cima para baixo e executa apenas o primeiro bloco cuja condição seja verdadeira.

if-elif-elsesintaxe

Encadeamento de múltiplas condições — apenas um bloco é executado:

# Sintaxe:
# if condição_1:
#     bloco_1
# elif condição_2:
#     bloco_2
# elif condição_3:
#     bloco_3
# else:
#     bloco_padrão (nenhuma condição anterior foi verdadeira)

# Exemplo: classificação de notas
nota = 7.5

if nota >= 9.0:
    conceito = "A"
    mensagem = "Excelente!"
elif nota >= 7.0:
    conceito = "B"
    mensagem = "Bom desempenho"
elif nota >= 5.0:
    conceito = "C"
    mensagem = "Aprovado"
elif nota >= 3.0:
    conceito = "D"
    mensagem = "Recuperação"
else:

    mensagem = "Reprovado"

print(f"Nota: {nota} | Conceito: {conceito} | {mensagem}")
# Saída: Nota: 7.5 | Conceito: B | Bom desempenho

💡 Dica: Ordem das Condições Importa!

No exemplo de notas acima, se invertêssemos a ordem (testando nota >= 3.0 primeiro), uma nota 9.5 entraria nesse bloco e nunca chegaria ao teste de nota >= 9.0. Sempre ordene do mais específico para o mais geral, ou do maior para o menor, conforme o caso.

1.5 — Condicionais Aninhadas (Nested if)

É possível colocar um if dentro de outro if, criando condicionais aninhadas. Porém, evite aninhar mais de 2-3 níveis — código profundamente aninhado é difícil de ler e manter.

Nested ifpadrão

Condicionais dentro de condicionais — use com moderação:

# Exemplo: sistema de autorização em camadas
usuario_autenticado = True
perfil = "admin"
mfa_ativo = True

if usuario_autenticado:
    if perfil == "admin":
        if mfa_ativo:
            print("✅ Acesso total concedido (admin + MFA)")
            liberar_painel_admin()
        else:
            print("⚠️ Admin sem MFA — acesso limitado")
            liberar_painel_basico()
    elif perfil == "editor":
        print("📝 Acesso de editor concedido")
        liberar_editor()
    else:
        print("👤 Acesso de leitor")
        liberar_leitura()
else:
    print("❌ Usuário não autenticado — redirecionando para login")
    redirecionar_login()

# ═══════════════════════════════════════════════════════════
# REFATORAÇÃO: Mesmo código sem aninhamento excessivo
# (técnica: early return / guard clauses)
# ═══════════════════════════════════════════════════════════

def autorizar_acesso(usuario_autenticado, perfil, mfa_ativo):
    """Versão refatorada — mais limpa e fácil de manter."""
    if not usuario_autenticado:
        print("❌ Não autenticado")
        return redirecionar_login()

    if perfil == "admin" and mfa_ativo:
        print("✅ Acesso total (admin + MFA)")
        return liberar_painel_admin()

    if perfil == "admin":
        print("⚠️ Admin sem MFA — acesso limitado")
        return liberar_painel_basico()

    if perfil == "editor":
        print("📝 Acesso de editor")
        return liberar_editor()

    print("👤 Acesso de leitor")
    return liberar_leitura()

⚠️ Anti-padrão: Pirâmide da Perdição (Pyramid of Doom)

Código com muitos níveis de aninhamento (5+) é chamado de "Pyramid of Doom". Isso torna o código difícil de ler, testar e manter. Prefira guard clauses (retornos antecipados) para eliminar níveis de indentação. Se uma função tem mais de 3 níveis de if aninhado, considere refatorar.

1.6 — Operador Ternário (Expressão Condicional)

Python oferece uma forma compacta de escrever condicionais simples em uma única linha, conhecida como operador ternário ou expressão condicional.

x = a if condição else bsintaxe

O operador ternário retorna um valor baseado em uma condição:

# Sintaxe: valor_se_true if condição else valor_se_false

# Exemplo básico
idade = 20
status = "maior" if idade >= 18 else "menor"
print(status)  # "maior"

# Equivalente ao if-else tradicional:
# if idade >= 18:
#     status = "maior"
# else:
#     status = "menor"

# Exemplo: valor padrão
nome = input("Nome: ").strip()
saudacao = f"Olá, {nome}!" if nome else "Olá, visitante!"

# Exemplo: formatação condicional
quantidade = 1
texto = f"{quantidade} item" if quantidade == 1 else f"{quantidade} itens"
print(texto)  # "1 item"

# Exemplo: limitar valor (clamp)
valor = 150
valor_limitado = valor if valor <= 100 else 100
print(valor_limitado)  # 100

# Exemplo DevOps: selecionar ambiente
ambiente = "production" if deploy_final else "staging"
endpoint = f"https://api.{'prod' if ambiente == 'production' else 'stg'}.cloudtrilhas.com"

# Ternário aninhado (EVITE — prejudica legibilidade)
# ❌ Difícil de ler:
resultado = "A" if nota >= 9 else "B" if nota >= 7 else "C" if nota >= 5 else "F"

# ✅ Preferível — use if-elif-else normal para 3+ condições:
if nota >= 9:
    resultado = "A"
elif nota >= 7:
    resultado = "B"
elif nota >= 5:
    resultado = "C"
else:
    resultado = "F"

# Uso legítimo em comprehensions:
numeros = [1, -2, 3, -4, 5]
absolutos = [n if n >= 0 else -n for n in numeros]
print(absolutos)  # [1, 2, 3, 4, 5]

# Uso em argumentos de função:
print("PAR" if x % 2 == 0 else "ÍMPAR")
registrar_log(nivel="ERROR" if falha_critica else "WARNING")

2.3 — Avaliação de Curto-Circuito (Short-Circuit Evaluation)

Os operadores and e or em Python utilizam avaliação de curto-circuito: eles param de avaliar assim que o resultado final é determinado. Além disso, eles retornam um dos operandos (não necessariamente True/False).

and / or — Short-Circuitimportante

Entenda como Python avalia expressões lógicas e o que elas retornam:

# ═══ REGRAS DE CURTO-CIRCUITO ═══
#
# 'and': retorna o PRIMEIRO valor falsy, ou o ÚLTIMO valor se todos truthy
# 'or':  retorna o PRIMEIRO valor truthy, ou o ÚLTIMO valor se todos falsy

# ═══ Operador 'and' ═══
print(1 and 2 and 3)        # 3 (todos truthy → retorna o último)
print(1 and 0 and 3)        # 0 (0 é falsy → retorna o primeiro falsy)
print(1 and "" and 3)       # "" (string vazia é falsy)
print([] and "texto")       # [] (lista vazia é falsy → para aqui)

# O segundo operando NÃO é avaliado se o primeiro é falsy:
def funcao_cara():
    print("Fui chamada!")
    return True

False and funcao_cara()  # "Fui chamada!" NÃO é impresso!
True and funcao_cara()   # "Fui chamada!" É impresso

# ═══ Operador 'or' ═══
print(0 or "" or "fallback")    # "fallback" (primeiro truthy)
print(0 or [] or None)          # None (todos falsy → retorna o último)
print("valor" or "default")    # "valor" (primeiro truthy)
print(None or 0 or "achei")    # "achei" (primeiro truthy)

# O segundo operando NÃO é avaliado se o primeiro é truthy:
True or funcao_cara()   # funcao_cara() NÃO é executada!
False or funcao_cara()  # funcao_cara() É executada

# ═══ USO PRÁTICO: Valores padrão com 'or' ═══
nome = input("Nome: ") or "Visitante"
# Se input for "" (falsy), usa "Visitante"

config_porta = os.environ.get("PORT") or "8080"
# Se variável de ambiente não existe (None) ou é vazia (""), usa "8080"

# ═══ USO PRÁTICO: Verificação segura com 'and' ═══
# Evita erros ao acessar atributos que podem ser None
usuario = obter_usuario(id=42)  # Pode retornar None

# ❌ Perigoso: AttributeError se usuario for None
# if usuario.ativo:
#     ...

# ✅ Seguro com curto-circuito:
if usuario and usuario.ativo:
    print(f"Usuário {usuario.nome} está ativo")
# Se usuario for None (falsy), 'usuario.ativo' NÃO é avaliado!

# ═══ USO PRÁTICO: Cadeia de fallbacks ═══
# Primeiro valor não-vazio vence
servidor = (
    os.environ.get("DB_HOST")       # 1ª prioridade: variável de ambiente
    or config.get("database_host")  # 2ª prioridade: arquivo de config
    or "localhost"                   # 3ª prioridade: valor padrão
)

⚠️ Armadilha do 'or' com Zero

Cuidado: valor or default substituirá qualquer valor falsy, incluindo 0, "" e [] — que podem ser valores legítimos! Se 0 é um valor válido, use o operador ternário ou if valor is not None em vez de or.

# Problema:
porta = 0  # Porta 0 pode ser válida em alguns contextos
resultado = porta or 8080  # resultado = 8080 (ERRADO! 0 era o valor desejado)

# Solução:

Match-Case — Pattern Matching (Python 3.10+)

Conheça o poderoso sistema de pattern matching introduzido no Python 3.10, que vai muito além de um simples switch-case — permitindo desestruturação, guards, wildcards e matching de estruturas complexas.

3.1 — Sintaxe Básica do match-case

O match-case foi introduzido na PEP 634 (Python 3.10, outubro 2021). Diferente do switch-case de outras linguagens, ele implementa structural pattern matching — um sistema sofisticado de correspondência de padrões que pode desestruturar dados.

match-casePython 3.10+

Sintaxe básica — matching de valores literais:

# Sintaxe básica:
# match expressão:
#     case padrão_1:
#         bloco_1
#     case padrão_2:
#         bloco_2
#     case _:
#         bloco_padrão (wildcard — captura tudo)

# Exemplo: comando de terminal
comando = input(">>> ")

match comando:
    case "help":
        print("Comandos disponíveis: help, status, deploy, exit")
    case "status":
        print("Todos os serviços estão operacionais")
    case "deploy":
        print("Iniciando deploy...")
        executar_deploy()
    case "exit":
        print("Saindo...")
        sys.exit(0)
    case _:
        print(f"Comando '{comando}' não reconhecido. Digite 'help'.")

# Exemplo: dia da semana
dia = "segunda"
match dia:
    case "segunda" | "terça" | "quarta" | "quinta" | "sexta":
        print("Dia útil — trabalhar!")
    case "sábado" | "domingo":
        print("Fim de semana — descansar!")
    case _:
        print("Dia inválido")

# NOTA: O operador | funciona como OR no pattern matching
# É diferente do 'or' lógico — aqui significa "case A ou case B"

⚠️ Requisito de Versão

O match-case requer Python 3.10 ou superior. Se seu projeto precisa suportar versões anteriores, use if-elif-else ou um dicionário de dispatch. Verifique sua versão com python --version.

3.2 — Wildcards e Captura de Variáveis

Wildcards e Capture Patternspadrão

O underscore (_) captura qualquer valor sem vinculá-lo a uma variável. Nomes capturam o valor em uma variável:

# Wildcard: _ (underscore) — captura qualquer valor, descarta

    case 200:
        print("OK")
    case 404:
        print("Not Found")
    case 500:
        print("Internal Server Error")
    case _:  # Wildcard — qualquer outro valor
        print(f"Status não tratado")

# ⚠️ CUIDADO: Variáveis em case CAPTURAM o valor (não comparam!)

    case ATIVO:  # ❌ ERRADO! Isso CAPTURA status na variável 'ATIVO'
        print("Está ativo")  # Sempre executa!

# Para comparar com variáveis, use guards (if):
match status:
    case valor if valor == ATIVO:  # ✅ Correto com guard
        print("Está ativo")

# Ou use valores literais diretamente:
match status:
    case "ativo":  # ✅ Correto: literal string
        print("Está ativo")

# Captura com nome (capture pattern):
match comando.split():
    case ["deploy", projeto]:  # 'projeto' captura o segundo elemento
        print(f"Deploy do projeto: {projeto}")
    case ["scale", servico, replicas]:
        print(f"Escalando {servico} para {replicas} réplicas")
    case ["help"]:
        print("Uso: deploy  | scale  ")
    case _:
        print("Comando inválido")

6.3 — Cláusula else em Loops

Python tem uma funcionalidade única: a cláusula else em loops. O bloco else é executado apenas quando o loop termina normalmente (sem break). Se o break for acionado, o else é pulado.

O else do loop detecta se o loop completou sem interrupção:

# else em for — executado se o loop NÃO foi interrompido por break

# Exemplo: verificar se um número é primo
def eh_primo(n):
    if n < 2:
        return False
    for i in range(2, int(n**0.5) + 1):
        if n % i == 0:
            break  # Encontrou divisor — NÃO é primo
    else:
        # Só executa se o for completou sem break
        # (nenhum divisor foi encontrado)
        return True
    return False

print(eh_primo(17))  # True
print(eh_primo(15))  # False

8.1 — O que é um Iterador? (iter() e next())

Todo loop for no Python utiliza o protocolo de iteração por baixo dos panos. Entender esse protocolo ajuda a criar código mais eficiente e elegante.

iter() / next()protocolo

Como o for funciona internamente — o protocolo de iteração:

# O for do Python faz isso internamente:
# 1. Chama iter(objeto) para obter um iterador
# 2. Chama next(iterador) repetidamente para obter elementos
# 3. Para quando recebe StopIteration

# Demonstração manual do protocolo:
frutas = ["maçã", "banana", "laranja"]

# Passo 1: Obter o iterador
iterador = iter(frutas)  # Cria um iterador a partir da lista
print(type(iterador))    # 

# Passo 2: Obter elementos um a um
print(next(iterador))    # "maçã"
print(next(iterador))    # "banana"
print(next(iterador))    # "laranja"

# Passo 3: Fim — StopIteration
# print(next(iterador))  # ❌ StopIteration exception!

# next() com valor padrão (evita exception)
iterador2 = iter([1, 2])
print(next(iterador2, "fim"))  # 1
print(next(iterador2, "fim"))  # 2
print(next(iterador2, "fim"))  # "fim" (em vez de StopIteration)

# ═══ ITERÁVEL vs ITERADOR ═══
# ITERÁVEL: objeto que pode ser iterado (tem __iter__)
#   Exemplos: list, str, dict, set, tuple, range, file
#   Pode criar MÚLTIPLOS iteradores

# ITERADOR: objeto que produz valores um a um (tem __next__)
#   É SINGLE-USE — uma vez consumido, acabou
#   Todo iterador é iterável, mas nem todo iterável é iterador

# Lista é ITERÁVEL (pode criar iteradores dela)
lista = [1, 2, 3]
it1 = iter(lista)  # Iterador 1
it2 = iter(lista)  # Iterador 2 (independente!)
print(next(it1))   # 1

print(next(it1))   # 2

# for item in colecao:
#     processar(item)

# Equivale internamente a:

8.2 — Geradores com yield

Um gerador é uma função especial que usa yield em vez de return. Ela "pausa" sua execução a cada yield e "retoma" na próxima chamada de next(). Isso permite gerar valores sob demanda, sem ocupar memória.

yieldgerador

Funções geradoras produzem valores um de cada vez, sem manter todos na memória:

# Função NORMAL retorna todos os valores de uma vez:
def quadrados_lista(n):
    resultado = []
    for i in range(n):
        resultado.append(i ** 2)
    return resultado  # Retorna lista INTEIRA na memória

# Função GERADORA produz um valor de cada vez:
def quadrados_gen(n):
    for i in range(n):
        yield i ** 2  # "Pausa" aqui e retorna o valor
        # Próxima chamada de next() retoma DAQUI

# Uso:
for q in quadrados_gen(5):
    print(q, end=" ")
# Saída: 0 1 4 9 16

# A diferença: memória!
import sys
lista = quadrados_lista(1_000_000)  # ~8MB na memória
gen = quadrados_gen(1_000_000)      # ~120 bytes na memória!
print(sys.getsizeof(lista))  # 8448728
print(sys.getsizeof(gen))    # 112

# ═══ GERADOR DE FIBONACCI ═══
def fibonacci():
    """Gera a sequência de Fibonacci infinitamente."""
    a, b = 0, 1
    while True:  # Infinito! Mas OK — é lazy
        yield a
        a, b = b, a + b

#     código arriscado
# except ExcecaoEspecifica as e:
#     tratamento se der erro
# else:
#     executado APENAS se NÃO houve exceção no try
# finally:
#     executado SEMPRE (com ou sem exceção) — limpeza/cleanup

# ═══ EXEMPLO COMPLETO ═══
def conectar_banco(host, porta, database):
    """Exemplo completo com try/except/else/finally."""
    conexao = None
    try:
        print(f"🔌 Conectando a {host}:{porta}/{database}...")
        conexao = criar_conexao(host, porta, database)
        conexao.testar()
    except ConnectionRefusedError:
        print(f"❌ Conexão recusada — servidor {host}:{porta} está ativo?")
        return None
    except TimeoutError:
        print(f"❌ Timeout — servidor {host}:{porta} não respondeu")
        return None
    except Exception as e:
        print(f"❌ Erro inesperado: {type(e).__name__}: {e}")
        return None

        return conexao
    finally:
        # SEMPRE executa — perfeito para cleanup
        print("🧹 Finalizando tentativa de conexão...")
        # Se a conexão falhou parcialmente, garantir cleanup
        if conexao and not conexao.esta_conectado():
            conexao.fechar()

9.4 — try/except no Controle de Fluxo (EAFP)

Python segue a filosofia EAFP (Easier to Ask Forgiveness than Permission) — é preferível tentar e tratar o erro do que verificar previamente se a operação é possível.

EAFP vs LBYLfilosofia

Duas abordagens para lidar com situações que podem falhar:

# ═══ LBYL (Look Before You Leap) — verificar antes ═══
# Estilo de outras linguagens (Java, C++)
# Verifica se é possível ANTES de tentar

# Verificar se chave existe antes de acessar
if "email" in usuario:
    email = usuario["email"]
else:
    email = "sem_email@default.com"

# Verificar se arquivo existe antes de abrir
import os
if os.path.exists("config.json"):
    with open("config.json") as f:
        config = json.load(f)
else:
    config = {}

# ═══ EAFP (Easier to Ask Forgiveness than Permission) — tentar e tratar ═══
# Estilo Pythônico — tenta e trata o erro se acontecer

# Tentar acessar, tratar se não existir
try:
    email = usuario["email"]
except KeyError:
    email = "sem_email@default.com"

# Mais Pythônico ainda: .get()
email = usuario.get("email", "sem_email@default.com")

# Tentar abrir, tratar se não existir
try:
    with open("config.json") as f:
        config = json.load(f)
except (FileNotFoundError, json.JSONDecodeError):
    config = {}

# ═══ POR QUE EAFP É PREFERÍVEL? ═══
# 1. Evita race conditions (arquivo pode ser deletado ENTRE o check e o open)
# 2. Mais conciso em muitos casos
# 3. Melhor performance quando o caso de sucesso é comum (exceções são raras)
# 4. Mais seguro para operações concorrentes

# ═══ VALIDAÇÃO DE INPUT COM try/except ═══
def obter_numero(mensagem="Digite um número: "):
    """EAFP: tenta converter e trata o erro."""
    while True:
        try:
            return float(input(mensagem))
        except ValueError:
            print("❌ Valor inválido! Digite um número.")

# ═══ CONVERSÃO SEGURA DE TIPOS ═══
def safe_int(valor, padrao=0):
    """Converte para int com fallback seguro."""
    try:
        return int(valor)
    except (ValueError, TypeError):
        return padrao

# Uso:
porta = safe_int(os.environ.get("PORT"), padrao=8080)
timeout = safe_int(config.get("timeout"), padrao=30)

# ═══ ACESSAR ATRIBUTOS COM FALLBACK ═══
def obter_nome_servico(obj):
    """Tenta várias formas de obter o nome."""
    try:
        return obj.nome
    except AttributeError:
        pass
    try:
        return obj["nome"]
    except (KeyError, TypeError):
        pass
    return str(obj)

💡 Quando NÃO Usar try/except

  • Não use para mascarar bugs — se um TypeError acontece, geralmente é um bug no SEU código
  • Não use except: genérico — sempre especifique a exceção
  • Não use para controle de fluxo normal quando um if simples resolve
  • Não silencie exceções com pass sem logging — isso cria bugs invisíveis

import time

def primos_ingenuo(limite):
    """Método ingênuo: testa cada número individualmente. O(n√n)"""
    primos = []
    for n in range(2, limite + 1):
        eh_primo = True
        for i in range(2, int(n**0.5) + 1):
            if n % i == 0:
                eh_primo = False
                break
        if eh_primo:
            primos.append(n)
    return primos

def crivo_eratostenes(limite):
    """Crivo de Eratóstenes: elimina múltiplos progressivamente. O(n log log n)"""
    if limite < 2:
        return []

    # Criar lista de booleanos (True = possivelmente primo)
    eh_primo = [True] * (limite + 1)
    eh_primo[0] = eh_primo[1] = False  # 0 e 1 não são primos

    # Para cada número primo encontrado, marcar seus múltiplos como não-primo
    for i in range(2, int(limite**0.5) + 1):
        if eh_primo[i]:
            # Marcar todos os múltiplos de i como não-primo
            # Começar de i² (múltiplos menores já foram marcados)
            for multiplo in range(i * i, limite + 1, i):
                eh_primo[multiplo] = False

    # Extrair os primos (comprehension!)
    return [n for n in range(2, limite + 1) if eh_primo[n]]

def crivo_comprehension(limite):
    """Versão mais concisa com set comprehension."""
    nao_primos = {j for i in range(2, int(limite**0.5) + 1) for j in range(i*i, limite+1, i)}
    return [n for n in range(2, limite + 1) if n not in nao_primos]

Exercício 12 — Conversor de Unidades com match-case (Python 3.10+)

Nível: ⭐⭐ Intermediário

Crie um conversor de unidades usando match-case que suporte: temperatura (°C ↔ °F ↔ K), distância (km ↔ mi ↔ m), peso (kg ↔ lb ↔ oz) e dados (B ↔ KB ↔ MB ↔ GB ↔ TB).

💡 Ver Solução 
def converter_unidade(valor, de, para):
    """
    Conversor universal usando match-case.
    Suporta temperatura, distância, peso e dados.
    """
    # Normalizar input
    de = de.lower().strip()
    para = para.lower().strip()

    if de == para:
        return valor

    match (de, para):
        # ═══ TEMPERATURA ═══
        case ("c", "f"):
            return valor * 9/5 + 32
        case ("f", "c"):
            return (valor - 32) * 5/9
        case ("c", "k"):
            return valor + 273.15
        case ("k", "c"):
            return valor - 273.15
        case ("f", "k"):
            return (valor - 32) * 5/9 + 273.15
        case ("k", "f"):
            return (valor - 273.15) * 9/5 + 32

        # ═══ DISTÂNCIA ═══
        case ("km", "mi"):
            return valor * 0.621371
        case ("mi", "km"):
            return valor * 1.60934
        case ("km", "m"):
            return valor * 1000
        case ("m", "km"):
            return valor / 1000
        case ("mi", "m"):
            return valor * 1609.34
        case ("m", "mi"):
            return valor / 1609.34

        # ═══ PESO ═══
        case ("kg", "lb"):
            return valor * 2.20462
        case ("lb", "kg"):
            return valor * 0.453592
        case ("kg", "oz"):
            return valor * 35.274
        case ("oz", "kg"):
            return valor / 35.274
        case ("lb", "oz"):
            return valor * 16
        case ("oz", "lb"):
            return valor / 16

        # ═══ DADOS (bytes) ═══
        case ("b", "kb") | ("kb", "mb") | ("mb", "gb") | ("gb", "tb"):
            return valor / 1024
        case ("kb", "b") | ("mb", "kb") | ("gb", "mb") | ("tb", "gb"):
            return valor * 1024
        case ("b", "mb"):
            return valor / (1024 ** 2)
        case ("b", "gb"):
            return valor / (1024 ** 3)
        case ("gb", "b"):
            return valor * (1024 ** 3)
        case ("mb", "gb"):
            return valor / 1024
        case ("gb", "tb"):
            return valor / 1024
        case ("tb", "gb"):
            return valor * 1024

        # ═══ NÃO SUPORTADO ═══
        case _:
            return None

def conversor_interativo():
    print("\n🔄 CONVERSOR DE UNIDADES")
    print("Unidades suportadas:")
    print("  Temperatura: C, F, K")
    print("  Distância: km, mi, m")
    print("  Peso: kg, lb, oz")
    print("  Dados: B, KB, MB, GB, TB")
    print("  Digite 'sair' para encerrar\n")

    while True:
        try:
            entrada = input("Converter (ex: 100 C F): ").strip()
            if entrada.lower() == "sair":
                break

            partes = entrada.split()
            if len(partes) != 3:
                print("  ❌ Formato: VALOR UNIDADE_ORIGEM UNIDADE_DESTINO\n")
                continue

            valor = float(partes[0])
            de = partes[1]
            para = partes[2]

            resultado = converter_unidade(valor, de, para)
            if resultado is not None:
                print(f"  ✅ {valor} {de.upper()} = {resultado:.4f} {para.upper()}\n")
            else:
                print(f"  ❌ Conversão de {de} para {para} não suportada\n")

        except ValueError:
            print("  ❌ Valor numérico inválido\n")
