Seção 1

Introdução a Funções

Funções são blocos de código reutilizáveis que encapsulam uma lógica específica. Elas são o pilar fundamental da programação modular, permitindo organizar código complexo em unidades menores, testáveis e com responsabilidades bem definidas.

1.1 — O que são Funções e Por que Usá-las?

Uma função é um bloco nomeado de código que executa uma tarefa específica. Em vez de copiar e colar o mesmo código várias vezes, você define uma função uma vez e a chama quantas vezes precisar.

🎯 Princípios Fundamentais — Por que usar Funções?

  • DRY (Don't Repeat Yourself): Elimina duplicação de código — escreva uma vez, use em qualquer lugar
  • Abstração: Esconde detalhes de implementação — o chamador não precisa saber COMO funciona, apenas O QUE faz
  • Reutilização: Uma função bem escrita pode ser usada em múltiplos projetos
  • Modularidade: Divide problemas complexos em partes menores e gerenciáveis
  • Testabilidade: Funções isoladas são muito mais fáceis de testar
  • Manutenção: Correções em um único lugar se propagam para todos os usos
  • Legibilidade: Nomes descritivos de funções documentam a intenção do código
  • Namespace: Variáveis locais evitam conflitos de nomes no programa

📋 A Palavra-chave def — Definindo Funções

# Sintaxe básica de uma função
# def nome_da_funcao(parametros):

# ═══ Função mais simples possível ═══
def saudacao():

saudacao()  # Olá! Bem-vindo ao CloudTrilhas!

def saudar_usuario(nome):
    """Saúda um usuário pelo nome."""
    print(f"Olá, {nome}! Bem-vindo ao CloudTrilhas!")

saudar_usuario("Ricardo")   # Olá, Ricardo! Bem-vindo ao CloudTrilhas!
saudar_usuario("Ana")       # Olá, Ana! Bem-vindo ao CloudTrilhas!

# ═══ Função com múltiplos parâmetros ═══
def calcular_custo_ec2(horas, preco_hora, regiao="us-east-1"):
    """Calcula o custo de uma instância EC2.
    
    Args:
        horas: Número de horas de uso
        preco_hora: Preço por hora da instância
        regiao: Região AWS (padrão: us-east-1)
    
    Returns:
        Custo total calculado
    """
    custo = horas * preco_hora
    print(f"[{regiao}] Custo para {horas}h: ${custo:.2f}")
    return custo

# Chamadas com argumentos posicionais e nomeados
calcular_custo_ec2(720, 0.0116)                    # 720h × $0.0116 = $8.35
calcular_custo_ec2(720, 0.0116, "sa-east-1")       # Com região explícita
calcular_custo_ec2(horas=168, preco_hora=0.096)    # Argumentos nomeados

# ═══ Diferença entre Parâmetro e Argumento ═══
# Parâmetro: variável na DEFINIÇÃO da função (nome, idade)
# Argumento: valor passado na CHAMADA da função ("Ricardo", 30)
def minha_funcao(parametro1, parametro2):  # ← parâmetros
    pass

minha_funcao("argumento1", "argumento2")   # ← argumentos

1.2 — Chamando Funções

Para executar uma função, basta usar seu nome seguido de parênteses. Os parênteses são obrigatórios — sem eles, você está apenas referenciando o objeto função, não executando-o.

📋 Formas de Chamar Funções

# ═══ Chamada simples ═══
def listar_instancias():
    """Lista todas as instâncias EC2."""
    print("Listando instâncias...")
    return ["i-001", "i-002", "i-003"]

# Executar a função
resultado = listar_instancias()
print(resultado)  # ['i-001', 'i-002', 'i-003']

# CUIDADO: sem parênteses NÃO executa!
referencia = listar_instancias  # Apenas referencia o objeto função
print(referencia)               # <function listar_instancias at 0x...>
print(type(referencia))         # <class 'function'>

# ═══ Chamada dentro de expressões ═══
def contar_recursos(servico):
    recursos = {"ec2": 5, "s3": 12, "lambda": 23}
    return recursos.get(servico, 0)

# Função como parte de expressão
total = contar_recursos("ec2") + contar_recursos("s3")
print(f"Total de recursos: {total}")  # Total de recursos: 17

# Em f-strings
print(f"Lambdas ativas: {contar_recursos('lambda')}")

# Em condições
if contar_recursos("ec2") > 3:
    print("Muitas instâncias! Considere auto-scaling.")

# Em list comprehensions
servicos = ["ec2", "s3", "lambda", "rds", "sqs"]
contagem = [(s, contar_recursos(s)) for s in servicos]
print(contagem)  # [('ec2', 5), ('s3', 12), ('lambda', 23), ('rds', 0), ('sqs', 0)]

1.3 — Valores de Retorno (return)

A instrução return encerra a execução da função e envia um valor de volta ao chamador. Toda função Python retorna um valor — se não houver return explícito, retorna None.

📋 O Statement return em Detalhes

# ═══ Retorno simples ═══
def quadrado(n):
    """Retorna o quadrado de um número."""
    return n ** 2

resultado = quadrado(5)
print(resultado)  # 25

# ═══ Função sem return explícito retorna None ═══
def apenas_imprime(msg):
    print(msg)
    # Sem return — retorna None implicitamente

valor = apenas_imprime("teste")  # Imprime "teste"
print(valor)                      # None
print(type(valor))                # <class 'NoneType'>

# ═══ return sem valor = return None ═══
def validar_idade(idade):
    if idade < 0:
        print("Idade inválida!")
        return  # Encerra a função, retorna None
    print(f"Idade válida: {idade}")
    return idade

# ═══ Múltiplos returns (saída antecipada — early return) ═══
def classificar_instancia(vcpus, memoria_gb):
    """Classifica instância EC2 por tamanho."""
    if vcpus <= 1 and memoria_gb <= 1:
        return "nano"
    if vcpus <= 2 and memoria_gb <= 4:
        return "small"
    if vcpus <= 4 and memoria_gb <= 16:
        return "medium"
    if vcpus <= 8 and memoria_gb <= 32:
        return "large"
    return "xlarge"

print(classificar_instancia(2, 4))   # "small"
print(classificar_instancia(16, 64)) # "xlarge"

# ═══ Retornando múltiplos valores (tupla) ═══
def analisar_custos(faturas):
    """Retorna estatísticas de custo."""
    total = sum(faturas)
    media = total / len(faturas)
    maior = max(faturas)
    menor = min(faturas)
    return total, media, maior, menor  # Retorna uma tupla!

# Desempacotamento (unpacking)
faturas_mensais = [150.0, 230.5, 180.0, 320.0, 195.5, 280.0]
total, media, maior, menor = analisar_custos(faturas_mensais)
print(f"Total: ${total:.2f}")   # Total: $1356.00
print(f"Média: ${media:.2f}")   # Média: $226.00
print(f"Maior: ${maior:.2f}")   # Maior: $320.00
print(f"Menor: ${menor:.2f}")   # Menor: $150.00

# Ou capturar como tupla
resultado = analisar_custos(faturas_mensais)
print(type(resultado))  # <class 'tuple'>
print(resultado[0])     # 1356.0 (total)

# ═══ Retornando dicionário (mais legível para muitos valores) ═══
def health_check(servico):
    """Verifica saúde de um serviço."""
    # Simulação
    return {
        "servico": servico,
        "status": "healthy",
        "latencia_ms": 45,
        "uptime_percent": 99.97,
        "ultimo_check": "2025-01-15T10:30:00Z"
    }

status = health_check("api-gateway")
print(f"{status['servico']}: {status['status']} ({status['latencia_ms']}ms)")

Parâmetros e Argumentos

Python oferece um sistema de parâmetros extremamente flexível e poderoso. Entender todas as variações — posicionais, nomeados, com valor padrão, *args, **kwargs, keyword-only e positional-only — é essencial para criar APIs elegantes e funções robustas.

2.1 — Argumentos Posicionais

Argumentos posicionais são passados na ordem em que foram definidos. A posição determina qual parâmetro recebe qual valor.

📋 Argumentos Posicionais em Detalhes

# Argumentos posicionais — a ORDEM importa!
def criar_bucket(nome, regiao, acl):
    """Cria um bucket S3 com configurações específicas."""
    print(f"Bucket: {nome}")
    print(f"Região: {regiao}")
    print(f"ACL: {acl}")

# A ordem dos argumentos DEVE corresponder à ordem dos parâmetros
criar_bucket("meu-app-dados", "sa-east-1", "private")
# Bucket: meu-app-dados
# Região: sa-east-1
# ACL: private

# Se trocar a ordem, os valores vão para parâmetros errados!
criar_bucket("private", "meu-app-dados", "sa-east-1")  # BUG!
# Bucket: private       ← ERRADO!
# Região: meu-app-dados ← ERRADO!
# ACL: sa-east-1        ← ERRADO!

# TypeError se faltar argumentos
# criar_bucket("meu-app")  # TypeError: criar_bucket() missing 2 required positional arguments

# TypeError se passar argumentos a mais
# criar_bucket("a", "b", "c", "d")  # TypeError: takes 3 positional arguments but 4 were given

2.2 — Argumentos Nomeados (Keyword Arguments)

Argumentos nomeados são passados com a sintaxe nome=valor. A ordem não importa — o nome identifica o parâmetro.

📋 Keyword Arguments — Clareza e Flexibilidade

# Keyword arguments — a ORDEM não importa!
def criar_instancia(tipo, regiao, nome, ambiente):
    """Cria uma instância EC2."""
    print(f"Tipo: {tipo}, Região: {regiao}, Nome: {nome}, Env: {ambiente}")

# Todas estas chamadas são equivalentes:
criar_instancia(tipo="t3.micro", regiao="us-east-1", nome="web", ambiente="prod")
criar_instancia(ambiente="prod", nome="web", tipo="t3.micro", regiao="us-east-1")
criar_instancia(regiao="us-east-1", ambiente="prod", tipo="t3.micro", nome="web")

# Misturando posicionais e nomeados
# REGRA: posicionais SEMPRE vêm antes dos nomeados!
criar_instancia("t3.micro", "us-east-1", nome="web", ambiente="prod")  # OK
# criar_instancia(tipo="t3.micro", "us-east-1", "web", "prod")  # SyntaxError!

# Vantagem de keyword arguments: LEGIBILIDADE
# ❌ Difícil de entender sem ver a definição da função:
conectar("192.168.1.1", 5432, True, False, 30)

# ✅ Muito mais claro:
conectar(host="192.168.1.1", porta=5432, ssl=True, verbose=False, timeout=30)

# Dica: Use keyword arguments quando a função tem mais de 2-3 parâmetros
# ou quando os valores não são óbvios pelo contexto

2.3 — Valores Padrão (Default Values)

Parâmetros podem ter valores padrão, tornando-os opcionais na chamada. Mas cuidado com a armadilha clássica de mutáveis como padrão!

📋 Parâmetros com Valores Padrão

# Parâmetros com valor padrão são OPCIONAIS na chamada
def criar_alarme(nome, metrica, threshold, periodo=300, evaluation_periods=3,
                 comparison="GreaterThanThreshold", actions=None):
    """Cria um alarme CloudWatch com configurações padrão sensatas."""
    if actions is None:
        actions = []
    print(f"Alarme: {nome}")
    print(f"Métrica: {metrica} {comparison} {threshold}")
    print(f"Período: {periodo}s, Avaliações: {evaluation_periods}")
    print(f"Ações: {actions}")

# Usando apenas os obrigatórios (os opcionais usam valores padrão)
criar_alarme("cpu-alta", "CPUUtilization", 80)

# Sobrescrevendo alguns padrões
criar_alarme("memoria-alta", "MemoryUtilization", 90,
             periodo=60, actions=["arn:aws:sns:..."])

# REGRA: Parâmetros com padrão devem vir DEPOIS dos sem padrão
# def errado(a=1, b):  # SyntaxError: non-default argument follows default argument
def correto(b, a=1):   # OK!

⚠️ ARMADILHA CLÁSSICA: Mutáveis como Valor Padrão!

# ❌ BUG CLÁSSICO — Lista mutável como padrão
def adicionar_tag(tag, tags=[]):
    """CUIDADO: Este código tem um bug sutil!"""
    tags.append(tag)
    return tags

print(adicionar_tag("env:prod"))    # ['env:prod'] — OK
print(adicionar_tag("app:web"))     # ['env:prod', 'app:web'] — BUG!
print(adicionar_tag("team:infra"))  # ['env:prod', 'app:web', 'team:infra'] — BUG!

# O que aconteceu? A lista padrão é criada UMA VEZ na definição
# da função e compartilhada entre todas as chamadas!

# ✅ CORREÇÃO: Use None como padrão e crie dentro da função
def adicionar_tag(tag, tags=None):
    """Versão correta: cria nova lista a cada chamada."""
    if tags is None:
        tags = []
    tags.append(tag)
    return tags

print(adicionar_tag("env:prod"))    # ['env:prod'] — OK!
print(adicionar_tag("app:web"))     # ['app:web'] — OK!

# O mesmo vale para dicionários:
# ❌ def config(opts={}):
# ✅ def config(opts=None):
#        if opts is None:
#            opts = {}

# E para qualquer objeto mutável (set, lista, dict, objetos custom)
# Imutáveis como padrão são sempre seguros: int, float, str, tuple, frozenset, None

2.4 — *args — Argumentos Posicionais Arbitrários

O prefixo * em um parâmetro coleta todos os argumentos posicionais extras em uma tupla. Isso permite funções que aceitam qualquer número de argumentos.

📋 *args em Detalhes

# *args coleta argumentos posicionais extras em uma TUPLA
def somar_todos(*numeros):
    """Soma qualquer quantidade de números."""
    print(f"Tipo de numeros: {type(numeros)}")  # <class 'tuple'>
    print(f"Valores: {numeros}")
    return sum(numeros)

print(somar_todos(1, 2, 3))           # 6
print(somar_todos(10, 20, 30, 40))    # 100
print(somar_todos(5))                  # 5
print(somar_todos())                   # 0 (tupla vazia)

# ═══ Combinando parâmetros normais com *args ═══
def log_mensagem(nivel, *mensagens):
    """Loga múltiplas mensagens com um nível."""
    for msg in mensagens:
        print(f"[{nivel.upper()}] {msg}")

log_mensagem("info", "Servidor iniciado", "Porta 8080", "Pronto para conexões")
# [INFO] Servidor iniciado
# [INFO] Porta 8080
# [INFO] Pronto para conexões

# ═══ Desempacotando lista/tupla com * na chamada ═══
custos = [150.0, 230.5, 180.0, 320.0]
total = somar_todos(*custos)  # Desempacota: somar_todos(150.0, 230.5, 180.0, 320.0)
print(f"Total: ${total:.2f}")  # Total: $880.50

# ═══ Exemplo prático: função que aceita múltiplos IDs ═══
def terminar_instancias(*instance_ids):
    """Termina múltiplas instâncias EC2."""
    for iid in instance_ids:
        print(f"Terminando {iid}...")
    print(f"Total: {len(instance_ids)} instâncias terminadas")

terminar_instancias("i-001", "i-002", "i-003")

# Ou com uma lista existente
ids_para_terminar = ["i-004", "i-005", "i-006", "i-007"]
terminar_instancias(*ids_para_terminar)  # Desempacota a lista

2.5 — **kwargs — Argumentos Nomeados Arbitrários

O prefixo ** coleta todos os argumentos nomeados extras em um dicionário. Ideal para funções que precisam aceitar configurações flexíveis.

📋 **kwargs em Detalhes

# **kwargs coleta argumentos nomeados extras em um DICIONÁRIO
def criar_recurso(tipo, nome, **configuracoes):
    """Cria um recurso AWS com configurações arbitrárias."""
    print(f"Tipo: {tipo}")
    print(f"Nome: {nome}")
    print(f"Configurações ({type(configuracoes)}):")
    for chave, valor in configuracoes.items():
        print(f"  {chave}: {valor}")

criar_recurso("EC2", "web-server",
              tipo_instancia="t3.micro",
              regiao="sa-east-1",
              vpc_id="vpc-abc123",
              subnet_id="subnet-def456",
              seguranca=["sg-001", "sg-002"])
# Tipo: EC2
# Nome: web-server
# Configurações (<class 'dict'>):
#   tipo_instancia: t3.micro
#   regiao: sa-east-1
#   vpc_id: vpc-abc123
#   subnet_id: subnet-def456
#   seguranca: ['sg-001', 'sg-002']

# ═══ Desempacotando dicionário com ** na chamada ═══
config = {
    "tipo_instancia": "m5.large",
    "regiao": "us-west-2",
    "encrypted": True,
    "monitoring": True
}
criar_recurso("EC2", "api-server", **config)

# ═══ Combinando *args e **kwargs ═══
def super_flexivel(*args, **kwargs):
    """Aceita literalmente qualquer combinação de argumentos."""
    print(f"Posicionais: {args}")
    print(f"Nomeados: {kwargs}")

super_flexivel(1, 2, 3, nome="teste", ativo=True)
# Posicionais: (1, 2, 3)
# Nomeados: {'nome': 'teste', 'ativo': True}

# ═══ Padrão wrapper — Repassar argumentos para outra função ═══
def wrapper_log(func, *args, **kwargs):
    """Wrapper que loga chamadas de função."""
    print(f"Chamando {func.__name__} com args={args}, kwargs={kwargs}")
    resultado = func(*args, **kwargs)
    print(f"Retornou: {resultado}")
    return resultado

def soma(a, b):
    return a + b

wrapper_log(soma, 3, 5)
# Chamando soma com args=(3, 5), kwargs={}
# Retornou: 8

# ═══ Mesclando dicionários com ** (Python 3.9+) ═══
padrao = {"timeout": 30, "retries": 3, "verbose": False}
usuario = {"timeout": 60, "debug": True}
final = {**padrao, **usuario}  # usuario sobrescreve padrao
print(final)  # {'timeout': 60, 'retries': 3, 'verbose': False, 'debug': True}

# Python 3.9+: operador | para merge
final = padrao | usuario  # Equivalente ao ** merge

2.6 — Keyword-Only Arguments (após *)

Parâmetros definidos após * ou *args só podem ser passados por nome — nunca por posição. Isso força clareza na chamada.

📋 Keyword-Only Parameters

# Tudo APÓS * ou *args é keyword-only
def conectar_db(host, porta, *, usuario, senha, database, ssl=True):
    """
    host e porta: podem ser posicionais ou nomeados
    usuario, senha, database, ssl: APENAS nomeados (keyword-only)
    """
    protocolo = "ssl" if ssl else "tcp"
    print(f"{protocolo}://{usuario}:***@{host}:{porta}/{database}")

# ✅ Correto — keyword-only passados por nome
conectar_db("localhost", 5432, usuario="admin", senha="s3cr3t", database="app")

# ❌ Erro — tentando passar keyword-only por posição
# conectar_db("localhost", 5432, "admin", "s3cr3t", "app")

# deletar_bucket("meu-bucket", True, False)

def deletar_bucket(nome, *, force=False, versioned=False):

2.7 — Positional-Only Arguments (antes de /)

Parâmetros definidos antes de / só podem ser passados por posição — nunca por nome. Recurso do Python 3.8+ usado em APIs que imitam funções C built-in.

📋 Positional-Only Parameters (Python 3.8+)

# Tudo ANTES de / é positional-only
def potencia(base, expoente, /):
    """base e expoente só podem ser passados por posição."""
    return base ** expoente

# ✅ Correto — passando por posição
print(potencia(2, 10))  # 1024

# ❌ Erro — tentando passar por nome
# print(potencia(base=2, expoente=10))
# TypeError: potencia() got some positional-only arguments passed as keyword arguments

# ═══ Combinando todas as formas ═══
def complexa(pos_only1, pos_only2, /, normal1, normal2, *, kw_only1, kw_only2):
    """
    pos_only1, pos_only2: APENAS posicional (antes de /)
    normal1, normal2: posicional OU nomeado (entre / e *)
    kw_only1, kw_only2: APENAS nomeado (depois de *)
    """
    print(f"pos_only: {pos_only1}, {pos_only2}")
    print(f"normal: {normal1}, {normal2}")
    print(f"kw_only: {kw_only1}, {kw_only2}")

# Chamada válida:
complexa(1, 2, 3, normal2=4, kw_only1=5, kw_only2=6)
complexa(1, 2, normal1=3, normal2=4, kw_only1=5, kw_only2=6)

# ═══ Por que usar positional-only? ═══
# 1. Permite mudar nomes de parâmetros sem quebrar código existente
# 2. Evita conflito quando **kwargs pode receber o mesmo nome
# 3. Imita comportamento de funções built-in (len, range, print)

# Exemplo: evitando conflito com **kwargs
def minha_func(nome, /, **kwargs):
    """'nome' é positional-only, então kwargs pode ter chave 'nome'."""
    print(f"Parâmetro nome: {nome}")
    print(f"kwargs: {kwargs}")

minha_func("Ricardo", nome="outro_valor", idade=30)
# Parâmetro nome: Ricardo
# kwargs: {'nome': 'outro_valor', 'idade': 30}

📐 Regra de Ordenação de Parâmetros

Seção 3

Escopo de Variáveis (LEGB)

O escopo determina onde uma variável é acessível. Python utiliza a regra LEGB (Local, Enclosing, Global, Built-in) para resolver nomes. Entender escopos evita bugs sutis e é essencial para trabalhar com closures e decoradores.

3.1 — A Regra LEGB

Quando Python encontra um nome (variável, função), ele busca nessa ordem: Local → Enclosing → Global → Built-in. A busca para no primeiro escopo onde o nome é encontrado.

📋 Os 4 Níveis de Escopo

# ═══ BUILT-IN — Nomes pré-definidos do Python ═══
# print, len, range, int, str, list, True, False, None, etc.
# Sempre disponíveis em qualquer lugar do código
print(len([1, 2, 3]))  # len e print são built-in

# ═══ GLOBAL — Definido no nível do módulo (arquivo .py) ═══
AMBIENTE = "production"  # Variável global
MAX_RETRIES = 3          # Constante global (convenção: MAIÚSCULAS)

def mostrar_ambiente():
    # Pode LER variáveis globais sem declaração especial
    print(f"Ambiente: {AMBIENTE}")  # OK — leitura

mostrar_ambiente()  # "Ambiente: production"

# ═══ ENCLOSING — Escopo de função externa (closures) ═══
def externa():
    mensagem = "Olá do escopo enclosing"  # Variável no escopo enclosing
    
    def interna():
        # Pode LER variáveis do escopo enclosing
        print(mensagem)  # Acessa 'mensagem' da função externa
    
    interna()

externa()  # "Olá do escopo enclosing"

# ═══ LOCAL — Definido dentro da função atual ═══
def calcular():
    resultado = 42  # Variável LOCAL — só existe dentro de calcular()
    print(resultado)

calcular()  # 42
# print(resultado)  # NameError: name 'resultado' is not defined

# ═══ Demonstração completa do LEGB ═══
x = "global"  # G

def externa():
    x = "enclosing"  # E
    
    def interna():
        x = "local"  # L
        print(f"Dentro de interna: {x}")  # "local" (L vence)
    
    interna()
    print(f"Dentro de externa: {x}")  # "enclosing" (E — local de externa)

externa()
print(f"Nível módulo: {x}")  # "global" (G)

# Sem variável local, busca no enclosing:
def externa2():
    x = "enclosing"
    
    def interna2():
        # Sem x local — busca no enclosing
        print(f"Dentro de interna2: {x}")  # "enclosing"
    
    interna2()

externa2()

3.2 — A Palavra-chave global

Para modificar uma variável global de dentro de uma função, você precisa declará-la com global. Sem isso, Python cria uma variável local com o mesmo nome.

📋 global — Modificando Variáveis Globais

# Sem 'global', atribuição cria variável LOCAL
contador = 0  # Global

def incrementar_errado():
    # Isto cria uma variável LOCAL 'contador', não modifica a global!
    contador = 1  # Nova variável local (shadowing)
    print(f"Local: {contador}")  # 1

incrementar_errado()
print(f"Global: {contador}")  # 0 — não mudou!

# Com 'global', modifica a variável GLOBAL
def incrementar_correto():
    global contador
    contador += 1
    print(f"Global modificada: {contador}")

incrementar_correto()  # "Global modificada: 1"
incrementar_correto()  # "Global modificada: 2"
print(f"Global: {contador}")  # 2 — foi modificada!

# ═══ Caso de uso legítimo: configuração simples ═══
_config = {}

def carregar_config(arquivo):
    global _config
    import json
    with open(arquivo) as f:
        _config = json.load(f)

def get_config(chave):
    return _config.get(chave)

# ═══ PORÉM: Evite 'global' sempre que possível! ═══
# Alternativas melhores:
# 1. Passe como argumento e retorne o valor modificado
# 2. Use uma classe para encapsular estado
# 3. Use um dicionário/objeto mutável (não precisa de global para mutar)

# Exemplo: dict mutável não precisa de global
metricas = {"requests": 0, "errors": 0}

def registrar_request(sucesso=True):
    # Não precisa de 'global' — estamos MUTANDO o dict, não reatribuindo
    metricas["requests"] += 1
    if not sucesso:
        metricas["errors"] += 1

registrar_request()
registrar_request(sucesso=False)
print(metricas)  # {'requests': 2, 'errors': 1}

3.3 — A Palavra-chave nonlocal

nonlocal permite modificar variáveis do escopo enclosing (função externa). Essencial para closures que mantêm estado.

📋 nonlocal — Modificando Escopo Enclosing

# nonlocal permite modificar variável da função EXTERNA
def criar_contador(inicio=0):
    """Factory que cria um contador com closure."""
    contagem = inicio  # Variável no escopo enclosing
    
    def incrementar():
        nonlocal contagem  # Permite MODIFICAR a variável enclosing
        contagem += 1
        return contagem
    
    def decrementar():
        nonlocal contagem
        contagem -= 1
        return contagem
    
    def valor():
        return contagem  # Apenas LER não precisa de nonlocal
    
    return incrementar, decrementar, valor

# Usando o contador
inc, dec, val = criar_contador(10)
print(inc())  # 11
print(inc())  # 12
print(inc())  # 13
print(dec())  # 12
print(val())  # 12

# Cada chamada a criar_contador cria um contador INDEPENDENTE
inc2, _, val2 = criar_contador(100)
print(inc2())  # 101
print(val())   # 12  — primeiro contador não foi afetado

# ═══ Sem nonlocal — UnboundLocalError ═══
def externa():
    x = 10
    
    def interna():
        # x += 1  # UnboundLocalError: local variable 'x' referenced before assignment
        # Python vê a atribuição e assume que x é LOCAL
        pass
    
    # Com nonlocal funciona:
    def interna_correta():
        nonlocal x
        x += 1
        return x
    
    return interna_correta

# ═══ Diferença: global vs nonlocal ═══
# global  → modifica variável do MÓDULO (nível mais externo)
# nonlocal → modifica variável da FUNÇÃO EXTERNA (um nível acima)
nivel_modulo = "global"

def func_externa():
    nivel_externo = "enclosing"
    
    def func_interna():
        # global nivel_modulo      → modifica variável do módulo
        # nonlocal nivel_externo   → modifica variável de func_externa
        pass

3.4 — Variable Shadowing — Armadilhas

Shadowing ocorre quando uma variável local tem o mesmo nome de uma variável em escopo superior. Isso pode causar bugs difíceis de detectar.

📋 Armadilhas Comuns de Escopo

# ═══ Shadowing de built-ins (MUITO comum!) ═══
# ❌ Evite usar nomes de built-ins como variáveis!
list = [1, 2, 3]        # Sombra o built-in list()!
# print(list("abc"))    # TypeError: 'list' object is not callable
# Agora list é [1, 2, 3], não a classe list!

# ❌ Outros nomes perigosos:
# id = 42              # Sombra id()
# type = "EC2"         # Sombra type()
# input = "dados"      # Sombra input()
# print = "mensagem"   # Sombra print()!
# dict = {}            # Sombra dict()
# str = "texto"        # Sombra str()
# len = 5              # Sombra len()
# max = 100            # Sombra max()
# min = 0              # Sombra min()
# sum = 0              # Sombra sum()

# ✅ Use nomes descritivos em vez de nomes genéricos:
lista_servidores = [1, 2, 3]   # Em vez de 'list'
tipo_instancia = "EC2"          # Em vez de 'type'
id_recurso = 42                 # Em vez de 'id'

# ═══ UnboundLocalError — O bug mais confuso ═══
x = 10

def confusa():
    print(x)  # Parece que deveria ler o global...
    x = 20    # ... mas Python vê ESTA linha e assume x é LOCAL!

# confusa()  # UnboundLocalError: local variable 'x' referenced before assignment

# Isso acontece porque Python analisa o corpo INTEIRO da função
# antes de executar. Se encontra atribuição, marca como local.

# ═══ Solução: use nomes diferentes ou global/nonlocal ═══
x = 10

def clara():
    x_local = x + 5  # Nome diferente — sem ambiguidade
    print(x_local)   # 15

clara()
print(x)  # 10 — não foi afetada

⚠️ Boas Práticas de Escopo

  • Minimize variáveis globais — passem valores como argumentos
  • Nunca use nomes de built-ins como variáveis (list, dict, str, id, type, input, print)
  • Prefira retornar valores em vez de modificar globais
  • Use classes quando precisar de estado compartilhado entre funções
  • Evite global — torna o código difícil de testar e debuggar
  • Use nonlocal com parcimônia — closures são poderosas mas podem confundir

Funções como Objetos de Primeira Classe

Em Python, funções são first-class objects — podem ser atribuídas a variáveis, passadas como argumentos, retornadas por outras funções e armazenadas em estruturas de dados. Esse conceito é a base para closures, decoradores e programação funcional.

4.1 — Funções como Variáveis

Uma função em Python é um objeto como qualquer outro. Quando você define def foo():, está criando um objeto função e atribuindo-o ao nome foo.

📋 Funções São Objetos

# Funções são objetos — podem ser atribuídas a variáveis
def saudar(nome):
    return f"Olá, {nome}!"

# Atribuindo a outra variável (sem parênteses = referência ao objeto)
cumprimentar = saudar  # 'cumprimentar' agora aponta para o mesmo objeto função

print(saudar("Ana"))        # "Olá, Ana!"
print(cumprimentar("Ana"))  # "Olá, Ana!" — mesmo resultado!
print(saudar is cumprimentar)  # True — mesmo objeto!

# Funções têm atributos como qualquer objeto
print(saudar.__name__)      # "saudar"
print(saudar.__doc__)       # None (sem docstring)
print(type(saudar))         # <class 'function'>

# ═══ Armazenando funções em estruturas de dados ═══
def start_ec2(instance_id):
    return f"Starting {instance_id}"

def stop_ec2(instance_id):
    return f"Stopping {instance_id}"

def terminate_ec2(instance_id):
    return f"Terminating {instance_id}"

# Dicionário de funções — padrão Strategy/Dispatch
acoes = {
    "start": start_ec2,
    "stop": stop_ec2,
    "terminate": terminate_ec2
}

# Dispatch — escolher ação em runtime
acao = "stop"
resultado = acoes[acao]("i-0abc123")
print(resultado)  # "Stopping i-0abc123"

# Equivalente a um switch/case gigante, mas muito mais elegante!
for acao_nome, funcao in acoes.items():
    print(f"{acao_nome}: {funcao('i-999')}")

# ═══ Lista de funções ═══
validacoes = [
    lambda x: len(x) > 0,
    lambda x: x.isalnum(),
    lambda x: not x.startswith("-"),
]

nome_bucket = "meu-bucket-123"
resultados = [v(nome_bucket) for v in validacoes]
print(resultados)  # [True, False, False]
todos_validos = all(v(nome_bucket) for v in validacoes)
print(f"Válido: {todos_validos}")  # False

4.2 — Funções como Argumentos (Callbacks)

Funções podem ser passadas como argumentos para outras funções. Isso é a base para callbacks, strategies e programação funcional.

📋 Higher-Order Functions — Recebendo Funções

# Uma função que RECEBE outra função como argumento
def aplicar_a_todos(funcao, lista):
    """Aplica 'funcao' a cada elemento de 'lista'."""
    return [funcao(item) for item in lista]

# Passando diferentes funções
numeros = [1, -2, 3, -4, 5]
print(aplicar_a_todos(abs, numeros))        # [1, 2, 3, 4, 5]
print(aplicar_a_todos(str, numeros))        # ['1', '-2', '3', '-4', '5']
print(aplicar_a_todos(lambda x: x**2, numeros))  # [1, 4, 9, 16, 25]

# ═══ Padrão Callback — Execução assíncrona/condicional ═══
def processar_instancias(instancias, filtro, acao):

4.3 — Funções Retornando Funções (Factories)

Funções podem criar e retornar outras funções. Esse padrão é chamado de function factory ou closure factory e é a base para decoradores.

📋 Function Factories

# ═══ Factory simples — cria funções customizadas ═══
def criar_multiplicador(fator):
    """Cria uma função que multiplica por 'fator'."""
    def multiplicar(x):
        return x * fator  # 'fator' é capturado do escopo enclosing
    return multiplicar

dobro = criar_multiplicador(2)
triplo = criar_multiplicador(3)
dez_vezes = criar_multiplicador(10)

print(dobro(5))     # 10
print(triplo(5))    # 15
print(dez_vezes(5)) # 50

# Cada função criada "lembra" seu fator — isso é uma CLOSURE!

# ═══ Factory de validadores ═══
def criar_validador(min_val=None, max_val=None, tipo=None):
    """Cria função de validação com regras configuráveis."""
    def validar(valor):
        if tipo and not isinstance(valor, tipo):
            return False, f"Tipo inválido: esperado {tipo.__name__}"
        if min_val is not None and valor < min_val:
            return False, f"Valor {valor} menor que mínimo {min_val}"
        if max_val is not None and valor > max_val:
            return False, f"Valor {valor} maior que máximo {max_val}"
        return True, "Válido"
    return validar

# Criando validadores específicos
validar_porta = criar_validador(min_val=1, max_val=65535, tipo=int)
validar_percentual = criar_validador(min_val=0, max_val=100, tipo=(int, float))

print(validar_porta(8080))     # (True, 'Válido')
print(validar_porta(99999))    # (False, 'Valor 99999 maior que máximo 65535')
print(validar_porta("80"))     # (False, 'Tipo inválido: esperado int')

# ═══ Factory de loggers com prefixo ═══
def criar_logger(modulo):
    """Cria função de log com prefixo do módulo."""
    def log(nivel, mensagem):
        from datetime import datetime
        ts = datetime.now().strftime("%H:%M:%S")
        print(f"[{ts}] [{nivel.upper()}] [{modulo}] {mensagem}")
    return log

log_db("warning", "Query lenta detectada (2.3s)")
log_auth("error", "Token expirado para user_id=42")

4.4 — Closures (Funções com Memória)

Uma closure é uma função interna que "lembra" variáveis do escopo onde foi criada, mesmo depois que a função externa terminou. É o mecanismo que dá "memória" às funções.

📋 Closures — Capturando Estado

# ═══ O que é uma Closure? ═══
# Closure = função interna + variáveis capturadas do escopo externo

def criar_acumulador():
    """Cria um acumulador que mantém estado entre chamadas."""
    total = 0  # Variável capturada pela closure
    
    def adicionar(valor):
        nonlocal total
        total += valor
        return total
    
    return adicionar

# Cada acumulador é independente!
acc1 = criar_acumulador()
acc2 = criar_acumulador()

print(acc1(10))  # 10
print(acc1(20))  # 30
print(acc1(5))   # 35

print(acc2(100)) # 100 — acc2 tem seu próprio 'total'
print(acc1(0))   # 35  — acc1 não foi afetado

# Verificando que é uma closure
print(acc1.__closure__)  # (<cell ...>,) — contém referência ao 'total'
print(acc1.__closure__[0].cell_contents)  # 35

# ═══ Closure prática: rate limiter ═══
import time

def criar_rate_limiter(max_chamadas, periodo_segundos):
    """Cria um rate limiter com sliding window."""
    chamadas = []  # Lista de timestamps — capturada pela closure
    
    def pode_executar():
        nonlocal chamadas
        agora = time.time()
        # Remove chamadas fora da janela
        chamadas = [t for t in chamadas if agora - t < periodo_segundos]
        
        if len(chamadas) < max_chamadas:
            chamadas.append(agora)
            return True
        return False
    
    return pode_executar

# Máximo 3 chamadas por segundo
limiter = criar_rate_limiter(3, 1.0)
for i in range(5):
    if limiter():
        print(f"Request {i+1}: ✅ Permitida")
    else:
        print(f"Request {i+1}: ❌ Rate limited!")

# Classe: estado complexo, muitos métodos, herança necessária

Funções lambda são funções anônimas de uma única expressão. São concisas e ideais para operações simples passadas como argumentos — como chaves de ordenação, callbacks rápidos e transformações em map/filter.

Decoradores (Decorators)

Decoradores são uma das features mais elegantes do Python. Permitem modificar ou estender o comportamento de funções sem alterar seu código-fonte — aplicando o princípio Open/Closed (aberto para extensão, fechado para modificação).

6.1 — O que São Decoradores?

Um decorador é simplesmente uma função que recebe uma função e retorna uma nova função (geralmente com comportamento adicional). É a aplicação prática de closures e funções de alta ordem.

📋 Construindo um Decorador do Zero

# ═══ Passo 1: Entendendo o conceito ═══
# Um decorador é uma função que:
# 1. Recebe uma função como argumento
# 2. Cria uma função wrapper que adiciona comportamento
# 3. Retorna a função wrapper

def meu_decorador(func):
    """Decorador que loga antes e depois da execução."""
    def wrapper(*args, **kwargs):
        print(f"▶ Chamando {func.__name__}...")
        resultado = func(*args, **kwargs)  # Chama a função original
        print(f"◀ {func.__name__} retornou: {resultado}")
        return resultado
    return wrapper

# ═══ Passo 2: Aplicando manualmente (sem @) ═══
def somar(a, b):
    return a + b

# Decorando manualmente:
somar_com_log = meu_decorador(somar)
resultado = somar_com_log(3, 5)
# ▶ Chamando somar...
# ◀ somar retornou: 8

# ═══ Passo 3: Usando a sintaxe @ (syntactic sugar) ═══
@meu_decorador  # Equivale a: subtrair = meu_decorador(subtrair)
def subtrair(a, b):
    return a - b

resultado = subtrair(10, 4)
# ▶ Chamando subtrair...
# ◀ subtrair retornou: 6

# A sintaxe @ é apenas açúcar sintático para:
# subtrair = meu_decorador(subtrair)

# ═══ Visualizando o que acontece ═══
@meu_decorador
def calcular_custo(horas, preco_hora):
    """Calcula custo de instância EC2."""
    return round(horas * preco_hora, 2)

# Quando chamamos calcular_custo(), na verdade chamamos wrapper()
# que chama a calcular_custo original internamente
custo = calcular_custo(720, 0.096)
# ▶ Chamando calcular_custo...
# ◀ calcular_custo retornou: 69.12

6.2 — functools.wraps — Preservando Metadados

Sem functools.wraps, o wrapper substitui o nome e docstring da função original, dificultando debugging. Sempre use @wraps em decoradores profissionais.

📋 @functools.wraps — Decorador Profissional

from functools import wraps

# ═══ Problema SEM @wraps ═══
def decorador_ruim(func):
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

@decorador_ruim
def minha_funcao():
    """Documentação importante."""
    pass

print(minha_funcao.__name__)  # "wrapper" — PERDEU o nome original!
print(minha_funcao.__doc__)   # None — PERDEU a docstring!

# ═══ Solução COM @wraps ═══
def decorador_bom(func):
    @wraps(func)  # Copia __name__, __doc__, __module__, etc.
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

@decorador_bom
def minha_funcao():
    """Documentação importante."""
    pass

print(minha_funcao.__name__)  # "minha_funcao" — ✅ Preservado!
print(minha_funcao.__doc__)   # "Documentação importante." — ✅ Preservado!

# ═══ Template padrão para QUALQUER decorador ═══
def template_decorador(func):
    """Template padrão — copie e adapte."""
    @wraps(func)
    def wrapper(*args, **kwargs):
        # === Código ANTES da função ===
        # (setup, validação, logging, timing...)
        
        resultado = func(*args, **kwargs)  # Chama a original
        
        # === Código DEPOIS da função ===
        # (cleanup, logging, transformação do resultado...)
        
        return resultado
    return wrapper

Para criar decoradores que aceitam argumentos, você precisa de um nível extra de aninhamento — uma "fábrica de decoradores".

📋 Decorador com Parâmetros

from functools import wraps
import time

# ═══ Decorador COM argumentos — 3 níveis de aninhamento ═══
def repetir(vezes=3, delay=0):
    """Fábrica de decorador: repete a função N vezes."""
    def decorador(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            resultados = []
            for i in range(vezes):
                resultado = func(*args, **kwargs)
                resultados.append(resultado)
                if delay and i < vezes - 1:
                    time.sleep(delay)
            return resultados
        return wrapper
    return decorador

@repetir(vezes=3, delay=0.1)
def ping(host):
    """Faz ping em um host."""
    return f"Pong de {host}!"

# Executa 3 vezes com 0.1s entre cada
respostas = ping("api.cloudtrilhas.com")
print(respostas)
# ['Pong de api.cloudtrilhas.com!', 'Pong de api.cloudtrilhas.com!', ...]

# ═══ Decorador retry com backoff exponencial ═══
def retry(max_tentativas=3, excecoes=(Exception,), backoff=2):
    """Retenta a função em caso de falha com backoff exponencial."""
    def decorador(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            for tentativa in range(1, max_tentativas + 1):
                try:
                    return func(*args, **kwargs)
                except excecoes as e:
                    if tentativa == max_tentativas:
                        print(f"❌ Falhou após {max_tentativas} tentativas: {e}")
                        raise
                    espera = backoff ** tentativa
                    print(f"⚠️ Tentativa {tentativa} falhou: {e}. "
                          f"Retentando em {espera}s...")
                    time.sleep(espera)
        return wrapper
    return decorador

@retry(max_tentativas=3, excecoes=(ConnectionError, TimeoutError))
def chamar_api(endpoint):
    """Chama API externa com retry automático."""
    import random
    if random.random() < 0.7:  # 70% chance de falha (simulação)
        raise ConnectionError("Servidor indisponível")
    return {"status": "ok", "endpoint": endpoint}

📋 Decorador de Cache (Memoização)

from functools import wraps

def cache(func):
    """Decorador de cache simples (memoização)."""
    _cache = {}  # Closure captura este dict
    
    @wraps(func)
    def wrapper(*args):
        if args in _cache:
            print(f"  📦 Cache hit para {func.__name__}{args}")
            return _cache[args]
        
        resultado = func(*args)
        _cache[args] = resultado
        print(f"  💾 Cache miss — armazenando {func.__name__}{args}")
        return resultado
    
    # Expõe método para limpar cache
    wrapper.cache_clear = lambda: _cache.clear()
    wrapper.cache_info = lambda: f"Entradas: {len(_cache)}"
    
    return wrapper

@cache
def fibonacci(n):
    """Calcula Fibonacci recursivamente (com cache é O(n))."""
    if n < 2:
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)

print(fibonacci(10))  # 55 (muito rápido com cache!)
print(fibonacci.cache_info())  # "Entradas: 11"

# NOTA: Python já tem isso built-in! Use @functools.lru_cache
from functools import lru_cache

@lru_cache(maxsize=128)
def fibonacci_builtin(n):
    if n < 2:
        return n
    return fibonacci_builtin(n - 1) + fibonacci_builtin(n - 2)

print(fibonacci_builtin(100))  # Instantâneo!
print(fibonacci_builtin.cache_info())  # CacheInfo(hits=98, misses=101, ...)

# ═══ @property — Transforma método em atributo ═══
class Instancia:

    @property
    def tipo(self):
        return self._tipo
    
    @tipo.setter
    def tipo(self, novo_tipo):

            raise ValueError(f"Tipo inválido: {novo_tipo}")
        self._tipo = novo_tipo

7.3 — O Guard __name__ == "__main__"

Quando um arquivo é executado diretamente, __name__ é "__main__". Quando é importado, __name__ é o nome do módulo. Esse padrão permite que um arquivo funcione como módulo E como script.

📋 O Padrão if __name__ == "__main__"

def validar_regiao(regiao):
    REGIOES = ["us-east-1", "us-west-2", "sa-east-1", "eu-west-1"]
    return regiao in REGIOES

def listar_regioes():
    return ["us-east-1", "us-west-2", "sa-east-1", "eu-west-1"]

# ═══ Este bloco SÓ executa quando o arquivo é rodado diretamente ═══
if __name__ == "__main__":
    # Testes rápidos ou CLI
    print("Executando aws_utils.py como script!")
    print(f"Regiões disponíveis: {listar_regioes()}")
    
    # Teste das funções
    assert validar_regiao("us-east-1") == True
    assert validar_regiao("invalida") == False
    print("✅ Todos os testes passaram!")

# ═══ O que acontece em cada cenário: ═══
# 1. python aws_utils.py → __name__ == "__main__" → executa o bloco if
# 2. import aws_utils    → __name__ == "aws_utils" → NÃO executa o bloco if

# ═══ Por que isso é importante? ═══
# Sem o guard, o código de teste/execução rodaria TODA VEZ que alguém
# importasse o módulo — provavelmente não é o que você quer!

9.4 — Funções Puras e Efeitos Colaterais

Uma função pura sempre retorna o mesmo resultado para os mesmos argumentos e não modifica nada fora dela. Funções puras são fáceis de testar, cachear e paralelizar.

📋 Puras vs Impuras

# ═══ Função PURA ═══
# ✅ Sem efeitos colaterais, determinística, testável
def calcular_desconto(preco: float, percentual: float) -> float:
    """Pura: mesmo input → sempre mesmo output."""
    return round(preco * (1 - percentual / 100), 2)

# Sempre retorna o mesmo resultado:
assert calcular_desconto(100, 20) == 80.0  # Sempre!
assert calcular_desconto(100, 20) == 80.0  # Sempre!

# ═══ Função IMPURA ═══
# ❌ Depende de estado externo, efeitos colaterais
total_vendas = 0  # Estado global

def registrar_venda(valor):
    """Impura: modifica estado global, depende de estado externo."""
    global total_vendas
    total_vendas += valor  # Efeito colateral!
    print(f"Venda: {valor}")  # Outro efeito colateral (I/O)!
    return total_vendas

# Resultado muda a cada chamada:
registrar_venda(100)  # 100
registrar_venda(100)  # 200 — mesmo input, output diferente!

# ═══ Refatorando impuro → puro ═══
# ✅ Versão pura: recebe estado, retorna novo estado
def registrar_venda_puro(total_atual: float, valor: float) -> float:
    """Pura: recebe estado como input, retorna novo estado."""
    return total_atual + valor

# Uso:
total = 0
total = registrar_venda_puro(total, 100)  # 100
total = registrar_venda_puro(total, 100)  # 200

# ═══ Quando efeitos colaterais são NECESSÁRIOS ═══
# - Escrever em banco de dados
# - Enviar requests HTTP
# - Imprimir no console / escrever logs
# - Ler/escrever arquivos
#
# Estratégia: isole efeitos colaterais nas "bordas" do sistema
# e mantenha a lógica central pura!

# Exemplo: separar lógica pura da I/O impura
def calcular_instancias_ociosas(instancias, threshold_cpu=5):

9.5 — Tratamento de Erros em Funções

Boas funções comunicam erros de forma clara. Há duas filosofias: raise (exceções) ou return (valores sentinela/Result pattern).

📋 Raise vs Return para Erros

# ═══ Filosofia 1: RAISE (EAFP — Easier to Ask Forgiveness) ═══
# Preferência do Python: tente fazer, trate a exceção se falhar

def buscar_recurso(recurso_id: str) -> dict:
    """Levanta exceção se o recurso não existir."""
    recursos = {"vpc-001": {"tipo": "vpc", "cidr": "10.0.0.0/16"}}
    
    if not recurso_id:
        raise ValueError("recurso_id não pode ser vazio")
    
    if recurso_id not in recursos:
        raise KeyError(f"Recurso '{recurso_id}' não encontrado")
    
    return recursos[recurso_id]

# Uso com try/except
try:
    recurso = buscar_recurso("vpc-999")
except KeyError as e:
    print(f"Não encontrado: {e}")
except ValueError as e:
    print(f"Input inválido: {e}")

# ═══ Filosofia 2: RETURN None/Sentinel (LBYL — Look Before You Leap) ═══
# Retorna None ou valor especial para indicar falha

def buscar_recurso_safe(recurso_id: str) -> Optional[dict]:
    """Retorna None se não encontrar (sem exceção)."""
    recursos = {"vpc-001": {"tipo": "vpc"}}
    return recursos.get(recurso_id)  # None se não existir

# Uso com verificação
recurso = buscar_recurso_safe("vpc-999")
if recurso is None:
    print("Recurso não encontrado")
else:
    print(f"Encontrado: {recurso}")

# ═══ Quando usar cada abordagem? ═══
# RAISE quando:
# - A falha é EXCEPCIONAL (não deveria acontecer no fluxo normal)
# - O chamador PRECISA saber que algo deu errado
# - Validação de input (ValueError)
# - Recurso obrigatório não encontrado

# RETURN None quando:
# - Não encontrar é um resultado VÁLIDO/ESPERADO
# - Funções de busca onde "não existe" é normal
# - APIs que retornam listas (lista vazia em vez de exceção)

# ═══ Pattern: Result Tuple ═══
def validar_config(config: dict) -> tuple[bool, str]:
    """Retorna (sucesso, mensagem)."""
    erros = []
    if "host" not in config:
        erros.append("Campo 'host' obrigatório")
    if "port" not in config:
        erros.append("Campo 'port' obrigatório")
    elif not (1 <= config["port"] <= 65535):
        erros.append(f"Porta inválida: {config['port']}")
    
    if erros:
        return False, "; ".join(erros)
    return True, "Configuração válida"

from datetime import datetime

def log_evento(mensagem: str, *tags: str, nivel: str = "INFO", **metadata) -> dict:
    """Registra um evento com tags e metadados flexíveis.

    Args:
        mensagem: Descrição do evento.
        *tags: Tags de categorização (ex: "deploy", "prod", "api").
        nivel: Nível do log (INFO, WARNING, ERROR). Keyword-only.
        **metadata: Metadados adicionais (chave=valor).

    Returns:
        Dict com o evento estruturado.

    Examples:
        >>> log_evento("Deploy iniciado", "deploy", "prod", versao="2.1.0")
        {'timestamp': '...', 'nivel': 'INFO', 'mensagem': 'Deploy iniciado',
         'tags': ['deploy', 'prod'], 'metadata': {'versao': '2.1.0'}}
    """
    evento = {
        "timestamp": datetime.now().isoformat(),
        "nivel": nivel.upper(),
        "mensagem": mensagem,
        "tags": list(tags),
        "metadata": metadata
    }

    tags_str = ", ".join(tags) if tags else "nenhuma"
    meta_str = ", ".join(f"{k}={v}" for k, v in metadata.items())
    
    print(f"[{evento['timestamp']}] [{evento['nivel']}] {mensagem}")
    print(f"  Tags: {tags_str}")
    if meta_str:
        print(f"  Metadata: {meta_str}")
    print()
    
    return evento

Exercício 3 — Closure: Criador de Filtros

Crie uma função criar_filtro_recurso que retorne uma closure para filtrar recursos AWS. A closure deve aceitar uma lista de recursos e retornar apenas os que atendem aos critérios configurados na criação.

💡 Resposta 
from typing import Callable, Any

def criar_filtro_recurso(tipo: str = None,
                         estado: str = None,
                         regiao: str = None,
                         custo_max: float = None,
                         tags: dict = None) -> Callable:
    """Factory de filtros para recursos AWS.

    Retorna uma closure que filtra recursos pelos critérios fornecidos.
    Apenas critérios não-None são aplicados (AND lógico).

    Args:
        tipo: Filtrar por tipo de recurso (ex: 'ec2', 's3').
        estado: Filtrar por estado (ex: 'running', 'stopped').
        regiao: Filtrar por região AWS.
        custo_max: Custo máximo por hora.
        tags: Dict de tags que o recurso deve ter.

    Returns:
        Função que recebe lista de recursos e retorna lista filtrada.
    """
    def filtrar(recursos: list[dict]) -> list[dict]:
        resultado = recursos
        
        if tipo is not None:
            resultado = [r for r in resultado if r.get("tipo") == tipo]
        
        if estado is not None:
            resultado = [r for r in resultado if r.get("estado") == estado]
        
        if regiao is not None:
            resultado = [r for r in resultado if r.get("regiao") == regiao]
        
        if custo_max is not None:
            resultado = [r for r in resultado 
                        if r.get("custo_hora", 0) <= custo_max]
        
        if tags is not None:
            resultado = [r for r in resultado
                        if all(r.get("tags", {}).get(k) == v 
                              for k, v in tags.items())]
        
        return resultado
    
    # Adicionar metadata à closure para inspeção
    filtrar.criterios = {
        "tipo": tipo, "estado": estado, "regiao": regiao,
        "custo_max": custo_max, "tags": tags
    }
    
    return filtrar
