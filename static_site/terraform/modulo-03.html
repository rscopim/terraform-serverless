🏗️ Terraform — Módulo 03

VPC + EC2 + RDS

Adicione um banco de dados RDS MySQL à infraestrutura. Aprenda DB Subnet Groups, Security Groups com referência cruzada, variáveis sensíveis e Locals.

Locals — Tags Reutilizáveis

O bloco locals permite definir valores reutilizáveis dentro do módulo. Ideal para tags comuns que serão aplicadas em todos os recursos.

locals { }locals.tf

Defina um mapa de tags comuns para manter consistência em toda a infraestrutura.

locals {
  common_tags = {
    Project     = "cloudtrilhas"
    Environment = var.environment
    ManagedBy   = "terraform"
  }
}
Uso das TagsReferência

Aplique as tags em qualquer recurso usando merge() para combinar com tags específicas.

# Uso direto
tags = local.common_tags

# Merge com tags adicionais
tags = merge(local.common_tags, {
  Name = "meu-recurso"
  Role = "database"
})

DB Subnet Group

O RDS exige um DB Subnet Group que define em quais subnets o banco pode ser provisionado. Para segurança, usamos as subnets privadas.

aws_db_subnet_grouprds.tf

Agrupa as subnets privadas para que o RDS seja lançado em uma rede isolada sem acesso público.

resource "aws_db_subnet_group" "main" {
  name       = "${var.project_name}-db-subnet-group"
  subnet_ids = [
    aws_subnet.private_a.id,
    aws_subnet.private_b.id
  ]

  tags = merge(local.common_tags, {
    Name = "${var.project_name}-db-subnet-group"
  })
}

RDS Security Group — Referência Cruzada

O Security Group do RDS permite tráfego apenas da instância EC2, usando source_security_group_id em vez de CIDR blocks. Isso garante que somente a EC2 autorizada acesse o banco.

aws_security_groupsg-rds.tf

Permite porta 3306 (MySQL) apenas do Security Group da EC2 — referência cruzada entre SGs.

resource "aws_security_group" "rds" {
  name        = "${var.project_name}-rds-sg"
  description = "Security group for RDS MySQL"
  vpc_id      = aws_vpc.main.id

  ingress {
    description              = "MySQL from EC2"
    from_port                = 3306
    to_port                  = 3306
    protocol                 = "tcp"
    source_security_group_id = aws_security_group.ec2.id
  }

  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }

  tags = merge(local.common_tags, {
    Name = "${var.project_name}-rds-sg"
  })
}
Referência CruzadaConceito

Em vez de abrir para um CIDR, referenciamos o SG da EC2 diretamente. Se o IP da EC2 mudar, a regra continua válida.

# ❌ Evite — IP pode mudar
cidr_blocks = ["10.0.1.50/32"]

# ✅ Correto — referência ao SG
source_security_group_id = aws_security_group.ec2.id

RDS Instance — MySQL 8.0

O recurso aws_db_instance provisiona o banco de dados gerenciado. Configuramos criptografia, backup e isolamento de rede.

aws_db_instancerds.tf

Instância RDS MySQL com todas as boas práticas de segurança e isolamento.

resource "aws_db_instance" "main" {
  identifier     = "${var.project_name}-mysql"
  engine         = "mysql"
  engine_version = "8.0"
  instance_class = var.db_instance_class

  allocated_storage = var.db_allocated_storage
  storage_type      = "gp3"

  db_name  = var.db_name
  username = var.db_username
  password = var.db_password

  db_subnet_group_name   = aws_db_subnet_group.main.name
  vpc_security_group_ids = [aws_security_group.rds.id]

  multi_az            = false
  publicly_accessible = false
  skip_final_snapshot = true

  backup_retention_period = var.db_backup_retention
  storage_encrypted       = true

  tags = merge(local.common_tags, {
    Name = "${var.project_name}-mysql"
    Role = "database"
  })
}
Parâmetros ImportantesReferência
ParâmetroDescrição
storage_type = "gp3"SSD de nova geração, melhor custo-benefício
multi_az = falseLab: single AZ. Produção: use true
publicly_accessible = falseSem IP público — acesso apenas via VPC
skip_final_snapshot = trueLab: sem snapshot ao destruir. Produção: false

Variáveis Sensíveis

Senhas e segredos nunca devem ser commitados no código. O Terraform oferece o atributo sensitive = true para proteger valores no output.

variable "db_password"variables.tf

Declare a variável como sensível para que o Terraform oculte seu valor nos logs e outputs.

variable "db_password" {
  description = "Password for the RDS MySQL instance"
  type        = string
  sensitive   = true

  validation {
    condition     = length(var.db_password) >= 8
    error_message = "A senha deve ter no mínimo 8 caracteres."
  }
}
Formas de Passar o ValorSegurança

Existem várias formas seguras de fornecer variáveis sensíveis sem expor no código.

# Opção 1: Variável de ambiente (recomendado em CI/CD)
export TF_VAR_db_password="MinhaSenhaSegura123!"
terraform apply

# Opção 2: Arquivo .tfvars (NÃO commitar!)
# secrets.tfvars
db_password = "MinhaSenhaSegura123!"

terraform apply -var-file="secrets.tfvars"

# Opção 3: Prompt interativo
terraform apply
# var.db_password
#   Enter a value: ********

# Opção 4: AWS Secrets Manager (produção)
data "aws_secretsmanager_secret_version" "db" {
  secret_id = "prod/db/password"
}
# Uso: data.aws_secretsmanager_secret_version.db.secret_string

⚠️ Importante: Adicione *.tfvars e .terraform/ ao seu .gitignore. Nunca commite arquivos com senhas no repositório.

Outputs — Endpoint e Porta

Outputs exportam valores úteis após o terraform apply. O endpoint do RDS é essencial para configurar a aplicação na EC2.

outputoutputs.tf

Exporte o endpoint e a porta do banco para uso na configuração da aplicação.

output "db_endpoint" {
  description = "RDS MySQL endpoint address"
  value       = aws_db_instance.main.endpoint
}

output "db_port" {
  description = "RDS MySQL port"
  value       = aws_db_instance.main.port
}

output "db_name" {
  description = "Database name"
  value       = aws_db_instance.main.db_name
}

# Exemplo de uso na EC2 (user_data):
# mysql -h ${output.db_endpoint} -P ${output.db_port} \
#   -u ${var.db_username} -p${var.db_password} ${var.db_name}
