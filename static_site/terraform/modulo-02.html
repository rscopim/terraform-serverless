VPC + EC2

Adicione instâncias EC2 à sua VPC com Security Groups, Key Pairs e User Data. Aprenda Data Sources e funções Terraform.

Data Source AMI

Data Sources permitem buscar informações da AWS sem criar recursos. Aqui buscamos a AMI mais recente do Amazon Linux 2023 dinamicamente.

data "aws_ami"Data Source
data "aws_ami" "amazon_linux" {
  most_recent = true
  owners      = ["amazon"]

  filter {
    name   = "name"
    values = ["al2023-ami-*-x86_64"]
  }

  filter {
    name   = "virtualization-type"
    values = ["hvm"]
  }

  filter {
    name   = "state"
    values = ["available"]
  }
}
ReferênciaUso

Use data.aws_ami.amazon_linux.id para referenciar o ID da AMI encontrada. Isso garante que sempre usamos a versão mais recente sem hardcoding.

# Acessar atributos do data source
data.aws_ami.amazon_linux.id
data.aws_ami.amazon_linux.name
data.aws_ami.amazon_linux.description

Security Group

Security Groups atuam como firewall virtual para suas instâncias EC2. Defina regras de ingress (entrada) e egress (saída).

aws_security_groupFirewall
variable "my_ip" {
  description = "Seu IP público para acesso SSH (formato: x.x.x.x/32)"
  type        = string
}

resource "aws_security_group" "web" {
  name        = "${var.project_name}-web-sg"
  description = "Security Group para instancia web"
  vpc_id      = aws_vpc.main.id

  # HTTP
  ingress {
    description = "HTTP from anywhere"
    from_port   = 80
    to_port     = 80
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  # HTTPS
  ingress {
    description = "HTTPS from anywhere"
    from_port   = 443
    to_port     = 443
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  # SSH - restrito ao seu IP
  ingress {
    description = "SSH from my IP"
    from_port   = 22
    to_port     = 22
    protocol    = "tcp"
    cidr_blocks = [var.my_ip]
  }

  # Egress - permitir todo tráfego de saída
  egress {
    description = "Allow all outbound"
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }

  tags = {
    Name = "${var.project_name}-web-sg"
  }
}

Key Pair

Key Pairs permitem acesso SSH às instâncias EC2. Use a função file() para ler a chave pública do disco.

aws_key_pairSSH
# Gerar key pair localmente (se ainda não tiver):
# ssh-keygen -t ed25519 -f ~/.ssh/terraform-key -C "terraform"

resource "aws_key_pair" "main" {
  key_name   = "${var.project_name}-key"
  public_key = file("~/.ssh/terraform-key.pub")

  tags = {
    Name = "${var.project_name}-key"
  }
}
Função file()Built-in

A função file(path) lê o conteúdo de um arquivo no disco local durante o plan/apply. Ideal para chaves públicas, scripts e templates.

# Exemplos de uso da função file()
file("~/.ssh/id_rsa.pub")
file("${path.module}/scripts/init.sh")
file("${path.root}/configs/policy.json")

EC2 Instance

O recurso aws_instance cria uma instância EC2 na subnet pública com todas as configurações de rede e inicialização.

aws_instanceCompute
resource "aws_instance" "web" {
  ami                    = data.aws_ami.amazon_linux.id
  instance_type          = "t3.micro"
  subnet_id              = aws_subnet.public[0].id
  key_name               = aws_key_pair.main.key_name
  vpc_security_group_ids = [aws_security_group.web.id]

  user_data = file("${path.module}/scripts/user-data.sh")

  tags = {
    Name = "${var.project_name}-web-server"
  }
}
Alternativa: HeredocInline

Para scripts curtos, você pode usar heredoc diretamente no user_data:

resource "aws_instance" "web" {
  ami                    = data.aws_ami.amazon_linux.id
  instance_type          = "t3.micro"
  subnet_id              = aws_subnet.public[0].id
  key_name               = aws_key_pair.main.key_name
  vpc_security_group_ids = [aws_security_group.web.id]

  user_data = <<-EOF
    #!/bin/bash
    yum update -y
    yum install -y httpd
    systemctl start httpd
    systemctl enable httpd
    echo "<h1>Hello from Terraform!</h1>" > /var/www/html/index.html
  EOF

  tags = {
    Name = "${var.project_name}-web-server"
  }
}

User Data Script

O User Data é executado automaticamente na primeira inicialização da instância (como root). Ideal para instalar pacotes e configurar serviços.

scripts/user-data.shBootstrap
#!/bin/bash
set -euxo pipefail

# Atualizar pacotes do sistema
yum update -y

# Instalar Apache HTTP Server
yum install -y httpd

# Iniciar e habilitar o serviço
systemctl start httpd
systemctl enable httpd

# Criar página inicial
cat <<'HTML' > /var/www/html/index.html
<!DOCTYPE html>
<html lang="pt-BR">
<head>
  <meta charset="UTF-8">
  <title>CloudTrilhas - EC2 com Terraform</title>
  <style>
    body { font-family: sans-serif; text-align: center; padding: 50px; }
    h1 { color: #2563eb; }
  </style>
</head>
<body>
  <h1>🚀 EC2 provisionada com Terraform!</h1>
  <p>Hostname: $(hostname)</p>
  <p>IP Privado: $(hostname -I | awk '{print $1}')</p>
  <p>Data: $(date)</p>
</body>
</html>
HTML

echo "User data script completed successfully"

Outputs

Outputs da instância EC2 para acesso e referência rápida.

outputs.tfSaídas
output "instance_id" {
  description = "ID da instância EC2"
  value       = aws_instance.web.id
}

output "public_ip" {
  description = "IP público da instância"
  value       = aws_instance.web.public_ip
}

output "public_dns" {
  description = "DNS público da instância"
  value       = aws_instance.web.public_dns
}
Acessar a instânciaUso
# Após terraform apply, acesse via SSH:
ssh -i ~/.ssh/terraform-key ec2-user@$(terraform output -raw public_ip)

# Ou acesse o web server no navegador:
# http://$(terraform output -raw public_dns)

Novos Comandos Aprendidos

Comandos avançados para controle granular do Terraform.

terraform plan -outSalvar Plano

Salva o plano de execução em um arquivo binário. Garante que o apply executará exatamente o que foi revisado.

# Salvar plano em arquivo
terraform plan -out=plan.tfplan

# Visualizar plano salvo
terraform show plan.tfplan
terraform apply plan.tfplanAplicar Plano

Aplica um plano salvo anteriormente. Não pede confirmação pois o plano já foi revisado.

# Aplicar plano salvo (sem prompt de confirmação)
terraform apply plan.tfplan
terraform apply -targetRecurso Específico

Aplica mudanças apenas em um recurso específico. Útil para debugging e deploys parciais.

# Aplicar apenas a instância EC2
terraform apply -target=aws_instance.web

# Aplicar apenas o security group
terraform apply -target=aws_security_group.web

# Múltiplos targets
terraform apply \
  -target=aws_security_group.web \
  -target=aws_instance.web

⚠️ Atenção: O uso de -target deve ser temporário. Em produção, sempre aplique o plano completo para manter o state consistente com a configuração.
