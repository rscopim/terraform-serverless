Seção 1

O que é um Endereço IP?

Entenda o identificador numérico que permite localizar qualquer dispositivo conectado a uma rede, assim como um endereço postal localiza uma casa em uma cidade.

1.1 — Definição Formal

Um endereço IP (Internet Protocol address) é um identificador numérico único atribuído a cada dispositivo (host) conectado a uma rede que utiliza o protocolo IP para comunicação. Ele serve a dois propósitos fundamentais:

  • Identificação do host: permite distinguir um dispositivo específico entre bilhões de outros na rede.
  • Localização na rede: indica em qual rede lógica o dispositivo se encontra, permitindo o roteamento correto dos pacotes.

Sem endereços IP, seria impossível encaminhar dados de um computador em São Paulo até um servidor no Japão. O endereço IP é a "identidade" do dispositivo no mundo das redes — é através dele que roteadores sabem para onde enviar cada pacote.

1.2 — Formato IPv4 (Notação Decimal Pontuada)

O IPv4 (Internet Protocol version 4) utiliza endereços de 32 bits, representados em notação decimal pontuada (dotted decimal notation). O endereço é dividido em 4 grupos de 8 bits (octetos), separados por pontos:

📐 Estrutura de um Endereço IPv4


  Endereço IPv4:    192  .  168  .    1  .  100
                     │        │       │       │
  Octeto:           1º       2º      3º      4º
  Bits:          8 bits   8 bits   8 bits   8 bits  = 32 bits total
  Binário:     11000000.10101000.00000001.01100100

  ┌─────────────────────────────────────────────────────────────────┐
  │  Faixa válida de cada octeto: 0 a 255 (2⁸ = 256 valores)       │
  │  Total de endereços possíveis: 2³² = 4.294.967.296 (~4,3 bi)   │
  └─────────────────────────────────────────────────────────────────┘

Cada octeto pode assumir valores de 0 a 255, pois com 8 bits temos 2⁸ = 256 combinações possíveis (de 00000000 a 11111111 em binário).

Decimal Binário Cálculo
0 00000000 Todos os bits desligados
1 00000001 2⁰ = 1
10 00001010 2³ + 2¹ = 8 + 2 = 10
128 10000000 2⁷ = 128
192 11000000 2⁷ + 2⁶ = 128 + 64 = 192
255 11111111 2⁷+2⁶+2⁵+2⁴+2³+2²+2¹+2⁰ = 255

1.3 — Analogia: O Endereço Postal

A melhor analogia para entender endereços IP é o sistema de endereços postais:

Endereço Postal Endereço IP Função
CEP (ex: 01310-100) Porção de rede (ex: 192.168.1.x) Identifica a região/rede onde o destino está
Número da casa (ex: 1578) Porção de host (ex: 192.168.1.100) Identifica o dispositivo específico na rede
Cidade + Estado Rede + Sub-rede Hierarquia que permite roteamento eficiente
País Bloco IP regional (LACNIC, ARIN, etc.) Organização de alto nível geográfica

💡 Por que a analogia funciona?

Assim como o carteiro não precisa conhecer todas as casas do Brasil — ele olha o CEP para descobrir a cidade, depois o bairro, depois a rua e enfim a casa — um roteador não precisa conhecer todos os 4,3 bilhões de endereços IP. Ele olha a porção de rede para encaminhar o pacote na direção certa, e o roteador seguinte cuida do próximo trecho. Essa hierarquia é o que torna a Internet escalável.

1.4 — Composição do Endereço: Porção de Rede e Porção de Host

Todo endereço IPv4 é logicamente dividido em duas partes:

🔀 Divisão Rede / Host


  Endereço IP:     192.168.1.100
  Máscara:         255.255.255.0  (ou /24)
  
  ┌──────────────────────────────┬──────────────┐
  │      PORÇÃO DE REDE          │ PORÇÃO HOST  │
  │      (Network Portion)       │(Host Portion)│
  ├──────────────────────────────┼──────────────┤
  │        192.168.1             │     .100     │
  │  (identifica A REDE)         │ (identifica  │
  │                              │  O DEVICE)   │
  └──────────────────────────────┴──────────────┘
  
  Analogia postal:
  • Porção de rede = CEP (identifica o bairro/cidade)
  • Porção de host = Número da casa (identifica a casa no bairro)

Todos os dispositivos na mesma rede compartilham a mesma porção de rede e diferem apenas na porção de host. Dispositivos em redes diferentes têm porções de rede distintas e precisam de um roteador (gateway) para se comunicar.

1.5 — Endereços IP Públicos vs Privados

Os endereços IP se dividem em duas grandes categorias de uso:

🌍 IP Público (Roteável na Internet)

Definição: Endereço globalmente único, visível e acessível pela Internet.

Atribuição: Fornecido pelo ISP (provedor de Internet) ou registradores regionais (LACNIC, ARIN, RIPE, etc.)

Custo: Recurso escasso e pago (IPv4 está esgotado desde 2019)

Exemplo: 200.189.55.73, 8.8.8.8 (Google DNS)

Uso: Servidores web, APIs públicas, qualquer recurso acessível da Internet

🏠 IP Privado (Não roteável na Internet)

Definição: Endereço usado apenas dentro de redes locais (LANs). Não é roteado na Internet.

Atribuição: Livre — qualquer organização pode usar internamente

Custo: Gratuito e ilimitado dentro da rede local

Exemplo: 192.168.1.100, 10.0.0.5, 172.16.30.1

Uso: Computadores de escritório, servidores internos, VPCs na nuvem

⚠️ Conceito-chave

Endereços privados não podem ser usados na Internet. Se um computador com IP privado (ex: 192.168.1.100) precisa acessar a Internet, ele passa por um dispositivo com IP público que faz NAT (Network Address Translation) — traduz o endereço privado para o público na saída e faz o caminho inverso na volta. Veremos NAT em detalhes na Seção 3.

1.6 — Atribuição de Endereços IP

Existem duas formas de atribuir um endereço IP a um dispositivo:

⚡ Dinâmico (DHCP)

O dispositivo recebe automaticamente um IP do servidor DHCP (Dynamic Host Configuration Protocol) ao se conectar à rede. É o método padrão para estações de trabalho, smartphones e dispositivos de usuário final.

Vantagens: Automático, sem configuração manual, reutiliza IPs

Desvantagens: IP pode mudar a cada conexão (lease expira)

📌 Estático (Manual)

O administrador configura manualmente o IP no dispositivo. Usado em equipamentos que precisam de um endereço fixo e previsível: servidores, impressoras de rede, roteadores, switches gerenciáveis, câmeras IP.

Vantagens: IP sempre o mesmo, previsível para DNS e firewall

Desvantagens: Trabalho manual, risco de conflito se mal gerenciado

💡 Na Prática Cloud (AWS)

Na AWS, instâncias EC2 recebem um IP privado automaticamente via DHCP interno da VPC. Para acesso externo, você pode associar um Elastic IP (IP público estático) ou usar um NAT Gateway para permitir saída à Internet sem expor a instância. O conceito é idêntico ao mundo on-premises — muda apenas quem gerencia a infraestrutura.

Seção 2

Classes de Endereço IPv4

O sistema classful original dividiu o espaço de endereçamento IPv4 em cinco classes (A a E). Embora ultrapassado na prática moderna, esse conhecimento é fundamental para entender a evolução do endereçamento e é cobrado em certificações.

2.1 — O Sistema Classful (Classes A, B, C, D, E)

Nos primórdios da Internet (década de 1980), os endereços IPv4 foram organizados em classes baseadas nos primeiros bits do endereço. Cada classe define automaticamente qual parte é rede e qual parte é host:

Classe 1º Octeto Bits Iniciais Máscara Padrão Nº de Redes Hosts/Rede Uso
A 1 – 126 0xxxxxxx 255.0.0.0 (/8) 126 16.777.214 Grandes organizações (IBM, Apple, DoD)
B 128 – 191 10xxxxxx 255.255.0.0 (/16) 16.384 65.534 Empresas médias e universidades
C 192 – 223 110xxxxx 255.255.255.0 (/24) 2.097.152 254 Pequenas empresas e redes locais
D 224 – 239 1110xxxx N/A N/A N/A Multicast (grupos de destino)
E 240 – 255 1111xxxx N/A N/A N/A Reservado (experimental/futuro)

📐 Visualização das Classes


  Espaço total IPv4: 0.0.0.0 a 255.255.255.255
  
  ┌─────────────────────────────────────────────────────────────────────────────┐
  │ Classe A │   Classe B    │  Classe C   │  D  │ E │
  │ 0-126    │  128-191      │  192-223    │224  │240│
  │ /8       │  /16          │  /24        │Multi│Res│
  │ ~50% IPs │  ~25% IPs     │  ~12.5% IPs│cast │erv│
  └─────────────────────────────────────────────────────────────────────────────┘
       │              │               │
       ▼              ▼               ▼
  16M hosts/rede   65K hosts/rede   254 hosts/rede
  
  OBS: 127.x.x.x (entre A e B) é reservado para LOOPBACK

2.2 — Classe A em Detalhes

Endereços de Classe A dedicam 1 octeto para rede e 3 octetos para host, resultando em poucas redes enormes:

🏢 Estrutura Classe A


  Endereço:   10  .  45  .  128  .   7
             ┌────┐┌────────────────────┐
             │REDE││       HOST         │
             │ /8 ││   24 bits          │
             └────┘└────────────────────┘
  
  Máscara:   255  .   0  .   0   .   0
  Binário:   11111111.00000000.00000000.00000000
  
  Faixa:     1.0.0.0   a   126.255.255.255
  Redes:     126 redes (1.x.x.x até 126.x.x.x)
  Hosts:     2²⁴ - 2 = 16.777.214 hosts por rede
  
  Exemplos de proprietários de redes /8:
  • 9.0.0.0/8   → IBM
  • 13.0.0.0/8  → Xerox
  • 15.0.0.0/8  → HP
  • 17.0.0.0/8  → Apple
  • 56.0.0.0/8  → US Postal Service

2.3 — Classe B em Detalhes

Endereços de Classe B dedicam 2 octetos para rede e 2 octetos para host:

🏫 Estrutura Classe B


  Endereço:   172  .  16  .   30  .  200
             ┌──────────┐┌──────────────┐
             │   REDE   ││    HOST      │
             │   /16    ││   16 bits    │
             └──────────┘└──────────────┘
  
  Máscara:   255  . 255  .   0   .   0
  Binário:   11111111.11111111.00000000.00000000
  
  Faixa:     128.0.0.0  a  191.255.255.255
  Redes:     16.384 redes
  Hosts:     2¹⁶ - 2 = 65.534 hosts por rede

2.4 — Classe C em Detalhes

Endereços de Classe C dedicam 3 octetos para rede e 1 octeto para host:

🏠 Estrutura Classe C


  Endereço:   192  . 168  .   1   .  100
             ┌─────────────────┐┌──────┐
             │      REDE       ││ HOST │
             │      /24        ││8 bits│
             └─────────────────┘└──────┘
  
  Máscara:   255  . 255  . 255  .   0
  Binário:   11111111.11111111.11111111.00000000
  
  Faixa:     192.0.0.0  a  223.255.255.255
  Redes:     2.097.152 redes
  Hosts:     2⁸ - 2 = 254 hosts por rede
  
  ⚠️ O "-2" existe porque:
  • Primeiro endereço = endereço de REDE (não atribuível)
  • Último endereço = endereço de BROADCAST (não atribuível)

⚠️ Por que subtraímos 2?

Em qualquer rede IP, dois endereços são reservados e não podem ser atribuídos a hosts:

1. Endereço de Rede (todos os bits de host = 0): identifica a rede como um todo. Ex: 192.168.1.0 — é o "nome" da rede, não um dispositivo.

2. Endereço de Broadcast (todos os bits de host = 1): usado para enviar dados a TODOS os dispositivos da rede simultaneamente. Ex: 192.168.1.255.

Por isso a fórmula de hosts utilizáveis é: 2ⁿ - 2 (onde n = número de bits de host).

2.5 — Endereços Especiais

Alguns endereços IPv4 têm funções especiais e reservadas:

Endereço Nome Função
127.0.0.1 Loopback (localhost) Referência ao próprio dispositivo. Tráfego nunca sai da máquina. Usado para testar a pilha TCP/IP local.
127.0.0.0/8 Rede Loopback inteira Todo o bloco 127.x.x.x é reservado para loopback (16 milhões de endereços para um uso!).
0.0.0.0 Endereço indefinido / "todas as redes" Em servidores: escutar em todas as interfaces. Em roteamento: rota padrão (default route).
255.255.255.255 Broadcast limitado Broadcast para todos os dispositivos na rede local. Nunca ultrapassa o roteador.
169.254.x.x APIPA (Link-Local IPv4) Auto-atribuído quando DHCP falha. Comunicação apenas na LAN, sem gateway.
224.0.0.0/4 Multicast Enviar para um grupo de hosts inscritos. Ex: 224.0.0.1 = todos os hosts, 224.0.0.2 = todos os roteadores.

💡 Testando a pilha TCP/IP com Loopback

O comando ping 127.0.0.1 (ou ping localhost) é o primeiro passo para diagnosticar problemas de rede: se funcionar, a pilha TCP/IP do sistema operacional está OK. Se falhar, o problema é na configuração local, não na rede. Exploraremos isso no Módulo 04.

2.6 — Problema do Sistema Classful

O sistema de classes era extremamente desperdiçador:

❌ Desperdício de Classe A

Uma empresa com 5.000 hosts recebia um /8 (16 milhões de endereços). Resultado: 99,97% dos endereços eram desperdiçados!

❌ Classe C muito pequena

Uma empresa com 300 hosts não cabia em uma Classe C (254 hosts), então recebia uma Classe B (65.534 hosts). Resultado: 99,5% desperdiçado.

❌ Tabelas de roteamento enormes

Milhões de redes /24 individuais enchiam as tabelas de roteamento dos roteadores de backbone, tornando o roteamento lento e consumindo memória.

✅ Solução: CIDR (1993)

O CIDR (Classless Inter-Domain Routing) eliminou as classes fixas e permitiu máscaras de qualquer tamanho (/1 a /32). Veremos em detalhes na Seção 6.

Seção 3

Endereços Privados (RFC 1918)

Conheça os blocos de endereços reservados para uso interno, por que eles existem e como o NAT permite que milhões de redes privadas compartilhem poucos endereços públicos.

3.1 — Os Três Blocos Privados

A RFC 1918 (1996) definiu três faixas de endereços IPv4 que nunca serão roteados na Internet pública. Qualquer organização pode usá-los livremente dentro de suas redes internas, sem necessidade de registro ou autorização:

Bloco Faixa Classe Equiv. Nº de IPs Uso Típico
10.0.0.0/8 10.0.0.0 a 10.255.255.255 1 rede Classe A 16.777.216 Grandes corporações, data centers, VPCs AWS
172.16.0.0/12 172.16.0.0 a 172.31.255.255 16 redes Classe B 1.048.576 Empresas médias, VPCs padrão AWS
192.168.0.0/16 192.168.0.0 a 192.168.255.255 256 redes Classe C 65.536 Redes domésticas, pequenos escritórios

  │  PRIV A  │          │   │        │ /12  │        │   /16    │     │
  │   /8     │          │   │        │      │        │          │     │

3.2 — Por que Endereços Privados Existem?

A motivação principal foi a escassez de endereços IPv4. Com apenas ~4,3 bilhões de endereços e bilhões de dispositivos conectados, era matematicamente impossível dar um IP público a cada um. A solução: reutilizar os mesmos endereços em redes internas separadas.

♻️ Reutilização de Endereços

Milhões de redes domésticas usam 192.168.1.0/24 simultaneamente. Não há conflito porque esses endereços nunca saem para a Internet — cada rede é um "universo" independente.

🔒 Segurança Natural

Dispositivos com IP privado são naturalmente inacessíveis da Internet (não roteáveis). Um atacante externo não pode alcançar diretamente o IP 192.168.1.50 da sua rede local.

💰 Economia de IPs Públicos

Um escritório com 500 computadores precisa de apenas 1 IP público (no roteador/gateway). Todos os 500 dispositivos usam IPs privados internamente e compartilham o IP público via NAT.

🏗️ Flexibilidade de Design

O administrador tem total liberdade para projetar o esquema de endereçamento interno sem depender de alocações externas. Pode criar quantas sub-redes quiser.

3.3 — NAT (Network Address Translation)

O NAT é o mecanismo que permite que dispositivos com endereços privados acessem a Internet. Ele traduz endereços privados para públicos na saída e faz o reverso na volta:

🔄 Como o NAT Funciona


  REDE INTERNA (IPs Privados)          ROTEADOR/NAT          INTERNET (IPs Públicos)
  ═══════════════════════════          ════════════          ══════════════════════════
  
  PC-1: 192.168.1.10 ────┐
                          │         ┌──────────────┐
  PC-2: 192.168.1.11 ────┼────────▶│  NAT Gateway │────────▶  200.189.55.73
                          │         │              │           (IP Público único)
  PC-3: 192.168.1.12 ────┘         │  Tradução:   │
                                    │  .10:5001 ↔  │
                                    │  .11:5002 ↔  │
                                    │  .12:5003 ↔  │
                                    └──────────────┘
  
  O NAT mantém uma TABELA DE TRADUÇÃO:
  ┌────────────────────────┬───────────────────────────┐
  │   IP Interno:Porta     │   IP Externo:Porta        │
  ├────────────────────────┼───────────────────────────┤
  │   192.168.1.10:50001   │   200.189.55.73:5001      │
  │   192.168.1.11:50002   │   200.189.55.73:5002      │
  │   192.168.1.12:50003   │   200.189.55.73:5003      │
  └────────────────────────┴───────────────────────────┘

Tipos de NAT:

1️⃣ NAT Estático (1:1)

Um IP privado mapeado permanentemente para um IP público. Usado quando um servidor interno precisa ser acessível da Internet (ex: servidor web).

192.168.1.10 ↔ 200.189.55.74 (fixo)

2️⃣ NAT Dinâmico

Pool de IPs públicos distribuídos conforme demanda. Quando um host interno precisa sair, recebe temporariamente um IP público do pool.

Pool: 200.189.55.74-78 (5 IPs)

3️⃣ PAT / NAT Overload (N:1)

Múltiplos IPs privados compartilham UM ÚNICO IP público, diferenciados pela porta. É o tipo mais comum — usado em roteadores domésticos e NAT Gateways AWS.

N hosts → 1 IP público (diferenciado por porta)

☁️ NAT na AWS

A AWS oferece o NAT Gateway (gerenciado) e o NAT Instance (EC2 fazendo NAT). Ambos permitem que instâncias em sub-redes privadas acessem a Internet para atualizações sem serem expostas publicamente.

Sub-rede privada → NAT GW → Internet GW

💡 NAT e o Problema das Conexões de Entrada

NAT funciona perfeitamente para conexões de saída (o host interno inicia a comunicação). Para conexões de entrada (alguém de fora quer alcançar um servidor interno), é necessário configurar Port Forwarding (DNAT) — redirecionar uma porta do IP público para um IP:porta interno. Na AWS, isso é feito através de Security Groups e Elastic IPs em sub-redes públicas.

3.4 — Blocos Privados na Prática Cloud

No mundo cloud, endereços privados são a base de toda a infraestrutura de rede:

Serviço Cloud Bloco Padrão Observação
AWS VPC (padrão) 172.31.0.0/16 VPC default criada automaticamente em cada região
AWS VPC (custom) 10.0.0.0/16 (recomendado) Permite até 65.536 IPs; subdivida em /24 por sub-rede
Docker bridge 172.17.0.0/16 Rede bridge padrão dos containers Docker
Kubernetes (pods) 10.244.0.0/16 (Flannel) CIDR de pods; cada nó recebe um /24
Kubernetes (services) 10.96.0.0/12 Cluster IP range para Services internos

⚠️ Cuidado com Overlapping!

Ao conectar redes via VPN ou VPC Peering, os blocos CIDR não podem se sobrepor. Se sua VPC AWS usa 10.0.0.0/16 e sua rede corporativa on-premises também usa 10.0.0.0/16, o peering/VPN não funcionará. Planeje o esquema de endereçamento com antecedência!

Seção 4

Máscara de Sub-rede

A máscara de sub-rede (subnet mask) é o mecanismo que define onde termina a porção de rede e começa a porção de host em um endereço IP. Sem ela, um dispositivo não sabe quem está na mesma rede e quem está em outra.

4.1 — O que a Máscara Faz

A máscara de sub-rede é um número de 32 bits que funciona como um "filtro": ela separa a porção de rede (bits 1) da porção de host (bits 0) no endereço IP.

🎭 A Máscara como Filtro


  Endereço IP:    192.168.1.100
  Máscara:        255.255.255.0
  
  Em binário:
  IP:       11000000.10101000.00000001.01100100
  Máscara:  11111111.11111111.11111111.00000000
            ├────────── REDE ──────────┤├─HOST─┤
  
  Operação AND bit a bit:
  IP:       11000000.10101000.00000001.01100100
  Máscara:  11111111.11111111.11111111.00000000
            ─────────────────────────────────────
  Resultado:11000000.10101000.00000001.00000000  = 192.168.1.0 (endereço de REDE)
  
  ┌─────────────────────────────────────────────────────────────┐
  │  A máscara "mascara" a porção de host, revelando apenas     │
  │  a porção de rede. Assim o dispositivo sabe sua rede!       │
  └─────────────────────────────────────────────────────────────┘

Quando um computador quer enviar dados para outro IP, ele aplica a máscara nos dois endereços (no seu e no destino). Se o resultado for igual, os dois estão na mesma rede e a comunicação é direta (camada 2). Se for diferente, estão em redes diferentes e o pacote deve ser enviado ao gateway padrão (roteador).

4.2 — Representação Binária da Máscara

A máscara é sempre uma sequência contínua de bits 1 seguida por bits 0. Nunca existem bits 1 intercalados com bits 0 (isso seria inválido):

Máscara Decimal Binário Prefixo Bits Rede Bits Host
255.0.0.0 11111111.00000000.00000000.00000000 /8 8 24
255.255.0.0 11111111.11111111.00000000.00000000 /16 16 16
255.255.255.0 11111111.11111111.11111111.00000000 /24 24 8
255.255.255.128 11111111.11111111.11111111.10000000 /25 25 7
255.255.255.192 11111111.11111111.11111111.11000000 /26 26 6
255.255.255.224 11111111.11111111.11111111.11100000 /27 27 5
255.255.255.240 11111111.11111111.11111111.11110000 /28 28 4
255.255.255.248 11111111.11111111.11111111.11111000 /29 29 3
255.255.255.252 11111111.11111111.11111111.11111100 /30 30 2
255.255.255.255 11111111.11111111.11111111.11111111 /32 32 0

4.3 — Notação de Prefixo (CIDR)

Em vez de escrever a máscara completa (255.255.255.0), podemos usar a notação de prefixo (também chamada notação CIDR), que indica apenas o número de bits 1 na máscara:

📝 Comparação de Notações


  Notação completa:    192.168.1.0  máscara 255.255.255.0
  Notação CIDR:        192.168.1.0/24
                                    └── 24 bits de rede (= 24 bits "1" na máscara)
  
  Mais exemplos:
  ┌──────────────────────────────┬────────────────┐
  │  Notação CIDR                │  Equivalente   │
  ├──────────────────────────────┼────────────────┤
  │  10.0.0.0/8                  │  255.0.0.0     │
  │  172.16.0.0/12               │  255.240.0.0   │

  /32 = endereço de um ÚNICO host (host route)
  /31 = link ponto-a-ponto (RFC 3021, 2 IPs sem broadcast)
  /30 = link ponto-a-ponto clássico (2 hosts utilizáveis)

💡 Regra Prática para Converter

Para converter rapidamente o último octeto da máscara: 256 - valor do octeto = tamanho do bloco (step).

Exemplo: máscara 255.255.255.192 → 256 - 192 = 64 → cada sub-rede tem 64 endereços (começando em 0, 64, 128, 192).

4.4 — Como a Máscara Determina a Comunicação

Veja na prática como um host decide se o destino está na mesma rede (comunicação direta via switch) ou em outra rede (precisa do gateway/roteador):

🔍 Exemplo: Mesma Rede vs Rede Diferente


  Host A:   192.168.1.10  /24   (máscara 255.255.255.0)
  Host B:   192.168.1.200 /24
  Host C:   192.168.2.10  /24
  
  ─── Host A quer falar com Host B ───
  Host A AND máscara: 192.168.1.10 AND 255.255.255.0 = 192.168.1.0
  Host B AND máscara: 192.168.1.200 AND 255.255.255.0 = 192.168.1.0
  Resultado: IGUAIS → MESMA REDE → comunicação DIRETA (ARP + Switch)
  
  ─── Host A quer falar com Host C ───
  Host A AND máscara: 192.168.1.10 AND 255.255.255.0 = 192.168.1.0
  Host C AND máscara: 192.168.2.10 AND 255.255.255.0 = 192.168.2.0
  Resultado: DIFERENTES → REDES DIFERENTES → envia ao GATEWAY (roteador)

⚠️ Erro Comum de Configuração

Se dois dispositivos na mesma LAN física tiverem máscaras diferentes (ex: um com /24 e outro com /25), eles podem "não se enxergar" mesmo estando no mesmo switch. Isso porque um deles calcula que o outro está em rede diferente e tenta enviar ao gateway em vez de comunicar diretamente. Sempre use a mesma máscara em todos os hosts de uma sub-rede!

4.5 — Endereço de Rede e Endereço de Broadcast

Dada uma combinação IP + máscara, podemos calcular dois endereços especiais:

📊 Cálculo de Rede e Broadcast


  Dado: 192.168.1.130/26 (máscara 255.255.255.192)
  
  Passo 1 — Tamanho do bloco: 256 - 192 = 64
  Passo 2 — Em qual bloco o .130 cai? 0, 64, 128, 192 → cai no bloco 128
  Passo 3 — Endereço de rede: 192.168.1.128 (início do bloco)
  Passo 4 — Broadcast: 192.168.1.191 (fim do bloco = próximo bloco - 1 = 192 - 1)
  Passo 5 — Primeiro host utilizável: 192.168.1.129
  Passo 6 — Último host utilizável: 192.168.1.190
  Passo 7 — Total de hosts: 2⁶ - 2 = 62

  │  Rede:       192.168.1.128/26              │
  │  Broadcast:  192.168.1.191                  │
  │  1º Host:    192.168.1.129                  │
  │  Último:     192.168.1.190                  │
  │  Total:      62 hosts utilizáveis           │

Seção 5

Sub-redes (Subnetting)

Subnetting é a técnica de dividir uma rede grande em redes menores (sub-redes). É uma habilidade fundamental para qualquer profissional de redes e cloud — usada diariamente no design de VPCs, VLANs e segmentação de tráfego.

5.1 — Por que Fazer Subnetting?

Dividir uma rede em sub-redes menores traz múltiplos benefícios:

🔒 Segurança e Isolamento

Departamentos ou funções diferentes ficam em sub-redes separadas. O tráfego entre elas passa por um roteador/firewall onde políticas de segurança podem ser aplicadas. Ex: servidores de banco de dados isolados dos desktops dos usuários.

📡 Redução de Broadcast

Broadcasts (ARP, DHCP, etc.) ficam confinados dentro de cada sub-rede. Em uma rede /24 com 254 hosts, cada broadcast atinge 254 dispositivos. Dividindo em 4x /26, cada broadcast atinge apenas 62 dispositivos.

📋 Organização Lógica

Facilita a administração, documentação e troubleshooting. "O problema está na sub-rede de servidores (10.0.1.0/24)" é muito mais específico que "está na rede 10.0.0.0/16".

⚡ Performance

Menos hosts por domínio de broadcast = menos tráfego desnecessário = melhor performance para todos. Especialmente importante em redes com muitos dispositivos.

☁️ Requisito Cloud

Na AWS, cada VPC DEVE ser dividida em sub-redes (subnets) distribuídas em Availability Zones. Sem subnetting, não é possível criar uma arquitetura altamente disponível na nuvem.

💰 Uso Eficiente de IPs

Em vez de desperdiçar um /24 inteiro (254 IPs) para um link ponto-a-ponto que precisa de apenas 2 IPs, usa-se um /30 (2 IPs utilizáveis). Economia de 252 endereços!

5.2 — Método Passo a Passo para Subnetting

Siga este método sistemático para dividir qualquer rede em sub-redes:

📋 Algoritmo de Subnetting


  ╔═══════════════════════════════════════════════════════════════════════╗
  ║  MÉTODO DE SUBNETTING — 6 PASSOS                                     ║
  ╠═══════════════════════════════════════════════════════════════════════╣
  ║                                                                       ║
  ║  1. DETERMINAR A NECESSIDADE                                          ║
  ║     → Quantas sub-redes você precisa? OU                              ║
  ║     → Quantos hosts por sub-rede você precisa?                        ║
  ║                                                                       ║
  ║  2. CALCULAR BITS EMPRESTADOS                                         ║
  ║     → Para N sub-redes: bits = ⌈log₂(N)⌉  (arredonda para cima)      ║
  ║     → Para H hosts: bits de host = ⌈log₂(H + 2)⌉                     ║
  ║                                                                       ║
  ║  3. NOVA MÁSCARA                                                      ║
  ║     → Máscara original + bits emprestados = nova máscara              ║
  ║     → Ex: /24 + 2 bits = /26                                         ║
  ║                                                                       ║
  ║  4. TAMANHO DO BLOCO (STEP/INCREMENTO)                                ║
  ║     → 2^(bits de host restantes) = tamanho de cada sub-rede           ║
  ║     → Ou: 256 - valor do último octeto da máscara                     ║
  ║                                                                       ║
  ║  5. LISTAR AS SUB-REDES                                               ║
  ║     → Começando em 0 e incrementando pelo tamanho do bloco            ║
  ║     → Sub-rede 0: .0, Sub-rede 1: .64, Sub-rede 2: .128, etc.        ║
  ║                                                                       ║
  ║  6. PARA CADA SUB-REDE, IDENTIFICAR:                                  ║
  ║     → Endereço de rede (primeiro do bloco)                            ║
  ║     → Primeiro host utilizável (rede + 1)                             ║
  ║     → Último host utilizável (broadcast - 1)                          ║
  ║     → Endereço de broadcast (último do bloco)                         ║
  ║                                                                       ║
  ╚═══════════════════════════════════════════════════════════════════════╝

Cenário: Você tem a rede 192.168.1.0/24 e precisa de 4 sub-redes (uma para cada departamento: TI, RH, Financeiro, Diretoria).

🧮 Resolução Passo a Passo


  Rede original: 192.168.1.0/24 (254 hosts)
  Necessidade: 4 sub-redes

Seção 6

CIDR (Classless Inter-Domain Routing)

O CIDR substituiu o sistema classful rígido, permitindo alocações flexíveis de endereços e agregação de rotas. É o sistema usado na Internet moderna, em cloud computing e em toda configuração de rede atual.

6.1 — Por que o CIDR Substituiu as Classes?

Nos anos 90, a Internet crescia exponencialmente e dois problemas ameaçavam sua sobrevivência:

🔥 Esgotamento de Endereços

Classes fixas causavam desperdício massivo. Uma empresa com 1.000 hosts recebia uma Classe B (65.534 IPs) — 98,5% desperdiçado. Os endereços estavam acabando rapidamente.

💥 Explosão de Tabelas de Roteamento

Cada rede Classe C precisava de uma entrada separada na tabela de roteamento dos roteadores de backbone. Com milhões de redes /24, os roteadores não tinham memória suficiente.

O CIDR (RFC 1517-1520, 1993) resolveu ambos os problemas ao eliminar as classes fixas e permitir:

  • Alocação flexível: máscaras de qualquer tamanho (/1 a /32), não apenas /8, /16, /24
  • Agregação de rotas (supernetting): múltiplas redes pequenas resumidas em uma única rota
  • VLSM: sub-redes de tamanhos diferentes dentro da mesma rede

6.2 — Notação CIDR

A notação CIDR usa o formato endereço/prefixo, onde o prefixo indica quantos bits são a parte de rede:

📝 Exemplos de CIDR no Mundo Real


  ┌─────────────────────────┬──────────────────────────────────────────────────┐
  │  CIDR                   │  Significado                                     │
  ├─────────────────────────┼──────────────────────────────────────────────────┤
  │  0.0.0.0/0              │  TODA a Internet (rota default)                  │
  │  10.0.0.0/8             │  Bloco privado classe A (16M IPs)                │
  │  10.0.0.0/16            │  Sub-bloco de 65.536 IPs dentro do 10.x.x.x     │
  │  10.0.1.0/24            │  Sub-rede típica (254 hosts)                     │
  │  10.0.1.128/25          │  Metade de uma /24 (126 hosts)                   │
  │  203.0.113.0/22         │  4 blocos /24 agregados (1.022 hosts)            │
  │  8.8.8.8/32             │  UM ÚNICO host (Google DNS)                      │
  └─────────────────────────┴──────────────────────────────────────────────────┘
  
  Regra geral:
  • Prefixo MENOR (/8) = rede MAIOR (mais hosts)
  • Prefixo MAIOR (/28) = rede MENOR (menos hosts)
  • Cada bit a mais no prefixo DIVIDE a rede pela metade

6.3 — Agregação de Rotas (Supernetting / Summarization)

O CIDR permite agregar múltiplas redes menores em uma única rota maior, reduzindo drasticamente o tamanho das tabelas de roteamento:

🔗 Exemplo de Agregação


  SEM AGREGAÇÃO (4 rotas na tabela):
  ┌────────────────────────────────────────┐
  │  192.168.0.0/24   →  Roteador A       │
  │  192.168.1.0/24   →  Roteador A       │
  │  192.168.2.0/24   →  Roteador A       │
  │  192.168.3.0/24   →  Roteador A       │
  └────────────────────────────────────────┘
  
  COM AGREGAÇÃO (1 rota na tabela):
  ┌────────────────────────────────────────┐
  │  192.168.0.0/22   →  Roteador A       │
  └────────────────────────────────────────┘
  
  Por que /22?
  • 4 redes /24 = 2² → precisamos de 2 bits a menos no prefixo
  • /24 - 2 = /22
  • /22 cobre: 192.168.0.0 a 192.168.3.255 (1.024 IPs)
  
  Verificação em binário:
  192.168.0.0   = 11000000.10101000.000000|00.00000000
  192.168.1.0   = 11000000.10101000.000000|01.00000000
  192.168.2.0   = 11000000.10101000.000000|10.00000000
  192.168.3.0   = 11000000.10101000.000000|11.00000000
                                    ^^^^^^
                            22 bits iguais → /22

💡 Impacto Real da Agregação

Sem CIDR, a tabela de roteamento global da Internet teria milhões de entradas individuais. Com CIDR e agregação, os ISPs resumem milhares de redes de clientes em poucas rotas agregadas. Em 2024, a tabela BGP global tem ~930.000 rotas — sem agregação, teria muito mais do que isso.

6.4 — VLSM (Variable Length Subnet Masking)

O VLSM é uma extensão natural do CIDR que permite usar máscaras de tamanhos diferentes dentro da mesma rede. No sistema classful, todas as sub-redes precisavam ter a mesma máscara. Com VLSM, cada sub-rede pode ter o tamanho ideal para suas necessidades:

📐 Exemplo VLSM: Rede 10.1.0.0/24


  Requisitos:
  • Departamento A: 100 hosts  → precisa de /25 (126 hosts)
  • Departamento B: 50 hosts   → precisa de /26 (62 hosts)
  • Departamento C: 25 hosts   → precisa de /27 (30 hosts)
  • Link WAN 1: 2 hosts        → precisa de /30 (2 hosts)
  • Link WAN 2: 2 hosts        → precisa de /30 (2 hosts)
  
  Alocação VLSM (sempre aloque do MAIOR para o MENOR):
  
  ┌──────────────────┬────────────────────┬────────────┬─────────────────────┐
  │  Departamento    │  Sub-rede          │  Hosts     │  Faixa              │
  ├──────────────────┼────────────────────┼────────────┼─────────────────────┤
  │  Depto A         │  10.1.0.0/25       │  126       │  10.1.0.1 - .126    │
  │  Depto B         │  10.1.0.128/26     │  62        │  10.1.0.129 - .190  │
  │  Depto C         │  10.1.0.192/27     │  30        │  10.1.0.193 - .222  │
  │  WAN Link 1      │  10.1.0.224/30     │  2         │  10.1.0.225 - .226  │
  │  WAN Link 2      │  10.1.0.228/30     │  2         │  10.1.0.229 - .230  │
  └──────────────────┴────────────────────┴────────────┴─────────────────────┘
  
  ✅ Total utilizado: 126 + 62 + 30 + 2 + 2 = 222 hosts
  ✅ IPs restantes (10.1.0.232 - 10.1.0.255): livres para expansão futura
  ✅ SEM VLSM (tudo /26): caberia apenas 4 × 62 = 248, mas desperdiçaria
     sub-redes inteiras nos links WAN

💡 VLSM na AWS

Na AWS, quando você cria sub-redes dentro de uma VPC, está usando VLSM naturalmente. Você pode ter uma sub-rede /24 para servidores web, uma /26 para bancos de dados e uma /28 para a sub-rede do NAT Gateway — tudo dentro da mesma VPC /16. Cada sub-rede tem o tamanho exato necessário.

Seção 7

IPv6 — Introdução

O IPv6 é o sucessor do IPv4, projetado para resolver definitivamente o problema de esgotamento de endereços e simplificar várias aspectos do protocolo. Com 128 bits, oferece um espaço de endereçamento praticamente infinito.

7.1 — Por que IPv6?

O IPv4 está esgotado. Todos os blocos /8 disponíveis já foram distribuídos pelos registradores regionais (RIRs). Novos endereços IPv4 só são obtidos por:

  • Compra/transferência de blocos existentes (mercado secundário — caro!)
  • Devolução de blocos subutilizados (raro)
  • Uso cada vez mais agressivo de NAT (CGN/CGNAT)

📊 IPv4 vs IPv6 — Números

IPv4: 2³² = ~4,3 bilhões de endereços

IPv6: 2¹²⁸ = ~340 undecilhões de endereços

(340.282.366.920.938.463.463.374.607.431.768.211.456)

Isso é aproximadamente 6,7 × 10²³ endereços por metro quadrado da superfície terrestre!

✅ Benefícios do IPv6

• Espaço de endereçamento virtualmente infinito

• Cabeçalho simplificado (mais eficiente para roteadores)

• Auto-configuração (SLAAC — não precisa de DHCP)

• IPsec integrado nativamente

• Sem necessidade de NAT (cada dispositivo tem IP público)

• Multicast melhorado (sem broadcast)

7.2 — Formato do Endereço IPv6

Um endereço IPv6 tem 128 bits, representados em 8 grupos de 4 dígitos hexadecimais (16 bits cada), separados por dois-pontos:

📐 Estrutura IPv6


  Formato completo (sem abreviações):
  2001:0db8:85a3:0000:0000:8a2e:0370:7334
  ├──┤├──┤├──┤├──┤├──┤├──┤├──┤├──┤
   16   16   16   16   16   16   16   16  = 128 bits
   bits bits bits bits bits bits bits bits
  
  Cada dígito hexadecimal = 4 bits
  Cada grupo = 4 dígitos hex = 16 bits
  8 grupos × 16 bits = 128 bits total
  
  Comparação visual:
  ┌─────────────────────────────────────────────────────────┐
  │  IPv4:  192.168.1.1           (32 bits, decimal)        │
  │  IPv6:  2001:0db8:85a3:0000:0000:8a2e:0370:7334        │
  │         (128 bits, hexadecimal)                         │
  └─────────────────────────────────────────────────────────┘

7.3 — Regras de Abreviação IPv6

Endereços IPv6 são longos, então existem duas regras de abreviação:

✂️ Regra 1: Omitir Zeros à Esquerda


  Completo:     2001:0db8:0085:0000:0000:8a2e:0370:7334
  Abreviado:    2001:db8:85:0:0:8a2e:370:7334
  
  • 0db8 → db8  (remove 0 à esquerda)
  • 0085 → 85   (remove 00 à esquerda)
  • 0000 → 0    (remove 000 à esquerda, mantém pelo menos um dígito)
  • 0370 → 370  (remove 0 à esquerda)

✂️ Regra 2: Substituir Grupos Consecutivos de Zeros por "::"


  Após Regra 1: 2001:db8:85:0:0:8a2e:370:7334
  Após Regra 2: 2001:db8:85::8a2e:370:7334
                           ^^
                           substitui ":0:0:" por "::"
  
  ⚠️ IMPORTANTE: o "::" só pode ser usado UMA VEZ por endereço!
  (senão seria ambíguo quantos grupos de zeros foram omitidos)
  
  Mais exemplos:
  ┌────────────────────────────────────────────────────────────────────────┐
  │  Completo                         │  Abreviado                        │
  ├────────────────────────────────────────────────────────────────────────┤
  │  2001:0db8:0000:0000:0000:0000:0000:0001  │  2001:db8::1            │
  │  fe80:0000:0000:0000:0210:a4ff:fee3:9566  │  fe80::210:a4ff:fee3:9566│
  │  0000:0000:0000:0000:0000:0000:0000:0001  │  ::1 (loopback!)        │
  │  0000:0000:0000:0000:0000:0000:0000:0000  │  :: (endereço indefinido)│
  │  ff02:0000:0000:0000:0000:0000:0000:0001  │  ff02::1 (all nodes)    │
  └────────────────────────────────────────────────────────────────────────┘

⚠️ Armadilha do "::"

O "::" só pode aparecer uma vez no endereço. Se aparecesse duas vezes, seria impossível saber quantos grupos de zeros cada "::" representa. Exemplo inválido: 2001::db8::1 — ERRADO! Ambíguo.

7.4 — Tipos de Endereço IPv6

Os principais tipos de endereço IPv6 que você encontrará:

Tipo Prefixo Exemplo Função
Global Unicast (GUA) 2000::/3 2001:db8:1::100 Equivalente ao IP público IPv4. Roteável globalmente na Internet.
Link-Local fe80::/10 fe80::1 Auto-configurado em toda interface. Comunicação apenas no link local (não roteável).
Unique Local (ULA) fc00::/7 (fd00::/8) fd00:1234::1 Equivalente aos IPs privados RFC 1918. Uso interno, não roteável na Internet.
Loopback ::1/128 ::1 Equivalente ao 127.0.0.1 do IPv4.
Multicast ff00::/8 ff02::1 Enviar para um grupo. ff02::1 = all nodes, ff02::2 = all routers.
Endereço Indefinido ::/128 :: Equivalente ao 0.0.0.0 do IPv4. Usado antes de receber endereço.

7.5 — Link-Local (fe80::)

Toda interface de rede com IPv6 habilitado recebe automaticamente um endereço link-local (fe80::/10). Não precisa de DHCP nem configuração manual:

🔗 Endereço Link-Local


  Formato: fe80::[Interface ID]/10
  
  O Interface ID geralmente é derivado do MAC address (EUI-64):
  
  MAC Address:    00:1A:2B:3C:4D:5E
  
  Processo EUI-64:
  1. Inserir FF:FE no meio:   00:1A:2B:FF:FE:3C:4D:5E
  2. Inverter bit U/L (7º):   02:1A:2B:FF:FE:3C:4D:5E
  3. Converter para IPv6:     fe80::021a:2bff:fe3c:4d5e
  
  Uso do Link-Local:
  • Descoberta de vizinhos (Neighbor Discovery Protocol - NDP)
  • Obter endereço global via SLAAC ou DHCPv6
  • Comunicação na LAN sem configuração
  • Next-hop em tabelas de roteamento IPv6
  
  ⚠️ Link-local NUNCA é roteado para fora do link (segmento de rede local)

7.6 — Global Unicast Address (GUA)

O GUA é o equivalente IPv6 de um endereço IP público. É globalmente roteável e estruturado hierarquicamente:

🌍 Estrutura do GUA


  |<──────── 48 bits ────────>|<─ 16 ─>|<────────── 64 bits ──────────>|
  ┌──────────────────────────┬─────────┬───────────────────────────────┐
  │   Global Routing Prefix  │Subnet ID│        Interface ID           │
  │   (ISP + Site)           │         │   (identifica o host)         │
  └──────────────────────────┴─────────┴───────────────────────────────┘
  
  Exemplo: 2001:0db8:acad:0001:0000:0000:0000:0100/64
           ├─── Routing Prefix ──┤├Sub─┤├──── Interface ID ─────────┤
  
  • Global Routing Prefix (48 bits): atribuído pelo ISP/RIR
  • Subnet ID (16 bits): permite 65.536 sub-redes dentro do site
  • Interface ID (64 bits): identifica o host na sub-rede
  
  Com /64 por sub-rede: 2⁶⁴ = 18.4 quintilhões de hosts por sub-rede!
  (mais que todos os grãos de areia da Terra)

💡 IPv6 na AWS

A AWS suporta dual-stack (IPv4 + IPv6 simultaneamente) em VPCs. Ao habilitar IPv6, a AWS aloca um /56 para a VPC e você pode criar sub-redes /64. Instâncias podem ter tanto um IPv4 privado quanto um IPv6 GUA público. O IPv6 na AWS é gratuito (sem custo adicional pelo endereçamento).

7.7 — IPv6 vs IPv4 — Resumo Comparativo

As principais diferenças entre os dois protocolos:

Característica IPv4 IPv6
Tamanho do endereço 32 bits 128 bits
Notação Decimal pontuada (192.168.1.1) Hexadecimal com : (2001:db8::1)
Total de endereços ~4,3 bilhões ~340 undecilhões
Configuração DHCP ou manual SLAAC, DHCPv6 ou manual
NAT Amplamente necessário Desnecessário (todo host tem GUA)
Broadcast Sim (255.255.255.255) Não (substituído por multicast)
Segurança IPsec opcional IPsec integrado (mandatório na spec)
Cabeçalho Variável (20-60 bytes) Fixo (40 bytes) + extension headers
Fragmentação Roteadores e hosts Apenas no host de origem
ARP Sim Substituído por NDP (Neighbor Discovery)

Exercício 1 — Identificar Rede, Broadcast e Hosts

Problema: Dado o endereço 172.16.35.123/20, determine:

  1. Endereço de rede
  2. Endereço de broadcast
  3. Primeiro host utilizável
  4. Último host utilizável
  5. Total de hosts utilizáveis
🔍 Clique para ver a solução passo a passo

📝 Resolução do Exercício 1


  Dado: 172.16.35.123/20
  
  PASSO 1: Identificar a máscara
  /20 = 20 bits de rede, 12 bits de host
  Máscara: 255.255.240.0
  (240 = 11110000 → os 4 primeiros bits do 3º octeto são rede)
  
  PASSO 2: Tamanho do bloco no 3º octeto
  256 - 240 = 16
  Os blocos no 3º octeto são: 0, 16, 32, 48, 64...
  
  PASSO 3: Em qual bloco cai o 35?
  32 ≤ 35 < 48 → cai no bloco 32
  
  PASSO 4: Calcular os endereços
  
  • Endereço de Rede:       172.16.32.0/20
    (3º octeto = início do bloco = 32, 4º octeto = 0)
  
  • Endereço de Broadcast:  172.16.47.255
    (próximo bloco - 1 = 48 - 1 = 47 no 3º octeto, 255 no 4º)
  
  • Primeiro Host:          172.16.32.1
  
  • Último Host:            172.16.47.254
  
  • Total de Hosts:         2¹² - 2 = 4.094 hosts
  
  VERIFICAÇÃO:
  Rede em binário:      172.16.  0010|0000.00000000 = 172.16.32.0
  IP em binário:        172.16.  0010|0011.01111011 = 172.16.35.123
  Broadcast binário:    172.16.  0010|1111.11111111 = 172.16.47.255
                              ────┘    └─────────────────────────────
                        20 bits rede    12 bits host

  • AZ-1: Sub-rede pública (web servers) — até 250 hosts
  • AZ-1: Sub-rede privada (app servers) — até 250 hosts
  • AZ-1: Sub-rede de banco de dados — até 50 hosts
  • AZ-2: Sub-rede pública (web servers) — até 250 hosts

Projete o esquema de endereçamento. Lembre-se que a AWS reserva 5 IPs por sub-rede.

🔍 Clique para ver a solução passo a passo

📝 Resolução do Exercício 3


  VPC CIDR: 10.0.0.0/16 (65.536 IPs disponíveis)

  • .0 = endereço de rede

Exercício 4 — Agregação de Rotas (Supernetting)

Problema: Sua empresa possui as seguintes redes atrás do mesmo roteador de borda:

  • 192.168.16.0/24
  • 192.168.17.0/24
  • 192.168.18.0/24
  • 192.168.19.0/24
  • 192.168.20.0/24
  • 192.168.21.0/24
  • 192.168.22.0/24
  • 192.168.23.0/24

Encontre uma única rota agregada (supernet) que cubra todas essas redes sem incluir redes adicionais desnecessárias.

🔍 Clique para ver a solução passo a passo

📝 Resolução do Exercício 4


  Redes para agregar: 192.168.16.0 a 192.168.23.0 (8 redes /24)
  
  PASSO 1: Converter o 3º octeto para binário
  
  16 = 0001|0000
  17 = 0001|0001
  18 = 0001|0010
  19 = 0001|0011
  20 = 0001|0100
  21 = 0001|0101
  22 = 0001|0110
  23 = 0001|0111
       ─────┘└──┘
       Iguais  Diferentes
       (5 bits)(3 bits)
  
  PASSO 2: Encontrar os bits em comum
  Os 5 primeiros bits do 3º octeto são iguais (00010)
  Os 3 últimos bits variam (000 a 111 = 0 a 7)
  
  PASSO 3: Calcular o novo prefixo
  • Bits fixos: 8 + 8 + 5 = 21 bits de rede
  • Novo prefixo: /21
  
  PASSO 4: Verificar o endereço base
  • 3º octeto com bits variáveis zerados: 00010|000 = 16
  • Endereço base: 192.168.16.0
  
  RESULTADO:
  ┌─────────────────────────────────────────────────────────────┐
  │  Rota agregada: 192.168.16.0/21                             │
  │                                                             │
  │  Cobre: 192.168.16.0 a 192.168.23.255 (2.048 IPs)          │
  │  = exatamente as 8 redes /24 desejadas                      │
  │                                                             │
  │  Verificação: 2²¹ padrão contém 8 × /24                    │
  │  /24 - /21 = 3 bits → 2³ = 8 redes ✅                       │
  └─────────────────────────────────────────────────────────────┘
  
  ANTES (8 rotas):                 DEPOIS (1 rota):
  192.168.16.0/24 → Router A       192.168.16.0/21 → Router A
  192.168.17.0/24 → Router A       
  192.168.18.0/24 → Router A       Economia: 87.5% menos rotas!
  192.168.19.0/24 → Router A       
  192.168.20.0/24 → Router A       
  192.168.21.0/24 → Router A       
  192.168.22.0/24 → Router A       
  192.168.23.0/24 → Router A       
  
  ⚠️ ATENÇÃO: a agregação só funciona perfeitamente porque:
  1. As 8 redes são contíguas (16-23, sem buracos)
  2. Começam em um limite de /21 (16 é múltiplo de 8)
  3. São exatamente 2ⁿ redes (8 = 2³)
  
  Se fossem 192.168.16.0 a 192.168.20.0 (5 redes), NÃO seria
  possível agregar em uma única rota sem incluir as redes 21-23.

🎯 Dicas para Praticar Subnetting

Dominar subnetting exige prática repetitiva. Aqui estão estratégias que funcionam:

⏱️ Pratique Velocidade

No início, use papel e caneta. Com o tempo, tente resolver mentalmente. O objetivo para certificações é resolver em menos de 1 minuto por questão.

📊 Memorize as Potências de 2

2¹=2, 2²=4, 2³=8, 2⁴=16, 2⁵=32, 2⁶=64, 2⁷=128, 2⁸=256. Saiba de cor: 256, 128, 64, 32, 16, 8, 4, 2 — são os tamanhos de bloco.

🔢 Memorize os Valores de Máscara

Os valores possíveis no último octeto variável da máscara são: 0, 128, 192, 224, 240, 248, 252, 254, 255. Correspondem a /24, /25, /26, /27, /28, /29, /30, /31, /32.

🌐 Use no Dia a Dia

Sempre que configurar uma VPC, Security Group ou firewall, faça o cálculo mental do CIDR. Pergunte-se: "quantos hosts cabem?", "qual é o broadcast?".
