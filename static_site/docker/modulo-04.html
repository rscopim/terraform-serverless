🐳 Docker — Módulo 04

Redes no Docker

Entenda como containers se comunicam entre si e com o mundo externo. Domine drivers de rede, DNS interno, port mapping e crie arquiteturas multi-container robustas.

Por que Redes Docker Importam?

Em aplicações reais, containers precisam se comunicar: uma API precisa acessar o banco de dados, um frontend precisa chamar o backend, um cache Redis precisa ser acessível por múltiplos serviços. O Docker fornece um sistema de rede completo com isolamento, DNS automático e diferentes drivers para diferentes cenários.

Drivers de Rede

DriverDescriçãoUso Ideal
bridge Rede padrão. Cria uma bridge virtual no host. Containers na mesma bridge se comunicam. Comunicação entre containers no mesmo host
host Remove isolamento de rede. Container usa a rede do host diretamente. Performance máxima, sem overhead de NAT
none Desabilita toda conectividade de rede. Containers que não precisam de rede (batch jobs isolados)
overlay Conecta containers em múltiplos hosts Docker (Swarm/Kubernetes). Clusters multi-host, Docker Swarm
macvlan Atribui um endereço MAC ao container, fazendo-o aparecer como dispositivo físico na rede. Integração com rede física, aplicações legadas

Comandos para Gerenciar Redes

docker network lsListar

Lista todas as redes Docker disponíveis.

docker network ls

# Saída padrão:
# NETWORK ID     NAME      DRIVER    SCOPE
# a1b2c3d4e5f6   bridge    bridge    local
# f6e5d4c3b2a1   host      host      local
# 1a2b3c4d5e6f   none      null      local
docker network createCriar

Cria uma rede customizada. Redes customizadas têm DNS automático entre containers.

# Criar rede bridge customizada
docker network create minha-rede

# Criar com subnet específica
docker network create \
  --driver bridge \
  --subnet 172.20.0.0/16 \
  --gateway 172.20.0.1 \
  minha-rede

# Criar rede overlay (Swarm)
docker network create --driver overlay minha-overlay
docker network inspectInspecionar

Mostra detalhes da rede: subnet, gateway, containers conectados, etc.

docker network inspect minha-rede

# Ver apenas containers conectados
docker network inspect minha-rede --format '{{json .Containers}}'
docker network rmRemover

Remove uma rede. Falha se houver containers conectados.

# Remover rede
docker network rm minha-rede

# Remover múltiplas
docker network rm rede1 rede2
docker network connectConectar

Conecta um container em execução a uma rede adicional.

# Conectar container a rede
docker network connect minha-rede meu-container

# Conectar com IP fixo
docker network connect --ip 172.20.0.10 minha-rede meu-container
docker network disconnectDesconectar

Remove um container de uma rede.

# Desconectar container
docker network disconnect minha-rede meu-container

# Forçar desconexão
docker network disconnect -f minha-rede meu-container
docker network pruneLimpar

Remove todas as redes não utilizadas.

docker network prune

# Sem confirmação
docker network prune -f

Comunicação entre Containers

Bridge Padrão vs Bridge Customizada

Bridge padrão❌ Sem DNS

Na rede bridge padrão, containers só se comunicam por IP. Não há resolução DNS por nome.

# Containers na bridge padrão
docker run -d --name app1 nginx
docker run -d --name app2 nginx

# Comunicação apenas por IP (não por nome)
docker exec app1 ping app2  # ❌ FALHA

# Precisa descobrir o IP manualmente
docker inspect --format '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}' app2
# → 172.17.0.3
docker exec app1 ping 172.17.0.3  # ✓ Funciona
Bridge customizada✅ DNS automático

Em redes customizadas, o Docker fornece DNS automático. Containers se encontram pelo nome.

# Criar rede customizada
docker network create app-network

# Containers na rede customizada
docker run -d --name app1 --network app-network nginx
docker run -d --name app2 --network app-network nginx

# Comunicação por nome ✓
docker exec app1 ping app2  # ✓ Funciona!
docker exec app2 ping app1  # ✓ Funciona!

# DNS resolve automaticamente
docker exec app1 nslookup app2
# → Address: 172.18.0.3

Exemplo Prático — App + Redis + PostgreSQL

Arquitetura multi-containerExemplo completo

Três containers se comunicando via DNS na mesma rede customizada.

# 1. Criar rede da aplicação
docker network create app-stack

# 2. Iniciar PostgreSQL
docker run -d \
  --name postgres \
  --network app-stack \
  -e POSTGRES_USER=app \
  -e POSTGRES_PASSWORD=secret \
  -e POSTGRES_DB=myapp \
  -v pgdata:/var/lib/postgresql/data \
  postgres:16-alpine

# 3. Iniciar Redis
docker run -d \
  --name redis \
  --network app-stack \
  redis:7-alpine

# 4. Iniciar aplicação (conecta ao DB e cache por nome)
docker run -d \
  --name api \
  --network app-stack \
  -e DATABASE_URL=postgresql://app:secret@postgres:5432/myapp \
  -e REDIS_URL=redis://redis:6379 \
  -p 3000:3000 \
  minha-api:latest

# 5. Verificar conectividade
docker exec api ping postgres   # ✓
docker exec api ping redis      # ✓

# 6. Ver containers na rede
docker network inspect app-stack --format '{{range .Containers}}{{.Name}} {{end}}'
# → postgres redis api

Rede Host

--network hostSem isolamento

O container compartilha a rede do host. Sem NAT, sem port mapping — a porta do container é a porta do host diretamente. Apenas Linux.

# Container usa rede do host diretamente
docker run -d --network host nginx

# Nginx agora escuta na porta 80 do HOST
# Não precisa de -p (port mapping)
curl http://localhost:80  # ✓ Acessa o nginx

# Útil para: monitoramento, performance máxima
# Desvantagem: sem isolamento de rede

Rede None

--network noneIsolado

Container completamente isolado da rede. Apenas interface loopback disponível.

# Container sem rede
docker run -d --network none alpine sleep 3600

# Verificar — apenas loopback
docker exec -it $(docker ps -q -l) ip addr
# → Apenas lo (127.0.0.1)

# Uso: processamento batch, tarefas que não precisam de rede

Port Mapping (Mapeamento de Portas)

-p (publish)Portas

Mapeia portas do host para portas do container, permitindo acesso externo.

# host:container
docker run -d -p 8080:80 nginx

# Múltiplas portas
docker run -d -p 8080:80 -p 8443:443 nginx

# Porta aleatória do host
docker run -d -p 80 nginx

# Bind em interface específica
docker run -d -p 127.0.0.1:8080:80 nginx

# Bind em interface específica com porta aleatória
docker run -d -p 127.0.0.1::80 nginx

# Range de portas
docker run -d -p 8000-8010:8000-8010 minha-app

# UDP
docker run -d -p 5353:53/udp dns-server
docker portVerificar

Mostra o mapeamento de portas de um container.

# Ver portas mapeadas
docker port meu-nginx

# Saída:
# 80/tcp -> 0.0.0.0:8080
# 443/tcp -> 0.0.0.0:8443

# Porta específica
docker port meu-nginx 80
# → 0.0.0.0:8080

DNS Aliases (--network-alias)

--network-aliasDNS

Permite que múltiplos containers respondam pelo mesmo nome DNS. Útil para load balancing básico e service discovery.

# Criar rede
docker network create app-net

# Dois containers com mesmo alias
docker run -d \
  --name web1 \
  --network app-net \
  --network-alias web \
  nginx

docker run -d \
  --name web2 \
  --network app-net \
  --network-alias web \
  nginx

# Resolver alias — retorna IPs de ambos (round-robin DNS)
docker run --rm --network app-net alpine nslookup web
# → Name: web  Address: 172.18.0.2
# → Name: web  Address: 172.18.0.3

# Requisições para "web" são distribuídas entre web1 e web2
docker run --rm --network app-net alpine wget -qO- http://web
