🐳 Docker — Módulo 03

Volumes e Persistência de Dados

Containers são efêmeros por natureza. Aprenda a persistir dados com volumes, bind mounts e tmpfs — e domine backup, restauração e transferência de dados.

O Problema: Containers são Efêmeros

Quando um container é removido, todos os dados escritos dentro dele são perdidos. Isso é por design — containers devem ser descartáveis e recriáveis. Mas aplicações reais precisam persistir dados: bancos de dados, uploads de usuários, logs, configurações.

Regra de ouro: Nunca armazene dados importantes apenas dentro do filesystem do container. Use volumes ou bind mounts para qualquer dado que precisa sobreviver à remoção do container.

Tipos de Armazenamento

TipoLocalizaçãoGerenciado porUso Ideal
Volume /var/lib/docker/volumes/ Docker Dados de produção, bancos de dados, dados compartilhados entre containers
Bind Mount Qualquer caminho no host Usuário Desenvolvimento (código-fonte), configurações do host
tmpfs Memória RAM do host Kernel Dados temporários sensíveis, cache em memória

Comandos para Gerenciar Volumes

docker volume createCriar

Cria um volume nomeado gerenciado pelo Docker.

# Criar volume
docker volume create meu-volume

# Criar com driver específico
docker volume create --driver local \
  --opt type=nfs \
  --opt o=addr=192.168.1.100,rw \
  --opt device=:/path/to/dir \
  nfs-volume
docker volume lsListar

Lista todos os volumes existentes no host.

# Listar volumes
docker volume ls

# Filtrar por driver
docker volume ls --filter driver=local

# Filtrar volumes não utilizados (dangling)
docker volume ls --filter dangling=true
docker volume inspectInspecionar

Mostra detalhes do volume: driver, mountpoint, labels, etc.

docker volume inspect meu-volume

# Saída:
# [{ "CreatedAt": "...",
#    "Driver": "local",
#    "Mountpoint": "/var/lib/docker/volumes/meu-volume/_data",
#    "Name": "meu-volume" }]
docker volume rmRemover

Remove um ou mais volumes. Falha se o volume estiver em uso.

# Remover volume específico
docker volume rm meu-volume

# Remover múltiplos
docker volume rm vol1 vol2 vol3
docker volume pruneLimpar

Remove TODOS os volumes não utilizados por nenhum container. Use com cuidado!

# Remover volumes órfãos
docker volume prune

# Sem confirmação
docker volume prune -f

Usando Volumes com Containers

-v (volume)Sintaxe curta

Monta um volume nomeado no container. Cria o volume automaticamente se não existir.

# Montar volume nomeado
docker run -d -v meu-volume:/app/data nginx

# Volume anônimo (Docker gera nome aleatório)
docker run -d -v /app/data nginx

# Volume somente-leitura
docker run -d -v meu-volume:/app/data:ro nginx
--mount (volume)Sintaxe explícita

Sintaxe mais verbosa e clara. Recomendada para scripts e documentação.

# Montar volume nomeado
docker run -d \
  --mount type=volume,source=meu-volume,target=/app/data \
  nginx

# Volume somente-leitura
docker run -d \
  --mount type=volume,source=meu-volume,target=/app/data,readonly \
  nginx

Demonstração de Persistência — MySQL

MySQL com VolumeExemplo prático

Dados do MySQL persistem mesmo após remover e recriar o container.

# Criar volume para dados do MySQL
docker volume create mysql-data

# Iniciar MySQL com volume
docker run -d \
  --name meu-mysql \
  -e MYSQL_ROOT_PASSWORD=senha123 \
  -e MYSQL_DATABASE=app_db \
  -v mysql-data:/var/lib/mysql \
  -p 3306:3306 \
  mysql:8.0

# Criar dados no banco
docker exec -it meu-mysql mysql -uroot -psenha123 -e \
  "CREATE TABLE app_db.users (id INT, name VARCHAR(50)); \
   INSERT INTO app_db.users VALUES (1, 'João');"

# Remover o container
docker rm -f meu-mysql

# Recriar — dados ainda estão lá!
docker run -d \
  --name meu-mysql \
  -e MYSQL_ROOT_PASSWORD=senha123 \
  -v mysql-data:/var/lib/mysql \
  -p 3306:3306 \
  mysql:8.0

# Verificar dados
docker exec -it meu-mysql mysql -uroot -psenha123 -e \
  "SELECT * FROM app_db.users;"
# → 1 | João ✓

Bind Mounts

Bind mounts mapeiam um diretório do host diretamente no container. Ideal para desenvolvimento — alterações no código são refletidas instantaneamente.

Linux / macOSBind Mount
# Montar diretório atual
docker run -d -v $(pwd):/app -p 3000:3000 node:20-alpine

# Caminho absoluto
docker run -d -v /home/user/projeto:/app nginx

# Somente-leitura
docker run -d -v $(pwd)/config:/etc/nginx/conf.d:ro nginx
Windows PowerShellBind Mount
# Montar diretório atual (PowerShell)
docker run -d -v ${PWD}:/app -p 3000:3000 node:20-alpine

# Caminho absoluto
docker run -d -v C:\Users\dev\projeto:/app nginx
Windows CMDBind Mount
# Montar diretório atual (CMD)
docker run -d -v %cd%:/app -p 3000:3000 node:20-alpine
--mount (bind)Sintaxe explícita

Sintaxe --mount para bind mounts. Falha se o diretório source não existir (mais seguro).

docker run -d \
  --mount type=bind,source=$(pwd)/src,target=/app/src \
  --mount type=bind,source=$(pwd)/config,target=/app/config,readonly \
  -p 3000:3000 \
  node:20-alpine

tmpfs — Armazenamento em Memória

--tmpfsMemória

Monta um filesystem temporário em RAM. Dados são perdidos ao parar o container. Ideal para dados sensíveis temporários.

# tmpfs simples
docker run -d --tmpfs /app/temp nginx

# Com --mount (mais opções)
docker run -d \
  --mount type=tmpfs,target=/app/temp,tmpfs-size=100m,tmpfs-mode=1770 \
  nginx

# Uso: cache de sessão, tokens temporários, dados sensíveis

Backup e Restauração de Volumes

Backuptar

Cria um arquivo tar com o conteúdo do volume usando um container auxiliar.

# Backup de volume para arquivo tar
docker run --rm \
  -v meu-volume:/data \
  -v $(pwd):/backup \
  alpine tar czf /backup/meu-volume-backup.tar.gz -C /data .

# Explicação:
# - Monta o volume em /data (leitura)
# - Monta diretório atual em /backup (escrita)
# - Cria tar.gz com conteúdo de /data
Restoretar

Restaura dados de um arquivo tar para um volume.

# Criar volume de destino
docker volume create meu-volume-restaurado

# Restaurar backup
docker run --rm \
  -v meu-volume-restaurado:/data \
  -v $(pwd):/backup \
  alpine tar xzf /backup/meu-volume-backup.tar.gz -C /data

# Verificar
docker run --rm -v meu-volume-restaurado:/data alpine ls -la /data

docker cp — Copiar Arquivos

docker cpCopiar

Copia arquivos entre o host e um container (em execução ou parado). Útil para debugging e extração de dados.

# Host → Container
docker cp ./config.json meu-container:/app/config.json
docker cp ./src/ meu-container:/app/src/

# Container → Host
docker cp meu-container:/app/logs/error.log ./error.log
docker cp meu-container:/var/log/ ./logs-extraidos/

# Funciona com container parado também
docker cp container-parado:/data/dump.sql ./backup.sql
