🐳 Docker — Módulo 05

Docker Compose

Orquestre múltiplos containers de forma declarativa, reproduzível e versionável. Defina toda a infraestrutura da sua aplicação em um único arquivo YAML.

O que é Docker Compose e Por que Usar

Orquestração Local conceito

Docker Compose é uma ferramenta para definir e executar aplicações multi-container. Com um único arquivo YAML você descreve todos os serviços, redes e volumes da sua aplicação.

# Vantagens principais:
# ✓ Declarativo — infraestrutura como código
# ✓ Reproduzível — mesmo resultado em qualquer máquina
# ✓ Versionável — arquivo YAML no Git
# ✓ Um comando — sobe toda a stack
# ✓ Isolamento — cada projeto em sua rede

Estrutura do docker-compose.yml

docker-compose.yml estrutura

Anatomia completa de um arquivo Compose com todas as diretivas principais.

services:
  nome-servico:
    image: imagem:tag           # Imagem do Docker Hub ou registry
    build:                      # OU build a partir de Dockerfile
      context: ./dir
      dockerfile: Dockerfile
      args:
        NODE_ENV: production
    container_name: meu-app     # Nome fixo do container
    ports:
      - "8080:80"               # host:container
      - "443:443"
    volumes:
      - ./src:/app/src          # Bind mount (dev)
      - dados:/var/lib/data     # Named volume (persistência)
    environment:
      - DB_HOST=postgres
      - DB_PORT=5432
    env_file:
      - .env                    # Variáveis de arquivo externo
    depends_on:
      - db
      - cache
    networks:
      - frontend
      - backend
    restart: unless-stopped     # Política de reinício

networks:
  frontend:
    driver: bridge
  backend:
    driver: bridge

volumes:
  dados:
    driver: local

Exemplo Completo: Web + API + DB + Cache

docker-compose.yml exemplo

Stack completa com frontend React, API Node.js, PostgreSQL e Redis.

services:
  web:
    build: ./frontend
    ports:
      - "3000:80"
    depends_on:
      - api
    networks:
      - frontend

  api:
    build: ./backend
    ports:
      - "4000:4000"
    environment:
      - DATABASE_URL=postgres://user:pass@db:5432/app
      - REDIS_URL=redis://cache:6379
    depends_on:
      db:
        condition: service_healthy
      cache:
        condition: service_started
    networks:
      - frontend
      - backend
    restart: unless-stopped

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: user
      POSTGRES_PASSWORD: pass
      POSTGRES_DB: app
    volumes:
      - pgdata:/var/lib/postgresql/data
    ports:
      - "5432:5432"
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U user"]
      interval: 10s
      timeout: 5s
      retries: 5
    networks:
      - backend

  cache:
    image: redis:7-alpine
    ports:
      - "6379:6379"
    volumes:
      - redisdata:/data
    networks:
      - backend

networks:
  frontend:
  backend:

volumes:
  pgdata:
  redisdata:

Comandos Essenciais

docker compose up iniciar

Cria e inicia todos os containers definidos no compose.

# Modo detached (background)
docker compose up -d

# Forçar rebuild das imagens
docker compose up --build

# Rebuild + detached
docker compose up -d --build

# Subir serviço específico
docker compose up -d api
docker compose down parar

Para e remove containers, redes criadas pelo compose.

# Parar e remover containers + redes
docker compose down

# Remover também os volumes
docker compose down -v

# Remover imagens locais criadas
docker compose down --rmi local

# Remover TODAS as imagens usadas
docker compose down --rmi all
docker compose ps status

Lista o status de todos os containers do projeto.

# Listar containers do projeto
docker compose ps

# Formato compacto
docker compose ps --format "table {{.Name}}\t{{.Status}}"

# Incluir containers parados
docker compose ps -a
docker compose logs debug

Visualiza logs dos containers do projeto.

# Logs de todos os serviços
docker compose logs

# Follow (tempo real)
docker compose logs -f

# Logs de serviço específico
docker compose logs -f api

# Últimas 50 linhas
docker compose logs --tail 50 api
docker compose stop/start/restart controle

Controla o ciclo de vida sem remover containers.

# Parar sem remover
docker compose stop

# Iniciar containers parados
docker compose start

# Reiniciar todos
docker compose restart

# Reiniciar serviço específico
docker compose restart api
docker compose exec executar

Executa comando em container já em execução.

# Shell interativo
docker compose exec api sh

# Comando direto
docker compose exec db psql -U user -d app

# Como root
docker compose exec -u root api sh
docker compose run executar

Cria container temporário para executar comando único.

# Executar e remover ao final
docker compose run --rm api npm test

# Executar migrations
docker compose run --rm api npx prisma migrate deploy

# Sem iniciar dependências
docker compose run --rm --no-deps api npm run lint
docker compose scale / build / pull gerenciar

Escalar réplicas, buildar imagens e baixar atualizações.

# Escalar serviço (múltiplas réplicas)
docker compose up -d --scale api=3

# Build sem iniciar
docker compose build

# Build sem cache
docker compose build --no-cache

# Baixar imagens atualizadas
docker compose pull

Recursos Avançados

depends_on + healthcheck dependência

Garanta que serviços só iniciem quando dependências estiverem saudáveis.

services:
  api:
    depends_on:
      db:
        condition: service_healthy
      cache:
        condition: service_started

  db:
    image: postgres:16-alpine
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U user"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 30s
.env + Variáveis config

Use arquivos .env para substituição de variáveis no compose.

# .env
POSTGRES_VERSION=16-alpine
APP_PORT=4000
DB_PASSWORD=supersecret

# docker-compose.yml
services:
  db:
    image: postgres:${POSTGRES_VERSION}
  api:
    ports:
      - "${APP_PORT}:4000"
    environment:
      - DB_PASS=${DB_PASSWORD}
Profiles avançado

Agrupe serviços em perfis para ativar sob demanda.

services:
  web:
    build: ./frontend
    # Sempre ativo (sem profile)

  debug:
    image: busybox
    profiles: ["debug"]

  monitoring:
    image: grafana/grafana
    profiles: ["monitoring"]

# Uso:
# docker compose up -d
# docker compose --profile debug up -d
# docker compose --profile monitoring up -d
Múltiplos Compose Files avançado

Combine arquivos para diferentes ambientes (override pattern).

# docker-compose.yml (base)
# docker-compose.override.yml (dev - auto-carregado)
# docker-compose.prod.yml (produção)

# Dev (carrega base + override automaticamente)
docker compose up -d

# Produção (especificar arquivos)
docker compose -f docker-compose.yml \
  -f docker-compose.prod.yml up -d

# Override desabilita volumes de dev
# e usa imagens do registry
Restart Policies resiliência

Defina como containers devem se comportar após falhas.

services:
  api:
    restart: "no"            # Nunca reinicia (padrão)

  web:
    restart: always          # Sempre reinicia

  worker:
    restart: on-failure      # Só se exit code != 0

  db:
    restart: unless-stopped  # Sempre, exceto se
                             # parado manualmente
Resource Limits recursos

Limite CPU e memória por serviço para evitar consumo excessivo.

services:
  api:
    deploy:
      resources:
        limits:
          cpus: "1.0"
          memory: 512M
        reservations:
          cpus: "0.25"
          memory: 128M

  worker:
    deploy:
      resources:
        limits:
          cpus: "2.0"
          memory: 1G
