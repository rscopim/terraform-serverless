Fundamentos

O que é Docker?

Docker é uma plataforma open-source que automatiza o deploy de aplicações dentro de containers — ambientes leves, portáteis e isolados que contêm tudo que a aplicação precisa para rodar.

Explicação simples

Imagine que você está mudando de casa. Você tem duas opções:

Sem Docker (VM)Analogia

É como levar a casa inteira com você — paredes, telhado, fundação, encanamento. Funciona, mas é pesado, lento e consome muitos recursos.

Com Docker (Container)Analogia

É como usar um container de mudança padronizado — você coloca apenas seus pertences dentro, e ele funciona em qualquer caminhão, navio ou trem. Leve, rápido e portátil.

💡 Em termos técnicos: Docker empacota sua aplicação + dependências + configurações em uma unidade padronizada (container) que roda de forma idêntica em qualquer lugar — seu notebook, um servidor na nuvem ou um cluster Kubernetes.

O problema que Docker resolve

Antes do Docker, desenvolvedores enfrentavam problemas constantes:

"Funciona na minha máquina"Problema

O desenvolvedor usa Python 3.11 no Mac, o servidor de produção tem Python 3.8 no Ubuntu. A aplicação quebra por incompatibilidade de versões, bibliotecas ausentes ou configurações diferentes.

# Dev: funciona perfeitamente
python3 app.py  # Python 3.11

# Prod: erro!
python3 app.py  # Python 3.8 → ModuleNotFoundError
Com Docker: consistência totalSolução

O container inclui a versão exata do Python, todas as bibliotecas e configurações. É idêntico em qualquer ambiente.

# Mesmo container em qualquer lugar:
docker run minha-app:v1.0

# Dev, staging, prod — comportamento idêntico

Docker vs Máquinas Virtuais — Entenda a diferença de verdade

Ambos oferecem isolamento, mas funcionam de formas fundamentalmente diferentes:

CaracterísticaMáquina VirtualContainer Docker
O que virtualizaHardware completo (CPU, RAM, disco, placa de rede)Apenas o espaço de usuário (filesystem, processos, rede)
Sistema OperacionalCada VM tem seu próprio SO completo (kernel + userland)Compartilha o kernel do host, cada container tem seu userland
TamanhoGBs (SO completo + aplicação)MBs (apenas aplicação + dependências)
Tempo de inicializaçãoMinutos (boot do SO)Segundos (apenas inicia o processo)
Overhead de recursosAlto (cada VM reserva RAM e CPU)Mínimo (compartilha recursos do host)
IsolamentoForte (hardware virtualizado)Bom (namespaces + cgroups do kernel)
PortabilidadeLimitada (formato de VM varia)Total (imagem OCI funciona em qualquer runtime)
Densidade~10 VMs por servidor~100+ containers por servidor
Quando usar cada um? 
VM  → Precisa de SO diferente do host (ex: Windows no Linux)
VM  → Requer isolamento máximo (compliance, multi-tenant hostil)
VM  → Aplicações legadas que precisam de kernel específico

Container → Microserviços e aplicações modernas
Container → CI/CD e ambientes de desenvolvimento
Container → Escalabilidade horizontal rápida
Container → 95% dos casos de uso atuais

Como Docker funciona por dentro

Docker usa três tecnologias do kernel Linux para criar o isolamento:

NamespacesIsolamento

Criam visões isoladas dos recursos do sistema. Cada container "pensa" que é o único no servidor.

# Namespaces usados pelo Docker:
PID  → Processos isolados (PID 1 dentro do container)
NET  → Rede isolada (IP próprio, portas próprias)
MNT  → Filesystem isolado (não vê arquivos do host)
UTS  → Hostname próprio
IPC  → Comunicação inter-processos isolada
USER → Usuários isolados (root no container ≠ root no host)
cgroupsRecursos

Limitam e contabilizam o uso de recursos (CPU, memória, I/O) por container. Impede que um container "devore" todos os recursos do host.

# Exemplo: limitar container a 512MB e 0.5 CPU
docker run --memory=512m --cpus=0.5 nginx

# Sem cgroups: um container com memory leak
# derrubaria todo o servidor
UnionFS (OverlayFS)Storage

Sistema de arquivos em camadas que permite que imagens Docker sejam eficientes. Cada instrução no Dockerfile cria uma camada somente-leitura. O container adiciona uma camada de escrita no topo.

# Imagem = camadas somente-leitura empilhadas:
┌─────────────────────────────────┐
│  Camada 5: COPY app.py /app/    │  ← Seu código
├─────────────────────────────────┤
│  Camada 4: RUN pip install ...  │  ← Dependências
├─────────────────────────────────┤
│  Camada 3: RUN apt-get update   │  ← Pacotes do SO
├─────────────────────────────────┤
│  Camada 2: ENV PYTHON=3.12      │  ← Configuração
├─────────────────────────────────┤
│  Camada 1: FROM python:3.12     │  ← Imagem base
└─────────────────────────────────┘

# Container = imagem + camada de escrita no topo:
┌─────────────────────────────────┐
│  Camada RW: logs, temp files    │  ← Escrita do container
├─────────────────────────────────┤
│  Imagem (somente-leitura)       │  ← Compartilhada entre containers
└─────────────────────────────────┘
💡 Por que isso importa na prática? Se você tem 10 containers rodando a mesma imagem base, o disco armazena a imagem uma única vez. Cada container adiciona apenas sua camada de escrita (poucos KB/MB). Isso é drasticamente mais eficiente que 10 VMs com 10 cópias do SO.
Arquitetura

Arquitetura do Docker — Client, Daemon e Registry

Docker usa uma arquitetura cliente-servidor. Entender cada componente é essencial para diagnosticar problemas e usar Docker de forma eficiente.

Os 3 componentes principais

Docker Client (CLI)Interface

É o comando docker que você digita no terminal. Ele não executa nada — apenas envia instruções para o Docker Daemon via API REST.

# Você digita:
docker run nginx

# O Client traduz isso em uma chamada API:
POST /containers/create {"Image": "nginx"}
POST /containers/{id}/start
Docker Daemon (dockerd)Engine

O processo que realmente faz o trabalho — cria containers, gerencia imagens, configura redes e volumes. Roda como serviço em background.

# Verificar se o daemon está rodando:
sudo systemctl status docker

# O daemon escuta em:
# Unix socket: /var/run/docker.sock (local)
# TCP: tcp://0.0.0.0:2376 (remoto, com TLS)
Docker RegistryArmazenamento

Repositório centralizado de imagens. O Docker Hub é o registry público padrão. Empresas usam registries privados (AWS ECR, GitHub Container Registry, Harbor).

# Baixar imagem do Docker Hub:
docker pull nginx:latest

# Baixar de registry privado (AWS ECR):
docker pull 123456789.dkr.ecr.us-east-1.amazonaws.com/minha-app:v1

# Registries populares:
# - Docker Hub (hub.docker.com) → público
# - AWS ECR → privado na AWS
# - GitHub ghcr.io → privado no GitHub
# - Harbor → self-hosted
Fluxo completo de um docker run: 
1. Você digita: docker run -d -p 80:80 nginx
2. Docker Client → envia comando ao Daemon via socket
3. Daemon verifica se imagem "nginx" existe localmente
4. Se não existe → Daemon faz pull do Docker Hub (Registry)
5. Daemon cria container: namespaces + cgroups + overlayfs
6. Daemon configura rede: bridge network + port mapping (80→80)
7. Daemon inicia o processo principal (nginx master)
8. Container está rodando → Client exibe o container ID

Conceitos-chave — Glossário completo

ConceitoO que éAnalogia
ImagemTemplate somente-leitura com filesystem e configurações. Definida por um Dockerfile.É a "receita" — não muda depois de pronta
ContainerInstância em execução de uma imagem. Tem estado, pode ser parado e removido.É o "bolo" feito a partir da receita
DockerfileArquivo texto com instruções sequenciais para construir uma imagem.É o "passo a passo" da receita
Layer (Camada)Cada instrução do Dockerfile gera uma camada. Camadas são cacheáveis e reutilizáveis.Cada ingrediente adicionado à receita
RegistryRepositório remoto de imagens. Permite compartilhar e versionar.É a "livraria de receitas" online
TagRótulo de versão de uma imagem (ex: nginx:1.25, python:3.12-slim).É a "edição" do livro de receitas
VolumeArmazenamento persistente independente do ciclo de vida do container.É um "HD externo" plugado no container
NetworkRede virtual para comunicação entre containers.É o "cabo de rede" ligando os containers
Port MappingRedireciona uma porta do host para uma porta dentro do container.É a "recepção" que encaminha visitantes à sala correta
Instalação

Instalação do Docker — Passo a Passo

Instruções completas para Linux (Ubuntu/Debian), Windows e macOS. Siga exatamente a ordem dos comandos.

Linux — Ubuntu / Debian (Método Oficial)

Nunca instale Docker via apt install docker.io — essa versão é desatualizada. Use sempre o repositório oficial do Docker:

Passo 1: Remover versões antigasLimpeza

Remove qualquer instalação anterior que possa conflitar.

sudo apt-get remove -y docker docker-engine docker.io containerd runc 2>/dev/null
sudo apt-get autoremove -y
Passo 2: Instalar dependênciasPré-requisitos

Pacotes necessários para adicionar o repositório Docker com HTTPS.

sudo apt-get update
sudo apt-get install -y \
  ca-certificates \
  curl \
  gnupg \
  lsb-release
Passo 3: Adicionar chave GPGSegurança

A chave GPG garante que os pacotes baixados são autênticos e não foram adulterados.

sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | \
  sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg
Passo 4: Adicionar repositórioAPT Source

Configura o APT para buscar Docker diretamente do repositório oficial.

echo \
  "deb [arch=$(dpkg --print-architecture) \
  signed-by=/etc/apt/keyrings/docker.gpg] \
  https://download.docker.com/linux/ubuntu \
  $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
Passo 5: Instalar Docker EngineInstalação

Instala o Docker Engine, CLI, containerd e plugins (Buildx + Compose).

sudo apt-get update
sudo apt-get install -y \
  docker-ce \
  docker-ce-cli \
  containerd.io \
  docker-buildx-plugin \
  docker-compose-plugin
Passo 6: Configurar para uso sem sudoPós-instalação

Adiciona seu usuário ao grupo docker. Sem isso, todo comando docker precisa de sudo.

# Adicionar usuário ao grupo docker
sudo usermod -aG docker $USER

# Aplicar mudança (ou faça logout/login)
newgrp docker

# Testar sem sudo:
docker run hello-world
⚠️ Segurança: Adicionar um usuário ao grupo docker é equivalente a dar acesso root ao sistema. O Docker daemon roda como root e quem tem acesso ao socket pode criar containers privilegiados. Em produção, use rootless Docker ou controle rigorosamente quem está no grupo.

Prática

Primeiros Comandos — Mão na massa

Agora que Docker está instalado, vamos executar containers reais e entender cada comando em detalhe.

Ciclo de vida de um container

Entenda o fluxo: 
docker pull   → Baixa imagem do registry
docker run    → Cria + inicia container (faz pull se necessário)
docker stop   → Para o container (SIGTERM → SIGKILL após 10s)
docker start  → Reinicia container parado
docker rm     → Remove container parado
docker rmi    → Remove imagem local

docker run — O comando mais importante

docker run é o comando que você mais usará. Ele combina create + start em um único passo.

Execução básicaForeground

Executa e mostra a saída no terminal. Ctrl+C para parar.

# Rodar Nginx e ver logs no terminal
docker run nginx

# O terminal fica "preso" — é foreground mode
# Ctrl+C para parar o container
Execução em background (-d)Detached

Executa em segundo plano. Libera o terminal imediatamente.

# -d = detached (background)
docker run -d nginx

# Retorna apenas o container ID:
# a1b2c3d4e5f6...

# Você pode continuar usando o terminal normalmente
Mapeamento de portas (-p)Networking

Sem -p, o container é inacessível de fora. O -p cria um redirecionamento: porta do host → porta do container.

# Formato: -p HOST:CONTAINER
docker run -d -p 8080:80 nginx

# Agora acesse http://localhost:8080
# O tráfego na porta 8080 do host
# é redirecionado para porta 80 do container

# Mapear múltiplas portas:
docker run -d -p 3000:3000 -p 3001:3001 minha-app
Nomeando containers (--name)Organização

Sem --name, Docker gera nomes aleatórios. Nomeie para facilitar gerenciamento.

# Sem nome: boring_keller, angry_einstein...
docker run -d nginx

# Com nome: fácil de referenciar
docker run -d --name meu-nginx -p 80:80 nginx

# Agora você pode usar o nome:
docker stop meu-nginx
docker start meu-nginx
docker logs meu-nginx
Variáveis de ambiente (-e)Configuração

Passa configurações para dentro do container sem alterar a imagem. Padrão de 12-Factor Apps.

# Passar variáveis individuais:
docker run -d \
  --name meu-postgres \
  -e POSTGRES_USER=admin \
  -e POSTGRES_PASSWORD=secret123 \
  -e POSTGRES_DB=meubanco \
  -p 5432:5432 \
  postgres:16

# A aplicação dentro do container lê essas variáveis
# para se configurar automaticamente
Modo interativo (-it)Shell

Abre um terminal dentro do container. Útil para debug e exploração.

# -i = interactive (mantém stdin aberto)
# -t = tty (aloca pseudo-terminal)
docker run -it ubuntu:22.04 bash

# Agora você está DENTRO do container:
root@a1b2c3d4:/# whoami
root
root@a1b2c3d4:/# cat /etc/os-release
# Ubuntu 22.04
root@a1b2c3d4:/# exit
# Voltou ao host
Remoção automática (--rm)Limpeza

Remove o container automaticamente quando ele para. Evita acúmulo de containers parados.

# Container é removido ao encerrar:
docker run --rm -it python:3.12 python -c "print('Hello!')"

# Útil para: testes rápidos, scripts one-shot,
# comandos únicos, builds temporários

Gerenciando containers em execução

docker psListar

Lista containers em execução. Use -a para incluir parados.

# Apenas rodando:
docker ps

# Todos (incluindo parados):
docker ps -a

# Formato compacto (apenas IDs):
docker ps -q

# Saída formatada:
docker ps --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}"
docker logsDebug

Mostra a saída do container (stdout + stderr). Essencial para debugging.

# Todos os logs:
docker logs meu-nginx

# Últimas 50 linhas:
docker logs --tail 50 meu-nginx

# Acompanhar em tempo real (como tail -f):
docker logs -f meu-nginx

# Com timestamps:
docker logs -t meu-nginx
docker execAcessar

Executa um comando dentro de um container já em execução. Diferente de run que cria um novo.

# Abrir bash dentro de container rodando:
docker exec -it meu-nginx bash

# Executar comando único:
docker exec meu-nginx cat /etc/nginx/nginx.conf

# Ver processos dentro do container:
docker exec meu-nginx ps aux
docker stop / killParar

stop = gracioso (SIGTERM, espera 10s, SIGKILL). kill = imediato (SIGKILL).

# Parar graciosamente (recomendado):
docker stop meu-nginx

# Forçar parada imediata:
docker kill meu-nginx

# Parar todos os containers de uma vez:
docker stop $(docker ps -q)

# Reiniciar:
docker restart meu-nginx
docker rm / pruneLimpar

Remove containers parados. prune remove todos de uma vez.

# Remover container específico:
docker rm meu-nginx

# Remover forçando (mesmo rodando):
docker rm -f meu-nginx

# Remover TODOS os containers parados:
docker container prune

# Limpeza total (containers + imagens + volumes + redes):
docker system prune -a --volumes
# ⚠️ CUIDADO: remove tudo que não está em uso!
docker inspectDetalhes

Mostra TUDO sobre um container: configuração, rede, volumes, variáveis, estado.

# JSON completo:
docker inspect meu-nginx

# Pegar apenas o IP do container:
docker inspect -f '{{range.NetworkSettings.Networks}}{{.IPAddress}}{{end}}' meu-nginx

# Ver variáveis de ambiente:
docker inspect -f '{{.Config.Env}}' meu-nginx
Exercícios

Exercícios Práticos — Consolide seu aprendizado

Execute cada exercício no seu terminal. A prática é essencial para fixar os conceitos.

Exercício 1: Servidor Web

  1. Execute um Nginx em background na porta 8080
  2. Acesse http://localhost:8080 no navegador
  3. Veja os logs do container
  4. Pare e remova o container
docker run -d --name web -p 8080:80 nginx
curl http://localhost:8080
docker logs web
docker stop web && docker rm web

Exercício 2: Banco de Dados

  1. Execute um PostgreSQL com senha definida
  2. Conecte-se ao banco via docker exec
  3. Crie uma tabela e insira um registro
  4. Pare o container e observe que os dados se perdem
docker run -d --name db \
  -e POSTGRES_PASSWORD=secret \
  -p 5432:5432 postgres:16

docker exec -it db psql -U postgres -c \
  "CREATE TABLE teste(id serial, nome text);
   INSERT INTO teste(nome) VALUES('Docker');"

docker stop db && docker rm db
# Dados perdidos! (Módulo 03 ensina volumes)

Exercício 3: Explorar um Container

  1. Execute um Ubuntu interativo
  2. Instale o curl dentro do container
  3. Faça uma requisição HTTP
  4. Observe que as alterações somem ao remover
docker run -it --rm ubuntu:22.04 bash

# Dentro do container:
apt-get update && apt-get install -y curl
curl https://ifconfig.me  # Mostra IP do container
exit  # Container removido automaticamente (--rm)

Exercício 4: Múltiplos Containers

  1. Execute 3 containers Nginx com nomes diferentes
  2. Liste todos com docker ps
  3. Pare todos de uma vez
  4. Remova todos de uma vez
docker run -d --name web1 -p 8081:80 nginx
docker run -d --name web2 -p 8082:80 nginx
docker run -d --name web3 -p 8083:80 nginx

docker ps  # 3 containers rodando

docker stop web1 web2 web3
docker rm web1 web2 web3
🎯 Dica de ouro: Sempre use --name e --rm em containers de teste. O --name facilita gerenciar, e o --rm evita acúmulo de containers parados ocupando disco.
Boas Práticas

Boas Práticas desde o Dia 1

Hábitos que vão te diferenciar como profissional desde o início.

Sempre nomeie containersOrganização

Containers sem nome geram nomes aleatórios que são impossíveis de lembrar. Use --name sempre.

Nunca use :latest em produçãoVersionamento

A tag :latest muda sem aviso. Use versões específicas: nginx:1.25, python:3.12-slim.

Limpe regularmenteManutenção

Imagens e containers acumulam e ocupam GBs. Execute docker system prune semanalmente.

Use imagens oficiaisSegurança

Prefira imagens com selo "Official" no Docker Hub. São mantidas, auditadas e atualizadas regularmente.

Prefira imagens slim/alpinePerformance

python:3.12 = 1GB. python:3.12-slim = 150MB. python:3.12-alpine = 50MB. Menos superfície de ataque.

Um processo por containerArquitetura

Cada container deve rodar apenas um processo principal. Banco separado do app. Nginx separado do PHP.
