Otimização, Segurança e Boas Práticas

Construa imagens menores, mais seguras e eficientes. Domine multi-stage builds, hardening de containers e monitoramento de recursos.

Multi-stage Build

Conceito otimização

Multi-stage build usa múltiplos FROM no mesmo Dockerfile. Cada estágio pode copiar artefatos do anterior, resultando em imagens finais muito menores — sem ferramentas de build, sem código-fonte, apenas o binário/artefato necessário.

# Benefícios:
# ✓ Imagem final contém APENAS o necessário para execução
# ✓ Ferramentas de build ficam no estágio intermediário
# ✓ Redução drástica de tamanho (ex: Go 1.2GB → 10MB)
# ✓ Menor superfície de ataque
# ✓ Um único Dockerfile para build + runtime
Node.js Multi-stage exemplo

Build com dependências de dev, runtime apenas com produção.

# Estágio 1: Build
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# Estágio 2: Runtime
FROM node:20-alpine AS runtime
WORKDIR /app
COPY package*.json ./
RUN npm ci --only=production
COPY --from=builder /app/dist ./dist
EXPOSE 3000
USER node
CMD ["node", "dist/server.js"]
Go com scratch (~10MB) exemplo

Compilação estática em Go resulta em imagem mínima com scratch.

# Estágio 1: Compilação
FROM golang:1.22-alpine AS builder
WORKDIR /app
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 GOOS=linux \
    go build -ldflags="-s -w" \
    -o /app/server ./cmd/main.go

# Estágio 2: Imagem mínima
FROM scratch
COPY --from=builder /app/server /server
COPY --from=builder /etc/ssl/certs/ca-certificates.crt \
     /etc/ssl/certs/
EXPOSE 8080
ENTRYPOINT ["/server"]
# Resultado: ~10MB!
React + Nginx exemplo

Build do React no Node, serve estático com Nginx.

# Estágio 1: Build React
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# Estágio 2: Nginx serve os estáticos
FROM nginx:alpine
COPY --from=builder /app/build /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
# Resultado: ~25MB

Otimização de Cache e Layers

Ordem das Layers cache

A ordem importa! Coloque o que muda menos primeiro para maximizar cache hits.

# ❌ RUIM — qualquer mudança no código
# invalida cache do npm install
COPY . .
RUN npm install

# ✅ BOM — package.json muda raramente
# npm install usa cache na maioria dos builds
COPY package*.json ./
RUN npm ci
COPY . .
Combine RUN + Alpine cache

Reduza layers combinando comandos e use imagens Alpine.

# ❌ RUIM — 3 layers, cache de apt desnecessário
RUN apt-get update
RUN apt-get install -y curl
RUN rm -rf /var/lib/apt/lists/*

# ✅ BOM — 1 layer, limpa cache
RUN apt-get update && \
    apt-get install -y --no-install-recommends \
      curl ca-certificates && \
    rm -rf /var/lib/apt/lists/*

# ✅ MELHOR — use Alpine (5MB base)
FROM node:20-alpine
# Alpine usa apk ao invés de apt

Segurança de Containers

Usuário não-root segurança

Nunca execute containers como root em produção. Crie um usuário dedicado.

# Criar grupo e usuário sem privilégios
RUN addgroup -S appgroup && \
    adduser -S appuser -G appgroup

# Copiar arquivos com ownership correto
COPY --chown=appuser:appgroup . /app

# Mudar para usuário não-root
USER appuser

# Verificar: docker exec container whoami
# Resultado: appuser (não root!)
Vulnerability Scanning segurança

Escaneie imagens para vulnerabilidades conhecidas antes de deploy.

# Docker Scout (integrado ao Docker Desktop)
docker scout cves minha-imagem:latest
docker scout recommendations minha-imagem:latest

# Trivy (open source, CI/CD friendly)
trivy image minha-imagem:latest
trivy image --severity HIGH,CRITICAL app:v1
trivy image --exit-code 1 app:v1  # Falha no CI

# Snyk
docker scan minha-imagem:latest
Boas Práticas de Segurança segurança

Checklist de segurança para imagens e containers em produção.

# ✓ Use tags específicas (NUNCA :latest)
FROM node:20.11.0-alpine

# ✓ Não coloque secrets na imagem
# Use env vars ou secrets manager

# ✓ Filesystem read-only
docker run --read-only app:v1

# ✓ Drop ALL capabilities
docker run --cap-drop ALL app:v1

# ✓ Nunca monte o Docker socket
# ❌ -v /var/run/docker.sock:/var/run/docker.sock

# ✓ Docker Content Trust (assinatura)
export DOCKER_CONTENT_TRUST=1
docker pull nginx  # Verifica assinatura
Runtime Hardening segurança

Restrições adicionais ao executar containers.

# Combinação completa de segurança
docker run -d \
  --name app-secure \
  --read-only \
  --cap-drop ALL \
  --cap-add NET_BIND_SERVICE \
  --security-opt no-new-privileges \
  --tmpfs /tmp:rw,noexec,nosuid \
  --memory 256m \
  --cpus 0.5 \
  --pids-limit 100 \
  --user 1000:1000 \
  app:v1

Monitoramento e Debug

docker stats monitorar

Monitore CPU, memória, rede e I/O em tempo real.

# Tempo real (atualiza a cada segundo)
docker stats

# Snapshot único (para scripts)
docker stats --no-stream

# Container específico
docker stats meu-app

# Formato customizado
docker stats --format \
  "table {{.Name}}\t{{.CPUPerc}}\t{{.MemUsage}}"
docker system df disco

Verifique uso de disco por tipo de objeto Docker.

# Resumo de uso de disco
docker system df

# Detalhado por objeto
docker system df -v

# Saída exemplo:
# TYPE          TOTAL   ACTIVE  SIZE    RECLAIMABLE
# Images        15      5       4.2GB   2.8GB (66%)
# Containers    8       3       120MB   85MB (70%)
# Volumes       12      4       1.5GB   900MB (60%)
# Build Cache   -       -       2.1GB   2.1GB
docker system prune limpeza

Limpe recursos não utilizados para liberar espaço.

# Limpar containers parados + imagens dangling
docker system prune

# Limpar TUDO não utilizado (cuidado!)
docker system prune -a

# Incluir volumes (dados persistentes!)
docker system prune -a --volumes

# Sem confirmação (scripts)
docker system prune -af
docker events / top / diff debug

Ferramentas avançadas de debug e inspeção.

# Eventos em tempo real do daemon
docker events
docker events --filter type=container

# Processos dentro do container
docker top meu-app
docker top meu-app aux

# Mudanças no filesystem do container
docker diff meu-app
# A = adicionado, C = modificado, D = deletado

# Salvar estado atual como nova imagem
docker commit meu-app debug-snapshot:v1

# Exportar filesystem como tar
docker export meu-app > app-fs.tar
Resource Limits recursos

Limite recursos para evitar que um container consuma toda a máquina.

# Limite de memória (container é killed se exceder)
docker run --memory 512m --memory-swap 1g app:v1

# Limite de CPU
docker run --cpus 1.5 app:v1          # 1.5 cores
docker run --cpu-shares 512 app:v1     # Peso relativo

# Limite de I/O de disco
docker run --device-read-bps /dev/sda:10mb app:v1
docker run --device-write-bps /dev/sda:5mb app:v1

# Verificar limites aplicados
docker inspect --format '{{.HostConfig.Memory}}' meu-app
docker stats --no-stream meu-app
