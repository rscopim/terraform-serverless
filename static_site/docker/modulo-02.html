🐳 Docker — Módulo 02

Imagens e Dockerfile

Domine o gerenciamento de imagens Docker e aprenda a construir imagens customizadas com Dockerfile — a base para containerizar qualquer aplicação.

O que é uma Imagem Docker?

Uma imagem Docker é um pacote somente-leitura composto por camadas (layers). Cada instrução no Dockerfile cria uma nova camada. Camadas são compartilhadas entre imagens, economizando espaço e acelerando downloads.

Cache de camadas: O Docker reutiliza camadas que não mudaram. Se você alterar apenas a última instrução do Dockerfile, todas as camadas anteriores vêm do cache — tornando builds subsequentes muito mais rápidos.

Comandos para Gerenciar Imagens

docker imagesListar

Lista todas as imagens locais com tamanho, tag e ID.

# Listar imagens
docker images

# Filtrar por nome
docker images nginx

# Mostrar apenas IDs
docker images -q
docker pullBaixar

Baixa uma imagem do registry (Docker Hub por padrão).

# Baixar última versão
docker pull nginx

# Baixar versão específica
docker pull nginx:1.25-alpine

# Baixar de registry privado
docker pull meu-registry.com/app:v2.0
docker rmiRemover

Remove imagens locais. Falha se houver containers usando a imagem.

# Remover imagem
docker rmi nginx:1.25-alpine

# Forçar remoção
docker rmi -f nginx

# Remover imagens sem tag (dangling)
docker image prune

# Remover TODAS as imagens não utilizadas
docker image prune -a
docker tagTaguear

Cria uma nova tag (alias) para uma imagem existente.

# Taguear para push
docker tag minha-app:latest meu-user/minha-app:v1.0

# Taguear para registry privado
docker tag minha-app:latest 123456789.dkr.ecr.us-east-1.amazonaws.com/minha-app:v1.0
docker pushEnviar

Envia uma imagem local para um registry remoto.

# Login no Docker Hub
docker login

# Push para Docker Hub
docker push meu-user/minha-app:v1.0

# Push para ECR (AWS)
docker push 123456789.dkr.ecr.us-east-1.amazonaws.com/minha-app:v1.0
docker historyHistórico

Mostra as camadas de uma imagem e os comandos que as criaram.

# Ver camadas da imagem
docker history nginx

# Sem truncar comandos
docker history --no-trunc nginx

Estrutura do Dockerfile

O Dockerfile é um arquivo de texto com instruções sequenciais para construir uma imagem. Cada instrução cria uma camada.

FROMObrigatório

Define a imagem base. Sempre é a primeira instrução.

FROM node:20-alpine
FROM python:3.12-slim
FROM ubuntu:22.04
FROM scratch  # imagem vazia
WORKDIRDiretório

Define o diretório de trabalho para instruções subsequentes (RUN, CMD, COPY, etc.).

WORKDIR /app
# Cria o diretório se não existir
COPYCopiar

Copia arquivos/diretórios do contexto de build para a imagem.

# Copiar arquivo específico
COPY package.json .

# Copiar tudo
COPY . .

# Copiar com permissões
COPY --chown=node:node . .
ADDAdicionar

Similar ao COPY, mas também extrai arquivos .tar e aceita URLs. Prefira COPY na maioria dos casos.

# Extrair tar automaticamente
ADD app.tar.gz /app/

# Baixar de URL (evite — prefira curl no RUN)
ADD https://example.com/file.txt /app/
RUNExecutar

Executa comandos durante o build. Cada RUN cria uma nova camada.

# Instalar dependências
RUN apt-get update && apt-get install -y \
    curl \
    vim \
  && rm -rf /var/lib/apt/lists/*

# Instalar pacotes Node.js
RUN npm ci --only=production
CMDComando padrão

Define o comando padrão ao iniciar o container. Pode ser sobrescrito no docker run.

# Forma exec (recomendada)
CMD ["node", "server.js"]

# Forma shell
CMD npm start
ENTRYPOINTPonto de entrada

Define o executável principal do container. Não é facilmente sobrescrito.

# Container como executável
ENTRYPOINT ["python", "app.py"]

# Combinado com CMD (args padrão)
ENTRYPOINT ["python", "app.py"]
CMD ["--port", "8000"]
EXPOSEPorta

Documenta a porta que o container escuta. Não publica a porta — é apenas metadata.

EXPOSE 3000
EXPOSE 8080/tcp
EXPOSE 8443/udp
ENVVariável

Define variáveis de ambiente disponíveis no build E no container em execução.

ENV NODE_ENV=production
ENV PORT=3000
ENV APP_HOME=/app
ARGBuild arg

Define variáveis disponíveis apenas durante o build. Não persiste no container final.

ARG NODE_VERSION=20
FROM node:${NODE_VERSION}-alpine

ARG BUILD_DATE
LABEL build-date=$BUILD_DATE
VOLUMEVolume

Cria um ponto de montagem para dados persistentes.

VOLUME /data
VOLUME ["/var/log", "/data"]
USERSegurança

Define o usuário para executar instruções subsequentes e o container. Evite rodar como root.

# Criar e usar usuário não-root
RUN addgroup -S appgroup && adduser -S appuser -G appgroup
USER appuser
LABELMetadata

Adiciona metadados à imagem (autor, versão, descrição).

LABEL maintainer="dev@example.com"
LABEL version="1.0"
LABEL description="API de pagamentos"
HEALTHCHECKSaúde

Define como verificar se o container está saudável.

HEALTHCHECK --interval=30s --timeout=10s --start-period=5s --retries=3 \
  CMD curl -f http://localhost:3000/health || exit 1

ENTRYPOINT vs CMD

AspectoCMDENTRYPOINT
Sobrescrito porArgumentos no docker runFlag --entrypoint
Uso típicoArgumentos padrãoExecutável principal
CombinaçãoENTRYPOINT define o comando, CMD define argumentos padrão
Exemplo combinadoPadrão
ENTRYPOINT ["python", "manage.py"]
CMD ["runserver", "0.0.0.0:8000"]

# docker run app → python manage.py runserver 0.0.0.0:8000
# docker run app migrate → python manage.py migrate

ARG vs ENV

AspectoARGENV
Disponível no build✅ Sim✅ Sim
Disponível no container❌ Não✅ Sim
Definido via CLI--build-arg-e no run
Persiste na imagem❌ Não✅ Sim

HEALTHCHECK — Exemplo Completo

HEALTHCHECKMonitoramento

O Docker verifica periodicamente a saúde do container. Status: healthy, unhealthy, starting.

FROM node:20-alpine
WORKDIR /app
COPY . .
RUN npm ci --only=production
EXPOSE 3000

HEALTHCHECK --interval=30s \
  --timeout=10s \
  --start-period=10s \
  --retries=3 \
  CMD wget --no-verbose --tries=1 --spider http://localhost:3000/health || exit 1

CMD ["node", "server.js"]

USER — Segurança com Usuário Não-Root

USERSegurança

Nunca execute containers como root em produção. Crie um usuário dedicado.

FROM node:20-alpine

# Criar usuário não-root
RUN addgroup -S appgroup && \
    adduser -S appuser -G appgroup

WORKDIR /app
COPY --chown=appuser:appgroup . .
RUN npm ci --only=production

# Trocar para usuário não-root
USER appuser

EXPOSE 3000
CMD ["node", "server.js"]

docker build — Construir Imagens

docker buildBuild

Constrói uma imagem a partir de um Dockerfile e um contexto de build.

# Build básico (Dockerfile no diretório atual)
docker build -t minha-app:v1.0 .

# Especificar Dockerfile diferente
docker build -f Dockerfile.prod -t minha-app:prod .

# Passar build arguments
docker build --build-arg NODE_VERSION=20 -t minha-app .

# Build sem cache (forçar rebuild completo)
docker build --no-cache -t minha-app .

# Ver output detalhado do build
docker build --progress=plain -t minha-app .

# Múltiplas tags
docker build -t minha-app:latest -t minha-app:v1.0 .

.git/
.gitignore

.idea/
*.swp

Exemplo Completo — Dockerfile Node.js

DockerfileNode.js
# Imagem base leve
FROM node:20-alpine

# Metadados
LABEL maintainer="dev@example.com"
LABEL version="1.0"

# Criar usuário não-root
RUN addgroup -S appgroup && adduser -S appuser -G appgroup

# Diretório de trabalho
WORKDIR /app

# Copiar apenas package files primeiro (cache de dependências)
COPY package.json package-lock.json ./

# Instalar dependências
RUN npm ci --only=production && npm cache clean --force

# Copiar código da aplicação
COPY --chown=appuser:appgroup . .

# Variáveis de ambiente
ENV NODE_ENV=production
ENV PORT=3000

# Trocar para usuário não-root
USER appuser

# Documentar porta
EXPOSE 3000

# Health check
HEALTHCHECK --interval=30s --timeout=10s --retries=3 \
  CMD wget --no-verbose --tries=1 --spider http://localhost:3000/health || exit 1

# Comando de inicialização
CMD ["node", "server.js"]

Exemplo Completo — Dockerfile Python

DockerfilePython
# Imagem base slim
FROM python:3.12-slim

# Metadados
LABEL maintainer="dev@example.com"

# Evitar criação de .pyc e buffering
ENV PYTHONDONTWRITEBYTECODE=1
ENV PYTHONUNBUFFERED=1

# Instalar dependências do sistema
RUN apt-get update && apt-get install -y --no-install-recommends \
    curl \
  && rm -rf /var/lib/apt/lists/*

# Criar usuário não-root
RUN groupadd -r appgroup && useradd -r -g appgroup appuser

# Diretório de trabalho
WORKDIR /app

# Copiar e instalar dependências Python
COPY requirements.txt .
RUN pip install --no-cache-dir --upgrade pip && \
    pip install --no-cache-dir -r requirements.txt

# Copiar código
COPY --chown=appuser:appgroup . .

# Trocar para usuário não-root
USER appuser

# Porta
EXPOSE 8000

# Health check
HEALTHCHECK --interval=30s --timeout=10s --retries=3 \
  CMD curl -f http://localhost:8000/health || exit 1

# Iniciar aplicação
ENTRYPOINT ["python"]
CMD ["app.py", "--host", "0.0.0.0", "--port", "8000"]
