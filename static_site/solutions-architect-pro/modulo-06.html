Árvores de Decisão

Escolha de Banco de DadosDecisão
Precisa de SQL/relacional?
├── Sim → Precisa de alta performance/escala?
│   ├── Sim → Aurora (MySQL/PostgreSQL)
│   └── Não → RDS (MySQL, PostgreSQL, Oracle, SQL Server)
└── Não → Que tipo de dados?
    ├── Key-value, alta escala → DynamoDB
    ├── Grafos/relações → Neptune
    ├── Time-series → Timestream
    ├── Ledger/imutável → QLDB
    ├── Wide-column (Cassandra) → Keyspaces
    ├── Document (MongoDB) → DocumentDB
    └── Cache/session → ElastiCache Redis

Precisa de data warehouse?
└── Sim → Redshift (ou Athena para ad-hoc)
Escolha de ComputeDecisão
Duração da execução?
├── <15 min, event-driven → Lambda
├── Longa duração, stateless → Containers (ECS/EKS + Fargate)
└── Longa duração, stateful → EC2

Precisa gerenciar infraestrutura?
├── Não → Fargate (containers) ou Lambda (functions)
└── Sim → EC2 ou ECS/EKS com EC2 launch type

Já usa Kubernetes?
├── Sim → EKS
└── Não → ECS (mais simples, AWS-native)

Batch processing?
├── Tolerante a interrupção → Spot Instances
├── Jobs em lote → AWS Batch
└── Big data → EMR
Escolha de ConectividadeDecisão
Conectar on-premises → AWS?
├── Precisa de baixa latência consistente?
│   ├── Sim → Direct Connect
│   └── Não → Site-to-Site VPN
├── Backup do Direct Connect?
│   └── VPN como failover
└── Usuários remotos (laptops)?
    └── Client VPN

Conectar VPCs entre si?
├── 2-3 VPCs, sem transitividade → VPC Peering
├── 5+ VPCs ou transitividade → Transit Gateway
└── Rede global complexa → Cloud WAN

Acessar serviços AWS sem internet?
├── S3 ou DynamoDB → Gateway Endpoint (grátis)
└── Outros serviços → Interface Endpoint (PrivateLink)

Performance global?
├── Conteúdo web (cache) → CloudFront
└── TCP/UDP, IPs estáticos → Global Accelerator
Escolha de Transferência de DadosDecisão
Volume de dados?
├── <10 TB → Internet/DataSync
├── 10 TB - 10 PB → Snowball Edge
└── >10 PB → Snowmobile

Transferência contínua ou única?
├── Contínua → DataSync (scheduled) ou DX
└── Única → Snow Family ou DataSync

Tipo de dado?
├── Arquivos (NFS/SMB) → DataSync
├── Banco de dados → DMS
├── Parceiros enviam via SFTP → Transfer Family
└── Streaming real-time → Kinesis

On-premises precisa acessar dados na AWS?
└── Sim → Storage Gateway (cache local)

Quando Usar X vs Y

Transit Gateway vs VPC PeeringNetworking
VPC Peering:
✓ 2-3 VPCs com comunicação direta
✓ Sem custo por hora (só data transfer)
✓ Menor latência (conexão direta)
✗ Não transitivo
✗ Não escala bem (N×(N-1)/2 conexões)

Transit Gateway:
✓ 5+ VPCs
✓ Conectividade transitiva
✓ Segmentação com route tables
✓ Integra com VPN e Direct Connect
✗ Custo por hora + data processing
✗ Latência ligeiramente maior (hop extra)
DynamoDB vs AuroraDatabase
DynamoDB:
✓ Key-value / document access patterns
✓ Escala massiva (milhões de requests/s)
✓ Single-digit millisecond latency
✓ Serverless (zero admin)
✓ Global Tables (multi-region active-active)
✗ Sem joins, sem SQL complexo
✗ Queries limitadas (partition key + sort key)

Aurora:
✓ SQL complexo, joins, transações ACID
✓ Compatível MySQL/PostgreSQL
✓ Read replicas para offload
✓ Global Database (cross-region)
✓ Queries flexíveis (qualquer coluna)
✗ Escala vertical (instance types)
✗ Mais caro para alta throughput simples
SQS vs KinesisMessaging
SQS:
✓ Desacoplamento simples (producer/consumer)
✓ Mensagem deletada após processamento
✓ Escala automática ilimitada
✓ Dead Letter Queue para falhas
✓ Quando: task queue, buffering, 1 consumer group
✗ Sem replay (mensagem some após consumo)
✗ Sem ordering garantido (Standard)

Kinesis Data Streams:
✓ Múltiplos consumers leem mesmos dados
✓ Replay (re-processar dados passados)
✓ Ordering por shard (partition key)
✓ Retenção até 365 dias
✓ Quando: analytics real-time, múltiplos consumers
✗ Gerenciar shards (capacity planning)
✗ Mais complexo de operar
CloudFront vs Global AcceleratorPerformance
CloudFront:
✓ Cache de conteúdo (estático e dinâmico)
✓ HTTP/HTTPS
✓ Lambda@Edge / CloudFront Functions
✓ Quando: websites, APIs, streaming de vídeo
✗ Não suporta TCP/UDP genérico
✗ IPs mudam (não pode fazer whitelist)

Global Accelerator:
✓ TCP/UDP (qualquer protocolo)
✓ 2 IPs Anycast estáticos (whitelist)
✓ Failover instantâneo entre regiões
✓ Quando: gaming, IoT, VoIP, non-HTTP
✓ Health checks com failover automático
✗ Sem cache
✗ Mais caro que CloudFront para HTTP
EventBridge vs SNSEvents
SNS:
✓ Fan-out simples e rápido
✓ Alta throughput
✓ Mobile push notifications
✓ SMS, Email
✓ Quando: notificações, fan-out para SQS queues
✗ Filtering limitado (atributos simples)
✗ Sem archive/replay

EventBridge:
✓ Content-based filtering avançado (JSON path)
✓ Schema Registry (descoberta automática)
✓ Archive & Replay de eventos
✓ Integração com SaaS (Zendesk, Datadog)
✓ Quando: event-driven architecture complexa
✗ Menor throughput que SNS
✗ Mais caro por evento
DataSync vs Storage GatewayData
DataSync:
✓ MOVER dados (migração, sync periódico)
✓ Alta velocidade (10x ferramentas open-source)
✓ Verificação de integridade
✓ Scheduling
✓ Quando: migrar NFS/SMB para S3/EFS
✗ Não fornece acesso contínuo on-premises

Storage Gateway:
✓ ACESSAR dados na AWS de on-premises
✓ Cache local para baixa latência
✓ Protocolos nativos (NFS, SMB, iSCSI)
✓ Quando: acesso híbrido contínuo
✗ Não é ferramenta de migração
✗ Throughput limitado pelo cache local

🎯 Dica final: No exame, identifique as palavras-chave no enunciado ANTES de ler as opções. Isso direciona seu raciocínio para o serviço correto e evita confusão com distratores. Pratique associar palavras-chave → serviço até virar automático.
