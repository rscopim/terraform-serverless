Complexidade Organizacional (26%)

Design de soluções para conectividade de rede, estratégia multi-conta, DNS híbrido, federação de identidade e governança em escala empresarial.

Conectividade de Rede

Serviços e padrões para conectar VPCs, data centers on-premises e escritórios remotos:

Transit Gateway

AWS Transit GatewayHub Central

Hub de rede regional que conecta VPCs e redes on-premises através de um ponto central.

Características:
• Hub-and-spoke: conecta milhares de VPCs
• Suporta peering inter-região (Transit Gateway Peering)
• Route tables para segmentação de tráfego
• Suporta multicast
• Bandwidth: até 50 Gbps por attachment
• Integra com Direct Connect Gateway e VPN

Quando usar:
• 3+ VPCs que precisam se comunicar
• Topologia hub-and-spoke
• Segmentação de rede entre ambientes
• Conectividade transitiva entre VPCs
Transit Gateway vs VPC PeeringDecisão
VPC Peering:
• Conexão 1:1 entre duas VPCs
• Não transitivo (A↔B e B↔C ≠ A↔C)
• Sem custo de hora (só transferência de dados)
• Suporta inter-região
• Melhor para: poucas VPCs (2-3)

Transit Gateway:
• Hub central para N VPCs
• Transitivo por padrão
• Custo por hora + transferência
• Route tables para segmentação
• Melhor para: muitas VPCs, topologia complexa

Regra: <5 VPCs sem transitividade → Peering
        5+ VPCs ou transitividade → Transit Gateway

Direct Connect

AWS Direct ConnectConexão Dedicada

Conexão de rede dedicada entre seu data center e a AWS. Não passa pela internet pública.

Tipos de conexão:
• Dedicated: 1 Gbps, 10 Gbps, 100 Gbps (porta física exclusiva)
• Hosted: 50 Mbps a 10 Gbps (via parceiro AWS)

Virtual Interfaces (VIFs):
• Private VIF → acesso a VPCs (via VGW ou Direct Connect Gateway)
• Public VIF → acesso a serviços públicos AWS (S3, DynamoDB)
• Transit VIF → acesso via Transit Gateway

Resiliência:
• Single connection = single point of failure
• High Resiliency: 2 conexões em 2 locais diferentes
• Maximum Resiliency: 2 conexões em cada um de 2 locais (4 total)

Lead time: semanas a meses para provisionar!
Direct Connect GatewayMulti-Região

Permite acessar VPCs em múltiplas regiões através de uma única conexão Direct Connect.

Sem DX Gateway:
• 1 Direct Connect → 1 região apenas
• Precisa de conexão por região

Com DX Gateway:
• 1 Direct Connect → múltiplas regiões
• Conecta a VGWs ou Transit Gateways
• Global (não é regional)

Combinação com Transit Gateway:
• DX → DX Gateway → Transit Gateway → VPCs
• Acesso a centenas de VPCs via 1 conexão
• Transit VIF necessário

VPN

Site-to-Site VPNIPsec

Conexão criptografada (IPsec) entre seu data center e a AWS via internet pública.

Componentes:
• Virtual Private Gateway (VGW) — lado AWS
• Customer Gateway (CGW) — lado on-premises
• 2 túneis IPsec para redundância

Características:
• Setup em minutos (vs semanas do DX)
• Bandwidth: até ~1.25 Gbps por túnel
• Criptografia IPsec
• Pode usar como backup do Direct Connect

VPN + Direct Connect (backup):
• DX como primário (baixa latência)
• VPN como failover (via internet)
• BGP para failover automático
Client VPNUsuários Remotos

VPN gerenciada para conectar usuários individuais (laptops) à AWS ou rede corporativa.

Características:
• Baseado em OpenVPN
• Escala elástica (milhares de usuários)
• Autenticação: AD, SAML, certificados
• Split-tunnel ou full-tunnel
• Integra com Security Groups

Quando usar:
• Funcionários remotos acessando VPCs
• Acesso seguro a recursos internos
• Substituir VPN on-premises

Diferença do Site-to-Site:
• Site-to-Site = rede-a-rede (data center → AWS)
• Client VPN = usuário-a-rede (laptop → AWS)

Outros Serviços de Rede

AWS PrivateLinkEndpoint Services

Acesso privado a serviços AWS ou serviços de terceiros sem expor tráfego à internet.

Tipos de VPC Endpoints:
• Interface Endpoint (PrivateLink): ENI na sua VPC
  → Maioria dos serviços AWS
  → Serviços de terceiros no Marketplace
  → Seus próprios serviços (via NLB)

• Gateway Endpoint: entrada na route table
  → Apenas S3 e DynamoDB
  → Sem custo adicional

Quando usar PrivateLink:
• Expor serviço para outras contas sem peering
• Acesso privado a SaaS
• Compliance: tráfego não pode sair da rede AWS
Global AcceleratorPerformance

Melhora performance de aplicações globais usando a rede backbone da AWS (Anycast IPs).

Como funciona:
• 2 IPs Anycast estáticos globais
• Tráfego entra na edge location mais próxima
• Viaja pela rede privada AWS (não internet)
• Roteamento inteligente para endpoints saudáveis

vs CloudFront:
• CloudFront: cache de conteúdo estático/dinâmico
• Global Accelerator: TCP/UDP sem cache
  → Gaming, IoT, VoIP
  → Failover instantâneo entre regiões
  → IPs estáticos (whitelist em firewalls)
AWS Cloud WANRede Global

Serviço gerenciado para construir, gerenciar e monitorar uma rede global unificada.

Características:
• Rede global como serviço
• Política centralizada (network policy)
• Segmentação automática
• Integra VPCs, DX, VPN, SD-WAN
• Dashboard de monitoramento

Quando usar:
• Rede global complexa (muitas regiões)
• Substituir Transit Gateway multi-região
• Gerenciamento centralizado de rede
• Segmentação por política

Estratégia Multi-Conta

AWS OrganizationsGovernança

Gerenciamento centralizado de múltiplas contas AWS com billing consolidado e políticas.

Estrutura:
• Management Account (payer) — raiz
• Organizational Units (OUs) — agrupamento lógico
• Member Accounts — contas individuais

Service Control Policies (SCPs):
• Definem permissões MÁXIMAS para contas/OUs
• NÃO concedem permissões (apenas restringem)
• Não afetam a Management Account
• Herança hierárquica (OU pai → OU filho)

Exemplo de SCP:
• Deny: criar recursos fora de regiões permitidas
• Deny: desabilitar CloudTrail
• Deny: sair da organização
AWS Control TowerLanding Zone

Configura e governa um ambiente multi-conta seguro seguindo melhores práticas (Landing Zone).

Componentes:
• Landing Zone: ambiente multi-conta pré-configurado
• Guardrails: regras preventivas e detectivas
  → Preventive: SCPs (bloqueia ações)
  → Detective: Config Rules (detecta violações)
• Account Factory: criação padronizada de contas
• Dashboard: visão de compliance

Contas criadas automaticamente:
• Log Archive Account (CloudTrail centralizado)
• Audit Account (acesso cross-account para auditoria)

Quando usar:
• Novo ambiente AWS multi-conta
• Padronizar criação de contas
• Governança automatizada

DNS Híbrido

Route 53 ResolverDNS Híbrido

Resolve consultas DNS entre a AWS e redes on-premises.

Endpoints:
• Inbound Endpoint:
  → On-premises DNS → AWS (resolve domínios privados AWS)
  → DNS on-prem encaminha queries para o endpoint
  → ENIs na VPC que recebem queries

• Outbound Endpoint:
  → AWS → On-premises DNS (resolve domínios corporativos)
  → Route 53 encaminha queries via regras
  → Forwarding Rules definem quais domínios

Resolver Rules:
• Forward: encaminha domínio X para DNS Y
• System: usa resolução padrão do Route 53
• Compartilháveis via RAM (Resource Access Manager)

Cenário típico:
• corp.internal → Outbound → DNS on-premises
• aws.internal → Inbound → Route 53 Private Hosted Zone
Private Hosted ZonesDNS Privado

Zonas DNS que respondem apenas dentro de VPCs associadas.

Características:
• Resolução apenas dentro de VPCs associadas
• Pode associar VPCs de outras contas (cross-account)
• Split-view DNS: mesmo domínio, respostas diferentes
  → Público: api.empresa.com → IP público
  → Privado: api.empresa.com → IP privado

Cross-account:
• Conta A cria a Private Hosted Zone
• Conta A autoriza associação da VPC da Conta B
• Conta B aceita e associa sua VPC
• Ambas resolvem os mesmos registros

Federação de Identidade

IAM Identity CenterSSO

Gerenciamento centralizado de acesso SSO para múltiplas contas AWS e aplicações.

Anteriormente: AWS SSO

Características:
• Login único para todas as contas da organização
• Integra com IdPs externos (AD, Okta, Azure AD)
• Permission Sets: definem acesso por conta
• Atribuição: usuário/grupo → permission set → conta

Identity Sources:
• Identity Center directory (built-in)
• Active Directory (AD Connector ou AWS Managed AD)
• External IdP (SAML 2.0 — Okta, Azure AD, etc.)

Quando usar:
• Acesso humano a múltiplas contas AWS
• SSO corporativo
• Gerenciamento centralizado de permissões
SAML 2.0 / OIDCFederação

Protocolos para federação de identidade com provedores externos.

SAML 2.0:
• Padrão enterprise (Active Directory, ADFS)
• Assume Role via STS (AssumeRoleWithSAML)
• Console AWS ou API/CLI
• Fluxo: User → IdP → SAML Assertion → STS → Credentials

OIDC (OpenID Connect):
• Padrão web/mobile (Google, Facebook, Cognito)
• AssumeRoleWithWebIdentity
• Melhor usar Cognito como intermediário

Amazon Cognito:
• User Pools: autenticação (sign-up/sign-in)
• Identity Pools: autorização (credenciais AWS temporárias)
• Federação com SAML, OIDC, social IdPs
• Quando usar: aplicações web/mobile com usuários externos

Governança e Compliance

AWS ConfigCompliance

Avalia, audita e monitora configurações de recursos AWS continuamente.

Componentes:
• Config Rules: regras de compliance
  → Managed Rules (pré-definidas pela AWS)
  → Custom Rules (Lambda)
• Conformance Packs: conjunto de regras
• Aggregator: visão multi-conta/multi-região
• Remediation: correção automática (SSM Automation)

Exemplos de regras:
• EBS volumes devem ser criptografados
• Security Groups não podem ter 0.0.0.0/0
• S3 buckets devem ter versionamento
• RDS deve ter backup habilitado

Multi-conta:
• Config Aggregator na conta de auditoria
• Delegated Administrator
• Organization Config Rules
CloudTrailAuditoria

Registra todas as chamadas de API feitas na conta AWS (quem fez o quê, quando).

Tipos de eventos:
• Management Events: operações de controle
  (CreateBucket, AttachPolicy, RunInstances)
• Data Events: operações em dados
  (GetObject, PutObject, Invoke Lambda)
• Insights Events: atividade incomum

Organization Trail:
• Trail na Management Account
• Captura eventos de TODAS as contas
• Centraliza logs em S3 da conta de segurança
• Imutável com S3 Object Lock

Integração:
• S3 (armazenamento de longo prazo)
• CloudWatch Logs (alertas em tempo real)
• Athena (queries SQL nos logs)
• EventBridge (automação baseada em eventos)
GuardDutyDetecção de Ameaças

Detecção inteligente de ameaças usando ML, análise de anomalias e threat intelligence.

Fontes de dados:
• CloudTrail Events (Management + Data)
• VPC Flow Logs
• DNS Logs
• EKS Audit Logs
• S3 Data Events

Tipos de findings:
• Reconnaissance (port scanning, API probing)
• Instance Compromise (crypto mining, C&C)
• Account Compromise (credenciais vazadas)
• S3 Compromise (acesso anômalo)

Multi-conta:
• Delegated Administrator na conta de segurança
• Habilitar para todas as contas da organização
• Findings centralizados
• Auto-enable para novas contas
Security HubPostura

Visão centralizada de segurança e compliance. Agrega findings de múltiplos serviços.

Agrega findings de:
• GuardDuty, Inspector, Macie
• Firewall Manager, IAM Access Analyzer
• Config, terceiros (Qualys, Palo Alto, etc.)

Security Standards:
• AWS Foundational Security Best Practices
• CIS AWS Foundations Benchmark
• PCI DSS
• NIST 800-53

Automação:
• Custom Actions → EventBridge → Lambda
• Automated response (quarantine, notify)
• Cross-account aggregation
• Integration com SIEM (Splunk, etc.)

🎯 Para o exame: "Detectar ameaças" → GuardDuty | "Compliance de configuração" → Config | "Auditoria de API" → CloudTrail | "Visão centralizada de segurança" → Security Hub | "Governança multi-conta" → Organizations + SCPs + Control Tower
