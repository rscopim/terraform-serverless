Monitoramento

Monitoramento do Sistema

Monitorar recursos (CPU, memória, disco, I/O) é fundamental para identificar gargalos, prever problemas e manter servidores saudáveis. Estas ferramentas são o "painel de controle" do sysadmin.

Memória e CPU

free — Uso de memóriaRAM
# Memória em formato legível:
free -h
#               total   used   free   shared  buff/cache  available
# Mem:          16Gi   4.2Gi  8.1Gi  256Mi   3.7Gi       11Gi
# Swap:         4.0Gi  0B     4.0Gi

# Explicação dos campos:
# total     = RAM física total
# used      = em uso por processos
# free      = completamente livre
# shared    = memória compartilhada (tmpfs)
# buff/cache = buffers do kernel + cache de disco
# available = disponível para novos processos
#             (free + cache que pode ser liberado)

# ⚠️ "available" é o número que importa, NÃO "free"!
# Linux usa RAM livre como cache — isso é NORMAL.

# Atualizar a cada 2 segundos:
watch -n 2 free -h

# Em megabytes:
free -m

# Total (sem detalhamento):
free -h --total

# Apenas uma linha resumida:
free -h | awk '/Mem:/{printf "RAM: %s/%s (available: %s)\n", $3, $2, $7}'
vmstat — Estatísticas de VMvmstat
# Snapshot atual:
vmstat
# procs --------memory--------- --swap-- ---io--- -system-- ------cpu-----
#  r  b  swpd   free   buff  cache  si  so  bi  bo  in  cs us sy id wa st
#  1  0  0    8345612 234512 3876544  0   0   5  12 150 300  3  1 95  1  0

# Campos importantes:
# r  = processos esperando CPU (run queue)
# b  = processos bloqueados (waiting I/O)
# si/so = swap in/out (deve ser 0 em produção!)
# bi/bo = block I/O in/out (disco)
# us = % CPU user space
# sy = % CPU kernel
# id = % CPU idle
# wa = % CPU waiting I/O (gargalo de disco!)

# Monitorar a cada 1 segundo, 10 amostras:
vmstat 1 10

# Com timestamps:
vmstat -t 1

# Estatísticas de disco:
vmstat -d

# Resumo desde o boot:
vmstat -s

# Alerta: se wa > 20%, há gargalo de I/O
# Alerta: se r > num_cpus, há gargalo de CPU
# Alerta: se si/so > 0 constantemente, precisa mais RAM

Disco e I/O

df — Espaço em discoDisco
# Uso de disco por filesystem:
df -h
# Filesystem      Size  Used  Avail  Use%  Mounted on
# /dev/sda1       50G   32G   16G    68%   /
# /dev/sdb1       200G  150G  40G    79%   /data
# tmpfs           8.0G  256M  7.8G   4%    /dev/shm

# Filtrar tipo de filesystem:
df -hT                    # mostra tipo (ext4, xfs...)
df -h --type=ext4         # apenas ext4
df -h --exclude-type=tmpfs

# Inodes (pode acabar antes do espaço!):
df -i
# Se inodes = 100%, não pode criar mais arquivos
# mesmo com espaço em disco disponível

# Apenas um filesystem:
df -h /home
df -h /var

# Em formato de bloco (scripting):
df --output=source,fstype,size,used,avail,pcent,target

# Monitorar com watch:
watch -n 5 'df -h | grep -v tmpfs'

# Alerta: partição acima de 80%:
df -h | awk '+$5 > 80 {print "ALERTA:", $0}'
du — Uso por diretórioDiretórios
# Tamanho de um diretório:
du -sh /var/log
# 2.3G    /var/log

# Top 10 maiores diretórios:
du -h --max-depth=1 /var | sort -rh | head -10

# Maiores arquivos no sistema:
find / -type f -size +100M -exec ls -lh {} \; 2>/dev/null | \
  sort -k5 -rh | head -20

# Tamanho de cada subdiretório:
du -sh /var/*/
# 1.5G   /var/log/
# 800M   /var/cache/
# 200M   /var/lib/

# Excluir padrões:
du -sh --exclude="*.log" /opt/app/

# Tamanho total de arquivos por extensão:
find /var/log -name "*.log" -exec du -ch {} + | tail -1

# ncdu — ferramenta interativa (recomendado!):
sudo apt install ncdu
ncdu /var              # navegar visualmente
ncdu -x /             # apenas filesystem local

# Comparar uso ao longo do tempo:
du -sb /var/log > /tmp/disk-$(date +%H).txt

# Instalar:

iostat

# Apenas um disco:

# Histórico (dados coletados pelo sysstat):
sar -u -f /var/log/sysstat/sa15   # CPU do dia 15

# Habilitar coleta histórica:
sudo systemctl enable --now sysstat

Logs

Gerenciamento de Logs

Logs são a principal ferramenta de diagnóstico em servidores. Saber onde ficam, como rotacioná-los e como centralizar é essencial para qualquer administrador.

Syslog e journald

Estrutura de logs no Linuxsyslog
# Diretório principal de logs:
ls /var/log/
# auth.log      → autenticação (login, sudo, SSH)
# syslog        → mensagens gerais do sistema
# kern.log      → mensagens do kernel
# dpkg.log      → instalações de pacotes
# apt/          → logs do apt
# nginx/        → logs do Nginx
# mysql/        → logs do MySQL
# journal/      → dados binários do journald

# Ler logs em tempo real:
tail -f /var/log/syslog
tail -f /var/log/auth.log

# Múltiplos logs simultâneos:
tail -f /var/log/syslog /var/log/auth.log

# Buscar por padrão:
grep "Failed password" /var/log/auth.log
grep "error" /var/log/syslog | tail -20

# rsyslog — daemon de logs (config):
cat /etc/rsyslog.conf
# Regras: facility.priority  destino
# auth.*           /var/log/auth.log
# kern.*           /var/log/kern.log
# *.emerg          :omusrmsg:*

# Facilities: auth, kern, mail, cron, daemon, user, local0-7
# Priorities: emerg, alert, crit, err, warning, notice, info, debug

# Enviar mensagem para syslog (de scripts):
logger "Backup concluído com sucesso"
logger -p local0.info -t meu-app "Mensagem customizada"
journald — Logs estruturadosjournald
# journald é o sistema de logs do systemd
# Vantagens: estruturado, indexado, comprimido, metadata

# Configuração: /etc/systemd/journald.conf
[Journal]
Storage=persistent         # auto, volatile, persistent, none
Compress=yes
SystemMaxUse=2G            # máximo em disco
SystemMaxFileSize=100M     # máximo por arquivo
MaxRetentionSec=30day      # retenção máxima
ForwardToSyslog=yes        # encaminhar para rsyslog

# Aplicar mudanças:
sudo systemctl restart systemd-journald

# journald vs rsyslog:
# journald: logs binários, estruturados, do systemd
# rsyslog:  logs texto, flexível, rede
# Ambos podem coexistir (ForwardToSyslog=yes)

# Uso de disco do journal:
journalctl --disk-usage
# Archived and active journals take up 1.2G

# Limpar logs antigos:
sudo journalctl --vacuum-time=7d
sudo journalctl --vacuum-size=500M
sudo journalctl --vacuum-files=5

# Verificar integridade:
journalctl --verify

logrotate — Rotação de logs

logrotate — Configuração e exemplosRotação
# logrotate previne que logs cresçam infinitamente
# Rotaciona, comprime e remove logs antigos automaticamente

# Configuração global:
cat /etc/logrotate.conf

# Configurações por aplicação:
ls /etc/logrotate.d/
# nginx, apt, dpkg, syslog, mysql, ...

# Exemplo: /etc/logrotate.d/minha-app
/var/log/minha-app/*.log {
    daily                   # rotacionar diariamente (weekly, monthly)
    rotate 14               # manter 14 arquivos rotacionados
    compress                # comprimir com gzip
    delaycompress           # comprimir apenas a partir do 2º arquivo
    missingok               # não dar erro se log não existir
    notifempty              # não rotacionar se arquivo vazio
    create 0640 appuser appgroup  # permissões do novo arquivo
    sharedscripts           # executar scripts uma vez (não por arquivo)
    
    postrotate
        # Comando executado APÓS rotação:
        systemctl reload minha-app > /dev/null 2>&1 || true
    endscript
    
    prerotate
        # Comando executado ANTES da rotação:
        echo "Iniciando rotação em $(date)" >> /var/log/logrotate-audit.log
    endscript
}

# Exemplo para Nginx:
/var/log/nginx/*.log {
    daily
    rotate 30
    compress
    delaycompress
    missingok
    notifempty
    create 0640 www-data adm
    sharedscripts
    postrotate
        [ -f /var/run/nginx.pid ] && kill -USR1 $(cat /var/run/nginx.pid)
    endscript
}

# Testar configuração (dry-run):
sudo logrotate -d /etc/logrotate.d/minha-app

# Forçar rotação manual:
sudo logrotate -f /etc/logrotate.d/minha-app

# logrotate é executado via cron:
cat /etc/cron.daily/logrotate
💡 Centralização de logs (introdução): Em ambientes com múltiplos servidores, centralize logs usando: rsyslog (envio via rede), Elasticsearch + Kibana (ELK stack), Grafana Loki, ou CloudWatch Logs (AWS). Isso permite correlacionar eventos e debugar problemas distribuídos.
Disco

Gerenciamento de Disco

Particionar discos, criar filesystems e gerenciar volumes é uma habilidade crítica para sysadmins. LVM adiciona flexibilidade permitindo redimensionar partições sem downtime.

Particionamento e formatação

fdisk/parted — Particionar discoPartição
# Listar discos e partições:
sudo fdisk -l
sudo lsblk
# NAME   MAJ:MIN RM   SIZE TYPE MOUNTPOINT
# sda      8:0    0    50G  disk
# ├─sda1   8:1    0    49G  part /
# └─sda2   8:2    0     1G  part [SWAP]
# sdb      8:0    0   100G  disk

# Informações do disco:
sudo fdisk -l /dev/sdb
sudo parted /dev/sdb print

# Particionar com fdisk (interativo):
sudo fdisk /dev/sdb
# Comandos: n=nova, d=deletar, p=print, w=write, q=quit

# Particionar com parted (GPT, discos > 2TB):
sudo parted /dev/sdb
# (parted) mklabel gpt
# (parted) mkpart primary ext4 0% 50%
# (parted) mkpart primary ext4 50% 100%
# (parted) print
# (parted) quit

# Parted não-interativo:
sudo parted -s /dev/sdb mklabel gpt
sudo parted -s /dev/sdb mkpart primary ext4 0% 100%

# Verificar partições após criar:
sudo partprobe /dev/sdb    # informar kernel
lsblk /dev/sdb
mkfs e mount — Formatar e montarFilesystem
# Formatar partição (CUIDADO: apaga dados!):
sudo mkfs.ext4 /dev/sdb1           # ext4 (padrão Linux)
sudo mkfs.xfs /dev/sdb1            # XFS (alta performance)
sudo mkfs.btrfs /dev/sdb1          # Btrfs (snapshots)

# Com label:
sudo mkfs.ext4 -L "dados" /dev/sdb1

# Montar filesystem:
sudo mkdir -p /mnt/dados
sudo mount /dev/sdb1 /mnt/dados

# Verificar montagem:
mount | grep sdb1
df -h /mnt/dados

# Desmontar:
sudo umount /mnt/dados
# Se "busy":
sudo umount -l /mnt/dados    # lazy unmount
# Ou encontrar quem está usando:
sudo lsof +D /mnt/dados
sudo fuser -mv /mnt/dados

# Montar com opções:
sudo mount -o noexec,nosuid /dev/sdb1 /mnt/dados
sudo mount -o ro /dev/sdb1 /mnt/readonly

# Montar por UUID (mais confiável):
sudo blkid /dev/sdb1
# /dev/sdb1: UUID="abc123..." TYPE="ext4"
sudo mount UUID="abc123..." /mnt/dados

# Verificar filesystem:
sudo fsck /dev/sdb1        # ⚠️ apenas com partition desmontada!
sudo e2fsck -f /dev/sdb1   # ext4 específico

fstab — Montagem automática no boot

/etc/fstab — Persistir montagensfstab
# /etc/fstab define o que montar automaticamente no boot
# ⚠️ ERRO no fstab pode impedir o sistema de iniciar!
# SEMPRE use UUID em vez de /dev/sdX (pode mudar!)

# Formato:
# <device>        <mountpoint>  <type>  <options>        <dump> <pass>
UUID=abc123...   /mnt/dados    ext4    defaults         0      2
UUID=def456...   /mnt/backup   xfs     defaults,noexec  0      2
UUID=ghi789...   none          swap    sw               0      0

# Campos:
# device    = UUID (ou /dev/sdX, mas UUID é mais seguro)
# mountpoint = onde montar
# type      = ext4, xfs, swap, nfs, etc.
# options   = defaults, noexec, nosuid, ro, noatime, etc.
# dump      = 0 (não fazer backup com dump)
# pass      = 0=não checar, 1=root, 2=outros (ordem de fsck)

# Opções comuns:
# defaults   = rw, suid, dev, exec, auto, nouser, async
# noexec     = não permitir executar binários
# nosuid     = ignorar bit SUID
# noatime    = não atualizar access time (performance!)
# ro         = read-only
# nofail     = não falhar boot se device não existir

# Workflow seguro para adicionar ao fstab:
# 1. Obter UUID:
sudo blkid /dev/sdb1

# 2. Fazer backup do fstab:
sudo cp /etc/fstab /etc/fstab.bak

# 3. Adicionar linha:
echo 'UUID=abc123... /mnt/dados ext4 defaults,noatime 0 2' | sudo tee -a /etc/fstab

# 4. Testar ANTES de reiniciar:
sudo mount -a           # monta tudo do fstab
# Se não der erro, está seguro!

# 5. Verificar:
df -h /mnt/dados

LVM — Logical Volume Manager

LVM — Conceitos e criaçãoLVM Create
# LVM permite:
# - Redimensionar partições sem downtime
# - Combinar múltiplos discos em um volume
# - Snapshots para backup consistente

# Hierarquia LVM:
# Physical Volumes (PV) → /dev/sdb, /dev/sdc
#   Volume Group (VG) → vg-dados
#     Logical Volumes (LV) → lv-app, lv-logs

# Instalar:
sudo apt install lvm2

# 1. Criar Physical Volumes:
sudo pvcreate /dev/sdb /dev/sdc
sudo pvs         # listar PVs
sudo pvdisplay   # detalhes

# 2. Criar Volume Group:
sudo vgcreate vg-dados /dev/sdb /dev/sdc
sudo vgs         # listar VGs
sudo vgdisplay   # detalhes

# 3. Criar Logical Volumes:
sudo lvcreate -L 50G -n lv-app vg-dados
sudo lvcreate -L 30G -n lv-logs vg-dados
sudo lvcreate -l 100%FREE -n lv-backup vg-dados  # todo espaço restante
sudo lvs         # listar LVs

# 4. Formatar e montar:
sudo mkfs.ext4 /dev/vg-dados/lv-app
sudo mkdir -p /opt/app
sudo mount /dev/vg-dados/lv-app /opt/app

# 5. Adicionar ao fstab:
echo '/dev/vg-dados/lv-app /opt/app ext4 defaults 0 2' | sudo tee -a /etc/fstab
LVM — Expandir e gerenciarLVM Manage
# === EXPANDIR VOLUME (principal vantagem do LVM!) ===

# Expandir LV em 20GB:
sudo lvextend -L +20G /dev/vg-dados/lv-app

# Expandir para usar todo espaço livre do VG:
sudo lvextend -l +100%FREE /dev/vg-dados/lv-app

# Expandir o filesystem (ONLINE, sem downtime!):
sudo resize2fs /dev/vg-dados/lv-app    # ext4
sudo xfs_growfs /opt/app               # XFS

# Tudo em um comando:
sudo lvextend -L +20G --resizefs /dev/vg-dados/lv-app

# === ADICIONAR DISCO AO VG ===
sudo pvcreate /dev/sdd
sudo vgextend vg-dados /dev/sdd
# Agora tem mais espaço para expandir LVs!

# === SNAPSHOTS ===
# Criar snapshot (backup consistente):
sudo lvcreate -L 10G -s -n snap-app /dev/vg-dados/lv-app

# Montar snapshot (read-only para backup):
sudo mount -o ro /dev/vg-dados/snap-app /mnt/snapshot

# Restaurar snapshot:
sudo lvconvert --merge /dev/vg-dados/snap-app

# Remover snapshot:
sudo lvremove /dev/vg-dados/snap-app

# === MONITORAR ===
sudo pvs      # physical volumes
sudo vgs      # volume groups  
sudo lvs      # logical volumes
sudo vgdisplay vg-dados   # espaço livre no VG
💡 Por que usar LVM em servidores?
  • Expandir /var/log quando enche — sem downtime
  • Adicionar discos extras e expandir volumes existentes
  • Snapshots antes de atualizações arriscadas
  • Migrar dados entre discos sem interrupção
Scripting

Shell Scripting Avançado

Domine recursos avançados do Bash: arrays, traps, debugging, getopts e heredocs para criar scripts robustos e profissionais de automação.

Arrays e Arrays Associativos

Arrays indexadosArrays
#!/bin/bash
# Array simples (indexado por número):
servers=("web1" "web2" "web3" "db1")

# Acessar elementos:
echo "${servers[0]}"       # web1 (primeiro)
echo "${servers[2]}"       # web3 (terceiro)
echo "${servers[-1]}"      # db1 (último)

# Todos os elementos:
echo "${servers[@]}"       # web1 web2 web3 db1
echo "${servers[*]}"       # web1 web2 web3 db1

# Número de elementos:
echo "${#servers[@]}"      # 4

# Adicionar elemento:
servers+=("db2")

# Remover elemento:
unset servers[1]           # remove web2

# Slice (subarray):
echo "${servers[@]:1:2}"   # web2 web3 (do index 1, 2 elementos)

# Iterar:
for server in "${servers[@]}"; do
    echo "Checking $server..."
    ssh "$server" "uptime" 2>/dev/null || echo "  FALHOU!"
done

# Array a partir de comando:
log_files=($(find /var/log -name "*.log" -mtime -1))
echo "Encontrados ${#log_files[@]} logs recentes"

# Array de linhas de um arquivo:
mapfile -t lines < /etc/hosts
echo "Hosts file tem ${#lines[@]} linhas"
Arrays associativos (hash/dict)Associativo
#!/bin/bash
# Declarar array associativo (Bash 4+):
declare -A config

# Atribuir valores:
config[host]="192.168.1.100"
config[port]="5432"
config[user]="postgres"
config[database]="production"

# Acessar:
echo "Conectando em ${config[host]}:${config[port]}"

# Todas as chaves:
echo "${!config[@]}"    # host port user database

# Todos os valores:
echo "${config[@]}"

# Iterar por chave/valor:
for key in "${!config[@]}"; do
    echo "$key = ${config[$key]}"
done

# Verificar se chave existe:
if [[ -v config[host] ]]; then
    echo "Host configurado: ${config[host]}"
fi

# Caso prático — status de servidores:
declare -A server_status
servers=("web1" "web2" "db1")
for srv in "${servers[@]}"; do
    if ping -c 1 -W 1 "$srv" &>/dev/null; then
        server_status[$srv]="UP"
    else
        server_status[$srv]="DOWN"
    fi
done

# Relatório:
for srv in "${!server_status[@]}"; do
    printf "%-10s %s\n" "$srv" "${server_status[$srv]}"
done

trap, debugging e getopts

trap — Capturar sinaisSinais
#!/bin/bash
# trap executa comando quando o script recebe um sinal

# Limpar arquivos temporários ao sair:
TMPFILE=$(mktemp)
trap "rm -f $TMPFILE; echo 'Limpeza concluída'" EXIT

# Capturar Ctrl+C:
trap "echo 'Interrompido!'; exit 1" INT

# Capturar múltiplos sinais:
trap "cleanup" EXIT INT TERM

# Função de cleanup:
cleanup() {
    echo "Limpando recursos..."
    rm -f /tmp/meu-app-*.tmp
    [ -n "$PID" ] && kill "$PID" 2>/dev/null
}

# Ignorar sinal:
trap "" HUP    # Ignora SIGHUP (nohup caseiro)

# Restaurar comportamento padrão:
trap - INT     # restaura Ctrl+C padrão

# Sinais comuns:
# EXIT (0)  = sempre ao sair do script
# INT (2)   = Ctrl+C
# TERM (15) = kill (padrão)
# HUP (1)   = terminal fechado
# ERR       = quando um comando falha (set -e)

# Trap com ERR (log de erros):
trap 'echo "ERRO na linha $LINENO: $BASH_COMMAND" >&2' ERR

# Lock file (evitar execução simultânea):
LOCKFILE="/tmp/meu-script.lock"
trap "rm -f $LOCKFILE" EXIT
if [ -f "$LOCKFILE" ]; then
    echo "Script já em execução!"
    exit 1
fi
echo $$ > "$LOCKFILE"
Debugging e getoptsDebug
#!/bin/bash
# === DEBUGGING ===

# set -x: mostra cada comando antes de executar
set -x    # ativar
set +x    # desativar

# Debug apenas de uma seção:
set -x
comando_suspeito
resultado=$(calculo_complexo)

bash -x meu-script.sh

# set -e: parar no primeiro erro
set -e

set -euo pipefail
# -e = exit on error
# -u = error on undefined variable
# -o pipefail = pipe retorna erro se qualquer etapa falhar

# === GETOPTS — Parsing de argumentos ===
#!/bin/bash
usage() {
    echo "Uso: $0 [-v] [-f arquivo] [-n numero] [-h]"
    exit 1
}

verbose=false
file=""
count=1

while getopts "vf:n:h" opt; do
    case $opt in
        v) verbose=true ;;
        f) file="$OPTARG" ;;
        n) count="$OPTARG" ;;
        h) usage ;;
        ?) usage ;;
    esac
done
shift $((OPTIND - 1))   # remover flags processadas

# $@ agora contém argumentos não-flag
echo "Verbose: $verbose"
echo "File: $file"
echo "Count: $count"
echo "Remaining args: $@"

# Função com retorno de string:
get_ip() {

    ip -4 addr show "$interface" 2>/dev/null | grep -oP '(?<=inet\s)\d+(\.\d+){3}'
}

require_root() {

    fi

# Retry pattern:
retry() {
    local max_attempts="${1:-3}"
    local delay="${2:-5}"
    shift 2
    local cmd="$@"
    
    for ((i=1; i<=max_attempts; i++)); do
        echo "Tentativa $i/$max_attempts: $cmd"
        if eval "$cmd"; then
            return 0
        fi
        [ $i -lt $max_attempts ] && sleep "$delay"
    done
    echo "FALHOU após $max_attempts tentativas" >&2
    return 1
}

# Uso:
retry 3 5 curl -sf http://api.example.com/health

Hardening é o processo de reduzir a superfície de ataque de um servidor. Cada camada de proteção dificulta a vida de atacantes — da configuração SSH até auditoria de sistema.

Performance Tuning

Tuning de performance envolve ajustar parâmetros do kernel, limites de processos e configurações de I/O para extrair o máximo do hardware. Cada carga de trabalho tem seu perfil ideal.

sysctl — Parâmetros do kernel

sysctl — Tuning de rede e memóriasysctl
# Ver todos os parâmetros:
sysctl -a

# Ver valor específico:
sysctl net.ipv4.ip_forward
sysctl vm.swappiness

# Alterar em runtime (temporário):
sudo sysctl -w vm.swappiness=10
sudo sysctl -w net.core.somaxconn=65535

# Persistir alterações: /etc/sysctl.d/99-tuning.conf
cat > /etc/sysctl.d/99-tuning.conf << 'EOF'
# === MEMÓRIA ===
vm.swappiness = 10                    # reduzir uso de swap (0-100)
vm.dirty_ratio = 20                   # % RAM suja antes de flush
vm.dirty_background_ratio = 5         # % RAM suja para flush em background
vm.overcommit_memory = 0              # heuristic overcommit

# === REDE ===
net.core.somaxconn = 65535            # backlog de conexões
net.core.netdev_max_backlog = 5000    # queue de pacotes recebidos
net.ipv4.tcp_max_syn_backlog = 65535  # SYN queue
net.ipv4.tcp_tw_reuse = 1            # reusar TIME_WAIT sockets
net.ipv4.ip_local_port_range = 1024 65535  # range de portas efêmeras
net.ipv4.tcp_fin_timeout = 30         # timeout de FIN_WAIT

# === SEGURANÇA DE REDE ===
net.ipv4.tcp_syncookies = 1           # proteção SYN flood
net.ipv4.conf.all.rp_filter = 1      # anti-spoofing
net.ipv4.conf.default.rp_filter = 1
net.ipv4.icmp_echo_ignore_broadcasts = 1

# === FILE DESCRIPTORS ===
fs.file-max = 2097152                 # max FDs do sistema
fs.inotify.max_user_watches = 524288  # para IDEs/watchers
EOF

# Aplicar:
sudo sysctl --system

I/O Scheduler e Swap

I/O SchedulerScheduler
# Ver scheduler atual:
cat /sys/block/sda/queue/scheduler
# [mq-deadline] kyber bfq none

# Schedulers disponíveis:
# none      → SSD/NVMe (sem reordenação, hardware faz)
# mq-deadline → servidores (latência previsível)
# bfq       → desktops (fairness entre processos)
# kyber     → SSD de alta performance

# Alterar temporariamente:
echo "none" | sudo tee /sys/block/sda/queue/scheduler

# Persistir com udev rule:
# /etc/udev/rules.d/60-scheduler.rules
ACTION=="add|change", KERNEL=="sd*", ATTR{queue/scheduler}="mq-deadline"
ACTION=="add|change", KERNEL=="nvme*", ATTR{queue/scheduler}="none"

# Verificar se disco é rotacional (HDD) ou SSD:
cat /sys/block/sda/queue/rotational
# 1 = HDD (rotacional)
# 0 = SSD

# Recomendações:
# SSD/NVMe → none ou mq-deadline
# HDD      → mq-deadline (servidores) ou bfq (desktop)
# VM/Cloud → mq-deadline

# Outros tunings de I/O:
# Read-ahead (prefetch de disco):
cat /sys/block/sda/queue/read_ahead_kb
echo 256 | sudo tee /sys/block/sda/queue/read_ahead_kb

Exercício 1: Script de monitoramento completo

Crie um script Bash que coleta CPU, memória, disco e conexões de rede. Se qualquer métrica ultrapassar o threshold (CPU > 90%, RAM available < 10%, Disco > 85%), envie um alerta para um arquivo de log. Use arrays associativos para os thresholds e trap para cleanup.

▶ Ver solução 
#!/bin/bash
set -euo pipefail

# Trap para cleanup
TMPFILE=$(mktemp)
trap "rm -f $TMPFILE" EXIT

# Configuração com array associativo
declare -A thresholds
thresholds[cpu]=90
thresholds[ram]=90
thresholds[disk]=85

LOG="/var/log/monitor-alertas.log"
HOSTNAME=$(hostname)

log_alert() {
    echo "[$(date '+%F %T')] [$HOSTNAME] ALERTA: $1" | tee -a "$LOG"
}

# Coletar métricas
cpu_usage=$(top -bn1 | grep "Cpu(s)" | awk '{print int($2 + $4)}')
ram_total=$(free -m | awk '/Mem:/{print $2}')
ram_available=$(free -m | awk '/Mem:/{print $7}')
ram_percent=$(( (ram_total - ram_available) * 100 / ram_total ))
disk_usage=$(df -h / | awk 'NR==2{print int($5)}')
connections=$(ss -tn state established | wc -l)

# Verificar thresholds
if [ "$cpu_usage" -gt "${thresholds[cpu]}" ]; then
    log_alert "CPU em ${cpu_usage}% (threshold: ${thresholds[cpu]}%)"
fi

if [ "$ram_percent" -gt "${thresholds[ram]}" ]; then
    log_alert "RAM em ${ram_percent}% (available: ${ram_available}MB)"
fi

if [ "$disk_usage" -gt "${thresholds[disk]}" ]; then
    log_alert "Disco em ${disk_usage}% (threshold: ${thresholds[disk]}%)"
fi

# Relatório
printf "CPU: %d%% | RAM: %d%% (%dMB free) | Disco: %d%% | Conexões: %d\n" \
    "$cpu_usage" "$ram_percent" "$ram_available" "$disk_usage" "$connections"

Exercício 2: Setup LVM + fstab completo

Dado um novo disco /dev/sdb de 100GB, configure LVM com: Volume Group "vg-app", dois Logical Volumes (lv-data 60GB ext4 em /opt/data, lv-logs 40GB xfs em /var/app-logs). Adicione ao fstab com opção noatime. Demonstre como expandir lv-data em 20GB posteriormente.

▶ Ver solução 
# 1. Criar Physical Volume:
sudo pvcreate /dev/sdb

# 2. Criar Volume Group:
sudo vgcreate vg-app /dev/sdb

# 3. Criar Logical Volumes:
sudo lvcreate -L 60G -n lv-data vg-app
sudo lvcreate -L 40G -n lv-logs vg-app

# 4. Formatar:
sudo mkfs.ext4 /dev/vg-app/lv-data
sudo mkfs.xfs /dev/vg-app/lv-logs

# 5. Criar pontos de montagem:
sudo mkdir -p /opt/data /var/app-logs

# 6. Montar:
sudo mount /dev/vg-app/lv-data /opt/data
sudo mount /dev/vg-app/lv-logs /var/app-logs

# 7. Adicionar ao fstab:
sudo cp /etc/fstab /etc/fstab.bak
echo '/dev/vg-app/lv-data /opt/data ext4 defaults,noatime 0 2' | sudo tee -a /etc/fstab
echo '/dev/vg-app/lv-logs /var/app-logs xfs defaults,noatime 0 2' | sudo tee -a /etc/fstab

# 8. Testar fstab:
sudo umount /opt/data /var/app-logs
sudo mount -a
df -h | grep vg-app

# === EXPANSÃO POSTERIOR ===
# Cenário: adicionar novo disco /dev/sdc de 50GB

# Adicionar disco ao VG:
sudo pvcreate /dev/sdc
sudo vgextend vg-app /dev/sdc

# Expandir lv-data em 20GB + resize filesystem:
sudo lvextend -L +20G --resizefs /dev/vg-app/lv-data

# Verificar:
df -h /opt/data   # agora mostra 80GB

Exercício 3: Hardening completo de servidor

Configure um servidor Ubuntu recém-instalado com: SSH hardening (chave apenas, sem root, porta 2222), UFW (apenas SSH e HTTPS), fail2ban, atualizações automáticas, e sysctl tuning para web server. Documente cada passo.

▶ Ver solução 
#!/bin/bash
# hardening.sh — Script de hardening para Ubuntu Server
set -euo pipefail

echo "=== 1. ATUALIZAR SISTEMA ==="
apt update && apt upgrade -y

echo "=== 2. SSH HARDENING ==="
cp /etc/ssh/sshd_config /etc/ssh/sshd_config.bak
cat > /etc/ssh/sshd_config.d/hardening.conf << 'EOF'
Port 2222
PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
MaxAuthTries 3
MaxSessions 5
X11Forwarding no
AllowAgentForwarding no
ClientAliveInterval 300
ClientAliveCountMax 2
EOF
sshd -t && systemctl restart sshd

echo "=== 3. FIREWALL ==="
ufw default deny incoming
ufw default allow outgoing
ufw allow 2222/tcp comment 'SSH'
ufw allow 443/tcp comment 'HTTPS'
ufw limit 2222/tcp
ufw --force enable

echo "=== 4. FAIL2BAN ==="
apt install -y fail2ban
cat > /etc/fail2ban/jail.local << 'EOF'
[DEFAULT]
bantime = 3600
findtime = 600
maxretry = 3
banaction = ufw
[sshd]
enabled = true
port = 2222
EOF
systemctl enable --now fail2ban

echo "=== 5. AUTO-UPDATES ==="
apt install -y unattended-upgrades
dpkg-reconfigure -plow unattended-upgrades

echo "=== 6. SYSCTL TUNING ==="
cat > /etc/sysctl.d/99-hardening.conf << 'EOF'
vm.swappiness = 10
net.core.somaxconn = 65535
net.ipv4.tcp_max_syn_backlog = 65535
net.ipv4.tcp_syncookies = 1
net.ipv4.conf.all.rp_filter = 1
fs.file-max = 2097152
EOF
sysctl --system

echo "=== 7. LIMITES ==="
cat > /etc/security/limits.d/99-tuning.conf << 'EOF'
* soft nofile 65535
* hard nofile 65535
EOF

echo "=== HARDENING COMPLETO ==="
echo "Porta SSH: 2222 | Firewall: ativo | fail2ban: ativo"
