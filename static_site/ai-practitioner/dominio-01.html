Fundamentos de IA e ML

Conceitos fundamentais de Inteligência Artificial, Machine Learning, Deep Learning e IA Generativa. Tipos de aprendizado, ciclo de vida do ML e serviços AWS.

Hierarquia de Conceitos

A Inteligência Artificial é o campo mais amplo, com subcampos progressivamente mais específicos:

NívelConceitoDescrição
1Inteligência Artificial (IA)Campo amplo que busca criar máquinas capazes de simular inteligência humana
2Machine Learning (ML)Subconjunto de IA — algoritmos que aprendem padrões a partir de dados sem programação explícita
3Deep Learning (DL)Subconjunto de ML — redes neurais com múltiplas camadas que aprendem representações complexas
4IA Generativa (GenAI)Subconjunto de DL — modelos que geram novo conteúdo (texto, imagem, código, áudio)

💡 Dica para o exame: GenAI ⊂ Deep Learning ⊂ Machine Learning ⊂ Inteligência Artificial. Toda GenAI é DL, mas nem todo DL é GenAI.

Tipos de Aprendizado

Aprendizado Supervisionado

O modelo aprende a partir de dados rotulados (input → output conhecido). É o tipo mais comum em produção.

ClassificaçãoCategorias

Prever uma categoria/classe discreta.

Exemplos:
• Spam ou não-spam (binária)
• Análise de sentimento (positivo/negativo/neutro)
• Diagnóstico médico (doença A, B ou C)
• Detecção de fraude (fraude/legítimo)
RegressãoValores

Prever um valor numérico contínuo.

Exemplos:
• Preço de imóvel
• Temperatura amanhã
• Receita do próximo trimestre
• Tempo de entrega estimado

Aprendizado Não-Supervisionado

O modelo encontra padrões em dados sem rótulos. Não há resposta "certa" — o modelo descobre estruturas ocultas.

ClusteringAgrupamento

Agrupa dados similares sem categorias pré-definidas.

Exemplos:
• Segmentação de clientes
• Agrupamento de documentos por tema
• Detecção de anomalias
• Compressão de dados
Redução de DimensionalidadeSimplificação

Reduz o número de features mantendo informações relevantes.

Exemplos:
• PCA (Principal Component Analysis)
• Visualização de dados complexos
• Remoção de ruído

Aprendizado por Reforço

O agente aprende por tentativa e erro, recebendo recompensas ou penalidades por suas ações em um ambiente.

Recompensa / PenalidadeFeedback

O agente maximiza recompensas acumuladas ao longo do tempo.

Exemplos:
• Jogos (AlphaGo, Atari)
• Robótica (navegação autônoma)
• Recomendação de conteúdo
• AWS DeepRacer (carros autônomos)
• Otimização de recursos
ComponentesEstrutura
• Agente: quem toma decisões
• Ambiente: onde o agente atua
• Estado: situação atual
• Ação: o que o agente faz
• Recompensa: feedback do ambiente
• Política: estratégia do agente

🎯 Dicas para o exame:

• "Dados rotulados" → Supervisionado | "Sem rótulos" → Não-supervisionado | "Recompensa" → Reforço

• Classificação = categorias discretas | Regressão = valores contínuos

• AWS DeepRacer = Aprendizado por Reforço

Ciclo de Vida do ML Pipeline

O desenvolvimento de modelos de ML segue um pipeline estruturado com etapas iterativas:

EtapaDescriçãoPalavras-chave / Serviços AWS
1. Definição do ProblemaIdentificar o problema de negócio e definir métricas de sucessoBusiness understanding, KPIs, viabilidade
2. Coleta de DadosReunir dados relevantes de diversas fontesS3, Kinesis, Glue, Data Pipeline
3. Preparação dos DadosLimpar, transformar e preparar dados para treinamentoSageMaker Data Wrangler, Glue ETL, Feature Store
4. Feature EngineeringCriar e selecionar features relevantes para o modeloFeature Store, transformações, normalização
5. TreinamentoTreinar o modelo com algoritmos e hiperparâmetrosSageMaker Training Jobs, algoritmos built-in
6. AvaliaçãoAvaliar performance com métricas e dados de testeAccuracy, Precision, Recall, F1, AUC-ROC
7. Deploy (Implantação)Disponibilizar o modelo para inferência em produçãoSageMaker Endpoints, Batch Transform
8. MonitoramentoMonitorar performance e detectar degradação (drift)SageMaker Model Monitor, CloudWatch

💡 Conceito importante: O pipeline é iterativo — se o modelo não atinge as métricas desejadas, volta-se a etapas anteriores (mais dados, features diferentes, outro algoritmo).

Tipos de Dados

TipoDescriçãoExemplos
EstruturadoDados organizados em tabelas com schema definidoBancos relacionais, CSV, planilhas
Não-estruturadoDados sem formato pré-definidoImagens, vídeos, áudio, texto livre
Semi-estruturadoDados com alguma organização mas sem schema rígidoJSON, XML, logs, e-mails
Rotulado (Labeled)Dados com a resposta correta associadaImagem + "gato", e-mail + "spam"
Não-rotulado (Unlabeled)Dados sem resposta associadaFotos sem descrição, textos sem categoria
Dados de Séries TemporaisDados ordenados no tempoPreços de ações, métricas de servidor, IoT

🎯 Para o exame: Dados rotulados → Supervisionado | Dados não-rotulados → Não-supervisionado | SageMaker Ground Truth é usado para rotular dados.

Métricas de Avaliação de Modelos

Métricas de Classificação

AccuracyAcurácia

Proporção de previsões corretas sobre o total. Boa quando classes são balanceadas.

Accuracy = (TP + TN) / Total
⚠️ Pode ser enganosa com classes desbalanceadas
PrecisionPrecisão

Dos que o modelo disse "positivo", quantos realmente são? Importante quando falso positivo é custoso.

Precision = TP / (TP + FP)
Exemplo: Detecção de spam — não quero perder e-mails legítimos
RecallSensibilidade

Dos que realmente são positivos, quantos o modelo encontrou? Importante quando falso negativo é custoso.

Recall = TP / (TP + FN)
Exemplo: Diagnóstico de câncer — não quero perder nenhum caso
F1-ScoreEquilíbrio

Média harmônica entre Precision e Recall. Útil quando ambos são importantes.

F1 = 2 × (Precision × Recall) / (Precision + Recall)
Bom para classes desbalanceadas
AUC-ROCCurva

Área sob a curva ROC. Mede a capacidade do modelo de distinguir entre classes. Valor de 0.5 = aleatório, 1.0 = perfeito.

AUC = 1.0 → Modelo perfeito
AUC = 0.5 → Modelo aleatório (inútil)
Independente do threshold escolhido

Métricas de Regressão

RMSERoot Mean Squared Error

Raiz da média dos erros ao quadrado. Penaliza erros grandes mais fortemente.

RMSE = √(Σ(yi - ŷi)² / n)
Mesma unidade da variável alvo
Sensível a outliers
MAEMean Absolute Error

Média dos erros absolutos. Mais robusto a outliers que RMSE.

MAE = Σ|yi - ŷi| / n
Mesma unidade da variável alvo
Menos sensível a outliers

Overfitting vs Underfitting

OverfittingSobreajuste

Modelo "decorou" os dados de treino mas não generaliza para dados novos.

Sintomas:
• Alta performance no treino, baixa no teste
• Modelo muito complexo para os dados

Soluções:
• Mais dados de treinamento
• Regularização (L1, L2)
• Dropout (redes neurais)
• Early stopping
• Cross-validation
UnderfittingSubajuste

Modelo é simples demais e não captura os padrões dos dados.

Sintomas:
• Baixa performance tanto no treino quanto no teste
• Modelo muito simples

Soluções:
• Modelo mais complexo
• Mais features
• Menos regularização
• Treinar por mais tempo
• Feature engineering

Tipos de Inferência

Como o modelo treinado faz previsões em produção:

Real-time (Online)Síncrono

Endpoint sempre ativo, resposta em milissegundos. Para aplicações que precisam de resposta imediata.

• SageMaker Real-time Endpoints
• Latência baixa (ms)
• Custo: paga enquanto endpoint está ativo
• Uso: chatbots, recomendações, detecção de fraude
Batch (Lote)Assíncrono

Processa grandes volumes de dados de uma vez. Sem necessidade de resposta imediata.

• SageMaker Batch Transform
• Processa dataset inteiro
• Custo: paga apenas durante processamento
• Uso: scoring mensal, relatórios, ETL
Async (Assíncrono)Fila

Para payloads grandes ou processamento demorado. Requisição entra em fila.

• SageMaker Async Inference
• Timeout de até 1 hora
• Escala para zero quando ocioso
• Uso: processamento de vídeo, documentos grandes
ServerlessOn-demand

Escala automaticamente para zero. Paga apenas por uso. Cold start possível.

• SageMaker Serverless Inference
• Escala para zero automaticamente
• Cold start (latência inicial maior)
• Uso: tráfego imprevisível, baixo volume
