Módulo 01

Fundamentos: VPC Completa

Providers, resources, variables, outputs e os comandos essenciais do Terraform. Construa uma VPC completa do zero.

1. Sintaxe HCL — Blocos Fundamentais

resourceEssencial

Define um recurso de infraestrutura a ser criado/gerenciado.

resource "aws_vpc" "main" {
  cidr_block           = "10.0.0.0/16"
  enable_dns_hostnames = true
  enable_dns_support   = true

  tags = {
    Name        = "main-vpc"
    Environment = "dev"
  }
}
variableInput

Declara variáveis de entrada para parametrizar a infraestrutura.

variable "region" {
  description = "AWS Region"
  type        = string
  default     = "us-east-1"
}

variable "vpc_cidr" {
  description = "CIDR block for VPC"
  type        = string
  default     = "10.0.0.0/16"
}
outputOutput

Exporta valores após o apply para uso externo ou outros módulos.

output "vpc_id" {
  description = "ID da VPC criada"
  value       = aws_vpc.main.id
}

output "public_subnets" {
  description = "IDs das subnets públicas"
  value       = aws_subnet.public[*].id
}
dataConsulta

Consulta recursos existentes sem criar/modificar.

data "aws_availability_zones" "available" {
  state = "available"
}

data "aws_ami" "ubuntu" {
  most_recent = true
  owners      = ["099720109477"]
  filter {
    name   = "name"
    values = ["ubuntu/images/hvm-ssd/*"]
  }
}
localsAuxiliar

Define valores locais calculados para reutilização.

locals {
  common_tags = {
    Project     = "cloudtrilhas"
    Environment = var.environment
    ManagedBy   = "terraform"
  }
  name_prefix = "${var.project}-${var.environment}"
}

2. Provider AWS — Configuração

terraform { } + providerSetup
terraform {
  required_version = ">= 1.5.0"

  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
}

provider "aws" {
  region = var.region

  default_tags {
    tags = local.common_tags
  }
}
Boas práticas: Sempre fixe a versão do provider (~> 5.0) e do Terraform (>= 1.5.0). Use default_tags para aplicar tags automaticamente em todos os recursos.

3. Comandos Terraform — Workflow

terraform initEssencial

Inicializa o diretório, baixa providers e configura backend.

$ terraform init
Initializing the backend...
Initializing provider plugins...
- Finding hashicorp/aws versions...
- Installing hashicorp/aws v5.31.0...

Terraform has been successfully initialized!
terraform planEssencial

Mostra o que será criado/alterado/destruído sem executar.

$ terraform plan
Plan: 8 to add, 0 to change, 0 to destroy.

# Salvar plan para apply seguro:
$ terraform plan -out=tfplan
$ terraform apply tfplan
terraform applyEssencial

Executa as mudanças na infraestrutura real.

$ terraform apply
Do you want to perform these actions?
  Enter a value: yes

Apply complete! Resources: 8 added,
0 changed, 0 destroyed.

# Auto-approve (CI/CD):
$ terraform apply -auto-approve
terraform destroyDestruir

Remove TODA a infraestrutura gerenciada. Cuidado!

$ terraform destroy
Plan: 0 to add, 0 to change, 8 to destroy.

Do you really want to destroy?
  Enter a value: yes

Destroy complete! Resources: 8 destroyed.
terraform fmtQualidade

Formata arquivos HCL no padrão canônico.

$ terraform fmt
main.tf
variables.tf

# Verificar sem alterar:
$ terraform fmt -check
# Recursivo:
$ terraform fmt -recursive
terraform validateQualidade

Valida sintaxe e configuração sem acessar a API.

$ terraform validate
Success! The configuration is valid.

# Útil em CI/CD antes do plan
terraform stateState

Gerencia o state file diretamente.

$ terraform state list
aws_vpc.main
aws_subnet.public[0]
aws_subnet.public[1]

$ terraform state show aws_vpc.main
$ terraform state rm aws_vpc.main
$ terraform import aws_vpc.main vpc-123abc

4. VPC Completa — Recursos de Rede

aws_vpc + aws_subnetRede

VPC com subnets públicas e privadas em múltiplas AZs.

resource "aws_vpc" "main" {
  cidr_block           = var.vpc_cidr
  enable_dns_hostnames = true
  enable_dns_support   = true
  tags = { Name = "${local.name_prefix}-vpc" }
}

resource "aws_subnet" "public" {
  count                   = length(var.public_subnet_cidrs)
  vpc_id                  = aws_vpc.main.id
  cidr_block              = var.public_subnet_cidrs[count.index]
  availability_zone       = data.aws_availability_zones.available.names[count.index]
  map_public_ip_on_launch = true
  tags = { Name = "${local.name_prefix}-public-${count.index + 1}" }
}

resource "aws_subnet" "private" {
  count             = length(var.private_subnet_cidrs)
  vpc_id            = aws_vpc.main.id
  cidr_block        = var.private_subnet_cidrs[count.index]
  availability_zone = data.aws_availability_zones.available.names[count.index]
  tags = { Name = "${local.name_prefix}-private-${count.index + 1}" }
}
aws_internet_gatewayGateway

Permite acesso à internet para subnets públicas.

resource "aws_internet_gateway" "main" {
  vpc_id = aws_vpc.main.id
  tags   = { Name = "${local.name_prefix}-igw" }
}
aws_nat_gatewayGateway

Permite que subnets privadas acessem a internet (saída).

resource "aws_eip" "nat" {
  domain = "vpc"
}

resource "aws_nat_gateway" "main" {
  allocation_id = aws_eip.nat.id
  subnet_id     = aws_subnet.public[0].id
  tags = { Name = "${local.name_prefix}-nat" }
}
aws_route_tableRotas

Tabelas de rota para direcionar tráfego público e privado.

resource "aws_route_table" "public" {
  vpc_id = aws_vpc.main.id
  route {
    cidr_block = "0.0.0.0/0"
    gateway_id = aws_internet_gateway.main.id
  }
  tags = { Name = "${local.name_prefix}-public-rt" }
}

resource "aws_route_table" "private" {
  vpc_id = aws_vpc.main.id
  route {
    cidr_block     = "0.0.0.0/0"
    nat_gateway_id = aws_nat_gateway.main.id
  }
  tags = { Name = "${local.name_prefix}-private-rt" }
}

resource "aws_route_table_association" "public" {
  count          = length(aws_subnet.public)
  subnet_id      = aws_subnet.public[count.index].id
  route_table_id = aws_route_table.public.id
}
Módulo 02

Computação: VPC + EC2

Security groups, key pairs, user data e provisioners. Adicione instâncias EC2 à sua VPC.

1. Security Groups

aws_security_groupSegurança

Firewall virtual que controla tráfego de entrada e saída.

resource "aws_security_group" "web" {
  name        = "${local.name_prefix}-web-sg"
  description = "Security group for web servers"
  vpc_id      = aws_vpc.main.id

  ingress {
    description = "HTTP"
    from_port   = 80
    to_port     = 80
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  ingress {
    description = "HTTPS"
    from_port   = 443
    to_port     = 443
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  ingress {
    description = "SSH"
    from_port   = 22
    to_port     = 22
    protocol    = "tcp"
    cidr_blocks = [var.my_ip]
  }

  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }

  tags = { Name = "${local.name_prefix}-web-sg" }
}

2. Key Pairs e Acesso SSH

aws_key_pairAcesso

Registra chave pública para acesso SSH às instâncias.

resource "aws_key_pair" "deployer" {
  key_name   = "${local.name_prefix}-key"
  public_key = file("~/.ssh/id_rsa.pub")
}

# Ou gerar via Terraform:
resource "tls_private_key" "ec2" {
  algorithm = "RSA"
  rsa_bits  = 4096
}

resource "aws_key_pair" "generated" {
  key_name   = "${local.name_prefix}-generated"
  public_key = tls_private_key.ec2.public_key_openssh
}
user_dataBootstrap

Script executado na primeira inicialização da instância.

resource "aws_instance" "web" {
  ami           = data.aws_ami.ubuntu.id
  instance_type = var.instance_type
  subnet_id     = aws_subnet.public[0].id
  key_name      = aws_key_pair.deployer.key_name

  vpc_security_group_ids = [
    aws_security_group.web.id
  ]

  user_data = <<-EOF
    #!/bin/bash
    apt-get update -y
    apt-get install -y nginx
    systemctl start nginx
    systemctl enable nginx
    echo "Hello from Terraform!" > /var/www/html/index.html
  EOF

  tags = { Name = "${local.name_prefix}-web" }
}

3. Provisioners

⚠️ Atenção: Provisioners são um último recurso. Prefira user_data, Ansible ou Packer. Use apenas quando não houver alternativa nativa.
remote-execProvisioner

Executa comandos na instância remota via SSH.

resource "aws_instance" "app" {
  # ... configuração da instância

  connection {
    type        = "ssh"
    user        = "ubuntu"
    private_key = file("~/.ssh/id_rsa")
    host        = self.public_ip
  }

  provisioner "remote-exec" {
    inline = [
      "sudo apt-get update",
      "sudo apt-get install -y docker.io",
      "sudo systemctl start docker",
    ]
  }
}
local-execProvisioner

Executa comandos na máquina local após criar o recurso.

resource "aws_instance" "app" {
  # ... configuração da instância

  provisioner "local-exec" {
    command = "echo ${self.public_ip} >> hosts.txt"
  }

  provisioner "local-exec" {
    command = "ansible-playbook -i '${self.public_ip},' setup.yml"
  }
}

Módulo 03

Banco de Dados: VPC + EC2 + RDS

Subnet groups, parameter groups e Multi-AZ. Adicione um banco de dados gerenciado à arquitetura.

1. DB Subnet Group

aws_db_subnet_groupRDS

Define em quais subnets o RDS pode ser provisionado. Requer pelo menos 2 AZs.

resource "aws_db_subnet_group" "main" {
  name       = "${local.name_prefix}-db-subnet-group"
  subnet_ids = aws_subnet.private[*].id

  tags = { Name = "${local.name_prefix}-db-subnet-group" }
}

# Security Group para RDS (apenas acesso interno)
resource "aws_security_group" "rds" {
  name        = "${local.name_prefix}-rds-sg"
  description = "Security group for RDS"
  vpc_id      = aws_vpc.main.id

  ingress {
    description     = "MySQL from EC2"
    from_port       = 3306
    to_port         = 3306
    protocol        = "tcp"
    security_groups = [aws_security_group.web.id]
  }

  tags = { Name = "${local.name_prefix}-rds-sg" }
}

2. Parameter Groups

aws_db_parameter_groupConfig

Customiza parâmetros do engine do banco de dados.

resource "aws_db_parameter_group" "main" {
  name   = "${local.name_prefix}-mysql-params"
  family = "mysql8.0"

  parameter {
    name  = "character_set_server"
    value = "utf8mb4"
  }

  parameter {
    name  = "collation_server"
    value = "utf8mb4_unicode_ci"
  }

  parameter {
    name  = "slow_query_log"
    value = "1"
  }

  parameter {
    name  = "long_query_time"
    value = "2"
  }

  tags = { Name = "${local.name_prefix}-mysql-params" }
}

3. RDS Instance — Multi-AZ

aws_db_instanceRDS

Instância RDS com Multi-AZ para alta disponibilidade.

resource "aws_db_instance" "main" {
  identifier     = "${local.name_prefix}-mysql"
  engine         = "mysql"
  engine_version = "8.0"
  instance_class = var.db_instance_class

  allocated_storage     = 20
  max_allocated_storage = 100
  storage_type          = "gp3"
  storage_encrypted     = true

  db_name  = var.db_name
  username = var.db_username
  password = var.db_password

  db_subnet_group_name   = aws_db_subnet_group.main.name
  vpc_security_group_ids = [aws_security_group.rds.id]
  parameter_group_name   = aws_db_parameter_group.main.name

  multi_az            = true
  publicly_accessible = false

  backup_retention_period = 7
  backup_window           = "03:00-04:00"
  maintenance_window      = "Mon:04:00-Mon:05:00"

  skip_final_snapshot       = false
  final_snapshot_identifier = "${local.name_prefix}-final-snapshot"
  deletion_protection       = true

  tags = { Name = "${local.name_prefix}-mysql" }
}
Multi-AZHA

Failover automático para outra AZ em caso de falha.

# Multi-AZ = true:
# - Réplica síncrona em outra AZ
# - Failover automático (~60s)
# - Mesmo endpoint DNS
# - Custo: ~2x da instância single

# Quando usar:
# ✅ Produção (sempre)
# ❌ Dev/Lab (custo desnecessário)

# Variável condicional:
variable "multi_az" {
  type    = bool
  default = false  # dev
}
# terraform.tfvars (prod):
# multi_az = true
Sensitive VariablesSegurança

Proteja credenciais do banco no state e logs.

variable "db_password" {
  description = "RDS master password"
  type        = string
  sensitive   = true
}

# Opção 1: terraform.tfvars (gitignore!)
# db_password = "SuperSecret123!"

# Opção 2: Environment variable
# export TF_VAR_db_password="SuperSecret123!"

# Opção 3: AWS Secrets Manager
data "aws_secretsmanager_secret_version" "db" {
  secret_id = "prod/rds/password"
}
Módulo 04

Storage e Arquitetura: VPC + EC2 + RDS + S3

Buckets, policies, lifecycle rules e arquitetura completa. O módulo final integra todos os componentes.

1. S3 Bucket

aws_s3_bucketStorage

Bucket S3 com versionamento e criptografia.

resource "aws_s3_bucket" "assets" {
  bucket = "${local.name_prefix}-assets-${data.aws_caller_identity.current.account_id}"

  tags = { Name = "${local.name_prefix}-assets" }
}

resource "aws_s3_bucket_versioning" "assets" {
  bucket = aws_s3_bucket.assets.id
  versioning_configuration {
    status = "Enabled"
  }
}

resource "aws_s3_bucket_server_side_encryption_configuration" "assets" {
  bucket = aws_s3_bucket.assets.id
  rule {
    apply_server_side_encryption_by_default {
      sse_algorithm = "AES256"
    }
  }
}

resource "aws_s3_bucket_public_access_block" "assets" {
  bucket                  = aws_s3_bucket.assets.id
  block_public_acls       = true
  block_public_policy     = true
  ignore_public_acls      = true
  restrict_public_buckets = true
}

2. Bucket Policy

aws_s3_bucket_policyIAM

Política que controla quem pode acessar o bucket e como.

resource "aws_s3_bucket_policy" "assets" {
  bucket = aws_s3_bucket.assets.id
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Sid       = "AllowEC2Access"
        Effect    = "Allow"
        Principal = {
          AWS = aws_iam_role.ec2_role.arn
        }
        Action = [
          "s3:GetObject",
          "s3:PutObject",
          "s3:ListBucket"
        ]
        Resource = [
          aws_s3_bucket.assets.arn,
          "${aws_s3_bucket.assets.arn}/*"
        ]
      },
      {
        Sid       = "DenyInsecureTransport"
        Effect    = "Deny"
        Principal = "*"
        Action    = "s3:*"
        Resource  = [
          aws_s3_bucket.assets.arn,
          "${aws_s3_bucket.assets.arn}/*"
        ]
        Condition = {
          Bool = { "aws:SecureTransport" = "false" }
        }
      }
    ]
  })
}

3. Lifecycle Rules

aws_s3_bucket_lifecycle_configurationCusto

Regras automáticas para transição e expiração de objetos.

resource "aws_s3_bucket_lifecycle_configuration" "assets" {
  bucket = aws_s3_bucket.assets.id

  rule {
    id     = "transition-to-ia"
    status = "Enabled"

    transition {
      days          = 30
      storage_class = "STANDARD_IA"
    }

    transition {
      days          = 90
      storage_class = "GLACIER"
    }

    expiration {
      days = 365
    }
  }

  rule {
    id     = "cleanup-incomplete-uploads"
    status = "Enabled"

    abort_incomplete_multipart_upload {
      days_after_initiation = 7
    }
  }

  rule {
    id     = "expire-old-versions"
    status = "Enabled"

    noncurrent_version_expiration {
      noncurrent_days = 30
    }
  }
}

4. State Management — Remote Backend

Por que Remote State? O state local (terraform.tfstate) não funciona em equipe. Use S3 + DynamoDB para locking e versionamento.
backend "s3"State

Configuração do backend remoto com S3 e DynamoDB para locking.

terraform {
  backend "s3" {
    bucket         = "cloudtrilhas-terraform-state"
    key            = "prod/vpc-ec2-rds-s3/terraform.tfstate"
    region         = "us-east-1"
    encrypt        = true
    dynamodb_table = "terraform-state-lock"
  }
}

# Criar os recursos do backend (executar primeiro, separado):
resource "aws_s3_bucket" "terraform_state" {
  bucket = "cloudtrilhas-terraform-state"
}

resource "aws_s3_bucket_versioning" "terraform_state" {
  bucket = aws_s3_bucket.terraform_state.id
  versioning_configuration { status = "Enabled" }
}

resource "aws_dynamodb_table" "terraform_lock" {
  name         = "terraform-state-lock"
  billing_mode = "PAY_PER_REQUEST"
  hash_key     = "LockID"
  attribute {
    name = "LockID"
    type = "S"
  }
}
