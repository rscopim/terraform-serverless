Otimização de Custos

Modelos de precificação, storage classes, right-sizing, ferramentas de gerenciamento de custos, data transfer e estratégias serverless. Este domínio representa 20% do exame.

1. Modelos de Precificação EC2

ModeloDescontoCompromissoCaso de Uso
On-Demand0% (preço cheio)NenhumWorkloads imprevisíveis, dev/test, picos curtos. Paga por segundo (Linux) ou hora (Windows).
Reserved Instances (RI)Até 72%1 ou 3 anosWorkloads estáveis e previsíveis. Standard RI (não muda) vs Convertible RI (pode trocar família).
Savings PlansAté 72%1 ou 3 anos ($/hora)Compromisso de gasto (não de instância). Compute SP (EC2+Lambda+Fargate) ou EC2 Instance SP.
Spot InstancesAté 90%Nenhum (pode ser interrompido)Workloads tolerantes a interrupção: batch, CI/CD, big data, containers stateless.
Dedicated HostsVariávelOn-Demand ou ReservedCompliance, licenças por socket/core (BYOL), requisitos regulatórios.
Dedicated InstancesVariávelOn-DemandHardware dedicado sem controle de placement. Menos controle que Dedicated Host.
Savings PlansFlexível
Compute Savings Plans:
• Aplica a EC2, Lambda e Fargate
• Qualquer região, família, OS, tenancy
• Mais flexível que RI
• Compromisso: $/hora por 1 ou 3 anos

EC2 Instance Savings Plans:
• Específico para família em uma região
• Ex: M5 em us-east-1
• Maior desconto que Compute SP
• Flexível em AZ, size, OS

Comparação com RI:
• SP é mais simples de gerenciar
• SP aplica automaticamente o desconto
• RI Standard não pode mudar família
• RI Convertible pode mudar (menor desconto)

💡 Savings Plans é a recomendação atual da AWS
   para a maioria dos cenários de desconto
Spot InstancesEconomia
Como funciona:
• Capacidade ociosa da AWS com desconto
• Preço flutua baseado em oferta/demanda
• AWS pode reclamar com 2 min de aviso
• Spot Fleet: mix de Spot + On-Demand

Estratégias Spot:
• Spot Fleet com diversificação de tipos
• Spot + Auto Scaling (mixed instances)
• Spot Block (1-6 horas, deprecated)

Boas práticas:
• Diversificar instance types e AZs
• Usar checkpointing para jobs longos
• Combinar com On-Demand para baseline
• Spot para scaling, On-Demand para base

NÃO usar Spot para:
• Databases
• Aplicações stateful críticas
• Workloads que não toleram interrupção

2. S3 Storage Classes e Lifecycle

ClasseDisponibilidadeMin StorageCaso de Uso
S3 Standard99.99%—Dados acessados frequentemente. Sem taxa de retrieval.
S3 Intelligent-Tiering99.9%—Padrão de acesso desconhecido. Move automaticamente entre tiers. Taxa de monitoramento.
S3 Standard-IA99.9%30 diasAcesso infrequente mas precisa de acesso rápido. Taxa de retrieval por GB.
S3 One Zone-IA99.5%30 diasDados recriáveis, infrequentes. Uma AZ apenas. 20% mais barato que Standard-IA.
S3 Glacier Instant Retrieval99.9%90 diasArquivo com acesso imediato (ms). Acesso ~1x por trimestre.
S3 Glacier Flexible Retrieval99.99%90 diasArquivo com retrieval em minutos a horas. Expedited (1-5min), Standard (3-5h), Bulk (5-12h).
S3 Glacier Deep Archive99.99%180 diasArquivo de longo prazo. Retrieval: Standard (12h), Bulk (48h). Mais barato.
Lifecycle RulesAutomação
Transition Actions (mover entre classes):
• Standard → Standard-IA (após 30 dias)
• Standard-IA → Glacier Instant (após 60 dias)
• Glacier Instant → Glacier Flexible (após 90 dias)
• Glacier Flexible → Deep Archive (após 180 dias)

Expiration Actions (deletar):
• Expirar objetos após X dias
• Expirar versões anteriores
• Deletar incomplete multipart uploads
• Deletar delete markers expirados

Regras:
• Mínimo 30 dias em Standard antes de transição para IA
• Mínimo 30 dias em IA antes de transição para Glacier
• Pode aplicar por prefixo ou tag
• Versões atuais e anteriores separadamente

💡 S3 Intelligent-Tiering é ideal quando não se conhece o padrão de acesso
   (sem taxa de retrieval, apenas monitoramento)

3. Right-Sizing

AWS Compute OptimizerRecomendações
Analisa métricas e recomenda:
• EC2: instance type ideal
• EBS: volume type e size
• Lambda: memory configuration
• ECS on Fargate: CPU e memory

Baseado em:
• Utilização de CPU, memória, rede
• Histórico de 14 dias (ou mais com Enhanced)
• Machine Learning para prever necessidades

Classificações:
• Over-provisioned → reduzir (economia)
• Under-provisioned → aumentar (performance)
• Optimized → manter

Enhanced Infrastructure Metrics:
• Até 3 meses de histórico
• Recomendações mais precisas
• Custo adicional
CloudWatch MetricsMonitoramento
Métricas para right-sizing:

EC2:
• CPUUtilization (< 10% = over-provisioned)
• NetworkIn/Out
• Disk Read/Write (instance store)
• Nota: memória requer CloudWatch Agent

EBS:
• VolumeReadOps / VolumeWriteOps
• VolumeQueueLength (> 1 = bottleneck)
• BurstBalance (gp2/st1/sc1)

RDS:
• CPUUtilization
• FreeableMemory
• ReadIOPS / WriteIOPS
• DatabaseConnections

Trusted Advisor:
• Low utilization EC2 instances
• Idle Load Balancers
• Underutilized EBS volumes
• Unassociated Elastic IPs

4. Ferramentas de Gerenciamento de Custos

FerramentaFunçãoQuando Usar
AWS Cost ExplorerVisualização e análise de custosAnalisar gastos passados, prever futuros, identificar tendências. Recomendações de RI/SP.
AWS BudgetsAlertas e limites de gastosDefinir orçamentos (custo, uso, RI/SP coverage). Alertas por e-mail/SNS. Budget Actions automáticas.
Cost Anomaly DetectionDetecção de gastos anormaisML detecta gastos inesperados automaticamente. Alertas proativos. Root cause analysis.
Compute OptimizerRecomendações de right-sizingIdentificar recursos over/under-provisioned. EC2, EBS, Lambda, ECS.
Cost and Usage Report (CUR)Relatório detalhado de custosDados granulares para análise avançada. Integra com Athena, QuickSight, Redshift.
Billing ConductorBilling customizadoCriar billing groups, aplicar pricing rules, showback/chargeback para departamentos.
AWS Budgets — ActionsAutomação
Budget Actions (automação de resposta):
• Aplicar IAM policy restritiva quando budget excedido
• Aplicar SCP para bloquear criação de recursos
• Parar instâncias EC2 automaticamente

Tipos de Budget:
• Cost Budget — limite de gasto em $
• Usage Budget — limite de uso (horas, GB)
• RI Utilization Budget — alerta se RI subutilizado
• RI Coverage Budget — alerta se cobertura RI baixa
• Savings Plans Utilization/Coverage

Alertas:
• Actual (quando atingir X%)
• Forecasted (quando previsão atingir X%)
• Múltiplos thresholds (50%, 80%, 100%)
• Notificação: e-mail, SNS, Chatbot

5. Custos de Data Transfer

Regras de TransferCusto
GRATUITO:
• Inbound (internet → AWS) = grátis
• Dentro da mesma AZ = grátis
• S3 → CloudFront = grátis
• Entre serviços na mesma região (alguns)

PAGO:
• Outbound (AWS → internet) = $$
• Entre AZs na mesma região = $
• Entre regiões = $$
• NAT Gateway processing = $

Otimizações:
• VPC Endpoints (evita NAT Gateway)
• CloudFront (reduz outbound)
• S3 Transfer Acceleration (uploads)
• Manter recursos na mesma AZ quando possível
• Direct Connect (preço menor que internet)

💡 Data transfer é frequentemente o custo
   "escondido" que surpreende em produção
Serverless Cost OptimizationServerless
Lambda:
• Paga por: requests + duration (GB-seconds)
• Otimizar memória (Power Tuning)
• Provisioned Concurrency tem custo fixo
• ARM (Graviton) = 20% mais barato

API Gateway:
• REST API: por request + data transfer
• HTTP API: 70% mais barato que REST
• WebSocket: por mensagem + connection time

DynamoDB:
• On-Demand: paga por request (RCU/WCU)
• Provisioned: capacidade reservada (mais barato)
• Reserved Capacity: desconto adicional
• Auto Scaling para provisioned

Fargate:
• Paga por vCPU + memória por segundo
• Spot Fargate: até 70% desconto
• Compute Savings Plans aplicável

6. Estratégias de Tagging

Cost Allocation TagsOrganização
Tags para alocação de custos:

AWS-generated tags (prefixo aws:):
• aws:createdBy — quem criou o recurso
• Ativadas no Billing Console

User-defined tags:
• Environment: prod, dev, staging
• Project: projeto-x, projeto-y
• Team: backend, frontend, data
• CostCenter: CC-001, CC-002
• Owner: email do responsável

Boas práticas:
• Definir tag policy na Organization
• Enforcement via SCPs ou Config Rules
• Tag Editor para aplicar em massa
• Ativar tags no Cost Explorer para filtrar custos
• Automação: Lambda + EventBridge para tag compliance

Tag Policies (Organizations):
• Define tags obrigatórias e valores permitidos
• Reporta non-compliance
• Não bloqueia criação (apenas reporta)
• Combine com SCPs para enforcement

🎯 Para o exame: Savings Plans > RI para flexibilidade. Spot para workloads tolerantes a interrupção. S3 Intelligent-Tiering para padrão desconhecido. VPC Endpoints reduzem custo de NAT. Tags são essenciais para cost allocation. Cost Anomaly Detection usa ML para alertas proativos.
