Módulo 01

Fundamentos de Redes

Conceitos essenciais de comunicação de dados, tipos de redes, topologias e meios de transmissão.

1. Conceitos Básicos

O que é uma rede? Um conjunto de dispositivos interconectados que compartilham recursos e trocam dados usando protocolos padronizados.
Tipos de RedeConceito

Classificação por abrangência geográfica.

LAN  — Local Area Network    (escritório, casa)
MAN  — Metropolitan Area     (cidade, campus)
WAN  — Wide Area Network     (países, continentes)
WLAN — Wireless LAN          (Wi-Fi)
PAN  — Personal Area Network (Bluetooth, NFC)
TopologiasConceito

Forma como os dispositivos são conectados.

Estrela  — Hub/Switch central (mais comum)
Barramento — Cabo compartilhado (legado)
Anel     — Token Ring (legado)
Malha    — Full/Partial mesh (alta disponibilidade)
Árvore   — Hierárquica (redes corporativas)
Meios de TransmissãoFísico

Cabos e conexões físicas.

Par trançado (UTP/STP):
  Cat5e — 1 Gbps, 100m
  Cat6  — 10 Gbps, 55m
  Cat6a — 10 Gbps, 100m

Fibra óptica:
  Monomodo — longa distância (km)
  Multimodo — curta distância (campus)

Wireless: 802.11ac (Wi-Fi 5), 802.11ax (Wi-Fi 6)

2. Dispositivos de Rede

SwitchCamada 2

Encaminha frames baseado em endereços MAC. Opera na camada de enlace.

Funcionalidades:
- Tabela MAC (CAM table)
- VLANs
- Spanning Tree (STP)
- Port Security
- PoE (Power over Ethernet)
RoteadorCamada 3

Encaminha pacotes entre redes diferentes usando endereços IP.

Funcionalidades:
- Tabela de rotas
- NAT/PAT
- ACLs (Access Control Lists)
- DHCP Server
- VPN Gateway
- QoS (Quality of Service)
FirewallSegurança

Filtra tráfego entre redes com base em regras.

Tipos:
- Stateless (filtro de pacotes simples)
- Stateful (rastreia conexões)
- NGFW (Next-Gen: DPI, IPS, App Control)
- WAF (Web Application Firewall)
Access PointWireless

Fornece conectividade Wi-Fi aos dispositivos.

Conceitos:
- SSID (nome da rede)
- Canais (2.4 GHz / 5 GHz / 6 GHz)
- WPA3 (segurança)
- Roaming (transição entre APs)
- Controller-based vs Autonomous
Módulo 02

Modelo OSI e TCP/IP

Os modelos de referência que definem como a comunicação em rede é organizada em camadas.

1. Modelo OSI — 7 Camadas

Mnemônico: "All People Seem To Need Data Processing" (de cima para baixo)
Camadas OSIModelo
Camada 7 — Aplicação     | HTTP, HTTPS, FTP, DNS, SMTP, SSH
Camada 6 — Apresentação  | SSL/TLS, JPEG, ASCII, criptografia
Camada 5 — Sessão        | NetBIOS, RPC, controle de sessão
Camada 4 — Transporte    | TCP (confiável), UDP (rápido)
Camada 3 — Rede          | IP, ICMP, ARP, roteamento
Camada 2 — Enlace        | Ethernet, MAC, switches, frames
Camada 1 — Física        | Cabos, sinais elétricos, conectores

PDU por camada:
  Camada 4: Segmento (TCP) / Datagrama (UDP)
  Camada 3: Pacote
  Camada 2: Frame
  Camada 1: Bits

2. Modelo TCP/IP — 4 Camadas

TCP/IP vs OSIComparação
TCP/IP              OSI Equivalente         Protocolos
─────────────────────────────────────────────────────────
Aplicação           7 + 6 + 5               HTTP, DNS, FTP, SSH
Transporte          4                       TCP, UDP
Internet            3                       IP, ICMP, ARP
Acesso à Rede      2 + 1                   Ethernet, Wi-Fi
TCP vs UDPTransporte

Dois protocolos de transporte com características distintas.

TCP (Transmission Control Protocol):
- Orientado a conexão (3-way handshake)
- Confiável (ACK, retransmissão)
- Controle de fluxo e congestionamento
- Uso: HTTP, SSH, FTP, SMTP

UDP (User Datagram Protocol):
- Sem conexão (connectionless)
- Sem garantia de entrega
- Menor overhead, mais rápido
- Uso: DNS, DHCP, VoIP, streaming
3-Way HandshakeTCP

Estabelecimento de conexão TCP.

Cliente → Servidor: SYN (seq=100)
Servidor → Cliente: SYN-ACK (seq=300, ack=101)
Cliente → Servidor: ACK (seq=101, ack=301)

Encerramento (4-way):
Cliente → FIN
Servidor → ACK
Servidor → FIN
Cliente → ACK

Módulo 03

Endereçamento IP e Sub-redes

IPv4, IPv6, CIDR, cálculo de sub-redes e planejamento de endereçamento.

1. Endereçamento IPv4

IPv4: 32 bits divididos em 4 octetos. Formato: 192.168.1.100. Total: ~4,3 bilhões de endereços.
Classes de IP (legado)Conceito
Classe A: 1.0.0.0   – 126.255.255.255   /8   (16M hosts)
Classe B: 128.0.0.0 – 191.255.255.255   /16  (65K hosts)
Classe C: 192.0.0.0 – 223.255.255.255   /24  (254 hosts)
Classe D: 224.0.0.0 – 239.255.255.255   (Multicast)
Classe E: 240.0.0.0 – 255.255.255.255   (Reservado)

⚠️ Classful é legado — hoje usamos CIDR (Classless)
IPs Privados (RFC 1918)Importante

Não roteáveis na internet. Usados em redes internas.

10.0.0.0/8       — 10.0.0.0 a 10.255.255.255
172.16.0.0/12    — 172.16.0.0 a 172.31.255.255
192.168.0.0/16   — 192.168.0.0 a 192.168.255.255

Outros reservados:
127.0.0.0/8      — Loopback
169.254.0.0/16   — Link-local (APIPA)
0.0.0.0          — Default route
IPs PúblicosInternet

Roteáveis na internet. Atribuídos por ISPs/RIRs.

Características:
- Únicos globalmente
- Atribuídos por IANA → RIRs → ISPs
- Necessários para servidores públicos
- Escassos (IPv4 esgotado)

RIRs regionais:
  ARIN    — América do Norte
  LACNIC  — América Latina
  RIPE    — Europa
  APNIC   — Ásia-Pacífico
  AFRINIC — África

2. Sub-redes (Subnetting) e CIDR

CIDR — Classless Inter-Domain RoutingEssencial
Notação CIDR: IP/prefixo → 192.168.1.0/24

Máscara de sub-rede:
/8  = 255.0.0.0       → 16.777.214 hosts
/16 = 255.255.0.0     → 65.534 hosts
/24 = 255.255.255.0   → 254 hosts
/25 = 255.255.255.128 → 126 hosts
/26 = 255.255.255.192 → 62 hosts
/27 = 255.255.255.224 → 30 hosts
/28 = 255.255.255.240 → 14 hosts
/30 = 255.255.255.252 → 2 hosts (ponto-a-ponto)
/32 = 255.255.255.255 → 1 host (host route)

Fórmula: Hosts = 2^(32 - prefixo) - 2
Exemplo de SubnettingPrática
Rede: 192.168.10.0/24 → dividir em 4 sub-redes

Novo prefixo: /26 (emprestamos 2 bits → 2² = 4 sub-redes)

Sub-rede 1: 192.168.10.0/26   (hosts: .1 a .62,   broadcast: .63)
Sub-rede 2: 192.168.10.64/26  (hosts: .65 a .126, broadcast: .127)
Sub-rede 3: 192.168.10.128/26 (hosts: .129 a .190, broadcast: .191)
Sub-rede 4: 192.168.10.192/26 (hosts: .193 a .254, broadcast: .255)

Cada sub-rede: 62 hosts utilizáveis

3. IPv6 — Visão Geral

IPv6Futuro
Formato: 128 bits em 8 grupos hexadecimais
Exemplo: 2001:0db8:85a3:0000:0000:8a2e:0370:7334
Abreviado: 2001:db8:85a3::8a2e:370:7334

Tipos de endereço:
  ::1/128          — Loopback
  fe80::/10        — Link-local (auto-configuração)
  2000::/3         — Global Unicast (público)
  fc00::/7         — Unique Local (privado)
  ff00::/8         — Multicast

Vantagens sobre IPv4:
- Espaço praticamente ilimitado (3.4 × 10³⁸)
- Sem necessidade de NAT
- Auto-configuração (SLAAC)
- IPSec nativo
- Header simplificado
Módulo 04

Comandos de Diagnóstico

Ferramentas essenciais para troubleshooting e análise de conectividade em redes.

1. Conectividade e Resolução

pingICMP

Testa conectividade usando pacotes ICMP Echo Request/Reply.

ping 8.8.8.8              # teste básico
ping -c 4 google.com      # 4 pacotes (Linux)
ping -t google.com         # contínuo (Windows)
ping -s 1472 -M do host   # testa MTU

Interpretação:
- Reply: conectividade OK
- Request timed out: host/firewall bloqueando
- Destination unreachable: rota inexistente
- TTL expired: muitos saltos
traceroute / tracertRota

Mostra o caminho (saltos) até o destino.

traceroute google.com       # Linux (UDP)
tracert google.com          # Windows (ICMP)
traceroute -I google.com    # Linux com ICMP
mtr google.com              # traceroute + ping

Cada linha = um roteador no caminho
* * * = roteador não responde (filtrado)
Latência alta = possível gargalo
nslookup / digDNS

Consulta registros DNS.

nslookup google.com
nslookup -type=MX gmail.com
nslookup google.com 8.8.8.8  # DNS específico

dig google.com +short
dig google.com A              # registro A
dig google.com MX             # registro MX
dig google.com NS             # nameservers
dig @8.8.8.8 google.com      # consulta DNS específico
dig google.com +trace         # resolução completa
host / whoisDNS

Consultas rápidas de DNS e registro de domínio.

host google.com
host -t AAAA google.com    # IPv6
host 8.8.8.8               # reverso

whois google.com           # info do domínio
whois 200.160.2.3          # info do IP

2. Conexões e Portas

netstat / ssEssencial

Exibe conexões de rede, portas em escuta e estatísticas.

# ss (moderno, substitui netstat)
ss -tuln                    # portas TCP/UDP em escuta
ss -tunap                   # com PID e nome do processo
ss -s                       # estatísticas resumidas
ss state established        # conexões ativas
ss -tuln | grep :443        # quem escuta na 443

# netstat (legado, ainda útil)
netstat -tuln               # portas em escuta
netstat -an                 # todas as conexões
netstat -rn                 # tabela de rotas
netstat -i                  # estatísticas de interface
nmapScanner

Scanner de portas e descoberta de rede.

nmap 192.168.1.1            # scan básico
nmap -sV 192.168.1.1        # versão dos serviços
nmap -O 192.168.1.1         # detecção de OS
nmap -p 80,443 192.168.1.0/24  # portas específicas
nmap -sn 192.168.1.0/24     # ping sweep (hosts ativos)
nmap -A 192.168.1.1         # scan agressivo
tcpdumpCaptura

Captura e analisa pacotes em tempo real.

sudo tcpdump -i eth0              # todo tráfego
sudo tcpdump -i eth0 port 80      # apenas porta 80
sudo tcpdump -i eth0 host 10.0.0.1  # host específico
sudo tcpdump -i eth0 -c 100       # 100 pacotes
sudo tcpdump -i eth0 -w captura.pcap  # salva arquivo
sudo tcpdump -r captura.pcap      # lê arquivo

# Filtros combinados
sudo tcpdump -i eth0 'tcp port 443 and host 10.0.0.5'

Módulo 05

Switches e VLANs

Switching na camada 2, segmentação com VLANs, trunking e Spanning Tree Protocol.

1. Fundamentos de Switching

Funcionamento do SwitchCamada 2
Processo de encaminhamento:
1. Frame chega na porta → switch lê MAC de origem
2. Aprende: associa MAC à porta (tabela CAM/MAC)
3. Verifica MAC de destino na tabela
4. Se encontra → encaminha para porta específica (unicast)
5. Se não encontra → flood para todas as portas (exceto origem)

Modos de switching:
- Store-and-Forward: recebe frame completo, verifica CRC, encaminha
- Cut-Through: encaminha após ler MAC destino (mais rápido)
- Fragment-Free: lê 64 bytes antes de encaminhar

2. VLANs (Virtual LANs)

VLAN: Segmenta logicamente uma rede física em múltiplos domínios de broadcast. Melhora segurança, performance e gerenciamento.
Configuração de VLANs (Cisco IOS)Config
# Criar VLANs
Switch(config)# vlan 10
Switch(config-vlan)# name FINANCEIRO
Switch(config)# vlan 20
Switch(config-vlan)# name TI
Switch(config)# vlan 30
Switch(config-vlan)# name GUEST

# Atribuir porta a uma VLAN (Access)
Switch(config)# interface fa0/1
Switch(config-if)# switchport mode access
Switch(config-if)# switchport access vlan 10

# Verificação
Switch# show vlan brief
Switch# show interfaces trunk
Switch# show mac address-table
Trunking (802.1Q)Inter-Switch
# Trunk carrega múltiplas VLANs entre switches
Switch(config)# interface gi0/1
Switch(config-if)# switchport mode trunk
Switch(config-if)# switchport trunk allowed vlan 10,20,30
Switch(config-if)# switchport trunk native vlan 99

# 802.1Q: adiciona tag de 4 bytes ao frame
# Native VLAN: frames sem tag (segurança: não usar VLAN 1)

# Inter-VLAN Routing (Router-on-a-Stick)
Router(config)# interface gi0/0.10
Router(config-subif)# encapsulation dot1Q 10
Router(config-subif)# ip address 192.168.10.1 255.255.255.0
Router(config)# interface gi0/0.20
Router(config-subif)# encapsulation dot1Q 20
Router(config-subif)# ip address 192.168.20.1 255.255.255.0

3. Spanning Tree Protocol (STP)

STP / RSTPRedundância
Problema: loops em topologias redundantes → broadcast storm
Solução: STP bloqueia portas redundantes, mantém caminho livre de loops

Eleição:
1. Root Bridge: switch com menor Bridge ID (prioridade + MAC)
2. Root Port: melhor caminho até o Root Bridge
3. Designated Port: melhor porta por segmento
4. Blocked Port: portas redundantes bloqueadas

Versões:
- STP (802.1D): convergência lenta (~50s)
- RSTP (802.1w): convergência rápida (~1-2s)
- PVST+: STP por VLAN (Cisco)

Switch(config)# spanning-tree mode rapid-pvst
Switch(config)# spanning-tree vlan 10 root primary

2. OSPF (Open Shortest Path First)

OSPFIGP
# Protocolo Link-State, usa algoritmo Dijkstra (SPF)
# Métrica: custo (baseado em bandwidth)
# AD (Administrative Distance): 110

# Conceitos:
# - Áreas (Area 0 = backbone, obrigatória)
# - LSA (Link-State Advertisements)

# Configuração básica
Router(config)# router ospf 1
Router(config-router)# network 192.168.1.0 0.0.0.255 area 0
Router(config-router)# network 10.0.0.0 0.0.0.255 area 1
Router(config-router)# passive-interface gi0/0

# Verificação
Router# show ip ospf neighbor
Router# show ip ospf interface brief
Router# show ip route ospf

3. BGP (Border Gateway Protocol)

BGPEGP
# Protocolo Path-Vector, usado entre Sistemas Autônomos (AS)

Proteção de redes com firewalls, ACLs, IDS/IPS e boas práticas de segurança.

1. Access Control Lists (ACLs)

ACLs — Cisco IOSFiltro

Router(config-ext-nacl)# permit udp any any eq 53

Router# show access-lists

2. Firewalls Linux (iptables / ufw)

iptablesLinux
# Chains: INPUT (entrada), OUTPUT (saída), FORWARD (encaminhamento)
# Targets: ACCEPT, DROP, REJECT, LOG

# Política padrão: bloquear tudo
sudo iptables -P INPUT DROP
sudo iptables -P FORWARD DROP
sudo iptables -P OUTPUT ACCEPT

# Permitir loopback
sudo iptables -A INPUT -i lo -j ACCEPT

# Permitir conexões estabelecidas
sudo iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT

# Permitir SSH, HTTP, HTTPS
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 80 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT

# Bloquear IP específico
sudo iptables -A INPUT -s 10.0.0.50 -j DROP

# Listar e salvar
sudo iptables -L -n -v
sudo iptables-save > /etc/iptables/rules.v4
ufw (Uncomplicated Firewall)Simples
# Frontend simplificado para iptables
sudo ufw enable
sudo ufw default deny incoming
sudo ufw default allow outgoing

# Regras
sudo ufw allow 22/tcp                    # SSH
sudo ufw allow 80,443/tcp                # Web
sudo ufw allow from 192.168.1.0/24       # rede interna
sudo ufw allow from 10.0.0.5 to any port 3306  # MySQL de IP específico
sudo ufw deny from 203.0.113.0/24        # bloquear rede

# Gerenciamento
sudo ufw status verbose
sudo ufw status numbered
sudo ufw delete 3                        # remove regra 3
sudo ufw reset                           # limpa tudo

3. IDS/IPS e Segurança Avançada

IDS vs IPSDetecção
IDS (Intrusion Detection System):
- Monitora e alerta (passivo)
- Não bloqueia tráfego
- Ferramentas: Snort, Suricata, OSSEC

IPS (Intrusion Prevention System):
- Monitora e bloqueia (ativo)
- Inline no tráfego
- Ferramentas: Suricata, Snort (inline)

Tipos de detecção:
- Signature-based (padrões conhecidos)
- Anomaly-based (desvio do normal)
- Heuristic (comportamento)
Boas PráticasSegurança
Defense in Depth:
1. Segmentação (VLANs, subnets)
2. Firewall perimetral + interno
3. IDS/IPS
4. Autenticação forte (802.1X)
5. Criptografia (TLS, IPSec)
6. Monitoramento contínuo
7. Patch management
8. Princípio do menor privilégio

Ataques comuns:
- ARP Spoofing → DAI (Dynamic ARP Inspection)
- MAC Flooding → Port Security
- VLAN Hopping → Desabilitar DTP
- DDoS → Rate limiting, CDN
Módulo 08

Serviços de Rede: DNS, DHCP, NAT e VPN

Serviços fundamentais que sustentam a operação de redes modernas.

1. DNS (Domain Name System)

Registros DNSEssencial
Tipos de registro:
  A      — Nome → IPv4           (example.com → 93.184.216.34)
  AAAA   — Nome → IPv6           (example.com → 2606:2800:...)
  CNAME  — Alias → outro nome    (www → example.com)
  MX     — Mail Exchange          (prioridade + servidor de e-mail)
  NS     — Nameserver             (ns1.example.com)
  TXT    — Texto livre            (SPF, DKIM, verificação)
  SOA    — Start of Authority     (info da zona)
  PTR    — IP → Nome (reverso)    (34.216.184.93 → example.com)
  SRV    — Serviço + porta        (_sip._tcp.example.com)

Hierarquia: Root (.) → TLD (.com) → Domain (google) → Subdomain (www)

Resolução:
1. Cache local → 2. Resolver recursivo → 3. Root → 4. TLD → 5. Autoritativo

2. DHCP (Dynamic Host Configuration Protocol)

DHCP — Processo DORAAutomático
Processo de obtenção de IP (DORA):
1. Discover — Cliente envia broadcast buscando servidor DHCP
2. Offer    — Servidor oferece IP disponível
3. Request  — Cliente aceita a oferta
4. Acknowledge — Servidor confirma e entrega configuração

Informações fornecidas:
- Endereço IP
- Máscara de sub-rede
- Default Gateway
- Servidores DNS
- Lease time (tempo de concessão)

# Configuração (Cisco IOS)
Router(config)# ip dhcp pool LAN
Router(dhcp-config)# network 192.168.1.0 255.255.255.0
Router(dhcp-config)# default-router 192.168.1.1
Router(dhcp-config)# dns-server 8.8.8.8 8.8.4.4
Router(dhcp-config)# lease 7
Router(config)# ip dhcp excluded-address 192.168.1.1 192.168.1.10

3. NAT/PAT (Network Address Translation)

NAT e PATTradução
Tipos de NAT:
- Static NAT: 1 IP privado → 1 IP público (servidores)
- Dynamic NAT: pool de IPs públicos compartilhados
- PAT/NAT Overload: múltiplos IPs privados → 1 IP público (mais comum!)

PAT usa portas para diferenciar conexões:
  192.168.1.10:5001 → 203.0.113.1:40001
  192.168.1.20:5002 → 203.0.113.1:40002
  192.168.1.30:5003 → 203.0.113.1:40003

# Configuração PAT (Cisco)
Router(config)# access-list 1 permit 192.168.1.0 0.0.0.255
Router(config)# ip nat inside source list 1 interface gi0/1 overload
Router(config)# interface gi0/0
Router(config-if)# ip nat inside
Router(config)# interface gi0/1
Router(config-if)# ip nat outside

# Verificação
Router# show ip nat translations
Router# show ip nat statistics

4. VPN (Virtual Private Network)

IPSec VPNSite-to-Site
Fases IPSec:
Fase 1 (IKE): estabelece canal seguro
  - Autenticação (PSK ou certificado)
  - Algoritmos (AES, SHA, DH group)
  - Resultado: IKE SA

Fase 2 (IPSec): túnel de dados
  - Transform set (ESP/AH)
  - Tráfego interessante (ACL)
  - Resultado: IPSec SA

Modos:
- Tunnel: encapsula pacote inteiro (site-to-site)
- Transport: apenas payload (host-to-host)

Protocolos:
- ESP: criptografia + autenticação
- AH: apenas autenticação (sem criptografia)
WireGuardModerno

VPN moderna, simples e de alta performance.

NetmikoPython

Biblioteca para conexão SSH com dispositivos de rede (Cisco, Juniper, Arista, etc.).

from netmiko import ConnectHandler

# Conexão com switch/router
device = {
    "device_type": "cisco_ios",
    "host": "192.168.1.1",
    "username": "admin",
    "password": "senha123",
}

# Comandos show
with ConnectHandler(**device) as conn:
    output = conn.send_command("show ip interface brief")
    print(output)

    # Configuração
    commands = [
        "interface loopback 99",
        "ip address 10.99.99.1 255.255.255.0",
        "description Criado via Python",
    ]
    conn.send_config_set(commands)
    conn.save_config()
ParamikoPython

Biblioteca SSH de baixo nível. Base do Netmiko.

import paramiko

# Conexão SSH direta
client = paramiko.SSHClient()
client.set_missing_host_key_policy(paramiko.AutoAddPolicy())
client.connect("192.168.1.1", username="admin", password="senha123")

# Executar comando
stdin, stdout, stderr = client.exec_command("show version")
print(stdout.read().decode())
client.close()

# Automação em massa
devices = ["192.168.1.1", "192.168.1.2", "192.168.1.3"]
for ip in devices:
    client.connect(ip, username="admin", password="senha123")
    stdin, stdout, stderr = client.exec_command("show running-config")
    with open(f"backup_{ip}.txt", "w") as f:
        f.write(stdout.read().decode())
    client.close()

Módulo 10

SD-WAN

Software-Defined WAN: arquitetura moderna para conectar filiais com inteligência e automação.

1. Conceitos de SD-WAN

SD-WAN — Visão GeralConceito
O que é SD-WAN?
Abstração da WAN tradicional usando software para gerenciar
conectividade, políticas e segurança de forma centralizada.

Componentes:
- vManage: console de gerenciamento centralizado
- vSmart: controlador de políticas e rotas
- vBond: orquestrador (autenticação de dispositivos)
- vEdge/cEdge: roteadores nas filiais

Benefícios vs WAN tradicional:
✓ Múltiplos links (MPLS + Internet + 4G/5G)
✓ Seleção inteligente de caminho (por aplicação)
✓ Gerenciamento centralizado (zero-touch provisioning)
✓ Criptografia end-to-end (IPSec automático)
✓ Visibilidade de aplicações (DPI)
✓ Redução de custo (substitui MPLS por internet)
Políticas SD-WANQoS
Application-Aware Routing:
- Mede latência, jitter, perda por link
- Direciona apps críticas pelo melhor caminho

Exemplo de política:
  VoIP/Video → Link MPLS (baixa latência)
  ERP/CRM → Link Internet (backup: MPLS)
  YouTube → Link Internet (rate-limited)
  Backup → Link mais barato

SLA Classes:
  Latência < 150ms
  Jitter < 30ms
  Perda < 1%
Vendors SD-WANMercado
Principais soluções:
- Cisco Viptela/Meraki
- VMware VeloCloud
- Fortinet Secure SD-WAN
- Palo Alto Prisma SD-WAN
- Aruba EdgeConnect (HPE)
- Versa Networks

SASE (Secure Access Service Edge):
SD-WAN + Segurança na nuvem
- CASB, SWG, ZTNA, FWaaS
- Vendors: Zscaler, Netskope, Cato Networks
Módulo 11

Observabilidade e Monitoramento

SNMP, Prometheus, Grafana e ferramentas para monitorar a saúde e performance da rede.

1. SNMP (Simple Network Management Protocol)

SNMPProtocolo
Componentes:
- Manager (NMS): coleta dados dos dispositivos
- Agent: software no dispositivo que responde queries
- MIB: banco de dados hierárquico de objetos gerenciáveis
- OID: identificador único de cada objeto

Operações:
- GET: consulta valor de um OID
- SET: altera valor de um OID
- TRAP: dispositivo envia alerta ao manager
- WALK: percorre toda a árvore MIB

Versões:
- SNMPv1: community strings (texto plano) — inseguro
- SNMPv2c: melhorias, mas ainda sem criptografia
- SNMPv3: autenticação + criptografia (recomendado!)

# Configuração (Cisco)
Router(config)# snmp-server community READONLY ro
Router(config)# snmp-server community READWRITE rw
Router(config)# snmp-server host 10.0.0.100 version 2c READONLY
Router(config)# snmp-server enable traps

# Consulta via Linux
snmpwalk -v2c -c READONLY 192.168.1.1 system
snmpget -v2c -c READONLY 192.168.1.1 sysUpTime.0

Módulo 12

Design de Redes

Arquiteturas corporativas, modelos hierárquicos, spine-leaf e boas práticas de design.

1. Modelo Hierárquico de 3 Camadas

3-Tier ArchitectureTradicional
┌─────────────────────────────────────────────┐
│              CORE (Núcleo)                  │
│  Alta velocidade, redundância, sem filtros  │
│  Equipamentos: Switches L3 de alta porta    │
└──────────────────┬──────────────────────────┘
                   │
┌──────────────────┴──────────────────────────┐
│          DISTRIBUTION (Distribuição)         │
│  Políticas, ACLs, QoS, inter-VLAN routing   │
│  Equipamentos: Switches L3, Firewalls       │
└──────────────────┬──────────────────────────┘
                   │
┌──────────────────┴──────────────────────────┐
│             ACCESS (Acesso)                  │
│  Conexão de endpoints, VLANs, PoE, 802.1X  │
│  Equipamentos: Switches L2, Access Points   │
└─────────────────────────────────────────────┘

Princípios:
- Cada camada tem função específica
- Redundância em core e distribution
- Escalabilidade horizontal no access
- Separação de responsabilidades

2. Spine-Leaf (Data Center)

Spine-Leaf ArchitectureModerno
     [Spine 1]    [Spine 2]    [Spine 3]
       / | \ \    / | \ \    / | \ \
      /  |  \ \  /  |  \ \  /  |  \ \
[Leaf1] [Leaf2] [Leaf3] [Leaf4] [Leaf5] [Leaf6]
  |       |       |       |       |       |
Servers Servers Servers Servers Servers Servers

Características:
- Cada leaf conecta a TODOS os spines
- Máximo 2 saltos entre quaisquer servidores
- Latência previsível e consistente
- Escalabilidade: adicione mais leafs ou spines
- Sem Spanning Tree (usa ECMP)

Protocolos:
- VXLAN: overlay para estender L2 sobre L3
- EVPN: control plane para VXLAN
- BGP: underlay routing (eBGP entre spine/leaf)

Quando usar:
- Data centers com tráfego East-West intenso
- Ambientes cloud e virtualização
- Redes que precisam escalar horizontalmente

3. Boas Práticas de Design

Alta DisponibilidadeResiliência
Redundância:
- Links redundantes (LAG/LACP)
- Equipamentos redundantes (HSRP/VRRP)
- Caminhos múltiplos (ECMP)
- Fontes de energia redundantes

HSRP/VRRP:
- Virtual IP compartilhado entre routers
- Failover automático (< 3s)
- Active/Standby

Link Aggregation (LACP):
- Múltiplos links físicos = 1 lógico
- Balanceamento de carga
- Tolerância a falha de link
DocumentaçãoOperação
Documentação essencial:
1. Diagrama de topologia (L1, L2, L3)
2. Plano de endereçamento IP
3. Inventário de equipamentos
4. Mapa de VLANs
5. Políticas de segurança
6. Runbooks de troubleshooting
7. Plano de disaster recovery

Ferramentas:
- Draw.io / Lucidchart (diagramas)
- NetBox (IPAM + DCIM)
- Nautobot (automação + docs)
- Git (versionamento de configs)
Checklist de DesignPlanejamento
Antes de implementar, responda:
□ Quantos usuários/dispositivos? (escala)
□ Quais aplicações críticas? (QoS)
□ Requisitos de disponibilidade? (SLA: 99.9%? 99.99%?)
□ Orçamento disponível? (CAPEX vs OPEX)
□ Crescimento previsto em 3-5 anos?
□ Requisitos de segurança e compliance?
□ Integração com cloud (hybrid/multi-cloud)?
□ Equipe disponível para operar?
□ Ferramentas de monitoramento e automação?
□ Plano de migração e rollback?
